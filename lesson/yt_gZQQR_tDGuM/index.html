🧑‍🏫 這支是樂天（Rakuten）的使用案例影片，講他們怎麼用 OpenAI 的 Codex 加快寫程式和修問題。值得看的是它給了具體成果：修復時間少一半、上線時程可望縮短，還講到用了 AI 之後人的工作重心會怎麼變。

  • 00:02 Rakuten 認為購物就是一種娛樂。
    ↳ 樂天把購物看成一種娛樂。逛、比價、挖到好東西的過程本身就好玩，不只是買完就走。這是他們看待自家業務的出發點。
  • 00:02 Codex 幫助 Rakuten 更快地做軟體開發、更快地寫程式。
    ↳ Codex 是 OpenAI 的 AI 寫程式工具，你用文字告訴它要做什麼，它就能幫忙寫、改、檢查程式碼。樂天的意思是，工程師有了它，整個開發流程都變快了。
  • 00:02 Rakuten 是一家全球創新公司，業務橫跨電子商務、金融科技、行動通訊及其他領域。
    ↳ 樂天不只做網購，也做金融科技（fintech，就是用科技提供支付、貸款等金融服務）和行動通訊（電信）等業務。業務範圍這麼廣，背後要寫的軟體也很多。
  • 00:02 在使用 Codex 之前，從規劃到把產品應用程式上線到正式環境可能要一季；有了 Codex，他們預估可以壓縮到幾週或幾個月。
    ↳ 以前一個產品從規劃到上線到正式環境（production，真正給使用者用的系統，不是測試版），可能要花一季，大約三個月。用了 Codex 之後，他們預估能縮短到幾週到幾個月。
  • 00:33 Rakuten 把 Codex 用在漏洞檢查（vulnerability check），平均恢復時間（mean time to recovery）因此降低 50%。
    ↳ 漏洞檢查（vulnerability check）是找出程式裡的安全缺口。平均恢復時間（mean time to recovery）是出狀況後平均要多久才修好。改用 Codex 做檢查後，修復時間少了一半。
  • 00:33 他們認為隨著 Codex 越來越聰明，自己的角色將轉為定義正確的規格，並驗證程式碼是否符合公司標準。
    ↳ 規格（specification）就是把「要做出什麼、要符合哪些條件」寫清楚的說明。他們預期程式會越來越常交給 Codex 寫，人的工作則是把需求講清楚，再檢查成品有沒有符合公司標準。
  • 00:33 他們認為這項技術能夠賦能每個人，並以此在全公司營造正向的動能。
    ↳ 他們認為這項工具能讓公司裡每個人都多做到一些事，所以把它推廣到全公司，帶起大家願意嘗試、互相帶動的正面氣氛。
📘 術語
vulnerability check（漏洞檢查）：字幕沒有定義，只提到 Rakuten 把 Codex 用在這件事上。
mean time to recovery（平均恢復時間）：字幕沒有定義，只提到用 Codex 做漏洞檢查後，這個指標降低了 50%。
production（正式環境）：字幕沒有定義，只提到要把產品應用程式上線到這裡。
specification（規格）：字幕說未來他們的角色是定義正確的規格。
fintech（金融科技）：字幕沒有定義，只把它列為 Rakuten 的業務領域之一。
