🧑‍🏫 這段是 Grok 官方直播裡的一場團隊腦力激盪。團隊想做一個幫人辦 popup 餐會的平台，但討論完決定先不急著寫程式，要自己實際辦一場，邊辦邊派 AI bot 找餐廳、打電話。值得看的是他們怎麼把一個大構想收斂成第一步，以及怎麼把 AI 當成手下分工。

  • 298:25 討論是否需要地圖或位置資料庫，幫使用者做市場調查，找出適合辦 popup 的地點
    ↳ 他們想過加地圖或位置資料庫，也就是把各個地點的資訊整理成能查詢的資料，讓使用者先做市場調查，看哪一區適合辦 popup（跟餐廳合作、為社群辦的短期餐會）。
  • 298:56 討論開發方式：先想大功能，還是用 tracer／MVP 方式先把流程從頭到尾走通；答覆是想先做很陽春（scrappy）的原型，但要先確定 hero use case 和 user flow
    ↳ 可以先規劃大功能，也可以用 tracer／MVP 的方式先把流程走通。MVP 就是最陽春、但能從頭跑到尾的版本。他們選後者，但要先定好 hero use case（最主要的使用情境）和 user flow（使用者的操作步驟）。
  • 298:56 Hero use case：一個人或一群人想辦餐廳 popup，找能合作的餐廳供餐，為自己的社群辦活動，並透過這個平台管理整個 popup 營運
    ↳ 最主要的情境是：一個人或一群人想為自己的社群辦餐會，找願意合作的餐廳供餐，再用這個平台把整場活動從頭管到尾。
  • 299:27 辦 popup 要做的事：找地點、雇人、協調菜單（餐點和飲料），並做活動計畫，例如 run of show 或活動時間表
    ↳ 辦一場要處理的事很多：找場地、找人手、跟餐廳談菜色和飲料。還要排 run of show，就是活動當天的流程表，寫清楚幾點開場、幾點上菜。
  • 299:57 還要能邀請人、管理出席者，活動可能售票也可能不售票
    ↳ 還要能發邀請、掌握誰會來。有的活動要賣票，有的不賣票，平台兩種都得能處理。
  • 299:57 擔心範圍太大，每一項本身都可能是一個產品，所以想把核心流程收斂到最小
    ↳ 他們發現場地、人手、售票這些項目，每一項拆開來都能做成一個獨立產品。全部都做會做不完，所以要砍到只剩最核心的流程。
  • 300:29 最小的活動欄位：活動名稱，加上開始和結束時間（可能要訂位）；另外要知道 popup 類型，是要預約 30 分鐘或一小時的時段，還是單純讓人來參加
    ↳ 最精簡的活動資料只要名稱、開始和結束時間。另外要分清楚活動型態：是讓人預約 30 分鐘或一小時的時段，還是人直接來參加就好。
  • 301:00 提議邊做邊 dog food：他們自己也要辦 popup，所以先專注把 popup 辦起來，再做工具協助，之後慢慢整合進平台
    ↳ 他們提議 dog fooding，就是自己先當自己產品的使用者。反正他們本來就要辦 popup，就先把活動辦起來，過程中卡在哪裡就做工具解決，之後再慢慢收進平台。
  • 301:30 要做的事：找餐廳經營者（字幕寫作 restaurant tour）負責菜單、找人、讓人預訂；但預訂卡在網站這一關
    ↳ 接下來要找餐廳經營者（字幕寫成 restaurant tour）負責菜單、找人手、開放預訂。但預訂要有網頁讓人下單，網站還沒弄好，所以卡在這裡。
  • 302:00 網站已經在收 email，但還沒公布活動時間等細節，所以要先把 landing page 做完
    ↳ landing page 是別人點進來第一眼看到的介紹頁。這一頁已經能收 email 名單，但活動日期等資訊都還沒放上去，所以要先把它補完。
  • 302:00 開始研究舊金山有哪些餐廳可能願意接這類預訂
    ↳ 同時開始調查舊金山有哪些餐廳可能願意接這種 popup 的預訂。
  • 302:31 想開 Twitter 帳號，招募舊金山的餐廳老闆或灣區的主廚；需要的是 outreach bot，不是市場研究 bot；會請 Dr. Eggbot 開始建立
    ↳ 想開 Twitter 帳號，招募舊金山的餐廳老闆或灣區主廚。他們說現在需要的是 outreach bot（主動聯絡人、發訊息的 AI 機器人），不是做研究的 bot，會請 Dr. Eggbot 開始建。
  • 303:03 大家都會寫程式，工程師不會是瓶頸；關鍵是先決定要先做什麼
    ↳ 團隊每個人都會寫程式，做工具不是難處。真正要想清楚的是順序，也就是先做哪一件。
  • 303:34 就像寫 agent skills 一樣，先手動做一遍再自動化；他們還不是辦 popup 的領域專家，不該跳過這一步
    ↳ 他們拿寫 agent skills 來比，那是教 AI 照固定步驟完成某類工作的說明。寫之前要先自己手動做過一遍，才知道怎麼自動化。他們還不懂辦 popup，所以不能跳過這一步。
  • 304:05 提議直接 cold call；Matt 之前分享過把 Grabbot 接上語音 agent 打電話的影片；不一定要全自動，可以先找到電話號碼、撥通後再由人接手
    ↳ 有人提議直接 cold call，也就是事先沒聯繫、直接打電話過去。Matt 分享過把 bot 接上語音 AI 打電話的影片。不必全自動，讓 bot 找號碼、撥通，再換真人講就好。
  • 304:35 可以用 bot 做研究，找餐廳或可合作對象的電話，也可能改寄 email
    ↳ 可以讓 bot 先做研究，把餐廳或可能合作對象的電話整理出來。不打電話的話，也可以改寄 email。
  • 304:35 設定 email：要到 versel 做 DNS 設定（已有網域）；討論要轉寄到其他信箱、申請 Google Workspace，還是用 agent mail 之類的服務
    ↳ 要用自家網域寄信，得到 Vercel（網站託管服務）設定 DNS，也就是告訴網路這個網域的信要送去哪裡。選項有三個：轉寄到現有信箱、申請 Google Workspace，或用 agent mail 這類服務。
  • 305:06 重點是寄出的 email 要像真人寫的（例如像 Matt Palmer 本人），大家也都有個人 email 可用
    ↳ 重點是寄出去的信要讀起來像真人寫的，例如像 Matt Palmer 本人寄的。反正大家都有個人信箱，也可以直接拿來用。
  • 305:06 請 Dr. Dragbot 開一個新的 Grockbot，研究有哪些 restaurant tours 或業者能協助辦 popup
    ↳ 請 Dr. Dragbot 另外開一個新的 bot（字幕寫作 Grockbot），專門研究有哪些餐廳經營者或業者能協助辦 popup。
  • 305:37 從頭到尾盤點後勤：需要能做餐點的服務和地點；列出的要素是幫手、日期、地點；最好先定日期，才能打電話告訴對方哪天辦活動
    ↳ 從頭盤點後勤：要有能出餐的服務和地點，基本要素是幫手、日期、地點三樣。日期最好先定，打電話時才能直接跟對方說「我們哪天要辦」。
  • 306:07 保守抓一個月前準備，暫定 October 15th，讓對外溝通有依據；這件事要記在 Notion，算是 business plan
    ↳ 保守抓一個月準備期，暫定 10 月 15 日，對外聯絡才有依據。這件事要記進 Notion（線上筆記與協作工具），當作初步的營運計畫（business plan）。
  • 306:07 接著要找舊金山和灣區所有能辦這類活動的人，例如 restaurant tour 或 catering company；原本想接 Google Drive 做清單，後來改在 Notion 開新頁面
    ↳ 接著要列出舊金山和灣區所有能辦這種活動的對象，像餐廳經營者或外燴公司。本來想接 Google Drive 來做清單，後來改在 Notion 開新頁面。
  • 306:38 之後再研究地點，並視需要派 bots 平行處理；目前畫面顯示的是 Lauren 的螢幕
    ↳ 地點之後再研究，需要的話可以派好幾個 bot 同時分頭查。這時直播畫面上是 Lauren 的螢幕。

    ↳ 有人的 bot 讀不到 repositories（存放程式碼的專案庫）。建議改接真的 GitHub，或裝 GitHub CLI（用打指令操作 GitHub 的工具）給 bot 用。當事人猜是接錯了 connector（AI 連外部服務的接口）。
  • 307:42 向 Steve 說明：平台會透過 dog fooding 來做，先自己實際辦 popup，再做讓流程變簡單的工具，覺得好用才正式做
    ↳ 跟 Steve 說明方向：平台會靠 dog fooding 做出來。先自己真的辦 popup，再做讓流程變簡單的工具，自己用過覺得好用，才正式做成產品。

    ↳ 第一個功能從找地點下手。講者用他們說的 potato mode，請 Tater 開一個 cloud agent（在雲端自己跑任務的 AI 助理），做幾版找餐廳工具的原型，而且要能很方便地打電話。

    ↳ 還想去 LinkedIn 之類的平台查餐廳背後的人，這樣才能直接找到經理這種能做決定的人，問對方願不願意合作。

    ↳ 工具的構想是：畫面上有地圖和搜尋，可以依菜系、地點找餐廳，找到就能馬上打電話。這只是團隊內部自用的小工具，不用做得好看。
