🧑‍🏫 這支影片的講者原本是 Anthropic 的業務，自認不太懂技術。講者用 Claude 自己做了一個幫忙寫 email 草稿的工具，後來因此換了職位。如果你每天被回信和找資料追著跑，又不是工程師，這支很適合看：它示範了普通上班族怎麼把重複的工作交給 AI。

  • 00:00 講者說一年前完全想不到自己會成為 Anthropic 的 go-to-market architect，也覺得自己不夠懂技術，但有了 Claude 後能設計、打造東西
    ↳ 講者一年前還是業務，覺得自己不夠懂技術。go-to-market architect 是講者後來的新職位，影片只說這個職位負責設計和打造解決方案。講者想說的是：有了 Claude，不會寫程式的人也能做出工具。
  • 00:00 新創客戶的 account executive 通常要管幾百個客戶；講者後期要管大約 600–700 個
    ↳ account executive（簡稱 AE）就是負責跟客戶談生意、維持關係的業務。服務新創公司的 AE 一個人要顧幾百個客戶，講者後期大約要顧 600 到 700 個，光是回信量就很驚人。
  • 00:00 以前常常做到晚上 8、9 點，都在回信，還要在 Slack、知識庫、Google Docs、Google Drive 裡翻找資料
    ↳ 客戶一問問題，講者就得去 Slack（公司內部聊天工具）、知識庫、Google Docs、Google Drive 到處找答案，常常忙到晚上八、九點。大部分時間都花在「找資料」，真正回答的時間反而不多。
  • 00:30 他開始思考怎麼讓 Claude 加入工作流程，於是開發 Class，用來產生寄給客戶的 email
    ↳ 講者沒有等公司發新工具，而是先想：哪段重複的工作可以交給 Claude？答案是寫給客戶的 email，所以講者自己做了一個叫 Class 的工具來產生回信草稿。
  • 00:30 Class 是 Claude Draft 的簡稱，靠串接背景知識（context knowledge）、system prompt 和 pattern matching 來處理收件匣
    ↳ Class 是 Claude Draft 的簡稱，由三樣東西組成：背景資料、system prompt（事先給 AI 的固定指示），還有 pattern matching（字面意思是比對規律，影片沒有細講）。三樣合起來幫忙處理收件匣。
  • 00:30 示範 AE 的一般流程：第一步要先設定 system prompt
    ↳ 用 Class 的第一步是設定 system prompt，也就是先跟 Claude 講清楚「你在幫誰、這個人做什麼工作」。先講好這些，後面寫出來的每封草稿，身分和語氣才會對。
  • 01:04 Class 背後用的是 Claude API；輸入名字（Jared），從下拉選單選角色 account executive，再填寫自己幫客戶處理哪些事，接著產生 prompt
    ↳ API 是讓程式直接呼叫 Claude 的管道，所以 Class 不用另外開聊天視窗。示範時只要填名字 Jared、從選單選 AE、寫下平常幫客戶處理哪些事，工具就會自動產生 system prompt。
  • 01:04 context retrieval（背景資料檢索）用 Google Docs 串接，也能抓網頁 URL，例如從 Claude Doc 網站產生背景資料；示範時是加入一份文件
    ↳ context retrieval 就是「幫 AI 找背景資料」。Class 可以連到 Google Docs，也可以貼網址，例如 Claude 的文件網站。示範時是加入一份文件，讓 Claude 寫信時有資料可以查。
  • 01:04 點開一封 email，再按 generate draft 產生草稿
    ↳ 實際用起來很簡單：在收件匣點開一封客戶來信，按 generate draft（產生草稿），一封回信草稿就出來了。
  • 01:34 Claude 會從官網、文件和內部背景資料抓資訊來寫草稿
    ↳ Claude 寫草稿之前，會先去官網、產品文件和公司內部資料找相關內容。所以草稿有真實資料當根據，不是憑空寫的。
  • 01:34 用這套系統，講者能跟客戶談更技術性的內容，不用再去 Slack、Google Docs 找回信方向，Claude 會先把資料載入再開始寫
    ↳ 以前講者要自己翻 Slack 和 Google Docs 找回信方向，現在改成 Claude 先把資料載入再開始寫。講者因此有餘力跟客戶談比較技術性的問題。
  • 01:34 Class 每天幫他省下至少 2–3 小時回信時間，這套系統大概已經寄出好幾千封 email
    ↳ 講者說 Class 每天至少幫忙省下 2 到 3 小時的回信時間，這套系統大概已經寄出好幾千封 email。回信量越大、內容越重複，省下的時間就越多。
  • 01:34 技術門檻逐漸消失，他能設計更多產品，最後一段再請資深工程師幫忙完成實作
    ↳ 「不懂技術」不再是卡住想法的那道牆。講者能自己設計更多產品，只在最後階段請資深工程師幫忙把實作做完。
  • 02:04 他因此轉任 go-to-market architect，覺得職涯幾乎完全改變，能做出以前做不到的解決方案
    ↳ 做出 Class 之後，講者轉任 go-to-market architect，覺得職涯幾乎整個改變，現在能做出以前做不到的解決方案。
📘 術語
go-to-market architect（GTM 架構師）：講者在 Anthropic 的新職位，負責設計和打造解決方案；字幕沒有進一步定義
account executive (AE)（客戶業務經理）：講者原本的職位，要管理大量客戶並回覆客戶 email
Class (Claude Draft)（Class 寄信草稿工具）：講者自製的工具，串接背景知識、system prompt 和 pattern matching 來處理收件匣
system prompt（系統提示詞）：Class 流程的第一步，輸入名字、角色和工作內容後產生
context retrieval（背景資料檢索）：透過 Google Docs 串接或網頁 URL 取得背景資料，給 Claude 寫草稿用
Claude API（Claude API）：Class 背後使用的技術
pattern matching（模式比對）：Class 處理收件匣的方法之一；字幕沒有進一步解釋
