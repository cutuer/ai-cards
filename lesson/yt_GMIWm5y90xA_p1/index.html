🧑‍🏫 這是 Anthropic 開發者大會 Code with Claude 2026 的開幕演講前段。講者先講自己為什麼愛上寫程式，再用客戶案例和數字說明 AI 進步得有多快，也公布今天的議程和用量上限放寬。最後回顧 Claude 模型一路怎麼演進。想知道 AI 工具接下來往哪走、為什麼大家說它變化快，看這段就夠了。

  • 02:34 講者回憶大學第一次寫複雜程式：當時要排隊直接登入伺服器，因為只有伺服器跑得動 ray tracer
    ↳ 講者大學第一次寫複雜程式時，得排隊登入學校的伺服器，因為只有它跑得動 ray tracer（模擬光線、算出逼真畫面的繪圖程式），一般電腦算不動。
  • 03:06 按下 compile、等著看程式能不能跑的那種喜悅、發現和鬆一口氣的感覺，還有做出世上從沒有過的東西，讓講者從此迷上寫程式
    ↳ compile 是把寫好的程式碼轉成電腦能執行的檔案。按下去後等結果，跑得動就又驚喜又放心；再加上做出世上沒有過的東西，讓他從此迷上寫程式。
  • 03:40 以前要在大學電腦教室排隊才有的東西，現在任何人、任何時間、在任何地方都能用，沒有門檻；常有人說 Claude 讓他們有了超能力
    ↳ 以前要排隊搶學校機器才用得到的運算能力，現在打開 Claude 就有，不用看身分、時間或地點。很多人說用了 Claude 像多了超能力，能做以前做不到的事。
  • 04:10 Stripe 的 developer infra 負責人 Alec Vicker 的團隊要先把 50,000 行 Scala 改寫成 Java 才能升級 JDK，原本估計要 10 個工程週，用 Claude 四天就完成
    ↳ Stripe 是知名的線上金流公司。Scala、Java 是兩種程式語言，JDK 是 Java 的開發工具包。他們要升級，得先把五萬行程式改寫成 Java，原本估 10 週，Claude 四天就做完。
  • 04:10 Binti 共同創辦人兼 CEO Felicia Kukuru 的軟體，是社工安置寄養兒童時用的系統（處理文書、家訪、寄養家庭認證流程）
    ↳ Binti 做的是給社工用的系統。社工安置寄養兒童時，要處理大量文書、安排家訪、審核寄養家庭資格，這些都在這套軟體裡完成。
  • 04:44 Binti 今年用 Claude API 幫社工省下原本花在文書上的時間，寄養家庭認證流程縮短 20 天；講者強調這不只是效率數字，而是讓孩子跟家庭接上
    ↳ Binti 透過 Claude API（讓自家軟體接上 Claude 的管道）幫社工省下寫文書的時間，寄養家庭認證快了 20 天。講者要說的是：這代表孩子能更早被接到家庭裡。
  • 05:14 每個人的感受不一樣：有人天天站在最前線，有人在帶身邊的人跟上，也有人感覺到局勢在變、想看看接下來會怎樣；講者說自己早上擬好的計畫常常中午就得推翻
    ↳ 面對 AI 的變化，每個人的位置不一樣：有人天天在用最新工具，有人在帶同事跟上，也有人還在觀望。講者自己也說，變化快到早上的計畫中午就得改。
  • 05:45 Anthropic 內部常談「the exponential」（指數成長）；幾年前的模型前沿，是能寫出一封像樣的 email
    ↳ the exponential 是指能力進步越跳越大、越跳越快，而不是穩穩往上爬。幾年前最厲害的模型，也只能寫出一封像樣的 email。
  • 06:18 一年前 Opus 4 是頭條，agent 在沒人檢查的情況下跑一小時還算是挑戰目標；六個月前 agent 已能整晚端到端執行，早上起床工作就做完了
    ↳ agent 是能自己連續做事、不用人一步步指揮的 AI。一年前讓它沒人盯著跑一小時就算難；半年前它已經能整晚從頭做到尾，人早上醒來工作就做好了。
  • 06:18 上個月 Mythos 讀完整個 OpenBSD 原始碼，找出一個存在 27 年的漏洞，這個漏洞近三十年來躲過了所有人工審查、fuzzer 和 static analyzer
    ↳ Mythos 讀完整個 OpenBSD（以安全著稱的開源作業系統）的原始碼，找出藏了 27 年的漏洞。人工審查、fuzzer（丟大量亂資料測程式）、static analyzer（不執行、直接掃程式碼找錯）都沒找到。
  • 06:48 能力躍進的幅度越來越大、間隔越來越短，但多數組織導入 AI 仍是線性的，所以 AI 能做到的和實際幫到人的之間有落差
    ↳ 模型能力是跳著往上衝，但公司導入 AI 是一步一步慢慢來。所以「AI 已經做得到的」和「真的幫到人的」之間，差了一大段。
  • 06:48 縮小這個落差、把模型能力轉成真人用來解決問題的東西，就是開發者在做的事
    ↳ 講者認為開發者的工作，就是把模型能力做成一般人拿來解決實際問題的工具，把這段落差補起來。
  • 07:20 Claude 平台的 API 用量年增將近 17 倍；Claude Code 的開發者平均每週執行 Claude 20 小時
    ↳ Claude 平台（開發者拿 Claude 做產品用的服務）的 API 用量一年成長將近 17 倍。Claude Code 是讓 Claude 直接寫程式的工具，開發者平均每週讓它跑 20 小時。
  • 07:52 今天沒有發表新模型，重點是讓產品更好用，好讓開發者幫其他人縮小落差
    ↳ 這次沒有發表新模型，重點是讓現有產品更好用，好讓開發者更容易做出幫到別人的東西。
  • 07:52 議程：Diane 談模型層；Claude 平台更新 Claude-managed agents、outcomes、dreaming、multi-agent orchestration；Angela 和 Caitlin 說明平台怎麼替你處理基礎設施
    ↳ 議程：Diane 談模型；平台新功能有 Claude-managed agents、outcomes、dreaming、multi-agent orchestration，這段只列了名稱沒細講；Angela 和 Caitlin 會說明平台怎麼幫你代管伺服器這類底層設施。
  • 08:25 Claude Code 部分由 Kat 和 Boris 介紹新的 primitives，例如 routines，能讓 Claude Code 自己對自己下 prompt，就算你不在電腦前也行
    ↳ Kat 和 Boris 會介紹 Claude Code 新的 primitives（可以拿來組合的基本功能）。例如 routines，能讓 Claude Code 自己給自己下指令接著做，你不在電腦前它也照樣跑。
  • 08:25 大多數人永遠不會呼叫 Claude API 或打開終端機，而是透過開發者做的東西接觸 AI，例如設計師用 Canva、律師用 Legora、開發者用 coding agent
    ↳ 大多數人不會直接呼叫 API，也不會打開終端機（輸入文字指令的視窗），而是透過開發者做好的產品用到 AI，像設計師用 Canva、律師用 Legora。
  • 09:31 即日起提高開發者在 Claude Code 和 Claude 平台的 rate limits
    ↳ rate limits 是一段時間內能用多少的上限，用完就得等。從今天起，Claude Code 和 Claude 平台的上限都提高了。
  • 09:31 Pro、Max、Team 和按席位計費的 Enterprise 方案，Claude Code 的 5 小時 rate limits 加倍；Claude Opus 的 API 上限也大幅調高
    ↳ Pro、Max、Team，還有按人頭計費的 Enterprise 方案，Claude Code 每 5 小時的用量上限都變成兩倍；透過 API 用 Claude Opus 的上限也大幅放寬。
  • 09:31 這些能做到，是因為擴大了算力合作：與 SpaceX 合作，使用其 Colossus One 資料中心的全部算力
    ↳ 上限能放寬，是因為算力（跑 AI 需要的電腦運算資源）變多了：Anthropic 跟 SpaceX 合作，用下它 Colossus One 資料中心的全部算力。
  • 10:04 這些算力直接投入個人開發者和小團隊；之後會繼續透過現有的算力計畫和更大膽的嘗試，幫大家把 Claude 用到最好
    ↳ 這批新算力會直接給個人開發者和小團隊用。之後還會透過現有的算力計畫，加上更大膽的嘗試，繼續讓大家把 Claude 用得更好。
  • 10:42 Diane 領導研究 PM 團隊，2023 年加入 Anthropic，參與了 Claude 2 以來的每個模型，共 18 個版本，涵蓋 Haiku、Sonnet、Opus，現在還有 Mythos
    ↳ Diane 帶領研究 PM（產品經理）團隊，2023 年加入，從 Claude 2 起參與了 18 個模型版本。Haiku、Sonnet、Opus 是不同等級的模型系列，現在又多了 Mythos。
  • 10:42 Opus 3 的挑戰是讓它確實遵守 JSON 格式，同時成為最會寫長篇程式碼的模型
    ↳ JSON 是固定格式的資料寫法，程式靠它交換資料，格式錯一點就讀不了。Opus 3 的挑戰是既要乖乖照格式輸出，又要是最會寫長篇程式的模型。
  • 11:12 Sonnet 3.5 new（後來大家稱 Sonnet 3.6）讓 Claude 學會安全地使用電腦
    ↳ Sonnet 3.5 new 後來被大家叫做 3.6。它讓 Claude 學會像人一樣操作電腦，像是看畫面、點滑鼠、打字，而且是用安全的方式。
  • 11:12 Sonnet 3.7 有點太過積極（overeager），團隊找出把這個特性開放給使用者和開發者的正確方式，讓大家能發揮 Claude 的最大效用
    ↳ Sonnet 3.7 做事太積極，常多做沒交代的事。團隊沒有硬把這點壓掉，而是找出適合的方式，讓使用者和開發者自己拿捏，發揮它最大的用處。
  • 11:12 去年這時候，團隊用 Claude 4 做出好用的 thinking dials，可以調整 test time compute
    ↳ test time compute 是模型回答時花多少運算去思考。thinking dials 就像旋鈕，可以調它想多久：簡單的問題快答，難題多想一下。去年隨 Claude 4 做到好用。
  • 11:43 過去 12 個月推出了 8 個 frontier model（本段在此結束）
    ↳ frontier model 是指當下最頂尖的模型。過去一年推出了 8 個，平均一個半月一個，正好呼應前面講的「進步越來越快」。
📘 術語
the exponential（指數成長）：Anthropic 常用的說法，指模型能力進步越來越快：躍進越來越大、間隔越來越短
rate limits（使用量上限）：字幕沒定義；提到 Claude Code 有「五小時 rate limits」，這次加倍
routines（例行任務（Claude Code primitive））：Claude Code 的新 primitive，能讓 Claude Code 自己對自己下 prompt，你不在電腦前也能運作
primitives（基本功能元件）：字幕沒定義，只用來稱呼 routines 這類 Claude Code 新功能
multi-agent orchestration（多 agent 協調）：字幕只列為 Claude 平台的更新項目之一，沒有進一步解釋
Claude-managed agents（由 Claude 代管的 agent）：字幕只列為 Claude 平台的更新項目之一，沒有進一步解釋
fuzzer（模糊測試工具）：字幕沒定義；和人工審查、static analyzer 並列為沒找到那個 27 年漏洞的檢查手段
static analyzer（靜態分析工具）：字幕沒定義；同樣是沒找到 OpenBSD 那個漏洞的檢查手段之一
thinking dials（思考程度調整）：在 Claude 4 做到好用的版本，用來調整 test time compute
test time compute（推論時的運算量）：字幕沒定義；只說可以透過 thinking dials 調整
frontier model（前沿模型）：字幕沒定義；提到過去 12 個月推出了 8 個
