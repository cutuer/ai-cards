🧑‍🏫 這是 OpenAI「Build Hour」（官方線上實作講座）的最後一段。主題是 workspace agents，也就是在 ChatGPT 裡建立、可以分享給同事、會自己跨工具把事情做完的 AI 助手（agent）。前半收尾 IT 申請工具的示範，後半是 Q&A，把怎麼建、權限、記憶、分享和費用一次講清楚，想在公司導入的人很實用。

  • 25:15 同一個申請 Screen Studio 的請求，agent Slate 判斷需要 IT review，無法自助取得，並清楚列出理由
    ↳ 有人申請 Screen Studio（一款螢幕錄影軟體），agent Slate 判斷這沒辦法自己直接拿到，要送 IT review，也就是交給 IT 審查，並把原因講清楚。
  • 25:15 已核准工具 Bloom 符合高品質 demo 錄影需求，但使用量過高、沒有可用授權，所以目前被封鎖
    ↳ 公司其實有核准過的錄影工具 Bloom，拍高品質 demo 也夠用。問題是用的人太多，授權（可用的使用名額）已經用完，所以現在拿不到。
  • 25:45 因此 agent 選擇升級給 IT。IT 可以加開授權，或破例允許使用 Screen Studio
    ↳ 自助走不通，agent 就 escalate，也就是把案子轉給 IT。IT 有兩條路可選：多開 Bloom 的授權，或破例讓這個人用 Screen Studio。
  • 25:45 agent 的回覆附上查過的來源、推理和給使用者的指引。使用者不必自己查工具，也不必自己寫理由
    ↳ 回覆裡會附上它查了哪些資料、怎麼判斷、你接下來該做什麼。你不用自己比較工具，也不用自己寫申請理由。
  • 26:16 最後一步，agent 在 Jira 建立 task 給 IT 審核，使用者和 IT 都不用自己開 ticket
    ↳ 最後它直接在 Jira（很多公司用來開單、追蹤工作的系統）建好一張 task 給 IT 審。申請人和 IT 都省掉開單這一步。
  • 26:16 這個 agent 目前處理團隊所有這類請求，替 IT 與 procurement 團隊省下大量時間。通常臨時提出的時效性請求也能及時拿到工具
    ↳ 現在團隊這類申請全交給它處理，IT 和 procurement（採購）省下很多時間。就算是臨時、急著要的工具，通常也能及時拿到。
  • 26:47 IT agent 段落回顧：用既有 skills 建 agent、設定 Slack、在 Slack 互動、查看 run history 與 traces、在 Jira 處理 escalations
    ↳ 回顧這段：用現成 skills（寫好的做事流程）建 agent、接上 Slack（團隊聊天軟體）並在裡面對話、看 run history 與 traces（每次執行的紀錄和步驟），再到 Jira 處理轉交的案子。
  • 27:18 建立 agent 有四種方式。第一種是在對話中建立：描述團隊常做的 workflow，ChatGPT 會協助設定
    ↳ 建 agent 有四種起手方式。第一種最直覺：直接跟 ChatGPT 說你們團隊平常固定在做什麼事，它會幫你把 agent 設定起來。
  • 27:48 第二種是從 templates 開始。templates 內建 skills 和 tools，起步較快，之後再自訂
    ↳ 第二種是套用 templates（現成範本）。裡面已經配好 skills 和 tools（agent 能動用的功能），先跑起來，之後再照自己的需求改。
  • 27:48 第三種是從其他平台匯入 skills 和 apps，帶入既有 workflow，不必從零開始
    ↳ 第三種：你在別的平台已經有 skills 或 apps（串接的外部軟體），可以直接匯進來，原本的工作流程延續下去，不用從頭寫。
  • 27:48 第四種是把已在用的 custom GPTs workflow 拿到 workspace agents 測試。GPTs 轉 workspace agents 的自動轉換器即將推出
    ↳ 第四種是給已經在用 custom GPTs（自訂版 ChatGPT）的人：把原本的流程搬到 workspace agents 試跑。官方說自動轉換工具快推出了。
  • 28:19 custom GPTs 是輕量流程自動化的第一步，許多團隊用它在 ChatGPT 建立共享模板。但剛推出時還沒有合適的模型與 platform primitives
    ↳ custom GPTs 是自動化的入門款，很多團隊拿它當共用範本。但它剛推出時，模型能力和 platform primitives（讓功能能擴充的平台基礎）都還不夠。
  • 28:51 workspace agents 是 GPTs 的下一階段：共享的 agents 能跨工具執行多步驟 workflow，支援排程、approvals 與 follow-through。已有 GPTs 的團隊可先用 agents 測試
    ↳ workspace agents 是升級版：能跨多個工具一步步把事做完，可以排程，碰到要核准的地方會等 approvals（核准），並追到完成。已經有 GPTs 的團隊可以先拿來試。
  • 28:51 權限：builder 始終掌控，決定 agent 能用哪些工具與資料，以及較敏感的任務何時需要 approval
    ↳ 權限由 builder（建立 agent 的人）決定：它能碰哪些工具和資料、哪些比較敏感的動作要先經過核准，都由 builder 設定。
  • 29:23 Enterprise 與 EDU 方案的 admin 可用 role-based access controls 決定誰能用 agents、哪些 apps 可用。compliance API 讓 admin 長期監控與管理使用情況
    ↳ 企業版、教育版（Enterprise／EDU）的 admin（管理員）可以用 role-based access controls 依角色決定誰能用 agents、能接哪些 apps；compliance API 則讓管理員長期監控使用狀況。
  • 29:53 agents 可搭配 Microsoft 工具，例如 SharePoint、Outlook、Teams。demo 用 Google Drive 只是因為較好設定
    ↳ 公司用的是 Microsoft 也沒關係，SharePoint、Outlook、Teams 都能接。demo 用 Google Drive，只是因為它比較好設定。
  • 30:23 agent 能讀寫哪些內容，取決於各 app、Microsoft 權限與 workspace admin 設定。demo 做的東西也能用 Microsoft 產品重現
    ↳ agent 能看、能改哪些內容，取決於各 app 的權限、Microsoft 那邊的設定，以及 workspace 管理員的設定。demo 的做法換成 Microsoft 也做得出來。
  • 30:23 agents 目前可在 ChatGPT 和 Slack 中執行。Teams 等工具還不行，官方正積極投入，之後會陸續增加
    ↳ 目前 agent 只能在 ChatGPT 和 Slack 裡運作，Teams 這類工具還不支援。官方說正在積極開發，之後會陸續增加。
  • 30:54 建立 agent 時可啟用 memory。memory 是持久的檔案系統，可存放檔案和筆記，供之後的 runs 重複使用
    ↳ 建立時可以打開 memory。它不是模糊的「記得你」，而是一個會一直保留的資料夾，存放檔案和筆記，之後每次執行（run）都能拿出來用。
  • 30:54 memory 可以透過 prompt 明確要求加入，agent 也可以自行決定自動加入
    ↳ 東西放進 memory 有兩種方式：你在指令裡直接叫它記下來，或是 agent 自己判斷值得記，就自動存進去。
  • 30:54 memory 依 channel 區分。在 ChatGPT 中，每位使用者的 agent instance 各有自己的檔案系統
    ↳ memory 會依使用的地方分開。在 ChatGPT 裡，每個人用的是自己那一份 agent，各有一個獨立的資料夾。
  • 31:26 每個 Slack channel 有自己的 memory。在共享 Slack channel 裡，所有訊息共用該 channel 的 memory
    ↳ 在 Slack 則是一個頻道一份 memory。在共享頻道裡，所有人的訊息都進同一份，等於頻道成員共用這個 agent 的記憶。
  • 31:58 agents 可以保持私人，也可以用連結分享給組織內任何人，或列在公司的 workspace agent directory
    ↳ agent 可以只給自己用，也可以用連結分享給公司任何人，或放上 workspace agent directory（公司內部的 agent 目錄），讓大家自己找來用。
  • 31:58 agents 只能分享給 ChatGPT workspace 成員。分享時可允許他人 duplicate 和 remix，例如 sales meeting prep agent
    ↳ 只能分享給同一個 ChatGPT workspace（公司帳號空間）的成員。你可以開放 duplicate／remix，讓別人複製一份改成自己的版本，例如改一個業務會議準備 agent。
  • 31:58 admin 可控制誰能 build、publish、share agents。Enterprise 與 EDU 方案透過 admin settings 與 role-based access controls 設定
    ↳ 誰能建立、發布、分享 agent，admin 都管得到。Enterprise 和 EDU 方案是在管理設定和依角色的權限控管裡調整。
  • 32:29 目前只有 agent 的 owner 能編輯，很快會開放多人共同編輯
    ↳ 目前只有 owner（建立並擁有這個 agent 的人）能修改設定。官方說很快會開放多人一起編輯。
  • 33:01 OpenAI 內部每個 business unit 都有 agents。agents 有明確專門角色、並配齊所需 apps、tools、files、skills、instructions 時效果最好
    ↳ OpenAI 內部每個部門都有 agent。他們的經驗是：讓一個 agent 專心負責一種工作，並備齊它需要的 apps、工具、檔案、skills 和指示，效果最好。
  • 33:01 可以把 agent 想成自己打造的能幹團隊成員，提供它成功所需的一切和指引
    ↳ 心態上可以把它當成你親手帶出來的能幹同事：要它做得好，就要給足資料和工具，並清楚交代怎麼做。
  • 33:31 agent 有 memory，可隨時間被引導或修正而持續改進。也可以繼續用 ChatGPT 修改、改善 agent 行為
    ↳ 因為有 memory，你每次糾正、引導，它都會越做越好。想改它的做法，也可以直接請 ChatGPT 幫你調整 agent。
  • 33:31 不一定要用 desktop app。可直接在 web 建立、執行、分享、檢視 agents，也能在 ChatGPT、Slack、desktop app、mobile 上使用
    ↳ 不一定要裝 desktop app（電腦版程式）。用網頁版就能建立、執行、分享和查看 agent；要用的時候，ChatGPT、Slack、電腦版、手機都可以。
  • 34:02 agents 在雲端執行，人不在時也會繼續工作。今天兩個 demo agent 都在雲端：一個依排程提供通勤時看的筆記，另一個在 Slack 運作
    ↳ agent 在雲端（OpenAI 的伺服器）上跑，你不在它也會繼續做。今天兩個例子都是這樣：一個照排程整理通勤時看的筆記，一個在 Slack 處理申請。
  • 34:33 定價：Workspace agents 目前是 research preview，May 6th 前免費，講者鼓勵大家在這段期間充分試用
    ↳ 定價：當時是 research preview（搶先試用階段），May 6th（5 月 6 日）前免費。講者鼓勵大家趁這段期間盡量多試。
  • 34:33 May 6th 之後改為 credit-based pricing。每次 agent run 消耗的 credits 取決於 agent 的複雜度與執行的任務
    ↳ 5 月 6 日之後改用 credit-based pricing，也就是點數制。每跑一次扣多少點，要看 agent 有多複雜、這次做的事有多大。
  • 35:04 計價概念類似較複雜的 Codex tasks 會用較多 credits，因為 agents 有相同的 harness，能執行長時間的複雜任務
    ↳ 概念跟 Codex（OpenAI 寫程式用的 agent）一樣，越複雜的任務花越多點數，因為兩者用同一套 harness，也就是能撐住長時間複雜工作的底層。
  • 35:04 接近 May 6th 時，會透過 admin 與 billing 管道提供更具體的定價說明
    ↳ 影片中還沒講具體價格，只說接近 5 月 6 日時，會透過管理員和帳務的管道公布更詳細的說明。
  • 35:35 與 Codex 的差異一：Workspace agents 是為 teams 設計，可分享給公司內不同職能的人
    ↳ 跟 Codex 的第一個差別：workspace agents 是為團隊設計的，可以分享給公司裡不同部門、不同職務的人一起用。
  • 35:35 與 Codex 的差異二：在雲端執行，電腦關機也會繼續跑。也可部署到不同環境，例如直接在 Slack 使用
    ↳ 第二個差別：它在雲端跑，你電腦關機它還在工作。它也能部署到不同地方，例如直接在 Slack 裡使用。
  • 35:35 更多 triggers 即將推出
    ↳ triggers 是讓 agent 開始動作的觸發方式，像是排程時間到了，或在 Slack 收到訊息。官方說會再推出更多種。
  • 36:05 skills 像是 playbook、best practices 與流程，可以被 codify，或是你已在其他平台和工具中使用的東西
    ↳ skills 是把「這件事該怎麼做」寫下來的東西，包括流程、注意事項和最佳做法；也可以是你在其他平台或工具已經在用的那一套。
  • 36:05 agent 是實際做事的 worker，會運用 skills 與其他 instructions 完成真正的工作
    ↳ agent 才是真正動手做事的角色。它依照 skills 和你給的其他指示，去把實際的工作完成。
  • 36:35 一個 agent 可以有多個 skills，並依手上的任務選用。skills 有時包含 scripts 或其他方向與指引
    ↳ 一個 agent 可以有好幾個 skills，遇到什麼任務就挑對應的來用。有些 skill 還附 scripts（可以直接執行的小程式）或其他指引。
  • 36:35 agent 除了 skills，也會使用 apps 和 tools 完成整體工作
    ↳ 除了 skills，agent 也會動用 apps 和 tools，例如讀寫雲端文件、在 Jira 開單，一起把整件事做完。
  • 37:06 會後將分享的資源：製作 sales meeting prep 的 cookbook，以及其他附加 demo 資源
    ↳ 會後會分享 cookbook（一步步的實作教學），教你做業務會議準備的 agent，另外還有其他 demo 的相關資源。
  • 37:06 接下來有兩場聚焦 API 的 build hours，可透過連結報名，也能觀看過去的 build hours
    ↳ 接下來有兩場以 API（讓程式串接 OpenAI 服務的介面）為主題的 Build Hour，可以從連結報名，過去的場次也能回看。
📘 術語
IT review（IT 審核）：請求無法自助完成時，交由 IT 審查處理，例如加開授權或破例允許使用
escalate / escalation（升級處理）：agent 判斷無法自助時，把請求轉交給 IT 處理
Jira（Jira）：agent 在其中建立 task，讓 IT 審核並解除使用者的阻礙
procurement（採購）：與 IT 並列、因這個 agent 省下大量時間的團隊
run history / traces（執行紀錄／追蹤紀錄）：IT agent 段落中示範可以查看的 agent 執行紀錄
templates（範本）：內建 skills 和 tools 的起點，可更快開始，再自行客製化
skills（技能）：像 playbook、best practices 與流程，有時含 scripts，供 agent 運用
custom GPTs（自訂 GPTs）：輕量流程自動化的第一步，常用來建立共享模板
platform primitives（平台基礎元件）：GPTs 剛推出時尚未具備、讓它真正強大可擴充的平台基礎
approvals（核准）：由 builder 決定較敏感的任務何時需要核准
role-based access controls（角色權限控管）：Enterprise／EDU admin 用來定義誰能用 agents、哪些 apps 可用
compliance API（合規 API）：讓 admin 長期監控與管理使用情況
memory（記憶）：持久的檔案系統，存放檔案和筆記供之後的 runs 使用，依 channel 區分
workspace agent directory（工作區 agent 目錄）：公司內列出 agents 的目錄，只限 ChatGPT workspace 成員
duplicate / remix（複製／改編）：分享 agent 時可允許他人複製並改編
research preview（研究預覽）：Workspace agents 目前的階段，May 6th 前免費
credit-based pricing（點數計價）：May 6th 後的計價方式，消耗量依 agent 複雜度與任務而定
harness（執行框架）：agents 與 Codex 共用、能執行長時間複雜任務的底層
triggers（觸發方式）：啟動 agent 的方式，例如 Slack，更多即將推出
cookbook（實作指南）：會後分享的 sales meeting prep 製作資源
✏️ 小考一題

根據影片，Workspace agents 目前的定價安排是什麼？
