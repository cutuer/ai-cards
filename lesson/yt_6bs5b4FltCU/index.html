🧑‍🏫 這支影片用「agent 循環」來說明 Claude Code 為什麼不只是聊天工具：它會自己找資料、動手改檔案，做完還會回頭檢查。影片也講了它一次能記住多少東西、它能用哪些工具，以及你怎麼控制它能不能自己動手。想放心把工作交給它，先懂這幾個觀念就夠了。

  • 00:05 Claude Code 和一般聊天 app 不同，最適合用「agent 循環」（agent cycle）來說明它怎麼運作
    ↳ 一般聊天 app 是你問一句、它答一句。Claude Code 是 agent，也就是會自己決定下一步、真的動手做事的 AI，所以要用「做事、檢查、再做」的循環來理解它。
  • 00:05 循環第一步：你在 Claude Code 輸入一個查詢（query）
    ↳ 循環從你開口開始：你輸入一個 query（查詢），就是你交代的任務或問題，例如「幫我把這份報表的日期格式統一」。
  • 00:05 第二步：Claude Code 收集執行請求所需的 context，方式是與模型互動，模型會回傳文字，或是呼叫一個工具
    ↳ 接著它先收集 context，就是完成任務需要的背景資訊。收集的方法是跟模型來回互動：模型可能直接回一段文字，也可能決定叫某個工具去查東西。
  • 00:05 第三步：採取行動，例如編輯檔案或執行指令
    ↳ 資訊夠了，它就真的動手，例如直接修改檔案內容，或在電腦上執行一個指令，而不是只告訴你「你可以這樣改」。
  • 00:35 第四步：檢查結果，判斷是否達成你查詢時預期的目標
    ↳ 做完不代表交差。它會回頭看結果，對照你一開始想要的東西，判斷到底有沒有做到。
  • 00:35 若已達成，Claude 就結束，等待下一個請求；若未達成，就回頭重新跑一次循環，直到結果完成且經過驗證
    ↳ 做到了，它就停下來等你下一個指令。沒做到就再跑一輪：再查、再改、再檢查，一直到結果完成而且確認過為止。
  • 00:35 循環進行中，你可以補充 context、中斷工作，或引導模型朝你的目標前進
    ↳ 它在跑的時候你不用乾等，可以隨時補充資訊、喊停，或是提醒它「方向不對，往這邊走」。
  • 00:35 Claude 有 context window，決定它能儲存和看到多少資訊，包括對話內容、檔案內容、指令結果等
    ↳ context window 是它一次能「看在眼裡」的資訊容量。你們的對話、它讀過的檔案、指令跑出來的結果，全都佔這個空間。
  • 01:05 達到上限時，Claude Code 會壓縮對話：自動決定哪些內容可以從 context window 移除、哪些要摘要，以騰出空間
    ↳ 空間快滿的時候，它會自動 compress（壓縮）對話：判斷哪些舊內容可以丟掉、哪些濃縮成摘要，騰出位置繼續做。所以很早講過的細節，可能最後只剩摘要。
  • 01:05 工具是 agent 運作的基礎；目前大多數 AI 助理只是接收和回傳文字，中間沒有任何動作
    ↳ tool（工具）是讓 AI 能實際做事的功能。大多數 AI 助理只會收文字、回文字，中間不會真的去做什麼事；有了工具，agent 才做得起來。
  • 01:35 工具讓 Claude Code 和其他 agent 能自己判斷何時要執行程式碼來完成任務，例如讀取檔案或網路搜尋的工具
    ↳ 有了工具，Claude Code 能自己判斷什麼時候該跑一段程式來完成任務，例如打開檔案來讀，或上網搜尋資料。
  • 01:35 Claude Code 用 semantic search 來判斷何時呼叫工具並取得結果
    ↳ semantic search（語意搜尋）是照「意思」找東西，不是逐字比對。影片說 Claude Code 靠它判斷什麼時候該叫工具，再把結果拿回來用。
  • 01:35 Claude Code 有權限模式；預設情況下，編輯檔案或在終端機執行指令前都必須取得明確許可
    ↳ permission modes（權限模式）決定它能自己做多少事。預設是改檔案前，或在 terminal（終端機，就是打指令操作電腦的視窗）跑指令前，都要先問過你。
  • 01:35 可以用 Shift + Tab 切換權限模式
    ↳ 在 Claude Code 裡按 Shift + Tab，就能在不同權限模式之間切換。
  • 01:35 「auto-accept」模式會直接編輯檔案、不再詢問，但執行指令時仍會請求許可
    ↳ auto-accept 模式下，改檔案它會直接改、不再問你；但要執行指令的時候，還是會先問你同不同意。
  • 02:05 Planning mode 使用唯讀工具，在開始動手前先擬出行動計畫
    ↳ Planning mode（規劃模式）只用唯讀工具，也就是只看不改。它會先把打算怎麼做列成計畫給你看，之後才開始動手。
  • 02:05 跳過權限時要小心：讓 Claude Code 完全自由執行指令，代表錯誤可能更難在發生前被發現
    ↳ 你也可以讓它完全跳過權限，想跑什麼指令就跑，但要小心：少了你把關，它出錯時你可能來不及在事情發生前攔下來。
  • 02:05 Claude Code 在你的終端機裡結合了多種 agent 概念：agent loop、受管理的 context window、工具、可自訂的權限
    ↳ 總結來說，Claude Code 把這幾個概念都裝進你的終端機裡：會自己跑的循環、會自己管理的記憶空間、工具，還有可以調整的權限。
  • 02:35 它能讀取你的程式碼庫、對其採取行動，並驗證自己的成果，這讓它和聊天視窗有根本上的不同
    ↳ 它能讀你的 codebase（整個專案的程式碼和檔案），直接動手修改，還會自己驗證成果。這是它和只能聊天的視窗最根本的差別。
📘 術語
agent cycle / agent loop（agent 循環）：輸入查詢→收集 context→採取行動→檢查結果，未達成就重複循環，直到完成並驗證
context（脈絡／上下文）：執行請求所需的資訊；循環中使用者也可以自行補充
context window（上下文視窗）：決定 Claude 能儲存和看到多少資訊，如對話、檔案內容、指令結果
compress (conversation)（壓縮對話）：達到上限時，自動決定哪些內容要移除、哪些要摘要，以騰出空間
tool（工具）：agent 運作的基礎，讓 agent 判斷何時執行程式碼完成任務，例如讀檔、網路搜尋
semantic search（語意搜尋）：Claude Code 用它來判斷何時呼叫工具並取得結果
permission modes（權限模式）：預設在編輯檔案或執行終端機指令前需取得明確許可；可用 Shift + Tab 切換
auto-accept mode（自動接受模式）：直接編輯檔案不詢問，但執行指令仍會請求許可
Planning mode（規劃模式）：使用唯讀工具，在開始前先擬出行動計畫
terminal（終端機）：Claude Code 運作的地方；在其中執行指令預設需要許可
codebase（程式碼庫）：Claude Code 能讀取它、對它採取行動，並驗證自己的成果
✏️ 小考一題

根據影片，Claude Code 的「auto-accept」模式怎麼處理權限？

A. 只使用唯讀工具，先擬出行動計畫B. 編輯檔案和執行指令都不再詢問C. 編輯檔案和執行指令前都必須取得明確許可D. 編輯檔案不詢問，但執行指令仍會請求許可
看答案
答案：D。[01:35]–[02:05] 提到「auto-accept」模式編輯檔案時不詢問，但執行指令仍會請求許可；只用唯讀工具的是 Planning mode，兩者都要許可則是預設模式
