🧑‍🏫 這支影片由 Notion 的產品經理示範，怎麼把 Claude Managed Agents 接進 Notion。Claude Managed Agents 是讓 Claude 在雲端幫你跑任務的產品，接進去之後，一次丟一大串工作，AI 就會同時處理。值得看的是它展示了一種「交代完就能去忙別的」的工作方式，而且示範的是非工程師也常做的新客戶導入流程。

  • 00:00 講者 Eric 是 Notion 的產品經理（PM），負責 agents 和 agent orchestration
    ↳ 講者 Eric 是 Notion 的產品經理（PM，決定產品要做什麼的人）。他負責 agent（能自己動手完成任務的 AI 助手），以及 agent orchestration（替工作找對的 agent，並統一管理流程）。
  • 00:00 他有 30 個任務要做成 prototype，全部拖去開始執行，Claude 就自己跑起來；他去拿個零食，回來時 prototype 全都做好了，他說這就是關鍵突破
    ↳ 他有 30 件事要先做成 prototype（先做出來看看的初版樣品），一口氣全丟給 Claude 開跑，自己去拿零食，回來就全做好了。突破在於：人不用守在旁邊一件一件盯。
  • 00:00 Notion 想成為 agent orchestration 平台，認為 Notion 很適合讓人和 agent 協作
    ↳ Notion 想成為指揮 agent 做事的地方。大家本來就把文件、任務和資料放在 Notion，所以人跟 agent 在同一個地方分工，是很自然的做法。
  • 00:33 目標是把適合這份工作的 agent 找來一起做，再由 Notion 幫忙管理你所有的 workflow
    ↳ 目標是每件工作都找最合適的 agent 來做，再由 Notion 統一管理你所有的 workflow（工作流程，也就是一件事從開始到完成的各個步驟）。
  • 00:33 把 managed agents 帶進 Notion 的原因：Claude 很擅長複雜、長時間執行的任務
    ↳ 為什麼接 Claude：它擅長步驟多、要跑很久的任務，例如從頭做出一個網頁，而不只是回你一句話。
  • 00:33 如果要自己從頭做，是一項超級燒腦的工程，好像要有這方面的博士學位才做得起來
    ↳ 要讓 AI 長時間穩定跑任務，背後有很多技術難題。Eric 的意思是，如果 Notion 自己從零打造，門檻高到好像要有這方面的博士學位才做得起來。
  • 00:33 managed agent 產品讓 Claude 可以 plug and play 直接接上，而且 session 是在雲端執行
    ↳ Claude Managed Agents 讓 Claude 可以 plug and play（像插頭插上就能用，不用從頭自己做）。每個任務的 session（一次執行的工作單位）都在雲端的伺服器上跑。
  • 01:03 Notion 只要串接 API，就能給客戶用；客戶因此可以在 Notion 裡一次啟動大量工作
    ↳ Notion 只要串接 API（讓兩個系統互相溝通的接口），就能把這個功能開放給客戶。客戶就能直接在 Notion 裡一次啟動大量工作。
  • 01:03 示範案例是很多非技術使用者會做的事：客戶 onboarding。以虛構客戶 Harbor and Pine（生活風格品牌）和它的一串待辦事項為例
    ↳ 示範刻意挑非工程師常做的事：客戶 onboarding（新客戶進來後的導入、開通、交接流程）。用一個虛構的生活風格品牌 Harbor and Pine 和它的一長串待辦來演示。
  • 01:34 Notion 裡有一個 custom agent，被授權存取所有客戶資料庫和任務看板，有完整 context 可以在背後協助 onboarding workflow；這個 agent 背後也是 Claude
    ↳ Notion 裡設了一個 custom agent（自訂的專屬 AI 助手），能讀取所有客戶資料庫和任務看板，掌握完整 context（背景資訊），在背後推動 onboarding。它背後也是 Claude。
  • 01:34 操作：叫出「client onboarding manager」，把待辦事項轉成任務，任務會出現在任務看板上
    ↳ 實際操作：叫出名為「client onboarding manager」的助手，讓它把待辦清單轉成一張張任務，這些任務就會出現在任務看板上。
  • 02:04 把任務全部丟進去，側邊會啟動一堆 agent threads，接著交給 Claude，由 Claude 為每個任務啟動一個 Claude session
    ↳ 把任務全丟進去後，側邊會出現一串 agent threads（每個任務各自的 AI 工作串）。接著交給 Claude，它替每個任務各開一個 session，同時進行。
  • 02:04 可以直接在 Notion 裡跟那個 Claude session 對話，畫面會同步反映實際啟動的 session
    ↳ 你可以直接在 Notion 裡跟某個 session 對話、下指令。Notion 畫面上顯示的，就是實際正在跑的那個 session。
  • 02:04 到 Claude platform 可以看到這個 session 正在 Claude Managed Agents 上執行，看到的是另一種角度的畫面
    ↳ 同一個 session 也能到 Claude platform（Anthropic 給開發者用的後台）查看，會看到它正在 Claude Managed Agents 上執行，只是換成開發者的角度。
  • 02:36 對開發端很有用：可以看到執行狀況，也可以拿這些 traces 回頭改進 agent
    ↳ 這對開發這套功能的人很有用：看得到每個任務的執行狀況，還能用 traces（AI 一步步做了什麼的執行紀錄）找出做不好的地方，回頭改進 agent。
  • 02:36 能跑長時間任務的 harness 非常重要，一個任務可能要跑 20 分鐘甚至一小時
    ↳ harness（包在模型外面、讓它能長時間工作的一套機制）很重要，因為一個任務可能要跑 20 分鐘，甚至一小時。
  • 02:36 持續執行、管理記憶、長時間維持高品質輸出，這一層建在模型之上，而且非常關鍵
    ↳ 模型本身負責思考；要讓它持續跑、記得前面做過什麼、做到後面品質也不掉，靠的是建在模型上面的這一層。Eric 認為這層非常關鍵。
  • 03:07 很多任務已經完成，例如做出一個範例首頁，內容是從 Notion 裡的 context 抓來生成的；想修改的話可以直接在那裡跟 Claude 對話
    ↳ 很多任務已經完成，例如一個範例首頁，內容是從 Notion 裡現有的資料生成的。想改哪裡，直接在那裡跟 Claude 說就好。
  • 03:07 Eric 說 managed agent 產品對他來說就像遊樂場，可以同時啟動一大堆工作
    ↳ Eric 說 managed agent 產品對他來說像遊樂場：可以同時開一大堆工作，不必一件一件排隊等。
📘 術語
agent orchestration（agent 協調調度）：把適合這份工作的 agent 找來一起做，並幫忙管理所有 workflow
Claude Managed Agents（Claude 託管式 agent）：讓 Claude 可以 plug and play 直接接上的產品，session 在雲端執行，串接 API 就能用
plug and play（隨插即用）：不用自己從頭做，就能直接把 Claude 帶進產品
session（工作階段）：Claude 為每個任務啟動的執行單位，可以在 Notion 裡跟它對話
custom agent（自訂 agent）：Notion 裡被授權存取客戶資料庫和任務看板、有完整 context 的 agent
agent threads（agent 執行串）：丟任務進去後在側邊啟動的一串串 agent 工作，會交給 Claude 處理
traces（執行紀錄）：在 Claude platform 上看到的執行過程，可以拿來改進 agent
harness（執行框架）：能跑長時間任務、管理記憶、維持輸出品質的一層，建在模型之上
prototype（原型）：Eric 用 30 個任務讓 Claude 自動做出來的東西
