🧑‍🏫 這支影片講 Claude Code（Anthropic 出的寫程式 AI 工具）的「工作記憶」怎麼運作：它能記多少、滿了會發生什麼事，還有幾個指令和習慣可以省空間。如果你跟 AI 聊很久之後，發現它忘了前面講過的事，這支影片會告訴你原因，也教你怎麼處理。

  • 00:06 Context 是 Claude 的工作記憶。它讀的每個檔案、跑的每個指令、你送的每則訊息，都會佔用 context window 的空間
    ↳ Context 就是 Claude 做事時腦中記著的東西。它看過的檔案、跑過的指令、你講的每句話都會累積在這裡，不會自己消失。
  • 00:06 Context window 是 Claude 記憶裡能容納的空間量。輸入 prompt、讀檔、執行 tool call、拿到 tool call 結果，都會加進 context window
    ↳ Context window 是這份工作記憶的容量上限。你打的 prompt（給 AI 的指令文字）、Claude 用工具去讀檔或跑指令（叫 tool call），以及工具傳回來的結果，全都會佔掉容量。
  • 00:06 Context window 能放的東西有限，所以要盡量優化它的使用
    ↳ 容量有限，塞滿了就放不下新東西。所以重點不是塞得越多越好，而是只留下對手上工作真正有用的內容。
  • 00:36 快到上限時，context window 會自動 compact：整理出重要細節的摘要，並移除不必要的 tool call 結果，騰出大量空間
    ↳ 記憶快滿時，Claude 會自動 compact（壓縮）：把前面的對話整理成重點摘要，再丟掉用不到的工具結果，一次空出很多位置，工作就能繼續。
  • 00:36 要注意，compaction 有可能遺失先前對話裡的細節
    ↳ 摘要一定有取捨，你之前交代的小條件或細節可能沒被留下來。很重要的要求，壓縮完最好確認 Claude 還記得。
  • 00:36 也可以用 /compact 手動 compact 到目前為止的所有內容。想清出空間、又想保留先前工作的記憶時很方便
    ↳ 不想等它自動壓縮，可以自己輸入 /compact。適合對話已經很長、但手上的事還沒做完，想留下前面的進度重點時用。
  • 01:07 想完全從頭開始、不保留先前工作的記憶，就執行 /clear，它會移除所有內容
    ↳ /clear 是整個清空，Claude 會忘掉這次對話的所有內容，等於開一個全新的對話。要做完全不相干的事時用它。
  • 01:07 執行 /context 可以查看 context 狀態：目前 context 有多大、哪些類別佔最多空間，還有一張圖表呈現這些資訊
    ↳ 輸入 /context 可以看目前記憶用了多少、哪一類東西最佔空間，還附一張圖，一眼就看得出是什麼在吃容量。
  • 01:07 經驗法則：正在做某個 feature、context 超出 context window 但還要繼續時，就用 compact，讓 context 跟這個 feature 保持相關
    ↳ 同一個 feature（一項功能）還沒做完、記憶卻快滿了，就用 compact。留下來的都是跟這項功能有關的重點，可以順順接著做。
  • 01:37 經驗法則：plan 完成、要開始新的 feature 時，就用 clear，避免先前的對話讓新東西產生偏差（bias）
    ↳ plan（事先規劃好的做法）執行完、要換下一個功能時，就用 clear。不然舊對話會帶偏（bias）Claude，讓新工作被前面的想法影響。
  • 01:37 希望 Claude 在其他 session 也記得的事，寫進 Claude.md 檔案，它就不必每次從頭重新摸索
    ↳ Claude.md 是一份寫給 Claude 看的說明檔。一個 session（一段對話）結束，記憶就沒了；把要長期記住的規則寫進這份檔案，開新對話就不用重教一次。
  • 02:10 要講得具體。反諷的是，prompt 寫得越短，長期下來反而更佔 context
    ↳ 把話講清楚比省字重要。一句很短的 prompt 看起來省空間，但 Claude 看不懂就得自己去找、去猜，長期下來反而用掉更多記憶。
  • 02:10 指示不夠明確，Claude 就得多翻你的 codebase、自己想，比你多寫一兩句說清楚要佔用更多 context window 空間
    ↳ 指令太模糊，Claude 就得翻遍你的 codebase（整個專案的程式碼）自己推敲，每翻一次都佔空間。多寫一兩句，講清楚要改哪裡、想要什麼結果，划算多了。
  • 02:10 MCP servers 預設會把所有可用的工具載入 context。如果裝了很多跟專案無關的 MCP servers，可以考慮關掉
    ↳ MCP server 是讓 Claude 連上外部工具或服務的擴充元件。它預設會把所有工具的說明都放進記憶，裝了很多跟專案無關的，就是白佔空間，可以關掉。
  • 02:10 也可以試試 skills。它的運作方式跟 MCP servers 類似，但不會把整個內容放進 context，能省空間
    ↳ Skills 是另一種幫 Claude 擴充能力的方式，用途跟 MCP server 類似，但不會一開始就把全部內容塞進記憶，比較省空間。
  • 02:40 Subagent 跟主 agent 平行執行，但有一個完全獨立的 context window
    ↳ Subagent 是主 agent（跟你對話、負責主要工作的那個 Claude）派出去的幫手。兩邊同時工作，但 subagent 有自己獨立的記憶空間，不會佔到主 agent 的。
  • 02:40 只需要答案、不需要過程的任務（例如「authentication endpoints 在哪裡」），可以交給 subagent 做，只把摘要回傳給主 agent
    ↳ 像「authentication endpoints（處理登入驗證的程式入口）在哪」這種只要答案的問題，可以交給 subagent 去找。它只回報結論，主對話就不會被搜尋過程塞滿。
📘 術語
context（脈絡／上下文）：Claude 的工作記憶，讀檔、跑指令、你的訊息都會佔用它的空間
context window（context 視窗）：Claude 記憶能容納的空間量，容量有限
tool call（工具呼叫）：字幕只提到執行 tool call 和它的結果都會加進 context window
compaction / /compact（壓縮）：整理出重要細節的摘要、移除不必要的 tool call 結果以騰出空間，可能遺失細節；快到上限時自動執行，也能手動執行
/clear（清除指令）：移除所有內容，完全從頭開始，不保留先前工作的記憶
/context（查看 context 指令）：顯示 context 大小、佔最多空間的類別，以及一張圖表
Claude.md（Claude.md 檔案）：放希望 Claude 在其他 session 也記得的事，讓它不必從頭重新摸索
MCP server（MCP 伺服器）：預設會把所有可用工具載入 context，與專案無關的可以關掉
skills（技能）：運作方式類似 MCP servers，但不會把整個內容放進 context，能省空間
subagent（子代理）：跟主 agent 平行執行，有完全獨立的 context window，可以只回傳摘要
