🧑‍🏫 這支是 Gradient Labs 創辦人分享他們怎麼用 AI 改造銀行客服：讓客戶不用被轉來轉去，從頭到尾只跟一個 AI 談完。也講到他們跟 OpenAI 怎麼合作，以及為什麼模型「回得快」對銀行很重要。想了解 AI 客服實際要解決什麼問題的人，可以看這支當具體案例。

  • 00:02 他們發現的問題是：銀行客服不可能只靠人力來擴大規模（scale）。
    ↳ 銀行客戶越多，問題就越多，不可能一直靠多請人來撐。scale（規模擴大）指業務量變大時服務還跟得上，光靠加人力做不到。
  • 00:02 例子：付款被拒時，客戶聯絡客服，客服看到帳戶上可能有 transaction monitoring alert，於是聯絡交易監控團隊。
    ↳ 例如你付款被拒，打給客服。客服看到帳戶有 transaction monitoring alert（交易監控警示，帳戶上被標記的警告），可能就是被拒的原因，但他得轉給交易監控團隊去查。
  • 00:02 交易監控團隊調查後，再請另一個團隊聯絡客戶，詢問這筆付款的更多資訊。
    ↳ 交易監控團隊（transaction monitoring team，專門調查這類警示的人）查完後，不會自己聯絡你，而是再請另一組人來問你這筆付款的詳細情況。
  • 00:02 結果客戶被一群人轉來轉去，每個人都只各自處理問題的一小部分。
    ↳ 對客戶來說，同一件事要跟好幾個人重講。每個人只管自己那一小段，沒有人從頭負責到尾，等待和溝通的麻煩全落在客戶身上。
  • 00:32 理想的做法是：客戶只要和一個 agent 對話，由它處理整個流程（full life cycle）。
    ↳ agent 在這裡指能接手並一路把事情辦完的 AI。理想是客戶只跟它談，從反映問題、調查到補問資料，整個 full life cycle（完整處理流程）都由它包辦。
  • 00:32 他們與 OpenAI 的關係不只是客戶與供應商，而是真正的夥伴關係（partnership）。
    ↳ 他們強調跟 OpenAI 不只是「付錢買服務」，而是 partnership（夥伴關係），雙方一起把產品做好。
  • 00:32 雙方能互相給回饋，他們需要時也能得到協助，大幅加快了他們的創新速度。
    ↳ 具體來說，雙方能直接交換意見，他們卡關時也找得到人幫忙，所以新東西可以做得更快。
  • 00:32 OpenAI 模型的好處是不必在品質與 latency 之間取捨，能以極佳的 latency 取得高品質、很有彈性的模型。
    ↳ latency（延遲）是從發問到 AI 回應之間要等的時間。他們說用 OpenAI 的模型不必在「答得好」和「回得快」之間二選一，而且模型好調整、好運用。
  • 00:32 這一點對金融機構的 voice agent 至關重要。
    ↳ voice agent 是用講電話方式服務客戶的 AI。電話裡停頓太久會很卡，銀行又不能答錯，所以速度和品質兩個都要，對金融機構特別關鍵。
📘 術語
transaction monitoring alert（交易監控警示）：帳戶上的警示，可能是付款被拒的原因，需要交交易監控團隊調查
transaction monitoring team（交易監控團隊）：負責調查交易監控警示的團隊
agent（代理（AI agent））：字幕指能讓客戶只對話一次、就處理整個流程的對象
full life cycle（完整流程）：從客戶反映問題到調查、補件的整個處理過程
latency（延遲）：字幕說 OpenAI 模型不必在品質與 latency 之間取捨
voice agent（語音代理）：字幕提到金融機構的 voice agent，特別需要高品質且低 latency 的模型
✏️ 小考一題

根據影片，Gradient Labs 認為 OpenAI 模型對金融機構 voice agent 的關鍵好處是什麼？

看答案
答案：D。[00:32] 提到 OpenAI 模型不必在品質與 latency 之間取捨，能以極佳的 latency 取得高品質模型，這對金融機構的 voice agent 至關重要。
