🧑‍🏫 這段直播示範怎麼把好幾個 Grok bot 當成一個小團隊來用。有的做原型，有的管技術，有的想品牌，大家一起規劃在舊金山辦餐飲快閃店。最值得看的是他們怎麼分工、怎麼給回饋、怎麼給 bot 背景資料，這些做法不會寫程式也能直接照著用。

  • 143:14 Peter 分享：他請 bot 用編號清單回報進度，方便逐條回覆好或不好；他也讓所有 bot 每週五向他回報，他給完回饋後，bot 再去做事
    ↳ Peter 要 bot 回報時用 1、2、3 編號列點，他就能直接回「2 可以、3 不行」，不用每段重打。所有 bot 固定每週五交報告，他給完意見，bot 才接著做。
  • 143:14 主持人整理：像雇用一群 bot 員工，自動處理你不想花時間做的事，並讓它們主動把東西推給你，而不是你去找它們
    ↳ 重點是角色反過來：不是你一直去問 AI 做好了沒，而是把不想花時間的雜事交給它，讓它做完主動來找你。你只要負責看和做決定。
  • 143:46 Peter 提功能需求：為何還要用 Slack？希望讓人類也能進到介面，在 channel 裡跟 bot 對話，大家一起協作；主持人說會記進功能待辦清單
    ↳ Slack 是公司常用的團隊聊天軟體，channel 是裡面依主題分開的聊天室。Peter 希望人也能直接進 bot 的介面，人和 bot 在同一個聊天室討論，就不必另外開 Slack。
  • 144:16 Lauren 回饋給 Steve：目前的 prototype 太無聊、太平淡；Steve 再傳訊息請 Grockpot 做新的 prototype
    ↳ prototype 是原型，也就是先做出來看反應的粗略版本。Lauren 覺得現在這版太平淡、沒有特色，Steve 就把意見轉給負責做原型的 Grockpot，請它重做一版。
  • 144:47 同時請 Dr. Eggbot 做一個 engineer bot 來思考 tech stack 與實際做法；Grockpot 只負責快速、用完即丟的 prototype
    ↳ 再加一個工程師 bot 專門想 tech stack，也就是產品要用哪些技術來做。分工很清楚：Grockpot 只做快速試看、用完就丟的草稿，正式要怎麼做交給工程師 bot 去想。
  • 145:17 新的 engineer bot 請聊天室幫忙取名，候選有 Spud、Tater，最後決定叫 Tater
    ↳ 新 bot 的名字交給直播聊天室的觀眾來想。Spud 和 Tater 在英文裡都是馬鈴薯的俗稱，最後定名 Tater。bot 有了名字，之後交辦事情時比較好點名。
  • 145:48 model 和 harness 的區別：Grok 是做事的 model，harness 是執行 model 的程式碼；Grockbot 很輕量，不是 Grok build 那種 coding harness
    ↳ model 是實際動腦做事的 AI，像 Grok；harness 是執行 model 的外層程式。Grockbot 屬於輕量型，不是 Grok build 那種專門寫程式的 coding harness。
  • 146:18 正式的工程工作會接上 Cursor 交給它做，因為 Cursor 的 harness 很會寫程式；Lauren 之後會大量使用 Cursor cloud agents
    ↳ Cursor 是一套 AI 寫程式工具，它的 harness 特別會寫程式，所以正式開發交給它。cloud agents 是在雲端自己執行任務的 AI 助手，Lauren 之後會大量使用。
  • 146:18 產品從 low fidelity 走向 high fidelity 的過程中會一直演變，這是完全正常的
    ↳ low fidelity 是粗略的草稿，high fidelity 是接近成品的精緻版。從草稿走到成品的過程中，方向和樣子一直改是正常的，第一版不滿意不代表失敗。
  • 146:49 請 Steve 轉告 Tater 開始思考這個平台的 tech stack；因為會有 Versel 和 Planet Scale 的朋友來，可能會用這兩個
    ↳ Vercel 是常用的網站架設服務，PlanetScale 是資料庫服務。因為這兩家公司的人會來上節目，所以技術上可能就順勢採用這兩家。
  • 147:21 原則：讓 bot 自己挑選、快速組好 tech stack；在追求 product market fit 的階段，避免無止境地爭論 tech stack
    ↳ product market fit 指產品真的做到有人需要、願意用。還在找這個點的階段，速度最重要，技術用哪一套讓 bot 快速決定就好，不要花時間一直爭論。
  • 147:51 用 Notion 文件做規劃，記下目前的共識：公司暫名 Ship by Thursday；Lauren 是 CTO，Roshan 是 CPO（負責產品）
    ↳ Notion 是線上文件和筆記工具。他們把目前的共識寫成一份文件：公司暫名 Ship by Thursday；CTO 是技術負責人，由 Lauren 擔任；CPO 是產品負責人，由 Roshan 擔任。
  • 148:52 計畫在舊金山做一個餐飲快閃（還沒決定是不是餐廳），再用這次經驗打造經營快閃店的 OS（meta product）；目標是多做喜歡的事：把人聚在一起
    ↳ 先在舊金山辦一場餐飲快閃，再把這次的經驗做成一整套經營快閃店的系統（OS）。這就是 meta product：不只是辦一場活動，而是做出辦活動的工具。初衷是多把人聚在一起。
  • 148:52 文件寫明要以快速推進為優先；把文件交給所有 Grok bot 當 context
    ↳ 文件裡寫明「速度優先」，再把整份文件當成 context 交給每一個 bot。context 就是給 bot 的背景資料。這樣所有 bot 都從同一份前提出發，不會各做各的。
  • 149:24 要讓 context spec 保持一致，因為每次來賓上節目要跟他們解釋在做什麼，也要跟 Grok bot 解釋
    ↳ spec 是規格說明。每次有新來賓，都要跟對方講一遍在做什麼，bot 也一樣要有人告訴它。維持一份統一的說明，對人和對 bot 講的才會一致。

    ↳ 聊天室觀眾發現 Lauren 用的 Grockpot app 出了新版，但直播中途更新怕出狀況，就決定等休息時再更新。跟重要簡報前不要更新電腦是同一個道理。

    ↳ 趁來賓還沒上線，先讓 cloud agents 開工，把 front end（使用者看到的畫面）和 backend（在後台處理資料的部分）的基本架構搭好，之後再往上加功能。
  • 151:56 已經建好 GitHub repo，名稱是 pop-up，並貼在 Slack channel

    ↳ 再加一個行銷 bot，負責品牌形象和取名，也負責跟其他 bot 協調。它接到的第一件工作，就是想出可以用的網址名稱。
  • 153:28 repo 有程式碼之後，所有 bot 都可以對它發 PR，大家一起讓產品演進
    ↳ PR 是修改提案：對 repo 提出一份改動，確認沒問題後再合併進去。等 repo 裡有程式碼，每個 bot 都能提出修改，大家一起把產品越改越好。

    ↳ 行銷 bot 提出八個候選網址，大多圍繞攤位、夜市、快閃這幾個概念，例如 claimthestall.com（搶攤位）、nightmarket.app（夜市）、popup.place（快閃地點）。
  • 154:28 主持人要把公司文件交給自己的 bot 當 context；文件刻意寫得很精簡，因為他認為越簡單越好
    ↳ 主持人也把公司文件交給自己的 bot 當背景資料。文件刻意寫得很精簡，因為他認為給 bot 的東西越簡單越好。
  • 154:58 給 AI 越多資訊，它就越依賴那些資訊；給它一堆爛資訊，就會得到一堆爛輸出，所以要提供最簡單、最精簡的 context
    ↳ AI 會照你給的資料做事，給得越多，它就越依賴這些資料；資料品質差，產出就差。所以給 bot 的背景要精簡，只放真正重要的，不要把一堆雜訊都丟給它。
📘 術語
model（模型）：實際在做事的東西，例如 Grok 就是 model
harness（執行框架）：執行 model 的程式碼；Grockbot 很輕量，Cursor 的 harness 很會寫程式
coding harness（寫程式用的 harness）：字幕舉 Grok build 為例，並說 Grockbot 不屬於這一類
Cursor cloud agents（Cursor 雲端代理）：正式工程工作會交給它們，用來搭 front end 與 backend 骨架
prototype（原型）：由 Grockpot 快速做出、用完即丟的版本
low fidelity / high fidelity（低擬真／高擬真）：產品從粗略版本演進到完整版本，過程中會一直改變
tech stack（技術組合）：實際打造產品要用哪些技術；交給 Tater 思考
product market fit（產品市場契合）：字幕說在追求它的階段要避免無止境爭論 tech stack
PR（合併請求）：repo 有程式碼後，bot 可以對 repo 發 PR 來一起改進產品
context（脈絡資訊）：交給 bot 的背景資料；給越多它越依賴，給爛資訊就得到爛輸出
CTO / CPO（技術長／產品長）：Lauren 最懂技術，擔任 CTO；Roshan 是產品負責人，擔任 CPO
meta product（後設產品）：用辦快閃的經驗，打造一套經營快閃店的 OS
