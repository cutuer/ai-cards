🧑‍🏫 這支影片介紹 Codex 的 goal 功能。Codex 是 OpenAI 做的 AI 程式助手，可以幫你寫程式、改程式。以前它多半做完一輪就停下來，現在你可以給它一個明確目標，它會持續做到目標達成為止。如果你想讓 AI 處理比較大、要花很久的工作，這支影片告訴你該怎麼交辦、中途怎麼管。

  • 00:00 Codex 現在能更持續地朝你的目標工作，時間可長達數小時甚至數天
    ↳ 以前多半是你問一句，它答一段，做完就停。現在 Codex 可以盯著同一個目標連續工作好幾小時，甚至好幾天，適合交辦比較大的工作。
  • 00:00 goal 功能已可在 Codex app、IDE extension 與 CLI 中使用
    ↳ 三個地方都能用：Codex app（獨立的應用程式）、IDE extension（裝在工程師寫程式軟體裡的外掛）、CLI（在文字視窗打指令來操作的方式）。
  • 00:00 可以指定一個具體的 goal，Codex 會持續工作直到該 goal 達成
    ↳ goal 就是你交給 Codex 的具體目標。它不會做一輪就交差，而是反覆做、檢查、再做，直到目標真的達成才停下來。
  • 00:00 在 message composer 輸入 /goal 即可啟用 goal mode，接著定義要給 Codex 的 goal
    ↳ message composer 就是你打字給 Codex 的輸入框。在裡面輸入 /goal 就會切換到 goal mode（目標模式），接著寫下你要它達成什麼。
  • 00:00 goal 有兩個作用：既是讓 Codex 開始任務的原始訊息，也是讓它判斷任務是否完成的指示
    ↳ 你寫的 goal 身兼兩職。一開始它是交辦的任務內容；做到一半，Codex 會拿這段話來對照，判斷自己做完了沒。所以寫得越清楚，它越知道什麼時候該停。
  • 00:31 最好的 goal 是能清楚判斷 Codex 是否真的達成的，例如指定可衡量的目標，或設定必須通過的明確測試標準
    ↳ 好的 goal 要能客觀判斷有沒有做到。「讓程式更好用」很難判斷；「某頁面 2 秒內載入完成」或「所有測試都要通過」就很明確。
  • 00:31 自己寫不出 goal 時可請 Codex 幫忙：先用 Plan Mode，再把產出的 plan 當作實作的 goal
    ↳ 不知道怎麼寫 goal 時，可以先開 Plan Mode（讓 Codex 先規劃、還不動手的模式）。它會列出一份計畫，你再把這份計畫當成 goal 交給它執行。
  • 00:31 另一種方式：請 Codex 先訪問（interview）你，再由它撰寫並自行設定 goal
    ↳ 另一招是請 Codex 反過來訪問你。它會一題一題問你想要什麼、做到什麼程度算完成，問清楚後自己寫出 goal 並設定好。適合你腦中只有模糊想法的時候。
  • 00:31 Codex 開始執行後，仍可用 steering 傳送額外訊息，例如讓 Codex 修正方向
    ↳ 交出去之後不是只能乾等。steering 就是在它工作途中傳訊息給它，例如「這部分方向錯了，改成那樣做」，讓它即時修正方向。
  • 01:01 可開啟 side chats 來了解目前已完成的工作，不必中斷主要任務
    ↳ side chats 是另外開的旁支對話。想知道它目前做到哪、做了什麼，可以在旁邊問，不會打斷主線上正在進行的任務。
  • 01:01 因為任務可能耗時數小時甚至數天，可以暫停（pause）之後再恢復（resume）goal
    ↳ 任務可能要好幾小時甚至好幾天，中間難免要停。pause 是暫停，resume 是恢復，暫停之後可以再讓它接著做這個 goal。
  • 01:01 暫停的使用情境舉例：準備離開辦公室、筆電即將斷網時
    ↳ 例如你準備下班離開辦公室，或筆電快要沒網路了，就可以先把 goal 暫停，等方便的時候再繼續。
  • 01:01 準備繼續時可恢復 goal；若目標改變或想給 Codex 更具體的指引，也可以編輯 goal
    ↳ 準備好繼續時，恢復 goal 就行。如果中途目標變了，或你想給它更具體的指示，也可以直接修改 goal 的內容。
  • 01:01 官方表示已看到許多人讓 Codex 在單一 goal 上處理複雜任務長達 100 小時以上
    ↳ OpenAI 表示，已經看到很多人讓 Codex 在同一個 goal 上處理複雜任務超過 100 小時。可見這個功能是設計來跑長期工作的，不只是幾分鐘的小任務。
