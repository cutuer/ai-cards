🧑‍🏫 這段是 Claude 2026 開發者大會開場演講的最後一段。講者先介紹 Claude Code 幾個新的自動化功能，接著談 Shopify、MercadoLibre 兩個客戶案例，最後由 Claude Code 負責人現場示範。值得看的原因是它講出一個方向：寫程式正從「人一句句指揮 AI」變成「讓 AI 自己接任務、自己檢查、自己收尾」。

  • 35:37 在 Anthropic 內部，每位工程師的 PR 數量增加 200%，工程團隊大幅擴編，程式碼品質標準仍然維持不變
    ↳ PR（pull request）是工程師把改好的程式碼送出、請團隊審核後合併的申請。Anthropic 內部每人送出的 PR 多了 200%，團隊也擴大了，但品質要求沒有放寬。
  • 35:37 講者表示會用 Claude 驅動的自動化來因應軟體工程的新挑戰，並依照使用者回饋逐一介紹新功能
    ↳ 程式碼變多、變快，人力一份一份看已經跟不上，所以要靠 Claude 自動化來補。接下來每個新功能，都對應使用者反映過的一個痛點。
  • 36:08 使用者想少花時間做 code review，所以推出 Code Review：派出一組 agent 幫你抓關鍵 bug。每天有數千家公司在用，包含 Anthropic 所有內部團隊
    ↳ code review 是上線前請別人檢查程式碼。新功能 Code Review 會派一組 agent（能自己動手做事的 AI 助手）幫你抓嚴重 bug，連 Anthropic 自己的團隊都在用。
  • 36:08 使用者想隨時隨地寫程式，所以推出 remote control，並把 Claude Code 加進 iOS 和 Android 的 Claude app，在哪裡都能丟任務出去
    ↳ remote control 讓你不必坐在電腦前，也能指揮 Claude Code。手機 Claude app 也能用，通勤時就能把寫程式的任務交代出去。
  • 36:40 使用者花很多時間「顧」PR：修不穩定的 CI 測試、回應 code review 意見、解 merge conflict，所以推出 Autofix
    ↳ PR 送出後常卡在雜事：CI（自動跑測試的流程）時好時壞、要回覆審查意見、要解 merge conflict（別人改了同一段，合不起來）。Autofix 就是處理這些的。
  • 37:11 Autofix 會監聽這些事件，主動提出修正，讓你的 PR 一直保持綠燈
    ↳ Autofix 會一直盯著你的 PR，一出現測試失敗、審查意見或衝突，就自己提出修法。「綠燈」指所有檢查都通過、可以合併的狀態。
  • 37:11 使用者常為新 ticket、新的客戶 bug 回報手動啟動 Claude Code 任務，所以推出 routines
    ↳ 很多工作的起點都很固定：來了新工單（ticket，待處理的任務單）或客戶回報 bug，就得有人手動叫 Claude Code 開工。routines 連「叫它開工」這一步都幫你省掉。
  • 37:11 routines 只要設定一次，就能監聽 webhook、API 事件或按排程執行，自動幫你啟動 Claude Code，不必再手動觸發
    ↳ webhook 是某件事發生時，一個系統自動通知另一個系統的機制。routines 設好之後，收到這類通知或到了排定時間，就會自動叫 Claude Code 開工。
  • 37:42 功能上線太快，資安團隊跟不上，所以推出 Claude Security：整晚掃描整個 codebase，還能啟動 Claude Code 處理找到的漏洞
    ↳ 功能上線速度太快，資安人員來不及一一檢查。Claude Security 會花一整晚掃過整個 codebase（公司全部的程式碼），找到漏洞還能直接叫 Claude Code 去修。
  • 37:42 這些 primitives 可以互相組合，幫助大家適應未來的工程樣貌；介紹的功能今天就能使用
    ↳ primitives 指這些基本積木：Code Review、Autofix、routines 等功能可以串起來，組成你自己的自動化流程。講者強調這些今天就能用，不是未來的規劃。
  • 38:13 客戶案例 Shopify：服務全球數百萬商家，把 AI 導入整個工程組織並改變文化
    ↳ Shopify 是幫商家架網路商店的平台。重點不只是導入 AI 工具，而是整個工程組織的做事習慣跟著改變。
  • 38:13 Shopify 全公司都在用 Claude Code，除了工程團隊，也包括設計、產品、資料科學等非工程團隊
    ↳ 在 Shopify 用 Claude Code 的不只是工程師，設計、產品、資料科學這些非工程職位的人也在用。
  • 38:44 Shopify 把它直接整合進自家平台，並大規模建置工具
    ↳ 他們不是各自零散地用，而是把 Claude Code 直接接進公司平台，大量打造自己需要的工具。
  • 38:44 Shopify 應用 AI 總監 Andrew McNamara 說「速度快到瘋狂」，Claude Code 徹底改變他們開發內部工具的方式
    ↳ 內部工具是給公司自己員工用的系統，例如後台、報表。Shopify 的負責人說開發速度快得誇張，做這類工具的方式整個不一樣了。
  • 38:44 客戶案例 MercadoLibre：拉丁美洲最受歡迎的電商平台，服務超過 1 億名買家，23,000 名工程師全都在用 Claude Code
    ↳ MercadoLibre 是拉丁美洲很受歡迎的電商平台，買家超過 1 億人，23,000 名工程師全部都在用 Claude Code，導入規模非常大。
  • 39:18 工程師把 agent 派去處理很久沒人碰、也沒人有空處理的技術債
    ↳ tech debt（技術債）是以前為了趕進度留下、該整理卻一直擱著的舊程式碼。現在這類沒人有空處理的事，他們就派 agent 去做。
  • 39:18 MercadoLibre 在人工監督下審查了超過 50 萬個 PR，並將超過 9,000 個 app 現代化
    ↳ 在有人把關的前提下，他們審查了 50 萬個以上的 PR，也把 9,000 多個 app 換成比較新的技術。規模很大，但人仍然在監督。
  • 39:18 技術負責人 Oscar Mullen 的目標是在今年 Q3 前達成 90% 自主寫程式，以及完全由 agent 驅動的 PR 流程
    ↳ 他們的目標是在今年 Q3（第三季）前，九成程式碼由 AI 自主寫出；PR 從開立到合併的整個流程，也完全由 agent 推動。
  • 39:48 講者最喜歡的細節：很多經理和 VP 又開始親自動手寫程式；Claude Code 讓過去幾十年忙於 roadmap 和審查的人重新回來寫程式
    ↳ roadmap 是產品的發展規劃。很多主管這些年忙著排規劃、審別人的成果，沒空寫程式。有了 Claude Code，他們又能自己動手做了。
  • 39:48 整個產業有數百萬開發者比以前交付更多產品，品質也更高
    ↳ 講者的結論：放大到整個產業來看，數百萬開發者做出的產品更多，品質也更好，而不是拿品質去換速度。
  • 40:18 Claude Code 負責人 Boris Cherny 上台 demo
    ↳ Boris Cherny 是 Claude Code 的負責人。接下來由他實際操作，示範前面講的功能怎麼串在一起用。
  • 41:19 Demo 情境：假設你是支付基礎設施公司 Acme Pay 的工程師，在 Claude desktop app 裡處理單一任務
    ↳ 示範的情境是：你在一家叫 Acme Pay 的支付公司當工程師，用 Claude 桌面版 app 處理一件工作。
  • 41:19 Claude 在 Acme 的商家後台加入退款功能，做出完整實作
    ↳ 任務是在商家用的管理後台加上「退款」功能。Claude 做出的是完整、可以用的版本，不是只給一份草稿。
  • 41:51 實作內容包括：idempotency（重複的 webhook 不會重複退款給商家）、涵蓋 Acme 所有服務地區的多幣別處理，以及給合規團隊的 audit log
    ↳ idempotency 指同一個請求重複送來也只執行一次，避免重複退錢。另外還處理了多種幣別，並留下 audit log（誰在什麼時候做了什麼的紀錄）給合規團隊查核。
  • 41:51 Claude 寫完實作後會自己驗證：打開商家後台觸發退款，發現沒有出現成功提示（toast）
    ↳ 寫完不代表結束，Claude 會自己打開後台按一次退款來測試，結果發現畫面沒跳出成功提示（toast，畫面角落短暫出現的訊息框）。
  • 42:25 Claude 看到失敗後，追查出原因是 optimistic update 中的 race condition；修好後，會先在瀏覽器確認真的能用，才把任務標為完成
    ↳ optimistic update 是畫面先顯示成功、再等伺服器確認；race condition 是兩件事搶先後而出錯。Claude 找出原因修好，在瀏覽器確認能用才收工。
  • 42:55 這個 session 只是許多平行執行、平行管理的 session 之一
    ↳ 剛剛看到的只是其中一件工作。同一時間還有很多個 Claude Code 工作各自在跑，由你一起管理。
  • 42:55 在 Claude desktop app 可以看到所有 Claude Code session：哪些正在跑、哪些需要你回應、哪些 PR 已經合併並關閉
    ↳ 桌面版 app 像一個總覽面板：哪些任務正在跑、哪些在等你回覆、哪些已經合併完成，一眼就看得到。
  • 42:55 同步寫程式現在只是任何時刻正在進行的工作中的一小部分
    ↳ 你坐在電腦前跟 Claude 一來一往地寫程式（同步），現在只占所有進行中工作的一小部分，大部分是它在背後自己跑。
  • 43:25 講者認為接下來會有更多程式碼以非同步方式寫成，所以一直強調驗證：只要 Claude 能檢查自己的成果，你就可以讓它跑，回來時拿到完全可用的結果
    ↳ async（非同步）就是交代完就去忙別的，晚點再回來看結果。這要行得通，前提是 Claude 會自己檢查成果，所以講者一直強調驗證。
  • 43:25 Boris 表示他現在很多程式碼是 routines 寫的：他不再自己下 prompt，而是建立會下 prompt 的 routine
    ↳ prompt 是給 AI 的指令。Boris 現在不再每次自己打指令，而是先設好 routine，讓它在適當的時機自動替他下指令。
  • 43:55 比喻：就像 higher-order function，routines 是「higher-order prompt」
    ↳ higher-order function 是程式裡「會產生或操作其他函式的函式」。套到這裡，routine 就是「會產生 prompt 的 prompt」，多了一層自動化。
  • 43:55 例：剛才的退款 session，是隊友半夜開了 GitHub issue，監看 repo 的 routine 非同步接手，接著在 Claude 裡啟動工作
    ↳ 前面那個退款任務其實不是 Boris 交代的：同事半夜在 GitHub（存放程式碼的平台）開了一張問題單，盯著專案的 routine 看到後，就自己接手開工。
  • 43:55 有了 routines，開發者可以設定非同步自動化，醒來時就有可以合併的 PR
    ↳ 實際效果是：睡前設好自動流程，隔天早上起床，就有已經做好、可以直接合併的 PR 在等你。
  • 44:26 routines 可以按排程執行，也能由 webhook 或任意 API 呼叫觸發；可以在本機或遠端的 Claude 運算資源上執行
    ↳ 觸發方式有三種：定時、webhook、任何 API 呼叫（API 是程式之間溝通的介面）。可以在你自己的電腦上跑，也可以在 Claude 的雲端機器上跑。
  • 44:26 CI autofix demo：監看前一個 session 開的 PR，任務是「顧」這個 PR，直到推上 production
    ↳ 第二段示範：一個 routine 專門盯著剛才那個 PR，一路顧到它上到 production（真正給使用者用的正式環境）為止。
  • 44:58 CI autofix 會自動處理 code review 和 security review 的意見、自動修 CI，有 merge conflict 時會自動 rebase
    ↳ 它會自動回覆程式審查和資安審查的意見、修好失敗的測試；遇到衝突就 rebase（把你的修改重新接到最新版的程式上）。
  • 44:58 Demo 中 CI 因網路逾時不穩定失敗，routine 被喚醒，判斷是已知的基礎設施問題，重跑 job 後轉為綠燈
    ↳ 示範中，測試因為網路逾時而失敗，routine 被叫醒，判斷這是已知的機器環境問題、不是程式寫錯，重跑一次就過了。
  • 44:58 在 Claude Code 自己的 codebase 裡，他們不只讓它重跑，而是每次都修掉根本原因
    ↳ 重跑只能解決眼前這一次。在 Claude Code 自己的專案裡，他們每次都會把造成失敗的根本原因修掉。
  • 45:29 負責這個 PR 的工程師永遠不會看到紅色叉叉，這些工作也不再落在他身上
    ↳ 負責這個 PR 的工程師完全不會看到測試失敗的紅色叉叉，這些顧 PR 的瑣事也不用再自己處理。
  • 45:29 核心轉變：預設不再是「我來 prompt Claude Code」，而是「我讓 Claude 去 prompt Claude Code」
    ↳ 整場的核心轉變：以前預設是你一句一句指揮 Claude Code，現在預設是讓 Claude 去指揮 Claude Code。
  • 45:29 demo 的所有內容今天都能使用，包括 routines 和 Claude desktop app 的最新更新
    ↳ 剛才 demo 裡的所有東西，包括 routines 和桌面版 app 的新功能，現在就能用，不是預告。
  • 45:59 總結：今天的演講是同一個故事的三個層次：Diane 的能力曲線、Angela 和 Caitlin 會自我評分與改進的 agent，以及 Kat 和 Boris 的展示
    ↳ 整場演講是同一個故事的三層：Diane 講模型能力的成長曲線，Angela 和 Caitlin 講會自己打分數、自己改進的 agent，Kat 和 Boris 展示實際產品。

    ↳ 講者認為技術能力已經到位了，現在真正的差距在於大家多快把它用進實際工作。

📘 術語
PR (pull request)（合併請求）：字幕沒有定義；提到會用每位工程師的 PR 數量衡量產出，PR 需要 review、CI 通過後才能合併
Code Review（程式碼審查（功能））：派出一組 agent 幫你抓關鍵 bug
remote control（遠端控制）：讓你隨時隨地寫程式、從任何地方丟出任務
flaky CI tests（不穩定的 CI 測試）：需要花時間「顧」PR 才能修好的問題之一；demo 中 CI 因網路逾時而失敗
merge conflict（合併衝突）：顧 PR 時要處理的問題；CI autofix 遇到時會自動 rebase
Autofix / CI autofix（自動修正）：監聽 PR 相關事件並主動提出修正，讓 PR 一直保持綠燈
routines（例行自動化）：設定一次，就能依 webhook、API 事件或排程自動啟動 Claude Code；被比喻為 higher-order prompt
webhook（Webhook（事件回呼））：字幕沒有解釋；是 routines 的觸發方式之一
Claude Security（Claude 資安掃描）：整晚掃描整個 codebase，並能啟動 Claude Code 處理找到的漏洞
primitives（基本構件）：指上述各項功能，它們可以互相組合
tech debt（技術債）：很久沒人碰、也沒人有空處理的程式碼，現在可以派 agent 去處理
idempotency（冪等性）：確保重複的 webhook 不會重複退款給商家
audit logging（稽核日誌）：給合規團隊用的紀錄
race condition（競態條件）：demo 中退款沒有出現成功提示的根本原因，出在 optimistic update
optimistic update（樂觀更新）：字幕沒有解釋；只說 race condition 出在這裡
async（非同步）：讓 Claude 自己跑，你去做別的事，回來拿到可用的結果
higher-order function / higher-order prompt（高階函式／高階提示）：用來比喻 routines：你不直接下 prompt，而是建立會下 prompt 的 routine
rebase（變基）：字幕沒有解釋；CI autofix 在有 merge conflict 時會自動執行
✏️ 小考一題

根據演講內容，MercadoLibre 的技術負責人在今年 Q3 前的目標是什麼？

A. 審查 100 萬個 PR 並將 9,000 個 app 現代化B. 達成 90% 自主寫程式，以及完全由 agent 驅動的 PR 流程C. 讓設計、產品、資料科學團隊全面改用 Claude CodeD. 將 23,000 名工程師的 PR 數量提升 200%
看答案
答案：B。[39:18] Oscar Mullen 的目標是在今年 Q3 前達成 90% 自主寫程式和完全由 agent 驅動的 PR 流程。PR 數增加 200% 是 Anthropic 內部數據 [35:37]，非工程團隊使用是 Shopify 的案例 [38:13]，MercadoLibre 審查的是超過 50 萬個 PR [39:18]
