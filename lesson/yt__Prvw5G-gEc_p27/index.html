🧑‍🏫 這是 Grok 官方直播「三天從零開一間遊戲工作室」的第 3 天片段。講者示範怎麼不寫程式就做出 AI 電話客服，把回饋集中到 Slack，再讓一群 bot 自己修 bug、分析數據。值得看的是，它實際演示了小團隊怎麼靠 AI 分工，也講了哪些事講者覺得還是該留給真人。

  • 308:33 xAI 那邊可以用 GUI 建立 voice agent，快速部署來接電話；講者示範時完全沒寫程式
    ↳ voice agent 是會聽也會講、能自己接電話回答問題的 AI。GUI 是用點選、填表單操作的圖形介面。講者全程沒寫一行程式，就做好一支能接電話的 AI 客服。
  • 308:33 用一個 webhook 接收 voice agent 的資料，再轉到團隊的 Slack channel
    ↳ webhook 是一種自動通知：某件事發生時，系統會自動把資料送到你指定的地方。這裡是把通話內容轉到 Slack（團隊聊天工具）的頻道，大家不用另外去查。
  • 308:33 這支電話號碼套用和 moderation 相同的保護與 guardrails，所以沒辦法透過電話亂來
    ↳ guardrails 是限制 AI 能說什麼、做什麼的安全護欄，moderation 是內容審核。電話這端用的是同一套保護，所以有人打電話來想誘導 AI 亂講話，也不會成功。
  • 309:13 畫面上意外露出 token，但只顯示一半，之後也已刪除；提醒大家 chat 裡不要放任何 secrets
    ↳ token 在這裡是像密碼一樣的存取金鑰，別人拿到就能用你的權限。secrets 泛指這類密碼和金鑰。直播時不小心露出半截，事後已經刪掉。平常也別把這些東西貼進聊天對話裡。
  • 309:47 Grokbot 能把各處的資料整合起來：Grok 的 voice 客服 agent、App 內回饋都會送進 Slack channel 集中彙整
    ↳ Grokbot 是講者用來指揮各種 bot 的 Grok 工具。它把分散各處的回饋收到同一個地方：打給語音客服講的話、App 裡填的意見，全都進同一個 Slack 頻道，不用到處翻。
  • 310:19 彙整後的回饋交給團隊的 bots，bots 可以啟動 cloud agent workflow 去修 bug、回報，讓很小的團隊也能像大公司一樣運作
    ↳ cloud agent 是在雲端自己運作、能改程式的 AI。bot 看完回饋，就能自動啟動修 bug、回報進度的流程。幾個人的小團隊，也能有大公司那種有人收件、有人處理的分工。
  • 310:19 講者猜未來可能出現更多小而靈活的 indie game studio，靠 AI 發揮超出規模的實力
    ↳ indie game studio 是獨立遊戲工作室，人少，也沒有大公司撐腰。講者猜 AI 能分擔大量雜事以後，這種小團隊會變多，做出超過人數規模的成果。這是他個人的預測。
  • 310:54 講者認為 Grok／xAI 的 voice agent 很好用，但不太放心讓它代替自己打電話給別人，仍重視人與人的接觸
    ↳ 他覺得語音 AI 很好用，但要它代替自己打給別人，他會猶豫。像打給朋友或重要的人，對方期待的是聽到真人的聲音，這種人跟人的連結他不想交給 AI。
  • 310:54 急著找人幫忙時遇到 voice agent 會很挫折，所以要想清楚什麼情況下讓使用者接觸 voice agent
    ↳ 想像一下，急著解決問題時打客服，卻一直跟機器人繞圈，一定很火大。所以要先想好：查資訊這類事可以交給 AI 接，緊急或情緒激動的狀況就該直接轉真人。
  • 311:30 可以替 voice agent 加上工具，例如 Notion tool、Slack tool，或透過 webhook 自己做的 custom tool
    ↳ 幫 AI 加工具，就是讓它除了講話，還能實際動手做事。Notion 是筆記兼資料庫軟體。可以接現成的 Notion、Slack 工具，也能用 webhook 串接自己的系統，做出專屬工具。
  • 311:30 工具舉例：刪除帳號（這類操作可能不適合開放）、更新地址、更新姓名等，由 agent 代替使用者執行，省下人力時間
    ↳ 例如客人說要改地址、改名字，agent 可以直接在系統裡幫他改好，不用等真人客服。但刪帳號這種做錯就救不回來的動作，講者認為可能不適合交給 AI。
  • 312:04 escalate 工具範例：顧客打電話到餐廳問營業時間，由 voice agent 回答；要點餐時就用 escalate tool 把電話轉給店家本人
    ↳ escalate 就是往上轉交。問營業時間這種答案固定的事，AI 回答就好；點餐這種需要真人確認的事，AI 就把電話轉給店家本人接，分工很清楚。
  • 312:04 這些自動化流程不限於 Grokbot，但屬於 Grok 的功能，是 xAI 提供的整套工具之一
    ↳ 上面這些電話客服、轉到 Slack 的做法，不一定要透過 Grokbot 才能用。它們是 xAI 提供的 Grok 整套工具之一，可以單獨拿來用。
  • 312:04 團隊已經建好所有回饋流程，客戶回饋 channel 很活躍，接下來要開始依回饋處理問題
    ↳ 收回饋的管道都接好了，客戶回饋頻道已經有很多人在留言。下一步就是從這些意見裡找出問題，一個一個處理。
  • 312:42 有個 cloud agent 在做「lineup 卡片顯示能力」的功能，已經產出 draft PR，講者覺得卡片細節還不夠，正在給它回饋
    ↳ PR 是「我改好了，請審核後合併」的修改申請，draft PR 是草稿版。AI 正在做「在陣容卡片上顯示能力」的功能，已經交出初稿。講者覺得卡片細節不夠，正在給意見要它再改。
  • 313:20 新開一個 metrics channel，用來在達成里程碑時慶祝成果
    ↳ 另外開一個專門放數據（metrics）的 Slack 頻道，達到某個里程碑時就在這裡慶祝，讓團隊看得到進展。
  • 313:52 在 ThursdayArena.com 啟用了 Versell analytics，當時頁面上大約有 1400 人
    ↳ Versell analytics 是網站流量分析工具，可以看有多少人來、從哪裡來。講者在遊戲網站 ThursdayArena.com 開啟這個工具，當時網站上大約有 1400 人。
  • 313:52 analytics 可以看出訪客從哪裡來、優化推廣方式，也能看手機和桌機的使用比例；目前手機玩家比桌機多
    ↳ 可以看出玩家是從哪個管道來的，就知道宣傳該加強哪裡。也能看用手機和用電腦的比例。目前用手機玩的人比較多，代表手機版的體驗要特別顧好。
  • 314:24 44% 的使用者用 iOS，可以當作排定開發優先順序的依據
    ↳ iOS 是 iPhone、iPad 用的系統。有 44% 的玩家用 iOS，團隊就能判斷 iOS 上的問題要優先處理，把時間花在最多人用的地方。
  • 314:24 Grokbot 有 Versell plugin，能直接抓這些數據，再幫忙擬定計畫
    ↳ plugin 是幫工具加裝功能的擴充模組。Grokbot 裝了 Versell 的 plugin，就能自己讀取流量數字，不用人手動匯出，還能根據這些數據幫忙規劃下一步。
  • 314:24 講者請負責產圖表的 data scientist bot 把 Versell analytics 加進它的例行工作，稱這是「隨需的資料科學」
    ↳ 團隊有個專門分析數據、畫圖表的 bot，講者請它把網站流量也納入例行工作。「隨需的資料科學」的意思是：想看分析時叫 bot 做就好，不用另外請一位資料科學家。
  • 315:00 play tester bot 正在試玩遊戲，發現跑馬燈（ticker）會擋住按鈕，已經有 PR 在修
    ↳ play tester 是試玩員。這個 bot 像真人一樣去玩遊戲找問題，發現畫面上滾動的跑馬燈文字蓋住了按鈕，讓人點不到，修正已經在進行中。
  • 315:33 修 bug 的 agent 正透過 computer use 測試自己的修改；讓 bot 能實際執行程式、截圖，才更能確定它真的理解問題
    ↳ computer use 是讓 AI 自己操作電腦：開程式、點畫面、截圖。修 bug 的 AI 改完之後親自跑一遍、看結果，才能確認它真的懂問題，而不是嘴上說改好了。
  • 316:04 Lauren 在 xAI 內部產品設了 verify skills：教 bot 一次怎麼測試產品，之後持續更新這個 skill，把驗證變成工作流程的一環
    ↳ skill 是教給 bot 的一套固定做法。Lauren 先教 bot 一次怎麼測試產品，之後有變動就更新。這樣 bot 每次做完事都會自己驗收，就像新人學會以後照 SOP 走。
  • 316:04 排行榜上出現第二位 diamond 玩家 dev arminus
    ↳ diamond 是排行榜上的高段位，也就是鑽石級。現在已經有第二位玩家打到這個等級，名字是 dev arminus。
  • 316:37 新功能構想：點玩家就能看他的遊戲歷史，學習頂尖玩家怎麼玩；首頁已經有記錄過去的對戰
    ↳ 新功能構想：點一下某個玩家，就能看到他過去每一場的對戰，其他人可以學高手怎麼玩。首頁本來就有記錄過去的對戰，資料是現成的。
  • 317:13 決定把排行榜／使用者名稱改成可以點擊，交給 bot 去做
    ↳ 具體做法是把排行榜上的名字改成可以點的連結，點下去就看到那個人的紀錄。這件事講者沒有自己動手，直接交給 bot 去做。
  • 317:44 進度回顧：今天是建立遊戲工作室的第 3 天，第一款遊戲早上約 10 點上線，網址 ThursdayArena.com，X 帳號 @ThursdayArena
    ↳ 幫剛進來的觀眾整理進度：這是開遊戲工作室的第 3 天，第一款遊戲當天早上大約 10 點上線，網址是 ThursdayArena.com，X 帳號是 @ThursdayArena。
  • 317:44 每次發現要修的地方，就交給一個 Grokbot，由它啟動 agents 去修
    ↳ 工作方式很簡單：發現要修的地方，就交給一個 Grokbot，它再派底下的 agents 去實際動手。人負責發現問題、做判斷，執行的部分交給 AI。
  • 318:14 講者發現 Simon Goldner 做的網站，上面有類似寶可夢卡的酷炫卡片特效（例如 chevron 發光效果），打算用這個開源 library 套到遊戲卡片上，但不確定在手機上效果如何
    ↳ 開源 library 是公開、大家可以免費拿來用的現成程式碼。講者看到有人做出像寶可夢閃卡那樣會發光的卡片特效，想借來用在遊戲卡片上，但不確定在手機上效果好不好。
  • 319:21 遊戲卡片都是用 Groc Imagine 設計的：取用 bot marketplace 上的 Grok bots，隨機分配稀有度，加上有趣的技能和作者名稱
    ↳ Groc Imagine 是 Grok 的產圖功能。卡片角色取自 bot marketplace，也就是大家上架分享 bot 的市集。系統隨機分配稀有度，再配上有趣的技能和作者名稱。
  • 319:21 成長點子：讓觀眾自己建立 bot 並出現在遊戲裡
    ↳ 成長點子：讓觀眾自己做一個 bot，它就能變成遊戲裡的一張卡。觀眾有了自己的作品在遊戲裡，參與感會更強。
  • 319:53 Grokbot 現在就能分享 bot：點右上角的分享圖示，選「share as template」
    ↳ template 是範本，別人可以直接複製來用。想分享自己的 bot，就點右上角的分享圖示，選「share as template」，別人就能拿你的 bot 當起點修改。
  • 319:53 分享時是在 chat 裡提示 bot 建立 template，bot 自己知道怎麼把自己做成 template
    ↳ 分享時不用自己去設定一堆東西，只要在對話裡叫 bot 把自己做成範本，它就知道要怎麼把自己打包好。
📘 術語
voice agent（語音代理）：在 xAI 用 GUI 建立、可以接電話回答問題的 agent，也能配備工具
GUI（圖形介面）：建立 voice agent 的地方，不需要寫程式
webhook（webhook）：接收 voice agent 的資料並轉到 Slack channel；也能用來做 custom tool
guardrails（防護機制）：套在電話號碼上的保護措施，和 moderation 用的一樣，防止有人亂來
cloud agent workflow（雲端 agent 工作流程）：bots 可以啟動的流程，用來修問題、回報問題
escalate tool（轉接工具）：voice agent 處理不了時，用它把電話轉給真正的店家
draft PR（草稿版 PR）：cloud agent 做卡片功能時產出的初版修改，講者再給回饋
plugin / connector（外掛／連接器）：Grokbot 有 Versell plugin，可以抓取 analytics 數據
computer use（computer use）：bot 實際執行程式、截圖來測試自己的修改
verify skills（驗證技能）：教 bot 一次怎麼測試產品，之後持續更新並納入工作流程
share as template（分享為範本）：把 bot 分享出去的選項，bot 會自己把自己做成 template
bot marketplace（bot 市集）：遊戲卡片的來源，上面的 Grok bots 被隨機分配稀有度
