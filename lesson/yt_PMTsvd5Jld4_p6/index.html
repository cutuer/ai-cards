🧑‍🏫 這段是 Grockbot 直播第一天的實機示範。講者用寄信的 agent 當主線，帶大家看怎麼複製、分享、分類 bot，再把好幾個 bot 拉進同一個群組一起做事。中間現場的 QR code 剛好打不開，講者就順勢示範怎麼教 AI 除錯，平常就在用 AI 工具的人看了很實用。

  • 59:40 agent 會遵守先前設定的規則（不要替我回信），送出內容前會請使用者確認；選「allow once」後會先顯示 email 草稿
    ↳ agent 是 Grockbot 裡替你做特定工作的 bot（AI 小幫手）。你先前定的規矩它會照做，例如「別替我回信」，寄出前也會先問你。按「allow once」（只准這一次）後，它會先給你看草稿。
  • 59:40 agent 可以複製，例如同時擁有五、六個 email agent
    ↳ 同一個 agent 可以複製好幾份，所以你可能同時有五、六個寄信用的 email agent，各自負責不同的事。
  • 60:11 講者會依收件對象分別建立 email agent：寄給高層（CTO、CFO）、寄給一般 Grockbot 使用者收集回饋、寄給自己的團隊，各自針對不同對象的反應做調整
    ↳ 講者依收件人分開建 agent：一個寄給高層，一個向一般使用者收回饋，一個寄給自己團隊。寫給老闆跟寫給同事，語氣本來就不一樣，分開調整會比較準。
  • 60:11 想在 agent 上嘗試多種不同策略時，複製 agent 很好用
    ↳ 想比較不同做法時，複製一份出來改就好，例如一份寫得正式、一份寫得輕鬆。原本那份不會被動到，可以擺在一起看哪個效果好。
  • 60:42 bot 可以「分享為範本」（share as template）給團隊其他人，是 Grockbot 多人協作（multiplayer）的重點；大家可再依自己的用途客製化
    ↳ share as template 是把你的 bot 當成範本分享出去，multiplayer 指很多人一起用。重點是一個人做好，同事拿去改成適合自己的版本就好，不用每個人重做。
  • 61:12 marketplace 有公開的 featured bots，例如來自 Cursor 的 Lauren、Eric 發布的 bot，可以拿來整合進自己的 Grockbot 生態系
    ↳ marketplace 是 bot 的市集，featured bots 是市集裡的精選公開 bot，例如來自 Cursor 的 Lauren、Eric 發布的 bot，都能直接拿來接進你自己那套 Grockbot。
  • 61:12 marketplace 裡也看得到自己團隊的 bot；也可以把自己的 Grockbot 發布給團隊或公司
    ↳ 市集裡也看得到你們團隊自己做的 bot。反過來，你做好的 bot 也能發布出去，給整個團隊或公司用。
  • 61:42 例子：設計團隊發布一個品牌設計 bot，確保全公司使用相同的顏色、字型、排版，維持一致性
    ↳ 例如設計團隊做一個品牌設計 bot，大家做簡報或文宣時都透過它，顏色、字型、排版就會統一，不會各做各的。
  • 61:42 發布後的 bot 仍可修改，其他人會拿到最新版本
    ↳ 發布之後還是可以改。你改完，其他人用到的就是最新版，不會一直卡在舊版本。
  • 62:12 分享方式：點畫面上方的「share as template」，任何人就能看到並使用你的 bot
    ↳ 操作很簡單：點畫面上方的「share as template」按鈕，別人就看得到、也能拿去用你的 bot。
  • 62:12 Grockbot 裡的 email 草稿會以 modal 視窗呈現，可編輯內容、更換收件人
    ↳ modal 是跳出來蓋在畫面上的小視窗。Grockbot 做好的信件草稿會用這種視窗顯示，你可以在裡面直接改內容、換收件人。
  • 62:43 草稿也可以刪除，或請它改寫（rephrase）；不必到信箱裡翻草稿，在 Grockbot 內就能完成
    ↳ 不滿意的草稿可以刪掉，或叫它 rephrase（換個說法重寫）。全部在 Grockbot 裡就能搞定，不用另外打開信箱去找草稿。
  • 62:43 Cursor 內部大量的 email outbound 是透過 Grockbot 進行
    ↳ outbound 指主動對外寄的信，例如聯絡潛在客戶。講者說 Cursor 內部很多這類寄信工作，都是用 Grockbot 在做。
  • 62:43 email agent 可以和 slide guru 等其他工具／agent 溝通，取得它們的 context 放進信件
    ↳ context 指背景資料、前後脈絡。email agent 可以去問 slide guru 這類其他 agent，把它們手上的資料寫進信裡，不用你自己複製貼上。
  • 63:14 請 data dan 把做好的咖啡問卷表單轉成 QR code，讓現場與線上觀眾掃描填寫
    ↳ QR code 是手機一掃就能打開網址的方形圖碼。講者請 data dan 把做好的咖啡問卷轉成 QR code，現場跟線上觀眾掃了就能填。
  • 63:14 計畫把收集到的回覆做成投影片，放進 Grockbot 101 簡報
    ↳ 講者打算把收回來的問卷答案做成投影片，放進「Grockbot 101」這份入門簡報，從收資料到做簡報一路串起來。
  • 63:44 Grockbot 可以把 bot 分類到不同區塊（sections）；「Unassigned」放還沒有歸屬的 bot
    ↳ sections 是分類區塊，像資料夾一樣把 bot 分組放；「Unassigned」（未分類）放的是還沒決定歸哪一區的 bot。
  • 64:14 講者另有一個區塊放工程團隊的 Grockbot，Ling 會在工程場次示範；分區方便把不同用途的 agent 分開
    ↳ 講者另外開了一區，專放工程團隊用的 bot，之後的工程場次會由 Ling 示範。不同用途分開放，bot 一多也不會亂。
  • 64:14 bot 數量沒有限制，也可以建立 bot 之間的群組聊天，群組同樣可以分類
    ↳ bot 想建幾個都行，沒有上限。也可以開 group chat（群組聊天），把好幾個 bot 拉進同一個對話，群組本身一樣能分區放。
  • 64:45 群組聊天與 bot 彼此私訊的差別在於「可見度」：把 email Ethan、data Dan、slides Sonia 放進群組，能直接看到它們如何互動
    ↳ bot 之間也能私下傳訊，但那樣你看不到過程。拉進群組以後，email Ethan、data Dan、slides Sonia 怎麼互相交辦、回應，你都看得到。
  • 65:17 當 Grockbot 拒絕執行或反問問題時，代表你可能需要教它或引導它到你要的方向
    ↳ Grockbot 不肯做或反問你問題，通常不是壞掉，而是它不確定你要什麼。這時就要教它，把方向講清楚。
  • 65:47 例：告訴它「稱呼我時只用名字，不要用全名」，這會永久存進它的記憶，之後都會照做
    ↳ 例如跟它說「叫我的時候只叫名字，不要叫全名」，它會把這條存進 memory（記憶），之後每次都照做，不用一直提醒。
  • 65:47 每次引導或修正 Grockbot，內容都會存在它的記憶裡（存放在 S3 buckets），供日後做決定時參考
    ↳ 你每次糾正或指點它，內容都會存進記憶。字幕說這些記憶存在 S3 buckets，那是 Amazon 的雲端儲存空間。它之後做判斷時會拿出來參考。
  • 66:18 QR code 產生後，現場掃描出現「no access」無法存取
    ↳ QR code 做好後，現場有人一掃就出現「no access」（沒有權限），代表這個連結還沒開放給別人看。
  • 66:52 直接請 Grockbot 處理：「大家無法掃描，確認這個連結是公開的」；講者表示之後的場次會談用 Grockbot 除錯
    ↳ 講者沒有自己去翻設定，而是直接跟 Grockbot 說「大家掃不到，確認這個連結是公開的」，還說之後的場次會專門講怎麼用它除錯。
  • 66:52 講者是 field engineer，工作重點之一是處理客戶回報的「東西壞了怎麼修」
    ↳ field engineer 是第一線直接支援客戶的工程師。講者平常很大一部分工作，就是處理客戶那句「這個壞了，要怎麼修」。
  • 67:23 除錯技巧：告訴 Grockbot 哪裡出錯、要怎麼修；它做對時也要給予肯定（validation）
    ↳ 除錯訣竅：講清楚哪裡錯、希望怎麼修；它做對時也要跟它說「對，這樣是對的」。這種肯定叫 validation，讓它知道哪個方向要繼續。
  • 67:23 講者的經驗：給的細節越多、對它測試方式給的肯定越多，Grockbot 表現越好（工程與 field engineering 都適用）
    ↳ 講者的經驗是，細節給得越多、它測試方法用對時越明確地肯定它，Grockbot 就表現得越好。寫程式跟處理客戶問題都一樣。
  • 67:55 Grockbot 會自行判斷要去檢查分享設定（sharing settings），並取得 responder 連結確保大家能開啟
    ↳ 被提醒之後，Grockbot 自己想到要去查 sharing settings（分享權限設定），並拿到 responder 連結，也就是給填答者用的問卷網址，讓大家都打得開。
  • 68:25 在群組聊天中，各 agent 維持在各自的職責範圍（swim lanes），同時理解其他 agent 能做什麼
    ↳ swim lanes 原意是泳道，意思是各游各的。群組裡每個 agent 只做自己份內的事，但也知道隊友各會做什麼。
  • 68:25 可以對 agent 說「Ethan，還記得你和 Sonia 一起寫的那封信嗎？」，它們能把這段 context 帶進其他任務
    ↳ 你可以直接說「Ethan，還記得你跟 Sonia 一起寫的那封信嗎？」它們會把當時的內容帶到新任務裡，你不用從頭再講一次。
  • 68:56 示範指令：請 slide Sonia 用先前咖啡資料的測試試算表，在簡報最後一頁建立圖表；完成後由 email Ethan 寄出含咖啡資料細節的 email
    ↳ 示範指令：請 Sonia 用之前咖啡資料的測試試算表，在簡報最後一頁做圖表；做完後由 Ethan 寄一封附上咖啡資料細節的信。一句話就串起兩個 agent。
  • 69:30 在群組聊天裡能看到 agent 之間的溝通方式；要不要一對一委派（delegation）由你決定，但群組是一次看清所有委派最簡單的方式
    ↳ delegation 是把工作分派出去。你可以一對一派給單一 agent，也可以丟進群組；群組的好處是誰交辦給誰、做到哪，一次就看清楚。
  • 70:00 每個 agent 都會回覆給 parent agent，讓你看到它們如何合作完成這個任務
    ↳ parent agent 是群組裡大家回報的對象，像專案負責人。每個 agent 做完都會回報給它，你就能看到大家怎麼分工把事情做完。
  • 70:00 Email agent 回覆會先把信件保留，等 Sonia 的投影片完成再寄：agent 能理解相依性（dependencies）
    ↳ dependencies 指工作的先後順序。Ethan 知道信裡要放 Sonia 的投影片，所以先把信留著不寄，等投影片做好才寄，不會先寄出半成品。
  • 70:31 理解相依性讓 agent 能協調工作、避免互相衝突的修改；在工程用途上可避免 merge conflicts
    ↳ agent 懂先後順序，才不會同時改同一份東西、互相蓋掉。工程上這叫 merge conflicts，指兩個人改到同一段程式碼，合併時對不起來。
  • 71:01 建議：Grok 完成不了任務時，先跟它說清楚你想要的結果（outcome），讓它從結果往回推
    ↳ Grok 做不出來的時候，先講清楚你最後想要的 outcome（結果）長什麼樣子，讓它從結果往回推要做哪些步驟。
  • 71:01 只說「這不能用」卻不給足夠細節，Grockbot 就無法從錯誤中學習；越能引導它到你要的地方越好
    ↳ 只丟一句「這不能用」，它不知道錯在哪，也就學不到東西。把哪裡不對、要的是什麼講清楚，越能把它帶到你要的方向。
📘 術語
agent（代理人／AI 助手）：Grockbot 裡執行特定工作的 bot，例如 email agent；可複製、分享、放進群組
share as template（分享為範本）：把 bot 以範本形式分享給團隊，其他人可依自己用途客製化
marketplace（市集）：可看到公開的 featured bots 與自己團隊發布的 bot，拿來整合使用
multiplayer（多人協作）：一個 agent 以範本分享給整個團隊，大家各自客製化使用
modal（彈出視窗）：email 草稿的顯示介面，可在裡面編輯內容、更換收件人
sections（分區）：把 bot 分類的區塊；Unassigned 放還沒有歸屬的 bot
group chat（群組聊天）：把多個 bot 放在一起，方便直接看到它們之間的溝通與委派
memory（記憶）：你對 Grockbot 的引導會存在記憶中（S3 buckets），之後做決定時會參考
S3 buckets（S3 儲存桶）：字幕提到 Grockbot 的記憶存放的位置
validation（肯定／確認）：告訴 Grockbot 它除錯或測試的方式是對的，能讓它表現更好
swim lanes（職責範圍）：群組中各 agent 維持在自己的工作範圍內
parent agent（上層 agent）：群組裡各 agent 回覆的對象
delegation（委派）：agent 之間分派工作；群組聊天能一次看清所有委派
dependencies（相依性）：agent 知道哪個工作要先完成，另一個 agent 再接著做
merge conflicts（合併衝突）：工程用途中，agent 理解相依性可避免這類衝突
✏️ 小考一題

講者說把多個 bot 放進 group chat，而不是讓它們彼此私訊，主要差別是什麼？

A. 成本：群組聊天比較省用量B. 安全性：群組聊天不需要權限確認C. 可見度：能直接看到 bot 之間如何溝通互動D. 速度：群組裡的 bot 回應比較快
看答案
答案：C。[64:45] 講者說跟 bot 彼此私訊相比，群組聊天「more so a visibility thing」，讓人更容易看到它們之間的溝通方式
