🧑‍🏫 這支影片是 Anthropic（開發 Claude 的公司）的工程師聊 Claude 怎麼改變他們的工作，有好處，也有他們會懷念的舊東西。值得看的地方是，連最會用 AI 的一群人都說，現在最難的不是技術，而是換個方式思考。這點對不寫程式的人一樣適用。

  • 00:00 現在當軟體工程師最難的地方是「釋放思維」：要一直思考現在有什麼可能、怎麼自動化更多、怎麼退一步想得更大
    ↳ 「釋放思維」的意思是別被舊做法綁住。工具能做的事變多了，要常問自己：還有哪些事可以整個交給機器？目標能不能訂得更大？
  • 00:00 這種思考方式其實一直都是工程師需要的，不是現在才有
    ↳ 這不是 AI 出現後才有的新要求。好的工程師本來就該常退一步看全局，想辦法把重複的工作省掉。工具換了，這個基本功一直都在。
  • 00:00 訪談中問工程師們，有沒有什麼是懷念的
    ↳ 訪談也問了反過來的問題：工作被 AI 改變之後，有沒有失去什麼、會捨不得的東西？
  • 00:00 一位工程師以前很享受 performance engineering：深入研究系統、提升它的效能；現在 Claude 在這方面比自己強很多
    ↳ performance engineering 是鑽進一個系統，找出哪裡慢，讓它跑得更快、更省資源。有位工程師以前很愛這種挑戰，但現在 Claude 做得比自己好很多，這就是會懷念的部分。
  • 00:00 有了想法之後，從構想到 prototype 再到 production 的速度快了很多
    ↳ prototype（原型）是先做出來、能試用的粗略版本；production（正式上線）是真正交給使用者用的版本。現在從點子到試用版、再到上線，都快了很多。
  • 00:30 因此注意力更多放在新想法上，以及能多快把想法做出來
    ↳ 動手做的時間縮短了，心力就不必都耗在「怎麼做出來」，可以多放在「接下來要做什麼新東西」和「多快能把點子做出來試試看」。
  • 00:30 Claude 讓整個軟體工程領域都變得觸手可及，不必再因為「我沒有那個技術能力」而解決不了問題
    ↳ 以前碰到不熟的技術，常常只能說「這我不會」就放棄。現在有 Claude 幫忙補上不會的那塊，因為能力不夠而卡住的情況少了很多。
  • 00:30 軟體工程領域裡的一切，現在都感覺在能力範圍內，這件事讓人非常興奮
    ↳ 軟體工程分工很細，各領域原本都有各自的專家。現在工程師覺得每一塊自己都碰得到、做得出來，這是他們最興奮的地方。
  • 00:30 軟體工程是一門「一直在改變的職業」：回頭看 10 或 20 年前，大家還在沒有任何框架的情況下手寫 JavaScript
    ↳ JavaScript 是做網頁互動功能最常用的程式語言。10、20 年前大家得從零一行一行手寫。重點是：這行本來就一直在變，AI 只是最新的一波。
  • 01:01 後來陸續發明了 framework、compiler 等各種工具
    ↳ framework（框架）是預先搭好的程式骨架，不用每次從零開始；compiler（編譯器）把人寫的程式碼轉成電腦能執行的形式。每出現一種新工具，工作方式就跟著變。
  • 01:01 軟體的本質在於：怎麼用這些工具創造出很棒的東西，做出越來越多好軟體
    ↳ 工具會一直換，但目標沒變：用手上的工具做出好軟體，而且越做越多。Claude 也是這串工具裡的新成員。
📘 術語
performance engineering（效能工程）：深入研究一個系統，並提升它的效能
prototype（原型）：字幕沒有解釋，只提到開發流程是從想法到 prototype 再到 production
production（正式上線環境）：字幕沒有解釋，是「想法→prototype→production」流程的最後一步
framework（框架）：字幕沒有解釋，只提到 10 或 20 年前手寫 JavaScript 時還沒有框架，後來才發明
compiler（編譯器）：字幕沒有解釋，只把它列為軟體工程後來發明的工具之一
