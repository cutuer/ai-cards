🧑‍🏫 這支影片是 Braintrust 的執行長分享他們怎麼用 Codex 處理客戶的功能需求：客戶一提需求，他就先用 AI 快速做出來給客戶看，再一起修改。重點不只在「做得快」，而是整個跟客戶合作的方式跟著改變，對任何需要回應別人需求的人都有參考價值。

  • 00:02 講者是 Braintrust 的 founder 兼 CEO Ankur Goyal
    ↳ 講者 Ankur Goyal 是 Braintrust 的 founder（創辦人）兼 CEO（執行長），也就是公司的最高負責人。影片內容是他本人的工作方式，不是別人轉述的案例。
  • 00:02 他用 Codex 不只嘗試一個點子，而是嘗試大約一百個點子
    ↳ Codex 是 OpenAI 做的 AI 寫程式工具，你用文字描述需求，它就幫你寫程式。做一個版本的成本變很低，所以他不用先挑出唯一的好點子，可以一次試上百個，再看哪些行得通。
  • 00:02 Codex 為他們解鎖的能力：即時試做客戶提出的 feature request
    ↳ feature request 就是客戶提出「希望你們加這個功能」的需求。Codex 讓他們在客戶提出的當下就能先做一版試試看，而不是只把需求記下來。
  • 00:02 Braintrust 的客戶非常積極回饋意見，公司也鼓勵客戶提出 feature request
    ↳ Braintrust 的客戶很愛給意見，公司也主動歡迎客戶提需求。所以需求本來就很多，回應得快不快，會直接影響客戶的感受。
  • 00:02 以前收到 feature request 會先放進 backlog，之後再排優先順序
    ↳ backlog 是「待辦清單」，收到的需求先放進去，之後再討論哪個先做。問題是客戶常常要等很久，有些需求甚至一直排不到。
  • 00:02 現在他常直接把客戶的 Slack 訊息複製貼上到 Codex
    ↳ Slack 是很多公司在用的工作聊天軟體。客戶在 Slack 上寫了需求，他就整段複製貼給 Codex，省掉先把需求整理成正式文件的步驟。
  • 00:33 接著建立 preview branch，大約 10 分鐘內就能把該功能請求展示給客戶看
    ↳ preview branch 是「試做版本」，在不影響正式產品的情況下另外做一份，可以直接給人看。從收到需求到拿給客戶看，大約只要 10 分鐘。
  • 00:33 好處是可以和客戶即時一起針對該功能請求迭代、發想
    ↳ 客戶看到實際做出來的東西，可以當場說「這裡不對」或「再加這個」。雙方邊看邊改、一起想，不用各自憑想像猜功能會長什麼樣子。
  • 00:33 這個流程讓使用者立即得到回應，還能在功能仍處於「molten phase」時就實際試用
    ↳ molten 原本是「熔化」的意思，molten phase 指功能還沒定型、隨時能改的階段。客戶不但馬上得到回應，還能在這個階段就親手試用。
  • 00:33 因此能取得非常高品質、有意思的回饋
    ↳ 在功能還能改的時候拿到意見，這些意見最有用。客戶是根據實際用過的東西在講，改起來也比較省事，比功能全部做完才聽到抱怨好很多。
📘 術語
feature request（功能請求）：客戶對 Braintrust 提出的功能需求，公司鼓勵客戶提出
backlog（待辦清單）：以前收到的功能請求會先放進 backlog，之後再排優先順序
preview branch（預覽分支）：用 Codex 建立，讓客戶在約 10 分鐘內看到功能請求的成果
molten phase（熔融／未定型階段）：字幕用來形容功能請求仍在與客戶即時迭代、尚未定型的階段
