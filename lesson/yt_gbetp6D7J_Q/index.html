🧑‍🏫 這支是 Claude Code 的入門影片。Claude Code 是 Anthropic 推出的 AI 程式助手，可以直接讀取、修改你電腦裡的專案檔案。影片教你兩件事：讓它自己動手，還是每一步都先問你；以及怎麼用 plan mode 讓它先規劃再動手。最後實際示範幫一個 app 加上深色模式開關。

  • 00:05 跟 Claude Code 對話的方式，就跟和任何 AI 助理對話一樣
    ↳ prompt（提示詞）就是你打給 Claude Code 的指示。不用學特殊語法，像平常跟 AI 聊天一樣，用自然的話講你要什麼就好。
  • 00:05 輸入 prompt 時有幾件事可以留意，既能保護自己，也能讓工作更輕鬆
    ↳ 下指令前有些小地方值得留意：一方面避免 AI 改到你不想改的東西，一方面讓它更快做對。接下來講的模式切換就是重點。
  • 00:05 可以選擇讓 Claude 自動接受它提出的每個檔案變更，或每次都先明確徵求你的許可
    ↳ Claude 要改檔案時，你可以選「全部自動放行」，也可以選「每改一處都先問我」。差別在於你要交給它多少控制權。
  • 00:05 按 Shift + Tab 可以在這兩種模式之間切換
    ↳ Shift + Tab 是鍵盤快捷鍵，同時按 Shift 和 Tab，就能在「自動放行」和「每次詢問」兩種模式之間切換，不用另外打指令。
  • 00:05 auto accept 模式下，編輯或建立檔案會自動核准，但執行指令前仍會先問你
    ↳ auto accept（自動接受）模式下，改檔案、新增檔案它會直接做；但要執行指令（例如跑程式）之前，還是會停下來問你，算是多留一道保險。
  • 00:05 兩種模式沒有對錯之分，看你自己用哪種最自在
    ↳ 想省事就開自動，想每一步都看清楚就選每次詢問。沒有標準答案，看你對它有多放心、用哪種比較自在。
  • 00:36 Shift + Tab 選單裡還有 plan mode
    ↳ 繼續按 Shift + Tab，還會切到第三種模式：plan mode（規劃模式）。這個模式是先把做法想清楚，不急著動手。
  • 00:36 plan mode 會根據你的 prompt，用唯讀工具分析你的 codebase，並研究你提議的實作方式
    ↳ plan mode 下 Claude 只看不改。它用唯讀工具（只能讀、不能寫的工具）翻你的 codebase，也就是整個專案的程式碼，研究你要的功能該怎麼做。
  • 00:36 plan mode 遇到需要釐清的地方，會主動向你提問
    ↳ 它不會自己亂猜。碰到說不清楚的地方，例如按鈕要放哪裡，它會先問你，確認之後才繼續規劃。
  • 00:36 最後會交給你一份很長、很詳細的計畫，Claude 可以照著這份計畫更細緻地執行
    ↳ 規劃完它會交給你一份很詳細的計畫。你看過同意後，Claude 就照著計畫一步步做，執行得更細、也比較不會走偏。
  • 00:36 plan mode 很適合用來規劃複雜的修改，或是做安全的 code review
    ↳ code review 是指檢查程式碼有沒有問題。因為 plan mode 只讀不寫，拿來規劃大改動或請它檢查程式碼，都不怕它順手改壞東西。
  • 00:36 很多時候你是請 Claude 為某個功能做多步驟的實作，這正是 plan mode 最擅長的事
    ↳ 你請 Claude 做的事，常常是一個功能要分好幾個步驟才能完成。這種得先拆步驟、排順序的工作，正是 plan mode 最擅長的。
  • 01:06 示範：有個應用程式很需要深色模式切換開關，要用 Claude Code 來實作
    ↳ 接著是實際示範：有個 app 很需要 dark mode toggle，也就是讓使用者在淺色、深色畫面之間切換的開關，要請 Claude Code 來做。
  • 01:06 先進到專案的根目錄，按幾次 Shift + Tab 切換到 plan mode
    ↳ root directory（根目錄）是專案最外層的資料夾。講者先在這裡開 Claude Code，讓它看得到整個專案，再按幾下 Shift + Tab 切到 plan mode。
  • 01:06 示範 prompt：整個 app 都要做深色模式，並在 header 加一個能切換淺色／深色模式的切換開關
    ↳ 講者的 prompt 講清楚兩件事：整個 app 都要支援深色模式，而且要在 header（畫面最上方那條標題列）放一個切換開關。
  • 01:36 prompt 裡還要求 Claude 根據現有的淺色主題，找出對比效果好的顏色
    ↳ prompt 裡還多交代一件事：深色配色要參考現有的淺色主題，挑對比清楚的顏色。這樣 Claude 除了把功能做出來，也會顧到畫面好不好讀。
  • 01:36 讓 Claude 規劃，講者看過計畫後覺得不錯
    ↳ 講者先讓 Claude 規劃，自己讀過計畫、覺得方向沒問題，才讓它開始做。重點是動手之前，有人先把關。
  • 01:36 做完之後，可以清楚看到 Claude 做了哪些事，以及它是怎麼得出結論的
    ↳ 做完之後，你可以清楚看到 Claude 改了哪些地方、為什麼這樣決定。過程不是黑箱，出了問題也比較好追。
  • 02:11 使用 Claude Code 時，prompt 要盡量寫得越詳細越好
    ↳ prompt 寫得越詳細越好。像示範裡連「放在 header」「顏色要有對比」都寫進去，Claude 要猜的就少，做出來也更接近你要的。
  • 02:11 如果想掌握每一個步驟也可以做到；可以用 plan mode 先讓 Claude 深入了解你的目標，再開始執行計畫
    ↳ 如果你想每一步都自己掌握，也做得到：先用 plan mode 讓 Claude 徹底搞懂你的目標，你確認計畫之後，再讓它照著執行。
📘 術語
prompt（提示詞）：你輸入給 Claude Code 的指示，用跟任何 AI 助理對話的方式寫就行
