🧑‍🏫 Claude Code 是 Anthropic 推出的 AI 寫程式助手：你用對話交代事情，它就在你的電腦上讀檔案、改程式、跑指令。這支是開發團隊親自介紹最近的新功能，分成兩大塊，一塊是「坐在電腦前用得更順手」，一塊是「你離開時它能自己多做事」，而且都有現場示範。想知道現在能怎麼把它用得更省力的人，很值得看。

  • 00:24 講者是 Anthropic 的 Dixon Tsai，在 Claude Code 團隊負責 plugins 和 Claude Code on the web
    ↳ 講者 Dixon Tsai 在 Anthropic 的 Claude Code 團隊工作。他負責 plugins（替 Claude Code 加裝功能的外掛），以及 Claude Code on the web（在瀏覽器裡用 Claude Code 的版本）。
  • 00:24 團隊出新功能的速度很快，公開 changelog 不太容易跟上。這場不逐條講 changelog，改成說明新功能之間怎麼搭配、團隊為什麼喜歡它們
    ↳ changelog 是官方公開的更新清單。更新太頻繁，一條條看很難抓到重點。所以這場改講這些功能怎麼搭配使用、團隊自己為什麼愛用，比較像使用心得。
  • 00:55 新功能分成兩大主題：一是開發者體驗，讓 Claude Code 更好用；二是自主性，讓 Claude 在你離開鍵盤時也能做更多事
    ↳ 新功能可以分成兩類：一類讓你坐在電腦前用得更順手；另一類讓你走開時，Claude 也能自己多做一點事，不必一直等你回來處理。
  • 01:25 最後會說明哪裡可以查到這場沒講到的內容。團隊自己每天都用 Claude Code，所以就算 Claude 能獨自處理長時間任務，他們還是很重視人的使用體驗
    ↳ 最後會告訴你去哪裡查這場沒講到的更新。團隊每天都在用自己的產品，所以就算 AI 越來越能獨立跑長任務，他們還是很在意人用起來順不順。
  • 01:25 Remote control：在自己電腦上開的 session，外出時可以接著用。用手機就能進入同一個 session，開發環境也一樣。可以先啟動長時間任務，再出門辦事
    ↳ session 是你和 Claude Code 一段連續的工作對話。remote control 讓你出門後用手機接手電腦上的 session，執行環境還是那台電腦，所以可以先丟長任務再出門。
  • 01:57 團隊做 Claude Code 時自己也想要更方便，remote control 正好解決這個需求
    ↳ 這個功能是從團隊自己的需要來的：他們天天用 Claude Code，也常希望離開座位時還能顧著進度，remote control 就解決了這件事。
  • 01:57 示範：在 session 中輸入 remote control 就能啟用，接著會拿到一個 Claude Code on the web 的連結
    ↳ 用法很簡單：在正在進行的 session 裡輸入 remote control，就會拿到一個網址。點開是 Claude Code on the web 的畫面，連著同一個 session。
  • 02:27 在網頁上可以看到 terminal 的內容。手機瀏覽器或手機 app 都能用。在網頁輸入 3 plus 3 會出現在 terminal，反過來在 terminal 輸入也會出現在網頁上
    ↳ terminal 是打字下指令的文字視窗，Claude Code 主要在這裡跑。網頁和 terminal 會即時同步：在網頁打「3 加 3」，terminal 也看得到，反過來也一樣。手機瀏覽器或 app 都能用。
  • 03:00 講者最常這樣用：對已經跨好幾個 PR、累積大量 context 的長時間 session 啟用 remote control，外出時請它開一個 subagent 把想法實作出來
    ↳ PR 是一批程式修改的合併申請；context 是 Claude 在對話中累積的背景理解。講者會替跑很久、很懂狀況的 session 開遠端，外出時請它派 subagent（分工的子助手）去實作新點子。
  • 03:00 Flicker-free rendering（無閃爍渲染）：畫面閃爍會破壞 terminal 使用體驗，這是使用者一再反映的問題
    ↳ 以前畫面輸出時會整片跳一下、閃一下，看久了很干擾，使用者反映過很多次。flicker-free rendering 指的就是讓畫面顯示時不再閃爍。
  • 03:33 閃爍的原因：以前的做法是把輸出附加到既有的 terminal scrollback，這很難做對。只要一點對不齊就會觸發重繪，畫面就會閃
    ↳ scrollback 是 terminal 往上捲時看到的舊內容。以前 Claude Code 把新內容接在舊內容後面，只要位置差一點點就得整片重畫，重畫那一下就是你看到的閃。
  • 03:33 現在 terminal UI 有 full screen mode，把 scrollback 虛擬化，因此能保證輸出不閃爍
    ↳ full screen mode（全螢幕模式）改由 Claude Code 自己管理整個畫面，只畫出眼前看得到的部分，這就是「虛擬化」。它不再依賴 terminal 原本那串紀錄，所以保證不會閃。
  • 04:03 Full screen mode 的其他好處：terminal 裡的元素可以點擊；session 再長，記憶體用量也維持平穩。團隊大多已經改用這個模式
    ↳ 全螢幕模式還有兩個好處：畫面上的東西可以用滑鼠點；對話拉得再長，記憶體用量也不會一直往上漲。團隊成員大多已經改用這個模式。
  • 04:35 啟用 full screen mode 的指令，字幕記為「2E full screen」，講者說 2E 是 terminal UI 的縮寫
    ↳ 開啟指令在字幕裡記成「2E full screen」，講者說 2E 是 terminal UI 的縮寫。terminal UI 英文常縮寫成 TUI，唸起來很像，可能是字幕聽錯了，實際指令請以官方文件為準。
  • 04:35 Claude Code 有 voice mode：用 /voice 開關，開啟後按住空白鍵就能用說的輸入 prompt
    ↳ voice mode 就是語音輸入：打 /voice 可以開或關。開著的時候按住空白鍵說話，就能把 prompt（給 AI 的指示）直接用說的輸入，不用打字。
  • 05:09 Full screen mode 下渲染很流暢，內容再長也不會出現渲染瑕疵。折疊起來的 tool call 點一下就能展開
    ↳ tool call 是 Claude 實際動手的每一步，例如讀檔、跑指令。在全螢幕模式下，內容再長畫面也不會亂掉；這些步驟平常收成一行，想看細節再點開就好。
  • 05:42 虛擬化捲動：往上翻看舊輸出時會出現「jump to bottom」按鈕。有新訊息時會提醒你，但不會打亂你正在看的畫面，可以之後再跳到底部查看
    ↳ 往上翻舊內容時，畫面會出現「jump to bottom（跳到最底）」按鈕。這時如果有新訊息，只會提醒你，不會把你硬拉到最下面；看完再按一下，就回到最新進度。
  • 06:15 有些工程師偏好 terminal，但也有越來越多人在桌面版和網頁上使用 Claude Code GUI
    ↳ 不是每個人都喜歡文字視窗。GUI 是有按鈕、視窗、可以用滑鼠操作的圖形介面，現在越來越多人在桌面版 app 和網頁上這樣使用 Claude Code。
  • 06:56 GUI 示範以 Excalidraw 為例：它是開源白板 app，原本只有矩形、菱形、橢圓三種基本形狀，示範用 Claude Code desktop 加上梯形功能
    ↳ Excalidraw 是免費開源的線上白板工具，原本只能畫矩形、菱形和橢圓三種形狀。講者用 Claude Code 桌面版示範，請 Claude 幫它加上梯形。
  • 07:27 Claude Code desktop 側邊欄新增 pinned 區，也有更進階的篩選和分組功能，例如可以依專案分組。從側邊欄拖放就能開 split view
    ↳ 桌面版左側清單可以把常用的 session 釘選（pinned）在最上面，也能依專案分組或篩選。把清單裡的項目拖到畫面上，就能開 split view，左右並排同時看。
  • 07:27 右上角有多種 session 檢視：可以開啟這個 session 對應的 plan，選取其中段落留言，留言之後可以彙整起來交給 Claude 處理
    ↳ plan 是 Claude 動手前寫好的工作計畫。你可以從右上角打開它，像審文件一樣選一段寫留言，最後把所有留言整包交給 Claude 照著修改。
  • 08:00 也可以開 diff view，在任何一行留言；還有 files view，能看到整個工作目錄並快速編輯
    ↳ diff view 會標出程式改了哪幾行，你可以在任何一行留言。files view 像檔案總管，看得到整個專案資料夾，發現小地方不對可以直接動手改。
  • 08:00 團隊押注的方向：Claude 越來越強，你和 Claude 相處的時間會越來越多，這些功能就變成選配，需要時再拿來用，而不是預設體驗
    ↳ 團隊判斷 Claude 會越來越強，你主要的時間會花在直接跟 Claude 對話。所以計畫、diff 這些檢視工具是選配，需要時才打開，預設畫面保持簡單。
  • 08:32 實驗性功能「pin as chapter」：滑鼠移到 assistant 訊息上，點 pin as chapter，就會替這則訊息產生一個符合 transcript 脈絡的標題，標題可以改名
    ↳ transcript 是整段對話紀錄。這個還在實驗階段的功能是這樣用的：把滑鼠移到 Claude 的某則回覆上，點 pin as chapter，它會依上下文替這段取個小標題，標題可以改。
  • 09:33 釘選多個 chapter 後會組成目錄，可以從左上角跳到 transcript 的不同段落。chapter 標題可以改名或刪除
    ↳ 釘了幾個 chapter 之後，就會組成一份目錄。從左上角點一下，就能跳到對話裡那一段，像書的章節一樣。標題可以改名，也可以刪除。
  • 09:33 對 Claude Code Desktop 有想要的功能，可以在 X 上告訴 Claude Code Desktop 負責人 Anthony Morris
    ↳ 如果你希望桌面版加什麼功能，講者建議直接到 X（前身是 Twitter）告訴桌面版負責人 Anthony Morris。
  • 10:05 在 desktop 裡直接開 terminal 啟動 server（localhost 3002），就能畫出梯形，還能改成橘色
    ↳ server 是讓網頁跑起來的程式，localhost 3002 是自己電腦上的測試網址。在桌面版裡開 terminal 啟動它之後，白板真的能畫梯形，還能改成橘色。
  • 10:36 第二個主題是自主性。這些功能的起點都一樣：講者交給 Claude 一個長時間任務，回來卻發現卡在小事上，例如 permission prompt、分支衝突、忘記的 build 指令
    ↳ 第二個主題是自主性，起點是同一種挫折：交代長任務後離開，回來卻發現卡在小事上，像是等你按允許、branch（程式分支）衝突，或不知道要用哪個 build 指令。
  • 10:36 接下來的功能是為了讓你離開時更有信心，相信 Claude 會照你的意思做事
    ↳ 所以接下來這些功能的目標，是讓你能放心走開，相信 Claude 會照你的意思一路做下去，不會回來才發現它停在半路。
  • 11:08 Auto mode 是 Claude Code 的新 permissions mode，由 Claude 用 classifier 代替你決定權限
    ↳ permission prompt 是 Claude 做某些動作前，跳出來問你「可以嗎？」的確認。auto mode 是新的權限模式，改由 classifier（專門做判斷的分類器）替你決定要不要放行。
  • 11:08 遇到原本會跳 permission prompt 的 tool call 時，classifier 會檢查兩件事：這個動作是否具破壞性、看起來像不像 prompt injection
    ↳ 遇到原本要問你的動作時，它會檢查兩件事：會不會造成破壞，例如刪掉檔案；像不像 prompt injection，也就是有人把惡意指令藏在網頁或檔案裡，想騙 AI 照做。
  • 11:08 判定安全就直接執行；不安全就擋下這個 tool call，由 agent 自己想下一步怎麼做
    ↳ 判斷安全就直接做，不用等你。判斷不安全就擋下這個動作，但任務不會就此停住，Claude 會自己想下一步怎麼繼續。
  • 11:40 Auto mode 幫 Anthropic 省下不少時間，也減少了「以為長時間任務在跑，回來才發現卡在 permission prompt」的情況
    ↳ Anthropic 內部用了之後省下不少時間，最明顯的是少了一種白等：以為任務一直在跑，回來才發現它一直停在那邊等你按允許。
  • 11:40 下一個痛點：同時開發多個功能時，怎麼讓多個 Claude 不互相干擾。Worktrees 是講者最愛的功能，因為它解決了這個問題
    ↳ 同時開發好幾個功能、開好幾個 Claude 時，它們可能在同一個資料夾裡改到彼此的東西。worktrees 是講者最愛的功能，就是讓它們各做各的、互不干擾。
  • 12:15 Git worktree 在 Claude Code 出現之前就有了，做法是建立一個新 branch……（本段字幕在此結束）
    ↳ Git 是記錄程式版本的工具，branch 是從主線分出來、獨立修改的路線。worktree 是 Git 早就有的功能，會建立新的 branch……這段字幕在這裡結束，後面留到下一段。
📘 術語
changelog（更新紀錄）：團隊公開的功能更新清單，因為更新很多所以不太好跟上
remote control（遠端控制）：在電腦上開的 session，可以用手機接手，開發環境一樣
session（工作階段）：一次 Claude Code 對話與工作的過程，會累積 context
Claude Code on the web（網頁版 Claude Code）：啟用 remote control 後拿到的連結，可以在網頁上看到並操作 terminal 內容
subagent（子代理）：講者在外出時請長時間 session 開一個 subagent 來實作想法
PR（Pull Request）：講者提到長時間 session 會跨多個 PR 累積 context
flicker-free rendering（無閃爍渲染）：改用 full screen mode 虛擬化 scrollback 後，保證輸出不閃爍
scrollback（回捲緩衝區）：以前把輸出附加在上面，對不齊就會重繪、造成閃爍
full screen mode（全螢幕模式）：terminal UI 的新模式，把 scrollback 虛擬化，不閃爍、可點擊、記憶體用量平穩
terminal UI（終端機介面）：Claude Code 在 terminal 中的介面，字幕中縮寫為「2E」
voice mode（語音模式）：用 /voice 開關，按住空白鍵用說的輸入 prompt
tool call（工具呼叫）：在 full screen mode 中會折疊顯示，點一下就能展開
GUI（圖形介面）：桌面版和網頁版的 Claude Code
split view（分割畫面）：從側邊欄拖放，並排開啟多個畫面
diff view（差異檢視）：檢視程式碼變更，可以在任何一行留言
pin as chapter（釘選為章節）：實驗性功能，替 assistant 訊息產生標題，可以組成 transcript 目錄
auto mode（自動模式）：新的 permissions mode，由 Claude 用 classifier 代替你決定權限
permission prompt（權限提示）：要求使用者核准的提示，長時間任務常因此卡住
classifier（分類器）：檢查 tool call 是否具破壞性、是否像 prompt injection
prompt injection（提示注入）：auto mode 的 classifier 會檢查的兩件事之一
worktrees（工作樹）：Git 本來就有的功能，會建立新 branch，用來避免多個 Claude 互相干擾
✏️ 小考一題

在 Claude Code 的 auto mode 中，classifier 碰到原本會跳出 permission prompt 的 tool call 時，會檢查哪兩件事？

A. 動作是否具破壞性，以及是否看起來像 prompt injectionB. 是否會超出 token 預算，以及是否需要網路存取C. 是否需要執行 build 指令，以及是否會刪除檔案D. 是否會修改 git branch，以及是否會造成分支衝突
看答案
答案：A。[11:08] 字幕說 classifier 會看兩件事：「One is the action destructive, and two, does it look like prompt injection?」
