🧑‍🏫 這段是 Grokbot「三天打造一間公司」直播第三天、也就是上線日的片段。前半段示範怎麼讓 bot 自動做品質檢查，還有處理收信這類日常雜事；後半段試玩團隊用 bot 做出來的卡牌對戰遊戲。想知道「把工作交給 AI 代理」實際長什麼樣，可以看這段。

  • 11:55 剛 merge 了 PR 124，這是一個 UI 重寫，過去幾小時內 rebase 了好幾次，可以看到 bot 之間如何互相溝通
    ↳ PR（pull request）是送出程式修改、請別人審核的申請，merge 則是正式併進去。PR 124 把介面整個重寫，幾小時內 rebase（把修改接到最新版上）好幾次，過程中看得到 bot 互相協調。
  • 11:55 團隊沒有 QA 團隊（昨天的實習生今天不在），所以設了一個名叫 play 的 bot 擔任 play tester，負責檢查每個 PR
    ↳ QA 是品質檢查，play tester 是專門試玩、找問題的人。團隊沒人做這件事，昨天的實習生今天也不在，乾脆設一個叫 play 的 bot 當試玩員，每個 PR 都由它把關。
  • 11:55 這個 QA bot 用的是 subscriptions 功能：可以建立 recurring task，或對某個事件做出回應
    ↳ subscriptions 讓 bot 能「定時做事」或「遇到某件事就動作」。recurring task 是固定重複的任務，像每天早上整理信；事件觸發則像一有新 PR 就自動去檢查。
  • 12:31 只要看到 PR 在 CI suite 上是綠燈，play bot 就會自動試玩：操作 UI、把整個遊戲從頭玩到尾，並在 merge 前提出需要修改的回饋
    ↳ CI suite 是程式送出後自動跑的一整套測試，綠燈代表全部通過。play bot 等到綠燈才上場，真的去點介面、把遊戲玩完，在併入前先回報哪裡要改。
  • 12:31 講者很喜歡 Grokbot 的 routines；也提到自己其實不喜歡「factory」這個詞，只是它是描述高度自動化最接近的比喻
    ↳ routines 是 Grokbot 把重複工作變成固定流程的功能。講者用 factory（工廠）形容高度自動化，但其實不喜歡這個詞，只是一時找不到更貼切的說法。
  • 13:04 即使不做工程，很多日常工作也很重複；例如講者不愛收信，因為要判斷垃圾信、該回哪封、要回什麼，很花時間
    ↳ 自動化不是工程師專用。像收信，每封都要判斷是不是垃圾信、要不要回、回什麼，一封封看很花時間，這種重複的判斷就很適合交出去。
  • 13:04 可以教 Grokbot 怎麼整理你的收件匣，它也能處理 Slack、GitHub PR，基本上想得到的事都能用 Grokbot 自動化
    ↳ 你可以把自己整理信的規則教給 Grokbot，讓它照著做。Slack 是公司常用的聊天工具，GitHub 是放程式碼、處理 PR 的平台，這些它都能接手。
  • 13:39 促銷活動（當時剩約 2 分 20 秒）：新用戶註冊 Grokbot 帳號並設定一個 recurring task，即可獲得一個月免費 Grokbot
    ↳ 直播當下的限時活動，當時只剩約 2 分 20 秒：新用戶註冊 Grokbot 並設好一個重複任務，就送一個月免費。這是當時的優惠，現在不一定還有。
  • 13:39 主持人總結：software factory 概念就是為 agent 建立良好的 feedback loop，讓 agent 能自己完成工作
    ↳ agent 是能自己規劃、自己動手完成任務的 AI。feedback loop（回饋迴圈）是指它做完能看到結果、發現錯就修。講者說的 software factory，重點就是把這個迴圈搭好。
  • 14:16 做法是移除原本要手動做的步驟：點 UI、驗證功能是否正常、看 log；只要給 agent 正確的資訊與 context，就可能自動化
    ↳ 以前這些要人來做：點畫面、確認功能正常、翻 log（系統自動留下的執行紀錄）。把這些步驟改成 agent 自己能做的事，再給它足夠的 context（背景資訊），它就能自己驗收。
  • 14:16 同樣方法可套用到 email 或其他營運流程：把人的工作流程拆解、隔離，再找出哪些部分該交給 agent 做，這就是用 AI 建立公司
    ↳ 同一套想法也能用在收信、營運這類非工程工作：先把平常的流程一步步拆開，找出哪幾步能單獨抽出來交給 agent。講者說，這就是「用 AI 建立公司」。
  • 14:51 例如 agent 也許不該幫你寄信，但可以清掉垃圾信、幫你取消訂閱名單、寄一封信提醒你該看的內容，並幫你擬草稿
    ↳ 不用把所有事都交給 agent。寄信這種出錯會有後果的事可以自己來，但清垃圾信、退訂電子報、提醒你哪封該看、先擬好回信草稿，都能交給它。
  • 14:51 講者在大家聊天時，同時派出幾個 bot 做額外的 UI 修飾
    ↳ 大家在聊天的時候，講者同時派了幾個 bot 去修介面細節。等於人在台上講話、bot 在背景做事，現場示範好幾個 bot 同時分工。

📘 術語
PR (pull request)（合併請求）：字幕中 QA bot 會檢查每個 PR，確認 CI 綠燈後試玩，merge 前給回饋
CI suite（持續整合測試套件）：PR 在 CI suite 上呈現綠燈時，QA bot 才會開始試玩
rebase（變基）：字幕只提到 PR 124 在過去幾小時內 rebase 了好幾次，沒有進一步解釋
QA / play tester（品質保證／試玩員）：好遊戲需要 QA 團隊；play bot 負責試玩每個 PR 並回饋問題
subscriptions（訂閱功能）：可以建立 recurring task，或對某個事件做出回應
recurring task（週期性任務）：透過 subscriptions 建立的重複任務；設定一個即可參加一個月免費的促銷
routines（例行任務）：講者喜歡的 Grokbot 功能，用來自動化重複性工作
software factory（軟體工廠）：比喻高度自動化；本質是為 agent 建立良好的 feedback loop，讓它自己做事
feedback loop（回饋迴圈）：移除手動步驟並提供正確 context，讓 agent 能自行完成、驗證工作
guest mode（訪客模式）：不用登入就能先試玩遊戲
leaderboard（排行榜）：遊戲的全球排名，也有分級（tier），例如 platinum tier
matchmaking（配對系統）：讓玩家與另一位玩家一對一對戰的機制
power-up（強化道具）：可在商店用 gold 購買，強化你的陣容
marketplace（市集）：Grokbot marketplace，遊戲中所有 bot 都來自這裡的真實 bot
load test（負載測試）：確認系統能承受大量玩家同時上線
chief of staff bot（幕僚長 bot）：名叫 Steve 的 bot，負責掌控整場直播節目
