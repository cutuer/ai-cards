🧑‍🏫 這段是 xAI 團隊在直播裡檢討新遊戲 ThursdayArena 上線當天的成績：人數、對局數、有多少人願意登入。他們也聊到比起這款遊戲，「用一群 AI bot 做遊戲的流程」可能更有價值，還現場展示新改的卡片介面和手機版。想知道「用 AI 做出產品之後，怎麼看數據、下一步做什麼」，這段很值得看。

  • 289:39 上線那一小時（上午 10 點）流量最高，之後觀眾進出直播，流量跟著有起伏
    ↳ 遊戲上午 10 點上線，那一小時玩的人最多。之後人數跟著直播起伏：看直播的人多，去玩的人就多；觀眾一走，人數就掉。
  • 289:39 bot 給出一句話摘要：超過 1,000 名使用者、3,500 場 practice sessions、勝率 47%，認為遊戲引擎調校有進步
    ↳ 他們讓 bot（幫忙處理事情的 AI 助手）直接看數據寫摘要：超過一千人來玩，打了 3,500 場練習局，勝率 47%。bot 判斷遊戲底層的調整有進步。
  • 290:10 PM 目前不太擔心漏斗：現在沒有強烈理由讓人登入，只有 leaderboard；之後功能變多，漏斗才會更重要
    ↳ PM（產品經理）說現在不急著盯漏斗（funnel，追蹤玩家從試玩走到登入，看在哪一步流失），因為登入目前只多一個排行榜（leaderboard），理由本來就弱。
  • 290:10 目標是讓玩家從「多玩 practice」轉成「多登入」
    ↳ 方向很明確：不希望大家只停在免費試玩，而是要讓更多人願意登入，變成有帳號、系統認得出來的玩家。
  • 290:10 要再查漏斗怎麼計算：practice 回合裡有 login with X 按鈕，但只出現在畫面上方，要確認它算不算真正的 conversion event
    ↳ 練習局裡有「用 X 帳號登入」的按鈕，但只放在畫面上方。要確認按它算不算 conversion event（轉換事件，就是「試玩的人變成登入的人」那個動作），不然數字會算錯。
  • 290:45 新 UI 可能是改善漏斗的好機會
    ↳ UI（使用者看得到、點得到的畫面）正在大改，剛好可以趁機把登入的入口和步驟設計得更順手，讓更多人願意登入。
  • 290:45 流失看起來是常見狀況：有開放的 practice mode，很多人進來試玩覺得不必登入也很好玩
    ↳ 很多人玩一玩就走、沒有登入，其實很常見。practice mode（練習模式）完全開放，不登入也玩得很開心，自然就沒動力多按那一下。
  • 290:45 下一波要思考能替已登入使用者做什麼，讓他們更投入產品
    ↳ 接下來要想：已經登入的人能多得到什麼？要給他們夠多專屬的東西，他們才會更常回來、玩得更投入。
  • 291:21 註冊數與 practice 開局數的時間圖：剛上線時有很大的高峰，希望展示新功能時再出現高峰
    ↳ 他們看註冊數和練習局數隨時間變化的圖：上線那一刻衝出一個大高峰。希望之後發表新功能時，能再衝出一次高峰。
  • 291:21 1908 是要打破的數字（目標）；再來一小時那樣的流量就會是很棒的一天
    ↳ 1908 是他們目前想打破的目標數字。只要再來一小時像上線時那樣的人潮，今天就算很成功。
  • 291:55 目前 13 點這一小時資料還不完整，但每小時仍有四到五百場遊戲，對全新遊戲來說算不錯
    ↳ 下午 1 點這一小時還沒跑完，數字不完整。不過每小時穩定有四、五百場對局，對剛推出的新遊戲來說算不錯。
  • 291:55 遊戲剛上線時非常陽春，UI 幾乎不能用
    ↳ 他們坦白說，剛上線的版本非常陽春，介面幾乎沒辦法好好用。等於是先推出能玩的版本，再邊聽意見邊改。
  • 291:55 展示累積使用者圖表（cumulative user chart），並自嘲 Y 軸再小看起來都很棒
    ↳ cumulative user chart（累積使用者圖，把每段時間的新用戶一直往上疊加）只會往上走。講者自嘲說，Y 軸數字再小都看起來很棒，所以別被它騙了。
  • 292:31 遊戲是 hit-driven 的產業；這是遊戲工作室的第一款遊戲，用來練習開發、收集回饋與迭代的流程
    ↳ hit-driven（靠少數爆紅作品撐起來的產業）：大多數遊戲不會紅。這是工作室第一款遊戲，重點是把開發、收意見、再修改的流程練熟。
  • 292:31 提出觀點：真正在打造的產品也許是遊戲工作室本身，因為經驗和設好的 Grokbot workflows 都能帶走
    ↳ 講者認為真正在做的產品可能是「做遊戲的團隊」本身。累積的經驗，還有設定好的 Grokbot 工作流程（一連串分好工的 AI 自動步驟），都能帶去下一款。
  • 293:05 可以用這些經驗做更好的 ThursdayArena 2，或嘗試別款遊戲來學習
    ↳ 有了這次的經驗，可以做出更好的續作 ThursdayArena 2，也可以換一種遊戲試試看，繼續學習。
  • 293:05 這套軟體工程流程應該可以重複利用：有 bot 負責遊戲設計、3D 原型、平面設計
    ↳ 這套做軟體的流程可以重複用：有 bot 負責想玩法、有的做 3D 原型（先做出可以看的立體模型試效果）、有的做平面美術，就像一個分工好的小團隊。
  • 293:35 有一套 coding engine 幫忙 play test：每個新 PR 進來，都能用 preview deployments 實際玩過該 PR 的改動
    ↳ 有個寫程式的 AI 幫忙試玩。每份 PR（送出來等審核的一包程式修改）都有 preview deployment（專為這包修改開的預覽版網站），可以直接玩到改了什麼。
  • 293:35 做任何遊戲都能沿用同一批 bot，提議最後整理成一套 game bot toolkit
    ↳ 不管做哪一款遊戲，都能叫同一批 bot 上工，所以提議把它們打包成 game bot toolkit（做遊戲專用的 bot 工具組）。
  • 293:35 另外還看了 practice sessions、打過對戰的人數與總數等數據切面
    ↳ 他們也從其他角度看數據：打了多少場練習局、有幾個人真的打過對戰、總共打了幾場。

    ↳ 總評：成績大致符合第一次 play test（請真人試玩、看反應）的預期。接下來繼續修改，把遊戲做得更好玩。

    ↳ 新介面加了即時 ticker（像股票跑馬燈那樣滾動的即時資訊），顯示現在有誰在玩。登入後，如果你以前來過這個網站，會直接顯示你的頭像。

    ↳ 講者一邊講解，介面一邊跟著改，觀眾看得到畫面即時變化，他說這才是真正的 real-time development（即時開發）。
  • 294:42 Lauren 介紹新卡片：原本的設計就有點像卡片，所以乾脆做成真正的卡片，並另派一個 bot 讓它更酷
    ↳ Lauren 說原本的設計就有點像卡片，乾脆做成真正的卡片，還另外派一個 bot 專門負責把卡片做得更酷。

    ↳ 每張 bot 卡片都有 rarity（稀有度），從普通到傳說分五級：common、uncommon、rare、epic、legendary，跟抽卡遊戲分 SR、SSR 是同樣的概念。

    ↳ bot 等級越高，卡片越華麗，會加上光暈之類的效果。早期原型做過閃亮卡片，之後也會加回來。
  • 295:48 之前收到很多回饋說手機版不好用，這次做了 responsiveness 改善
    ↳ 之前很多人反映手機版很難用，這次改善了 responsiveness（響應式設計：畫面會照螢幕大小自動調整排版，手機、電腦都看得清楚）。

    ↳ 他們用 Chrome 的 device simulation（在電腦瀏覽器裡模擬手機螢幕來預覽）檢查過，確認這次在手機上真的好用了。

    ↳ 如果還有問題就繼續回報，Grokbots 會負責修。另外，登入後網頁一打開就認得你，不用再重新登入。

    ↳ 有人建議把幾個 play（開始玩）按鈕集中放在一起，不要分散在不同地方。
📘 術語
funnel（漏斗）：從 practice 玩家轉成登入使用者的過程，用來看玩家在哪裡流失
conversion event（轉換事件）：字幕懷疑畫面上方的 login with X 按鈕算不算真正的轉換事件
leaderboard（排行榜）：目前唯一讓玩家有理由登入的功能
practice mode（練習模式）：開放模式，不用登入就能試玩
cumulative user chart（累積使用者圖表）：呈現使用者成長的圖表，講者說它讓一切看起來都很棒
hit-driven business（靠爆款驅動的產業）：講者推想遊戲業就是這種產業
PR（合併請求（Pull Request））：每個新 PR 進來，都能實際玩過其中的改動
preview deployments（預覽部署）：用來實際玩過某個 PR 改動後版本的方式
rarity（稀有度）：電玩常見概念，分 common、uncommon、rare、epic、legendary
responsiveness（響應式設計）：回應手機版不好用的回饋，放大或調整視窗大小都要能正常顯示
device simulation（裝置模擬）：在 Chrome 視窗裡模擬手機，確認網站 mobile friendly
