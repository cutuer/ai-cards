🧑‍🏫 這段是 xAI 連續 72 小時直播的第三天，三個人用一大群 AI 機器人（Grokbot）經營一間小遊戲工作室。這一段示範玩家回報問題後，bot 自己接手修改、產出修改提案，人只負責最後把關。想知道讓 AI 自己跑一整套工作流程實際長什麼樣子，這段講得很具體。

  • 427:18 使用者可以提交電話回饋，這些回饋會流進 feedback channel；目前很多回饋都跟 Elo 系統有關，團隊表示需要修正
    ↳ 玩家打電話留的意見，會集中到 feedback channel，也就是專門收使用者意見的聊天室。最常被抱怨的是 Elo，這是依實力幫玩家評分、再配對對手的機制，團隊也承認得修。
  • 427:18 團隊的 agents 已經連上 Slack，可以直接在 Slack 裡請 bot 處理事情
    ↳ Slack 是公司常用的聊天軟體；agents 指能自己動手做事的 AI 助手。兩邊接起來以後，在 Slack 打一句話交代，bot 就會去辦，就像在工作群組裡指派同事。
  • 427:52 Matt 請他的 chief of staff bot 建立「cupcake feedback fixer」（cupcake 是專案原本的代號），讓它監聽 Slack 的 cupcake feedback channel
    ↳ chief of staff bot 是 Matt 的總管 AI，負責接下各種事情再轉派出去。Matt 叫它生出一個新 bot，專門盯著 cupcake 的回饋頻道，有意見進來就處理。cupcake 只是專案的舊代號。
  • 427:52 回饋一進來，bot 就自動開始做修正。例如 Lauren 回報的 Elo feed（AI matchmaking rated play），bot 開了一個 cursor cloud agent 處理，Matt 再審查產生的 PR
    ↳ Lauren 回報配對排名功能有問題，bot 就自動叫 cursor cloud agent（在雲端寫程式的 AI）去修，產出 PR，也就是一份「我改了哪些地方」的修改提案，Matt 看過才放行。
  • 428:27 主持人開玩笑說，這是把使用者提交、沒經過審查的修正直接送上去（full send）
    ↳ full send 是英文俚語，意思是「不管了，直接衝」。主持人在自嘲：使用者隨口一句話，bot 就改好送上線，中間沒有人仔細把關，其實有點冒險。
  • 428:27 Matt 在 Lauren 推薦下開始用 Cursor 的 projects。他認為 projects 是長期組織工作的方式，用法類似把一堆事情丟給 chief of staff bot
    ↳ Cursor 是一套用 AI 寫程式的工具，projects 是它的一個功能。Matt 覺得它適合管長期的大工作：把一整包事丟進去讓它自己拆解，跟交代總管 bot 的感覺很像。
  • 428:59 例如要做 UI refresh，可以開一個新 project。project 就像一個 master chat，會把工作分派給 sub agents 去做
    ↳ 例如想把整個介面翻新（UI refresh），就開一個 project。它像一個主對話（master chat）負責規劃，再把細項分給好幾個 sub agents，也就是分工出去的小助手，各自去做。
  • 428:59 project 是一個持久、長期的 session，可以聊一個或多個主題，再用 sub agents 修正問題；Matt 示範時是在聊 ads product
    ↳ session 指一段持續進行的工作對話。project 不會聊完就消失，可以在同一條線上長期討論一個或好幾個題目，發現問題再派 sub agents 去修。Matt 示範時聊的是廣告產品。
  • 429:29 projects 團隊保證可以在幾個月內進行上千個 chats，底層有機制維持 context；Matt 說他聽到的都是好評，但自己還沒實際測過
    ↳ context 是 AI 當下記得的前情提要。聊太久 AI 通常會忘記前面講過的內容；Cursor 團隊說 projects 有辦法撐過幾個月、上千段對話。Matt 聽到的都是好評，但自己還沒驗證過。
  • 429:29 Eric 大約三、四週前在內部 alpha 時稍微試過 projects
    ↳ alpha 是很早期、只給內部試用的版本。Eric 大約三、四週前在那個階段碰過 projects，只稍微試了一下。
  • 430:05 Eric 現在改用 Grokbot 寫程式，覺得在同一個 bot 裡調用所有 cloud agents 很方便
    ↳ Grokbot 是這次直播主角的 AI 機器人。Eric 現在直接用它寫程式，好處是只要跟這一個 bot 講，它就能叫動各種雲端 agent，不用每個工具分開操作。
  • 430:05 Matt 有一個 loop bot，也就是他的 engineering bot，負責分派任務。他沿用 Lauren 的模式：由 chief of staff bot 交給 engineering bots，再由它們自行委派
    ↳ loop bot 是 Matt 的工程 bot，負責派工。分工照 Lauren 的做法：總管 bot 接下需求，交給工程 bot，工程 bot 再自己往下分給其他 bot 去做。
  • 430:05 Matt 另外還有一個 grind bot 要設定，並表示自己在 grind 這方面進度落後 Lauren
    ↳ grind bot 是 Matt 另一個還沒設定好的 bot，影片沒說明它具體做什麼（grind 在英文有埋頭苦幹的意思）。Matt 自嘲在這方面進度落後 Lauren。
  • 430:40 loop bot 混用 potato mode 和驗證機制；Matt 要求每次送出的東西都要看到驗證結果
    ↳ potato mode 影片沒有解釋是什麼。重點在後半句：Matt 規定 bot 每次交東西都要附上驗證（verification），也就是證明真的做好的證據，不能只回一句「完成了」。
  • 430:40 Matt 在 Twitter 分享過一個流程：自動找有趣的 demo、把它做出來、啟動 Cloudflare preview deploy，最後截圖給他看
    ↳ demo 是展示用的小作品；Cloudflare preview deploy 是先把網站放到臨時網址上預覽。Matt 的流程是 bot 自己找點子、做出來、放上預覽網址，再截圖給他看。
  • 431:14 可以用 Grokbot 和 cursor cloud agent 的截圖功能做原型、驗證成果；驗證是好 loop 的一部分，也是 Lauren 常強調的重點
    ↳ 截圖就是最直接的驗證：Matt 不用打開程式，看圖就知道成果對不對。先做出原型再用截圖確認，是讓 bot 能自己穩定運作的關鍵一環，也是 Lauren 常強調的重點。

    ↳ 有人提議讓 bot 自動把成果連同截圖、影片發到 Twitter（現在叫 X）。Matt 不放心：只要是對外公開的東西，他都堅持要自己先看過。

📘 術語
Elo system（Elo 評分系統）：遊戲的配對評分機制，收到很多回饋；相關功能被稱為 AI matchmaking rated play
feedback channel（回饋頻道）：Slack 裡收集使用者回饋（包括電話回饋）的頻道
chief of staff bot（幕僚長 bot）：負責接收各種事情、再委派給其他 bot 的總管 bot
cursor cloud agent（Cursor 雲端 agent）：被 bot 開啟來處理修正、產生 PR 的 agent，也有截圖功能
PR（Pull Request（合併請求））：bot 產出的修正，會交給人審查後合併
projects（專案（Cursor 功能））：長期組織工作的方式，像一個 master chat，會把工作分派給 sub agents
sub agents（子 agent）：由 project 分派出去、實際執行修正的 agents
loop bot（循環 bot）：Matt 的 engineering bot，負責分派任務並驗證成果
verification（驗證）：確認 bot 的成果，例如用截圖；是好 loop 的一部分
Cloudflare preview deploy（Cloudflare 預覽部署）：Matt 的流程中，把 demo 做出來後啟動的預覽部署，接著再截圖
full send（直接衝）：用來自嘲把未經審查的修正直接送上線
