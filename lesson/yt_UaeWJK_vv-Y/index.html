看全部 3 條重點

🧑‍🏫 AI agent 是能自己動手幫你完成任務的 AI 助理，例如幫你查資料、改檔案。這支影片介紹 Agent Plugins：AWS、OpenAI 等公司一起訂的共通格式，讓替 agent 加新能力的擴充功能不必替每個產品各做一套。常在不同 AI 工具之間切換的人，看完會知道以後裝擴充為什麼可能更省事。

  • 00:03 每個 agent 產品要求的 manifest、資料夾結構、設定流程都不同；AWS、Cursor、GitHub、Microsoft、OpenAI、Vercel 的貢獻者因此合作推出 Agent Plugins，這是開放、不綁定特定廠商的 agent 擴充功能打包方式
    ↳ manifest 是擴充功能的說明檔，寫它叫什麼、裝了哪些東西。過去每家 agent 產品規定的說明檔、資料夾擺法、設定步驟都不同，所以六家公司的人合訂一套大家都能用的打包方式。
  • 00:34 agent plugin 最簡單的形式就是一個資料夾，根目錄放一個叫 plugin.json 的 manifest；第一版聚焦在 agent skills 和 MCP servers
    ↳ plugin 就是擴充包，就是個資料夾，最外層放說明檔 plugin.json。第一版只收兩種：skills（重複用的做事步驟）、MCP servers（讓 agent 接工具和資料）。
  • 01:05 plugin 作者要寫的平台專屬 glue code 變少；agent 產品可以支援 skills、MCP 或兩者都支援。這份 spec 只規範打包與探索，不管 marketplace、權限或 runtime；入門網址是 agentplugins.org
    ↳ 作者為各平台另寫的銜接程式會變少；產品可只支援 skills 或 MCP，或兩者都支援。規格只管怎麼打包、怎麼被找到，不管上架商店、權限和執行；入門看 agentplugins.org。
📘 術語
Agent Plugins（Agent 外掛）：開放、不綁定廠商的格式，用來打包 agent 的擴充功能
plugin.json（外掛描述檔）：放在 plugin 資料夾根目錄的 manifest
agent skills（agent 技能）：可重複使用的指示和工作流程
MCP servers（MCP 伺服器）：讓 agent 連接工具和資料

根據影片，Agent Plugins 這份 spec 標準化的是什麼？

A. Marketplace 上架機制B. 打包（packaging）與探索（discovery）C. Plugin 的權限（permissions）管理D. Plugin 的執行環境（runtime）
看答案
答案：B。[01:05] 字幕說：This spec standardizes packaging and discovery, not marketplaces, permissions, or runtimes.
