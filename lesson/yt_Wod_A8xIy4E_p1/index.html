🧑‍🏫 這支影片的作者試用了 Meta 推出的 AI agent「Muse」，並拿它和 Hermes、Grockbot 等幾個 agent 比較。這一段主要介紹 Muse 的功能，也說明哪種人適合用它。如果你常覺得「AI 很厲害，但不知道要拿它做什麼」，Muse 的 Goals 和 Ideas 這兩個功能就是針對這個問題設計的。

  • 00:00 作者認為 Meta Muse 可能是目前最好的 AI agent，但不一定適合很多人；影片會拿它和 Hermes、OpenClaw、Grockbot 等比較
    ↳ 作者認為 Meta Muse 可能是現在最好的 AI agent（不只陪你聊天，還會幫你動手辦事的 AI 助理）。不過最強不代表每個人都適合，所以他會拿 Hermes、OpenClaw、Grockbot 來比較。
  • 00:30 影片流程：先介紹所有功能和用法，再說明適合哪些人換過去，接著講優缺點，最後做排名，並分享作者目前使用的 AI agent 組合
    ↳ 這條是整支影片的順序：先講 Muse 能做什麼、怎麼用，再判斷誰值得換過去，接著講優缺點，最後排名，並分享作者自己實際搭配用哪幾個 agent。
  • 01:02 作者自創「godthread agent」一詞：不像 Grockbot（字幕作 Rockbot）有多個具名的 agent，也不像 ChatGPT work（字幕作 chat GBT work）是一個 agent 開多個 thread
    ↳ 作者自己取了「godthread agent」這個名字來形容 Muse。它不像 Grockbot 有好幾個各有名字的 agent，也不像 ChatGPT work 是一個 agent 同時開好幾個對話串（thread）。
  • 01:34 godthread 就是只有一個大聊天串，所有事都在裡面做；可以開 side chats，但只算是例外
    ↳ godthread 的意思是所有事情都丟進同一個大聊天串裡處理。你也可以另開 side chats（主聊天串以外的小聊天）處理別的事，但那是例外，平常還是都在主串裡做。
  • 01:34 作者認為選哪種形式要看工作類型：把 AI agent 用在很多不同任務的重度使用者，比較適合 multi-agent、multi-thread 的方式
    ↳ 兩種形式沒有絕對的好壞。如果你每天拿 AI 做很多種不同的工作，分成多個 agent（multi-agent）或多個對話串（multi-thread）各管一塊，比較不會混在一起。
  • 02:04 「make me a reservation」族群（訂電影、訂餐廳、幫忙談低帳單）比較適合 godthread，只要用手機叫出一個 agent 就好，例如請它訂附近的希臘餐廳
    ↳ 如果你的需求是「幫我訂個位」，像是訂電影票、訂餐廳、幫你談降帳單，一個聊天串就夠了。拿起手機叫出 agent，說「幫我訂附近的希臘餐廳」就行。
  • 02:35 畫面右側有 activities feed，可以按日期、時間看當天用 agent 做過的所有事；作者很喜歡，希望每個 agent 都有
    ↳ 畫面右邊的 activities feed 是一份紀錄，列出 agent 今天幫你做了哪些事，可以照日期、時間往回翻。作者很喜歡這個設計，希望每個 agent 都有。
  • 03:05 作者說一天結束時常覺得自己沒做多少事，activities feed 能讓他看到其實完成了很多，心情會比較好
    ↳ 作者說，他常在一天結束時覺得自己好像沒做什麼。翻一下紀錄，才發現其實透過 agent 完成了不少事，心情就好多了。所以這個功能除了查紀錄，也有打氣的作用。
  • 03:05 介面上還整理了 approvals（需要你核准的事項）、upcoming tasks（字幕說這些就是 crown jobs）和 identity
    ↳ approvals 是 agent 要等你按同意才會去做的事。upcoming tasks 是排好時間會自動執行的任務（字幕寫 crown jobs，應該是指 cron jobs，也就是排程任務）。另外還有 identity 區，影片沒有細講。
  • 03:35 客製化光譜：Hermes 幾乎什麼都能調；Grockbot 幾乎不能調（不能選模型、不能改個性、看不到記憶）；Muse 在中間，什麼都能改，只是藏起來了
    ↳ 三家能讓你自己調整的程度差很多。Hermes 幾乎什麼都能調。Grockbot 幾乎都不能改，不能選模型、不能改個性，也看不到它記了什麼。Muse 在中間，都能改，只是設定藏起來了。
  • 04:06 作者希望 Grockbot 能改個性，覺得它說話有時很怪，像「Claude Opus syndrome」，講了話卻沒什麼實際意思；Muse 則是適合 power users 的平衡點
    ↳ 作者嫌 Grockbot 講話有時很怪，說它有「Claude Opus syndrome」，意思是話講很多，內容卻很空，偏偏又不能改它的個性。Muse 讓 power users（喜歡自己調設定的人）找得到設定，剛好平衡。
  • 04:06 Muse 的語音功能即將推出，之後可以用語音和 agent 對話
    ↳ Muse 很快會加上語音功能。到時候不用打字，直接開口跟 agent 說話，就能交代事情。
  • 04:36 【業配】贊助商 Assembly AI：作者說 AI agent 如果聽不懂你說的話（例如 email 地址），整個 agent 就沒用了
    ↳ 【業配】贊助商 Assembly AI 的說法是：agent 再聰明，只要聽錯你說的話，例如把 email 地址聽錯，後面做的事就全部白費。
  • 05:07 【業配】Assembly AI 的 real time API 能即時把語音轉成文字，還會參考 agent 正在問的問題來理解語音，例如知道在問 email 就會辨識成 email 地址
    ↳ 【業配】它的 real time API 是即時語音轉文字的服務（API 是讓不同程式互相串接的窗口）。它會參考 agent 正在問什麼來辨識，例如 agent 在問 email，就照 email 地址的格式來聽。
  • 05:40 【業配】可用在 AI receptionists、personal assistants、customer support agents；Assembly AI 負責聽，可以串接任何 AI model，API key 可免費取得
    ↳ 【業配】可以用在 AI 總機、個人助理、客服機器人。Assembly AI 只負責「聽」，後面要接哪家 AI 模型都可以。API key（使用這個服務的通行碼）可以免費申請。
  • 06:11 Feed 功能：把晨報、午報、內容簡報這類 brief 從 agent 裡拿出來放進 feed，feed 可以隨意自訂
    ↳ Feed 是另外一區，專門放 agent 定期整理的簡報（brief），像晨報、午報、內容摘要。簡報不會跟聊天內容混在一起，要放哪些簡報也可以自己決定。
  • 06:11 作者的用法是讓 agent 每天整理科技和 AI 新品發布的 brief，這樣可以少花時間在社群媒體上；有了 feed 就不用在 agent 裡塞一堆 crown jobs
    ↳ 作者讓 agent 每天整理科技和 AI 新產品的消息，他看簡報就好，不用一直滑社群媒體。簡報集中放在 feed，他就不必在 agent 裡設一堆定時任務。
  • 06:41 Ideas 功能：Meta 提供推薦點子，用來對抗 blank canvas syndrome，也就是拿到萬能的 agent 卻不知道要做什麼
    ↳ Ideas 是 Meta 準備好的點子清單，用來解決 blank canvas syndrome：拿到一個什麼都能做的 agent，就像面對一張白紙，反而不知道從哪裡開始，最後什麼都沒做。
  • 07:12 Goals 功能可能是作者最愛的：等於把作者常講的「brain dump to reverse prompt」直接做進 agent，點選一個目標後它會開始問你問題
    ↳ Goals 可能是作者最愛的功能。作者常推薦先 brain dump（把腦中想法全倒出來），再 reverse prompt（讓 AI 反過來列出能幫你做什麼）。Goals 把這套方法直接做進去，選好目標它就會開始問你問題。
  • 07:43 例子：作者點了「grow my creator business」，它用多選題引導他 brain dump，再 reverse prompt 列出它能根據這個目標做的所有事
    ↳ 作者選了「經營我的創作者事業」這個目標。它用選擇題一題一題問出他的狀況，再列出它能根據這個目標幫他做的所有事。整個過程不用自己想要怎麼下指令。
  • 07:43 例子：作者的目標之一是在 LinkedIn 上成長，它提出一堆點子，最後幫他做了 LinkedIn carousel，是作者自己沒想到的
    ↳ 作者的另一個目標是在 LinkedIn（職場社群平台）上成長。它提出很多點子，最後直接幫他做了一份 LinkedIn carousel（可以左右滑的多頁圖文貼文），這是作者自己沒想到的做法。
  • 08:13 作者認為能幫人發現 unknown unknowns 的功能很重要，因為大家用 AI 最大的難題就是不知道要拿它做什麼；Goals 也確保你用 agent 做出有生產力的事
    ↳ 作者覺得最有價值的是幫你找出 unknown unknowns（你根本不知道自己可以做的事）。多數人用 AI 最大的難題是不知道要拿它做什麼。Goals 讓 agent 做的事都對準你的目標。
  • 08:44 Library 功能；Muse 的一大優勢是比其他 AI agent 主動得多，特別會主動產生 artifacts
    ↳ Library 是存放成品的地方。作者覺得 Muse 最大的優勢是很 proactive（沒人要求也會主動做事），特別會主動做出 artifacts，也就是網站、網頁、圖片這類成品。
  • 08:44 例子：作者請它研究自己是誰，它沒被要求就自動做了一個網站，整理它知道的所有關於作者的資訊
    ↳ 例如作者只請它研究自己是誰，它沒被要求就自己做了一個網站，把查到的作者資訊都整理進去。你只問了一句，拿到的卻是一份成品。
  • 09:15 例子：作者請它研究大家用 Muse 做什麼，它主動做了一個 HTML 網站列出熱門用法，存在 library 裡
    ↳ 作者又請它研究大家都拿 Muse 做什麼。它主動做了一個 HTML 網頁（用瀏覽器就能打開的網頁檔），列出熱門用法，並存進 library，之後可以回頭看。
  • 09:46 用量：作者說在 Grockbot 做一支影片就會耗掉一週用量；Muse 則免費給大量 tokens
    ↳ token 是 AI 計算用量的單位，做越多事就用越多。作者說在 Grockbot 做一支影片的工作量，就會用掉一整週的額度；Muse 則免費給你很多 token。
  • 09:46 Meta 有內建在 Instagram、Facebook 等產品裡的付費方案，可以再多給用量；作者說方案有點混亂，但重點是免費用量就很多
    ↳ Meta 也有付費方案，綁在 Instagram、Facebook 等自家產品裡，付費可以拿到更多用量。作者承認方案有點亂，但重點是免費額度就已經很多。
  • 10:17 作者認為用量多是因為 Meta 主要靠 Instagram 廣告等 AI 以外的管道賺錢，可以把獲利投入 Muse 這類 AI 產品
    ↳ 作者推測，Meta 主要靠 Instagram 廣告這類 AI 以外的生意賺錢，所以有本錢把錢投進 Muse，大方給用量。這是作者自己的推測，不是 Meta 的官方說法。
  • 10:47 護城河：Grockbot 是深度整合 X；Meta 則是能取得 Instagram 和 Facebook 的內容
    ↳ 護城河（moat）是指別人很難複製的優勢。Grockbot 的優勢是和 X（原本的 Twitter）深度整合；Meta 的優勢是能用上 Instagram 和 Facebook 上的內容。
  • 10:47 示範：請 Muse 找討論 Muse 的 Instagram reel，它很快找到一支 Casey Neistat 的 reel 並附上連結，點了就跳到 Instagram
    ↳ 作者現場示範，請 Muse 找討論 Muse 的 Instagram reel（IG 上的短影音）。它很快找到 Casey Neistat 的一支 reel 並附上連結，一點就直接跳到 Instagram 打開。
  • 11:18 作者覺得 X 上看好 AI 的人比較多、Instagram 上 AI doomers 比較多；留言反應很兩極，很多人對 Meta 的隱私抱持懷疑
    ↳ 作者觀察到，X 上看好 AI 的人比較多，Instagram 上 AI doomers（對 AI 悲觀的人）比較多。所以留言反應很兩極，很多人不信任 Meta 會保護隱私。
  • 11:49 作者認為對多數人來說，看更多 Instagram 內容大概是壞事，但對某一群人可能有用（這一段字幕到這裡中斷）
    ↳ 作者也坦白說，對多數人來說，被 AI 帶去看更多 IG 內容大概不是好事，但對某些人可能有用。字幕在這裡就斷了，他指的是哪些人要看第 2 段。
📘 術語
godthread agent（單一主線程 agent）：作者自創的詞：只有一個大聊天串，所有事都在裡面做，side chats 只是例外
multi-agent（多 agent）：像 Grockbot 那樣有好幾個不同名字的 agent
side chats（側邊聊天）：在主聊天串之外另開的聊天，算是例外
activities feed（活動紀錄）：按日期、時間列出當天用 agent 做過的所有事
approvals（待核准事項）：agent 需要你核准的事情
identity（身分設定）：字幕只提到介面上有這一區，作者很喜歡，沒有進一步說明
power users（進階使用者）：想自己動手調整設定的使用者；Muse 把可調整的設定藏起來，但他們還是找得到
real time API（即時 API）：Assembly AI 的產品，能即時把語音轉成文字
feed（資訊流）：把各種 brief 從 agent 拿出來集中放置的地方，可以自訂
blank canvas syndrome（空白畫布症候群）：拿到什麼都能做的 AI agent，反而不知道要做什麼，結果做得更少
brain dump（腦袋傾倒）：把腦中的想法全倒出來；Goals 會用多選題引導你這樣做
reverse prompt（反向提示）：agent 根據你的目標，反過來列出它能幫你做的所有事
unknown unknowns（未知的未知）：你自己沒想到的用法，例如作者沒想到可以做 LinkedIn carousel
artifact（產出物）：agent 主動產生的成品，例如網站、HTML 網頁、視覺圖，會存在 library
proactive（主動）：沒被要求也會主動做事，例如自己產生 artifacts
moat（護城河）：別人做不到的優勢，例如 Grockbot 整合 X、Meta 取得 Instagram 和 Facebook 內容
AI doomers（AI 悲觀派）：和看好 AI 的人相對的一群；作者覺得他們多半在 Instagram 上
