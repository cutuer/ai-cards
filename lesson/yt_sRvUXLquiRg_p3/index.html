🧑‍🏫 這段是 Claude Code 新功能介紹的最後一段，講三件事：讓 Claude 幫你審程式碼、讓 Claude 在你不在的時候自己開工、在同一個畫面管好幾個同時進行的任務。這些功能的共同方向是「事情交給 Claude 在背景做，你回來看結果就好」。就算你不寫程式，也能從這段看出 AI 工具接下來會怎麼幫人做事。

  • 21:25 Code review 能在幾分鐘內找出原本要花好幾個小時才找得到的錯誤或邏輯問題
    ↳ Code review（程式碼審查）就是改動上線前，先檢查有沒有寫錯。重點在於：人要翻好幾個小時才抓得到的錯誤或邏輯漏洞，Claude 幾分鐘就能找出來。
  • 21:25 如果 GitHub repo 已經安裝 Claude，GitHub app 上就原生支援 code review，可以設定成每個新的 pull request 都自動審查
    ↳ GitHub 是存放程式碼的網站，repo 是一個專案的倉庫；pull request（PR）是「我改好了，請收進去」的申請。repo 裝了 Claude，就能設定成每張新 PR 都自動審。
  • 21:25 除了自動審查，也可以手動啟動 review
    ↳ 不一定要等它自動審，你想檢查某個改動的時候，也可以自己手動叫它審。
  • 21:56 在 Claude Code terminal 輸入 /ultra-review 就能開始新的 review session，用跟 Anthropic 團隊一樣的方式做 PR review
    ↳ terminal 是打指令的文字視窗。在 Claude Code 裡打 /ultra-review，就會開一個專門審 PR 的 session（一次獨立的工作對話），審的方式跟 Anthropic 自家團隊一樣。
  • 21:56 Routines 在這個月初推出，目前還是 research preview，可以讓 Claude Code session 自動啟動，不用你手動觸發
    ↳ Routines 就是讓 Claude 自己開工：條件一到，就自動開一個 Claude Code 工作，不用你去按。research preview 是研究試用階段，功能之後還可能會改。
  • 22:26 Routines 可以用三種方式觸發：其他系統的 API call、計時器排程、webhook
    ↳ 有三種觸發方式：API call 是別的系統用程式直接叫它；計時器是到了固定時間就跑；webhook 是某件事一發生，網站就自動通知它，例如 GitHub 上有人開了問題回報。
  • 22:26 Routines 原生支援 GitHub；例子：電商每成交一筆就用 API call 啟動一個 routine
    ↳ 它本來就能直接跟 GitHub 串接。影片舉的例子是網路商店：每成交一筆訂單，商店系統就送一個 API call 過來，自動啟動一個 routine。
  • 22:56 Routine 能做的事跟一般 Claude Code session 一樣，例如對其他系統送 curl request、使用 connectors
    ↳ 自動啟動的 routine 不是陽春版，平常 Claude Code 會做的它都會。curl request 是對其他系統送出網路請求；connectors 則是讓 Claude 連到外部服務的接頭。
  • 23:26 Demo：Claude Code desktop 上方有 Routines 按鈕
    ↳ Demo 用的是 Claude Code 桌面版 App，畫面上方就有 Routines 按鈕，不用打指令，用點的就能設定。
  • 23:26 範例 routine：每天早上 8 點和下午 4 點各跑一次，檢查一個公開 repo 有沒有新的 commit 和新的 issue，裡面也能加 curl request
    ↳ commit 是一筆存檔紀錄，issue 是有人回報的問題。這個範例每天 8 點和 16 點各檢查一次某個公開專案有沒有新的 commit 和 issue，也可以順便叫它對其他系統送請求。
  • 24:00 每次執行都有紀錄，不需要人介入；因為 routine 跑在雲端，你的電腦甚至不用開著
    ↳ 每次執行都會留紀錄，事後可以回頭查，全程不用有人盯著。而且它是在雲端（也就是遠端伺服器）上跑，你的電腦關機也照樣會執行。
  • 24:34 建立步驟：點 new routine，選 remote environment，輸入名稱（issue triage）和指令（評估 issue 並給出 review，而且要講話像中世紀騎士）
    ↳ 建立步驟：按 new routine，選 remote environment（在雲端跑的環境），取名叫 issue triage（問題分類），再寫指令叫它評估 issue、給出意見。要它講話像中世紀騎士，是講者開的玩笑。
  • 25:06 接著選一個遠端 repo（講者自己的 fork），GitHub event 選 issue opened，之後只要有人開 issue 就會執行這個 routine
    ↳ fork 是把別人的專案複製一份到自己帳號底下。接著選講者自己的 fork，觸發事件設成「有人開 issue」，之後只要有新 issue，這個 routine 就會自動跑。
  • 25:06 Routine 也可以加 connectors；這個例子用不到，所以直接按 create
    ↳ routine 可以視需要加上 connectors；這個例子不需要連外部服務，所以直接按 create 建好。
  • 25:36 測試方式：到 repo 開一個新 issue（內容假裝發現 backdoor），這樣會觸發 webhook，進而啟動 routine
    ↳ 測試方式很直接：真的去專案開一個 issue，內容假裝發現了 backdoor（被人偷偷留下的後門）。開 issue 這個動作會觸發 webhook，routine 就跟著啟動。
  • 26:07 另一個 routine 會在有人開 pull request 時審查 PR，並把發現直接留言在 PR 上；剛才建立的 issue routine 則不會回覆 issue，只產出報告給講者
    ↳ 兩個 routine 的做法不一樣：審 PR 的那個會把意見直接留言在 PR 上，大家都看得到；剛建好的 issue routine 不會回覆 issue，只把報告交給講者自己看。
  • 26:40 不用有人去 tag，也不用另外做整合，GitHub webhook 就能直接觸發 Claude session 完成 PR review
    ↳ 重點是省掉中間的人工步驟：不用有人去 tag Claude，也不用另外寫串接程式，GitHub 上一有動靜，就會自動叫 Claude 把 PR 審完。
  • 27:13 GitHub webhook 或外部系統的 API call 都能在雲端執行，電腦不用開；呼應 Boris 說的「非同步工作」：讓 Claude 做事，你回來評估結果就好
    ↳ 不管是 GitHub 送來的通知，還是外部系統的呼叫，都在雲端跑，電腦不用開。這就是 Boris 說的「非同步工作」：交代完就去忙別的，回來再看結果。
  • 27:46 Agents view：在同一個畫面看到所有 Claude Code session，適合同時開很多平行 session 的人
    ↳ Agents view 是一個總覽畫面，把你所有的 Claude Code 工作集中在一起看。適合常常同時開好幾個任務、讓它們平行跑的人。
  • 27:46 Agents view 會依狀態列出 session，例如等待 prompt、已完成、需要你輸入
    ↳ 它會照狀態幫你排好：哪些在等你給 prompt（給 Claude 的指示）、哪些已經做完、哪些需要你回答，一眼就知道該先處理哪個。
  • 28:19 用 claude agents 啟動 session 就能進入 Agents view，而且 session 會在背景執行
    ↳ 用 claude agents 這個指令開工作，就會進到 Agents view，而且工作是在背景跑，你不用守在旁邊看它做。
  • 28:50 可以一次派出多個任務平行執行，例如查今天行程、產生 Spotify 播放清單、規劃 app 的 dark mode
    ↳ 可以一次派好幾件事同時進行，像是查今天的行程、做一份 Spotify 播放清單、規劃 app 的深色模式，不用等上一件做完才交代下一件。
  • 29:22 就算離開 Claude Code，任務也會繼續跑，不用一直掛在 terminal 上
    ↳ 就算你把 Claude Code 關掉，任務也會繼續做，不用一直把 terminal 開著掛在那邊。
  • 29:22 按 Enter 進入某個 session；按 Space 可以直接對該 session 送 prompt，不用進入 session
    ↳ 操作方式：按 Enter 進到某個工作裡看細節；按空白鍵可以直接對那個工作補一句指示，不用點進去。
  • 29:55 Session 會依 working 到 complete 等狀態分組，需要輸入的 session 會特別標出來
    ↳ 工作會照「進行中」到「已完成」等狀態分組，需要你回應的會特別標出來，不會淹沒在一堆任務裡。
  • 29:55 Agents view 已經以 public preview 釋出，推薦給同時使用多個 Claude Code session 的人
    ↳ public preview 是公開試用版，大家都能用，但還在調整中。講者推薦給會同時開好幾個 Claude Code 工作的人。
  • 30:27 講者請大家繼續提供回饋、功能需求和 bug 回報，這些新功能都是靠這些回饋做出來的
    ↳ 講者請大家繼續提供意見、想要的功能，還有回報 bug（程式錯誤），因為這次這些新功能都是從使用者回饋裡做出來的。
  • 30:27 給管理團隊或企業部署的新功能：更好的 Windows 支援，以及搭配 Google Cloud Platform 和 AWS 的部署 wizard
    ↳ 給公司 IT 或管理團隊的功能：Windows 支援變好了；另外還有部署 wizard（一步步帶你設定的精靈），方便裝在 Google Cloud 和 AWS 這兩個雲端平台上。
  • 30:57 提供 native binaries，可以直接從你的 governance pipeline 安裝
    ↳ native binaries 是可以直接執行的安裝檔。很多公司有 governance pipeline，也就是軟體要先審核、再統一發給員工的流程，現在可以直接從這個流程安裝 Claude Code。
  • 30:57 想掌握更新：在社群追蹤開發團隊（Twitter 上的 Claude Devs），也可以看文件裡的 what's new 區塊和 changelog、訂閱 newsletter
    ↳ 想跟上更新的話：在 Twitter（現在叫 X）追蹤 Claude Devs 帳號、看官方文件裡的 what&#x27;s new 和 changelog（更新紀錄），或是訂閱電子報。
  • 31:29 結語：持續學習、持續打造、持續思考
    ↳ 結尾三句話：繼續學、繼續做、繼續想。
📘 術語
code review（程式碼審查）：幾分鐘內找出要花好幾小時才能發現的錯誤或邏輯問題
pull request (PR)（合併請求）：repo 收到的變更請求；可以設定成每個新 PR 都自動 review
/ultra-review（ultra-review 指令）：在 Claude Code terminal 啟動新的 review session 的指令
Routines（例行任務）：不用手動觸發就能啟動 Claude Code session，可以用 API call、計時器或 webhook 觸發
research preview（研究預覽版）：字幕說 Routines 目前還在 research preview 階段
webhook（webhook）：觸發 routine 的方式之一，例如 GitHub 開了 issue 就觸發
API call（API 呼叫）：讓其他系統觸發 routine，例如電商成交時
curl request（curl 請求）：routine 裡可以讓 Claude 對其他系統送出的請求
connectors（連接器）：可以加進 routine 裡使用
remote environment（遠端環境）：建立 routine 時選的環境，在雲端執行，電腦不用開
Agents view（Agents 檢視）：在同一個畫面管理所有 Claude Code session，依狀態分組
public preview（公開預覽版）：Agents view 目前的釋出階段
native binaries（原生二進位檔）：可以直接從 governance pipeline 安裝 Claude Code
changelog（更新紀錄）：文件裡可以查看更新的地方
