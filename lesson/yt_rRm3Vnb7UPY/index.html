🧑‍🏫 Figma 是很多人用來設計 App 和網頁畫面的線上設計工具。這支影片是 Figma 團隊分享試用 GPT-6 Astra 的經驗：他們出了一個很難的題目，模型花了大約 2 小時，幾乎自己做出一整套直升機飛控介面的原型。值得看的地方是，它具體呈現了 AI 從「回答問題」變成「接下一件案子、自己做完」的樣子。

  • 00:01 模型幾乎獨力做出整個駕駛艙（cockpit）介面，受訪者強調它完成的工作量很大
    ↳ 駕駛艙（cockpit）是飛行員坐著操作的地方，這裡指駕駛艙裡的操作畫面。受訪者想強調的是，這一大包畫面幾乎都是模型自己做完的，不是只幫忙做一小塊。
  • 00:01 Figma 的方向是讓 Figma 內外都變得 agentive
    ↳ agentive 指像代理人一樣，能自己規劃步驟、把事情做完，不只是一問一答。Figma 想讓這種「交代任務，它就自己做」的能力，在 Figma 裡面和外面都用得到。
  • 00:01 Figma 希望讓所有最好的模型都能在 Figma 裡使用，也希望工作流程不論從 Figma 外的哪裡開始，都能用到 Figma
    ↳ 意思是 Figma 不綁定某一家的 AI，哪個模型好，就讓你能在 Figma 裡用。反過來，你在別的工具開始工作，中途也能接上 Figma，不必每件事都從 Figma 開始。
  • 00:01 第一印象：使用時感受到一種和以前試過的模型都有點不同的「自信」
    ↳ 「自信」指它做事不太猶豫，會直接拿出一個做法，不會丟給你一堆模稜兩可的選項。受訪者覺得，這種感覺和他們以前用過的模型不太一樣。
  • 00:31 模型似乎對怎麼做有自己的主見，不太需要多下 prompt
    ↳ prompt 是你給 AI 的指令或說明文字。這一點是說，你不用把每個細節都交代清楚、改了又改，模型自己就有一套判斷，知道該怎麼做。
  • 00:31 模型會先花時間理解新任務再動手，受訪者認為這讓結果明顯變好
    ↳ 就像有經驗的人接到案子，會先把需求看懂再開工。模型也會先花時間搞懂任務，不會一拿到就急著動手。受訪者認為，成品因此好很多。
  • 00:31 最特別的是：模型執行任務的過程中，仍然可以指揮、調整它
    ↳ 一般常見的情況是等 AI 跑完才能修改，不滿意就整個重來。這個模型在做的途中就能讓你插話、改方向，有點像和同事邊做邊討論。
  • 00:31 示範題目：為一台針對短距離最佳化的單人直升機，設計飛行控制系統
    ↳ 題目刻意出得很具體，也很冷門：一架只坐一個人、專門飛短程的直升機，要幫它設計操作飛行的介面。這比做一般常見的 App 更考驗模型。
  • 01:01 做法是先找出關鍵情境與 user journey，再請模型想出「怎樣的原型算成功」的概念，接著直接實作
    ↳ user journey 是使用者從開始到完成一件事經過的每一步；prototype（原型）是可以實際點點看的試作版。他們先想清楚使用情境、訂好成功標準，再讓模型動手做。
  • 01:01 模型在這件事上工作了大約 2 小時，做出這個介面的新原型
    ↳ 2 小時是模型持續自己工作的時間，最後產出一版全新的介面原型。重點在於它能長時間專心做同一件事，不是做幾分鐘、回一段話就停下來。
  • 01:01 成果包含統一的品牌系統、正確使用 components 維持一致性，並橫跨多個畫面串成連貫的使用旅程
    ↳ components（元件）是按鈕、選單這類做好一次就能重複使用的零件，改一個地方，所有用到它的地方都會跟著變。成品的風格統一、零件用得正確，好幾個畫面也能一路點下去。
  • 01:31 成果能展示這個 app 如何在不同裝置間互動
    ↳ 成品不只是一個畫面，還能呈現這個 app 放在不同裝置上時，彼此怎麼搭配、怎麼互動。
  • 01:31 受訪者表示，從未見過一個只用幾百個 tokens 起頭的點子，能被這麼高精準度地實作出來
    ↳ tokens 是 AI 計算文字的單位，可以想成字詞的小片段，幾百個 tokens 大概就是一小段話。意思是：只給了短短一段想法，就做出細節很到位的成品。
  • 01:31 受訪者從未見過模型用上這麼多 Figma 功能並全部做對：從 design system、components 到整個互動流程
    ↳ design system（設計系統）是一整套規範，把顏色、字體、元件的用法都統一定好。受訪者驚訝的是，從規範、元件到整個操作流程，模型都用上了，而且都沒用錯。
  • 01:31 要有效率地完成這種工作，得先想清楚這類設定一般需要哪些基本原則，甚至要在進入設計本身之前就想好
    ↳ 想省時間，關鍵在開工前的準備：這類產品通常要遵守哪些基本規則，最好在畫第一個畫面之前就先想好。模型會做，但原則要先由人定清楚。
  • 02:01 下一步：想把它更深入整合進自己的工作流程，並思考它會如何改變 Figma 打造與發布功能的方式
    ↳ 這次試用只是開始。接下來，他們想把模型放進每天的實際工作裡，也在思考 Figma 自己開發、推出新功能的方式，會因此出現哪些改變。
  • 02:01 期望從最初的 spec 開始，把混亂的點子摸索過程，收斂成大家都認同的清楚願景
    ↳ spec（規格書）是寫清楚一個功能要做什麼、長什麼樣子的文件。專案初期點子多又亂，他們希望模型幫忙把這些發想整理成全團隊都認同的明確方向。
  • 02:01 在流程的每個階段，不只用來做原型、把想法視覺化，也用來降低最複雜部分的技術風險
    ↳ 模型不只能把想法快速做成看得到的原型，還能先試做最難、最容易卡住的部分。這樣可以提早發現技術上行不通的地方，免得做到一半才出問題。
  • 02:31 能同時、平行地做完這些事，受訪者認為會大幅加快工作流程，最終能更快做出更多產品
    ↳ 以前這些步驟常常要一件做完才能接著做下一件。如果能同時進行，整個流程會快很多，同樣的時間就能推出更多產品。
📘 術語
agentive（代理化／具代理能力）：Figma 希望讓產品內外都 agentive，並讓最好的模型能在 Figma 中使用

prototype（原型）：先定義怎樣的原型算成功再實作；模型做出了介面的新原型
user journey（使用者旅程）：示範中先找出關鍵情境與 user journey，再實作到應用程式裡
components（元件）：字幕提到正確使用 components 能確保一致性
