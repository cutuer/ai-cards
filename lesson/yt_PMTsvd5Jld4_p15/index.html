🧑‍🏫 這段是 Grok 官方直播的一段，團隊邊開公司邊示範怎麼叫 AI bot 指揮雲端的 AI 工程助手寫程式，還會碰到上線卡關、程式多到看不完這些現場狀況。後半段來賓 Cody 分享用 AI 做的營運儀表板，也給出很實在的創業建議：先確認有人願意買單。

  • 167:06 harness 內建工程 knowhow，bot 可以代為管理 Cursor cloud agents，所有工程工作都能在 bot 裡完成
    ↳ harness 是包在 AI 外面、決定它怎麼做事的框架，這裡已內建工程經驗。所以 bot 能替你指揮 Cursor（AI 寫程式工具）的 cloud agents（雲端 AI 工程助手），工程上的事都在 bot 裡搞定。
  • 167:06 Cursor cloud agents 在雲端執行，各自有 virtual machine，可以測試應用程式、在畫面上點擊操作、擷取 CPU traces
    ↳ 每個 cloud agent 各有一台 virtual machine（雲端上模擬出來的電腦），所以能真的把 app 跑起來、在畫面上點點看，還能抓 CPU traces（記錄電腦運算狀況，常用來找卡頓原因）。
  • 167:38 使用方式：直接叫你的 bot 去 spawn 一個 cloud agent
    ↳ 用法就是直接跟你的 bot 說，叫它 spawn（新開）一個 cloud agent 來做事。你只要下指令，不用自己去一個個設定。
  • 167:38 如果已經有 repo，可以請 bot 幫忙設定環境，讓 cloud agents 知道怎麼在雲端啟動、執行你的應用程式
    ↳ repo 是存放程式碼的地方。已經有程式的話，可以請 bot 先把環境設好，讓雲端的 agent 知道怎麼把你的 app 開起來跑，之後它才能自己測試。
  • 167:38 團隊的工程 bot 叫 Tater；直播中想幫它加標題，但似乎只能加 label
    ↳ 團隊負責寫程式的 bot 叫 Tater。直播中想幫它加個標題方便辨認，結果介面好像只能加 label（分類標籤），算是現場邊用邊摸索的小插曲。
  • 168:09 Tater 建立了一個 project：一種特別的 cloud agent，很適合長期專案，用來保存應用程式的所有技術工程脈絡
    ↳ Tater 開了一個 project：這是一種特別的 cloud agent，會一直記住這個 app 的技術細節，適合長期專案，不用每次都從頭交代背景。
  • 168:40 需要做更多工程工作時，就再傳訊息給這個 project；講者也說最後不一定會採用 project
    ↳ 之後有新的工程工作，就傳訊息給這個 project 接手。不過講者也坦白說這只是先試試，最後不一定會用 project 這種做法。
  • 168:40 PlanetScale 的 credentials 還沒拿到，所以先在本機、自己的雲端機器或 cloud agent 的機器上開發，完成後回傳影片或截圖，部署之後再處理
    ↳ PlanetScale 是雲端資料庫服務，credentials 是登入用的帳密或金鑰。因為還沒拿到，只好先在本機或雲端機器上開發，做好回傳影片或截圖確認，正式上線之後再處理。
  • 169:44 團隊買下網域 shipbyths（口頭唸作 ship by Thursday），網站放在 Versell（字幕原文拼寫）上
    ↳ 他們買了網域（網址）shipbyths，唸作 ship by Thursday，字面意思是「星期四前出貨」。網站放在字幕拼成 Versell 的平台上，應該是指網站代管服務 Vercel。
  • 169:44 ship by Thursday 是公司主站（company lander），也就是「公司背後的公司」；實際產品之後會放在另一個產品網域
    ↳ 這個網站是 company lander（公司的門面首頁），代表做產品的「那家公司」本身。真正要賣的產品之後會另外用一個網址，兩者分開。
  • 170:15 產品名稱還沒決定，團隊認為至少需要先有一個暫定名稱（working title）
    ↳ 產品還沒取名，但團隊覺得至少要先有個 working title（暫定名稱），不然大家討論、做東西時連怎麼稱呼它都沒有。
  • 170:15 講者正在幫 bot 安裝 Cursor team kit、其他 skills 和 pstack，再串接 Cursor cloud agents，準備好後就開始寫 company lander 的程式
    ↳ 講者正在幫 bot 裝工具：Cursor team kit、其他 skills（教 AI 做特定工作的技能包）和 pstack，影片沒細講各是什麼。接好 cloud agents 後就開始寫公司首頁。
  • 170:46 團隊強調是在直播中邊 hacking 邊建立公司，要做的東西很多，這也是樂趣所在
    ↳ 他們刻意在直播中邊 hacking（動手快速拼出東西）邊開公司，待辦事項一大堆，但這種邊做邊解決的過程正是好玩的地方。
  • 170:46 bot Steve 開了一個 pull request，講者訂下新規則：暫時不開 pull request，直接 ship 到 main
    ↳ bot Steve 開了一個 pull request（把改好的程式送審，等人同意才合併）。講者改規則：先不送審，直接 ship（推上去）到 main，也就是正式版本的主線。
  • 171:49 Steve 開的那個 pull request 大約 2,000 行，講者說不會全部讀完
    ↳ 那個 pull request 大約 2,000 行程式，講者直說不會全部讀完。AI 一次產出這麼多，人工逐行檢查已經不實際。
  • 171:49 講者想規劃工程工作流程：除了工程 bot Tater，還要再加一個負責 review 的 bot
    ↳ 所以他想把流程規劃好：Tater 負責寫程式，再加一個專門 review（檢查程式品質）的 bot，用 AI 補上人看不完的部分。
  • 172:22 因為技術問題直播暫時切到等待畫面，回來後由 Lauren 接手 factory creation
    ↳ 直播因技術問題暫時切到等待畫面，回來後換 Lauren 接手 factory creation。字幕沒進一步說明這部分具體在做什麼。
  • 175:02 講者開了新頻道叫 high level，在做公司的 lander，也能在 Cursor 裡看到團隊其他人正在跑的 agents
    ↳ 講者開了一個叫 high level 的新頻道，專門做公司首頁。在 Cursor 裡也看得到其他成員正在跑哪些 agents，大家的進度都一目了然。
  • 176:03 Cody 分享一個有 135,000 名使用者的儀表板，用來追蹤兩天後的新書發表，他們把新書發表當成產品上市來辦
    ↳ Cody 展示一個儀表板（把關鍵數字集中在同一個畫面的工具），有 135,000 名使用者，用來追蹤兩天後的新書發表。他們把出書當成產品上市在辦。
  • 176:34 這個儀表板用了一部分 Grok 做出來，放在 Versell 上，可以即時追蹤參加人數
    ↳ 這個儀表板有一部分是用 Grok 做出來的，放在 Versell 上，參加人數即時更新，不用等活動結束才統計。
  • 176:34 儀表板也會追蹤付費和自然流量的比例、各個管道的表現，以及平均 CAC 和平均訂單金額的對比
    ↳ 它還分開追蹤付費廣告和 organic（自己找上門的自然流量）各占多少、哪個管道有效，並比較 CAC（拉到一位客人的平均成本）和平均訂單金額，看這樣做划不划算。
  • 177:04 第二個例子是叫 pulse 的儀表板，用來規劃怎麼經營事業，會依照最低的獲利槓桿（profit levers）擬定計畫
    ↳ 第二個例子叫 pulse，用來規劃怎麼經營事業，會從最低的 profit levers（能拉高獲利的關鍵因素）下手擬計畫。字幕沒說「最低」具體怎麼判斷。
  • 177:35 Cody 認為先想清楚你最大的問題是什麼：好問題才能得到最好的答案
    ↳ Cody 的觀點是先把自己最大的問題想清楚。問題問得好，得到的答案才會好，這也適用在你問 AI 的時候。
  • 178:06 團隊的點子是辦餐廳快閃店（restaurant popup）：媒合餐廳經營者和想體驗的客人、找場地，之後再把整個流程做成軟體出售
    ↳ 團隊的點子是 restaurant popup（餐廳快閃店）：媒合想辦快閃的餐廳經營者和想去吃的客人、幫忙找場地，流程跑順之後，再把整套做法做成軟體賣給別人。
  • 178:36 團隊打算先處理營運，法律相關問題之後再找法務研究
    ↳ 他們打算先把營運跑起來，法律上的問題之後再找法務研究，不讓它一開始就卡住進度。
  • 178:36 Cody 的建議：決定要做什麼事業之前，先看看能不能賣給三個人
    ↳ Cody 建議：決定要做哪門生意之前，先試著賣給三個人。真的有人付錢，才代表這個需求存在，而不只是你自己覺得不錯。
  • 178:36 Cody 提到每 2,000 家公司只有 2 家拿得到 VC，餐廳快閃店這類生意不太可能拿到創投資金，但仍然可以是好生意
    ↳ Cody 說每 2,000 家公司只有 2 家拿得到 VC（創業投資的資金）。餐廳快閃這類生意不太可能拿到創投，但不靠創投也能是門好生意。
📘 術語
Cursor cloud agents（Cursor 雲端代理）：在雲端執行、有自己的 virtual machine，能測試應用程式、點擊操作、擷取 CPU traces
harness（執行框架）：字幕只說它內建工程 knowhow，沒有進一步解釋
virtual machine（虛擬機器）：每個 cloud agent 都有自己的一台，用來執行和測試應用程式
CPU traces（CPU 追蹤紀錄）：cloud agent 在虛擬機器上可以擷取的項目之一，字幕沒有另外說明
project（專案）：一種特別的 cloud agent，適合長期專案，用來保存技術工程脈絡
credentials（憑證）：團隊還在等 PlanetScale 的 credentials，所以暫時沒辦法部署
lander（公司／產品的著陸頁）：公司主站，放在 ship by Thursday 網域
working title（暫定名稱）：產品正式命名前至少要先有的名字
pull request（合併請求）：Steve 開了一個約 2,000 行的；新規則是暫時不開，直接 ship 到 main
main（主分支）：新規則下程式直接推送到這裡
label（標籤）：直播中無法幫 bot 加標題，但似乎可以加 label
CAC（客戶取得成本）：儀表板會拿平均 CAC 和平均訂單金額做比較
organic（自然流量）：儀表板會和付費流量分開追蹤
profit levers（獲利槓桿）：pulse 會依照最低的獲利槓桿擬定經營計畫
VC（創投資金）：每 2,000 家公司只有 2 家拿得到
restaurant popup（餐廳快閃店）：團隊的創業點子：媒合餐廳經營者和客人、找場地，再把流程做成軟體
