🧑‍🏫 這是 OpenAI DevDay 2026 的一場示範（上半段），主題是 Codex Cloud：把 Codex 的任務搬到雲端跑。這樣筆電闔上任務也不會停，不用再為了讓 AI 一直工作而多買電腦。如果你常把耗時的工作丟給 AI，這支在講的就是「交辦之後不用守在電腦前」。

  • 00:00 講者 Dominic 在 OpenAI 負責 developer experience
    ↳ 講者叫 Dominic，在 OpenAI 負責 developer experience（開發者體驗），也就是讓工程師用 OpenAI 工具時順不順手、好不好上手的那一塊。
  • 00:30 Sam 稍早發表約 20 個新功能，過去一年 OpenAI 推出約 300 個功能，已大幅改變 OpenAI 內部與開發者的開發方式
    ↳ Sam 稍早的主題演講發表了約 20 個新功能，過去一年 OpenAI 總共推出約 300 個。這些功能已經實際改變 OpenAI 內部和外部開發者寫程式的方式。
  • 00:30 功能多到很難跟上，本場用約 25 分鐘示範如何把這些功能實際納入工作流程
    ↳ 新東西多到連關注的人都追不上。所以這場不再列清單，而是花約 25 分鐘示範這些功能怎麼真的放進每天的工作流程。
  • 01:02 目標是讓你能用自己想要的方式，在任何地方使用 Codex
    ↳ 整場的核心訴求是：Codex 不該被綁在某台電腦或某個介面上。你想在哪裡用、用什麼方式用，都應該可以。
  • 01:02 年初講者通常只同時跑一兩個任務；看到 Peter 推文同時跑約 40 個 Codex，當時覺得難以想像
    ↳ 年初講者一次只跑一兩個任務。看到 Peter 發文說同時開約 40 個 Codex，他當時覺得不可思議，可見那時大量多工還很少見。
  • 01:33 Codex app 推出後，委派與切換任務變容易，同時跑多個 agent 幾乎成為常態
    ↳ agent 指能自己動手完成任務的 AI 助手。Codex app 推出後，把工作交出去、在任務間切換都變簡單，同時讓好幾個 agent 各做各的就成了日常。
  • 01:33 模型在 computer use 與長時間工作上變強後，開始把更大的問題交給模型，常常一跑就是數小時甚至數天
    ↳ computer use 指模型像人一樣操作電腦畫面。這項能力和長時間工作的能力變強後，大家開始交付更大的工作，一跑就是好幾小時甚至好幾天。
  • 02:04 結果大家開會時把筆電半開著帶著走，只為了讓任務繼續跑
    ↳ 問題是任務在自己筆電上跑，筆電一闔就停。結果出現大家開會時捧著半開的筆電走來走去、只為了不讓任務中斷的狀況。
  • 02:04 很多人因此買 Mac Mini、Raspberry Pi 或租 VPS 來讓 agent 持續運作
    ↳ 為了讓 agent 不停工作，有人買 Mac Mini 或樹莓派一直開著，或租 VPS（向業者租的遠端電腦，放在機房 24 小時運作）。
  • 02:04 機器變多就得處理更多維護、磁碟空間、更新與容量管理，想做更多事就得再採購更多機器
    ↳ 機器一多，人就變成在當網管：要顧硬碟空間、裝更新、算容量夠不夠。想同時做更多事，就得再買更多機器，負擔越滾越大。
  • 02:39 理念：委派工作應該只要叫 Codex 去做就好，不必另外採購電腦
    ↳ OpenAI 的想法是：你要的是把事情交出去，不是去管電腦。理想狀態是開口叫 Codex 做就好，不必為此另外買硬體。
  • 02:39 你應該能在任何想用的介面使用 Codex harness，並自行選擇工作在哪裡執行，讓流程能跟上越來越強的 agent 與模型
    ↳ Codex harness 指讓 Codex agent 運作的那套底層框架。從哪個介面叫它、工作放在哪裡跑，都該由你決定，流程才跟得上越來越強的模型。
  • 03:11 今天發表 Codex Cloud、ChatGPT in Slack and Teams 等功能
    ↳ 這次發表的新功能包括 Codex Cloud（讓 Codex 任務在雲端跑），也能在 Slack、Teams 這類工作聊天軟體裡直接使用 ChatGPT。
  • 03:11 這些功能都使用同一個 Codex agent，能透過帳號裡已安裝的 plug-in 取得相同的工具與資訊，不必從頭開始
    ↳ plug-in 是裝在帳號裡的外掛，讓 Codex 連到其他工具。這些新功能背後都是同一個 Codex，外掛裝一次到處通用，換地方不用重新設定。
  • 03:42 桌面 app 除了在本機或 remote 跑任務，現在也能在雲端跑，可用團隊已建立的 environment 或新建 environment
    ↳ environment（環境）是任務實際執行的工作空間。桌面 app 原本能在本機或遠端機器跑，現在多了雲端選項，可用團隊建好的環境，也可以自己開新的。
  • 03:42 新建 environment 時，可以挑選要讓它存取的 repository
    ↳ repository（程式庫，簡稱 repo）是存放專案程式碼與修改紀錄的地方。開新環境時，你可以勾選要讓它看到哪些 repo，沒勾的它碰不到。
  • 04:15 示範選了 Blossom Music（Holly 在做的專案）中的兩個專案
    ↳ 示範拿的是真實專案：Blossom Music 裡的兩個專案，是同事 Holly 正在做的東西。
  • 04:15 選好後 Codex 會自動檢查 repository、相依套件與程式碼，完成所需設定；以前這要大量手動設定，非常麻煩
    ↳ dependencies（相依套件）是程式跑起來前要先裝好的其他元件。選好 repo 後，Codex 會自己讀程式碼、找出要裝什麼並設定好，以前這些都得手動處理。
  • 04:15 設定過程中 Codex 會寫一份 startup skill，教 agent 如何使用這個環境
    ↳ startup skill 是 Codex 自己寫的一份說明，告訴之後進來的 agent 這個環境怎麼用、專案有哪些細節要注意，作用像交接文件。
  • 04:47 也會寫一份 startup script，讓它能在這些環境中快速迭代
    ↳ startup script 是環境啟動時自動執行的一段指令，負責把環境準備好，讓 Codex 每次進來都能馬上開工、反覆修改和測試。
  • 04:47 專案同時有 iOS 與 web 相依套件；因為是 Linux 環境，Codex 正確判斷無法執行行動 app，講者只需要它能參考那份程式碼
    ↳ 專案同時有 iOS app 和網頁版。雲端環境是 Linux 系統，跑不了 iOS app，Codex 自己判斷出了這點。講者本來只需要它參考那份程式碼，所以不影響。
  • 05:17 未來將能使用自己的雲端環境（bring your own cloud environments），依需求調整任務的執行方式
    ↳ 之後會開放 bring your own cloud environments，也就是用你們公司自己的雲端主機來跑任務，依需求調整執行方式。
  • 05:17 花了很多心力在檔案系統 snapshotting，讓後續任務啟動更快
    ↳ snapshotting 是把環境當下的檔案狀態拍一張快照存起來。下次開任務直接從快照開始，不用重裝一遍，啟動就快很多。
  • 05:50 也能在背景更新，確保環境有最新的 repo 變更，並執行其他必要的更新腳本
    ↳ 環境也會在背景自動更新：把 repo 最新的修改拉進來，並跑該跑的更新腳本，確保下次用時不是拿舊版本在工作。
  • 05:50 範例：先前把一張 app shot 送到雲端環境，請 Codex 實作在 Figma 設計好的 shader
    ↳ shader 是計算畫面視覺效果的一小段程式，負責光影、漸層這類效果。講者先前把一張 app 截圖丟到雲端，請 Codex 實作在 Figma 設計好的 shader。
  • 06:24 Codex 透過帳號裡安裝的 Figma plug-in，直接從 Figma 抓取所需細節，接著實作 shader、測試，並產生影片
    ↳ Figma 是常用的介面設計工具。帳號裝了 Figma 外掛，所以 Codex 能自己去 Figma 抓設計細節，接著寫程式、測試，最後錄一段影片呈現成果。
  • 06:24 因為環境能使用所有 plug-in，講者又請 Codex 把 shader 做成可互動的 playground，並部署成網站
    ↳ playground 是能動手調參數、即時看效果的測試頁面。雲端環境也能用所有外掛，所以講者接著請 Codex 做出這種頁面，還直接架成網站。
  • 06:56 可在正式部署前先在 playground 測試、微調 shader，再把設定更新送回 app
    ↳ 好處是效果可以先在網頁上試、調到滿意，再把設定值帶回 app 正式上線，不用每改一次就重出一版 app。
  • 06:56 和本機用 Codex 一樣，可在 app 裡直接對被修改的程式碼留言、檢視變更內容
    ↳ 跟在自己電腦上用 Codex 一樣，可以在 app 裡看它改了哪些程式碼，也能直接在某一行留言請它修改，像在文件上加註解。
  • 07:26 也能開一個側邊聊天，針對剛執行完的任務提問
    ↳ 也能開一個側邊聊天視窗，針對剛跑完的任務發問，例如「你為什麼這樣改」，不會打斷主畫面的工作。
  • 07:26 雲端環境常見的缺點是難以存取私有資源，也就是想讓雲端環境用、但不想暴露在公開網路上的資源
    ↳ 雲端環境常卡在一件事：公司內部的資料或服務不想公開在網路上，卻又希望雲端裡的 Codex 用得到。這就是私有資源的存取問題。
  • 07:58 示範：一台 Raspberry Pi 上跑著一個小 API，沒有對外開放到網路
    ↳ 示範用一台樹莓派跑一個小 API（讓程式之間互相查資料、下指令的介面），而且刻意不對外開放，外面連不到。
  • 07:58 把 TailScale 設定為環境的 VPN 存取，並提供 TailScale 的 auth key，Codex 就能存取 TailScale 網路上的任何資源
    ↳ VPN 是在公開網路上建一條私人通道。用 TailScale（把多台裝置串成私人網路的工具）當 VPN，再給 auth key（登入金鑰），Codex 就能進這個網路。
  • 08:29 同時新增了 OIDC 支援，可以透過 OIDC 存取雲端資源
    ↳ 另外新增 OIDC 支援。OIDC 是一種通用的身分驗證標準，讓雲端環境用標準方式證明自己的身分，進而取得雲端服務的存取權。
  • 08:29 證明 API 不在雲端：直接連該 port 沒有回應，筆電連上同一個 TailScale 網路後就有回應
    ↳ port（連接埠）像電腦上的門牌號。直接連那個 port 沒反應，筆電接上同一個 TailScale 網路後才有回應，證明 API 只在私人網路裡。
  • 09:06 keynote 期間有服務中斷，現場示範不順，改用事先跑好的備份任務展示
    ↳ 主題演講期間服務剛好出狀況（講者說有 SEV，也就是正在處理的服務事故），現場示範不順，所以改放事先跑好的備份任務。
  • 09:06 備份任務中，Codex 成功呼叫只存在 TailScale 網路裡的 API
    ↳ 備份任務裡可以看到，Codex 成功呼叫了那個只存在 TailScale 私人網路裡的 API，證明雲端環境真的連得進去。
  • 09:36 回頭看環境設定任務：Codex 判斷無法測試 iOS 變更，但仍可編輯行動版原始碼
    ↳ 回到環境設定任務：Codex 判斷這裡沒辦法測試 iOS 的修改，但仍可以改行動版的程式碼，只是改完無法在這裡實際跑起來驗證。
  • 09:36 Codex 建議了一份 install script 和一份 startup skill；可以手動修改，也可以繼續用對話指示 Codex 調整環境設定
    ↳ install script（安裝腳本）負責把需要的東西裝好。Codex 提出安裝腳本和 startup skill 的建議版本，你可以自己動手改，也可以用講的請 Codex 改。
  • 10:09 這些調整可以在第一次建立環境時做，也可以之後隨時回來繼續迭代
    ↳ 這些設定不必一次到位。第一次建環境時可以調，之後發現哪裡不對，也隨時能回來繼續修。
  • 10:09 接受設定後，還能控制網路存取、設定網路 secrets，並設定環境變數
    ↳ 確認設定後還能進一步控管：能不能上網、能連哪裡；設定 network secrets（連線時用的密碼或金鑰）；以及設定環境變數。
  • 10:09 環境變數可以是這個雲端環境專用的，也可以使用存在 vault 裡的個人環境變數
    ↳ environment variables（環境變數）是程式執行時讀取的設定值。可以只給這個環境用，也可以取用存在 vault（集中保管機密的保險箱）裡的個人設定。
  • 10:39 環境可以選擇只給自己用，或分享給整個團隊
    ↳ 建好的環境可以只給自己用，也可以分享給整個團隊。大家共用同一套設定，不必各自重建。
  • 10:39 因為任務在雲端執行，可以直接闔上筆電，改用手機或瀏覽器繼續存取這些任務
    ↳ 因為任務在雲端跑，筆電可以直接闔上帶走。之後用手機或瀏覽器打開，就能看進度、繼續下指令，這就是標題「離開筆電」的意思。
📘 術語
developer experience（開發者體驗）：講者在 OpenAI 負責的工作領域，字幕未進一步解釋
agent（代理程式）：Codex 用來執行任務的主體；Codex app 推出後，同時跑多個 agent 幾乎成為常態
computer use（電腦操作能力）：模型變強的面向之一；模型變強後開始被交付更大、更長時間的工作
VPS（虛擬專用伺服器）：有人租 VPS 來讓 agent 持續運作
Codex harness（Codex 執行框架）：應該能在任何你想用的介面中使用，並自行選擇工作在哪裡執行
plug-in（外掛）：裝在帳號裡，讓 Codex 取得相同的工具與資訊，例如 Figma plug-in
environment（（雲端）環境）：在雲端跑 Codex 任務的地方，可指定能存取的 repository，可用團隊既有的或新建
repository（程式碼倉庫）：建立 environment 時可挑選讓環境存取的 repository
dependencies（相依套件）：Codex 設定環境時會自動檢查並找出相依套件
startup skill（啟動技能說明）：Codex 寫的文件，教 agent 如何使用這個環境，並描述專案所需細節
startup script / install script（啟動腳本／安裝腳本）：Codex 寫的腳本，讓它能在環境中快速迭代
snapshotting（快照）：對檔案系統做快照，讓後續任務啟動更快
shader（著色器）：示範中在 Figma 設計、交給 Codex 實作並做成 playground 測試的東西
playground（試玩介面）：Codex 把 shader 做成可部署成網站的互動介面，可在正式部署前測試與微調
TailScale（TailScale（VPN 服務））：講者用它做 VPN 存取，給 Codex auth key 後就能存取私有網路上的資源
VPN（虛擬私人網路）：讓雲端環境存取私有資源，又不必暴露到公開網路
auth key（驗證金鑰）：提供給環境的 TailScale 金鑰，讓 Codex 能存取該網路上的資源
OIDC（OIDC）：新增的支援，可透過 OIDC 存取雲端資源
port（連接埠）：API 執行所在的 port；未連上 TailScale 時沒有回應
SEV（SEV（事故處理））：講者提到 keynote 期間有服務中斷，有 SEVs 正在處理
network secrets（網路機密設定）：建立環境時可以設定的項目之一
environment variables（環境變數）：可設定雲端環境專用的，或使用存在 vault 裡的個人環境變數
vault（保管庫）：存放個人環境變數的地方，可供雲端環境使用

A. 把環境設定為透過 TailScale 做 VPN 存取，並提供 TailScale 的 auth keyB. 把 API 的 port 對公開網路開放C. 用 Figma plug-in 轉接 API 請求D. 把 API 搬到 Mac Mini 上執行
