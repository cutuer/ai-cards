🧑‍🏫 這支 OpenAI 官方 Build Hour 介紹 ChatGPT 裡的新功能 workspace agents。agent 是能自己分步驟做事的 AI 助手。影片示範不用寫程式，只要用講的，就能做出一個每天早上自動幫你準備會議資料的 agent。如果你常被重複又零碎的準備工作卡住，這支能讓你看到這類工作可以交給 AI 到什麼程度。

  • 00:05 Build Hours 的目的是用真實範例與技巧，幫助團隊從 OpenAI 產品獲得更多實用價值；本集主題是在 ChatGPT 中建立 workspace agents
    ↳ Build Hours 是 OpenAI 定期辦的實作直播，用真實例子教團隊把產品用出價值。這集的主題是 workspace agents，也就是 ChatGPT 裡幫團隊做事的 AI 助手。
  • 00:36 workspace agents 目前以 research preview 形式，開放給 ChatGPT business、enterprise、EDU 與 ChatGPT for teachers 方案
    ↳ research preview 指功能還在測試階段，先開放部分用戶試用。目前只開放 Business、Enterprise、EDU 和教師版方案，個人方案不在名單內。
  • 00:36 本集流程：Christina 先介紹 workspace agents，Hojun 示範兩個 demo，Christina 再分享入門技巧、agents 與 GPTs 的比較、企業管理員控制，最後現場問答
    ↳ 這集分三塊：先講概念，再看兩個實作例子，最後講上手訣竅、和 GPTs 的差別、公司管理員怎麼控管。GPTs 是 ChatGPT 裡可以自訂的聊天助手。
  • 00:36 Demo 一是會議準備 agent：查看行事曆、做研究、產出會議簡報（meeting brief）
    ↳ 第一個例子是幫你做開會前的功課。agent 自己看你的行事曆、查對方資料，整理成 meeting brief，也就是開會前讀的重點整理。
  • 00:36 Demo 二是軟體審查 agent：處理員工在 Slack 提出的請求，並依公司政策安排下一步
    ↳ 第二個例子是內部申請流程。同事在 Slack（公司常用的聊天工具）提出想用某套軟體，agent 會依照公司規定判斷下一步怎麼處理。
  • 01:06 workspace agents 是 ChatGPT 中由 Codex 驅動的 agents，用來處理橫跨多個系統、複雜且長時間執行的工作，可存取檔案、程式碼與工具
    ↳ Codex 是 OpenAI 擅長執行任務的 AI 代理技術。workspace agents 用它當引擎，所以能翻檔案、用工具，處理步驟多、要跨好幾個系統的事。
  • 01:37 它不只是一人對一個 prompt：能蒐集合適的 context、在背景持續執行，並可分享到 ChatGPT 或 Slack 讓整個團隊一起使用
    ↳ 一般用 ChatGPT 是你問一句、它答一句。agent 會自己去找需要的 context（做事需要的背景資料），你不在時也繼續做，還能分享給整組人用。
  • 01:37 workspace agents 具備 memory，可在對話中被引導，並隨時間改善
    ↳ memory 是讓它記得過去的互動。你在對話中糾正它，它會記住，越用越貼近你們的做法，不用每次重教。
  • 01:37 開始方式：點 ChatGPT 側邊欄的 agents，描述團隊現有的工作流程，ChatGPT 會協助把它轉成 agent
    ↳ 上手不用寫程式。在 ChatGPT 左側欄點 agents，用平常說話的方式描述你們現在怎麼做這件事，ChatGPT 會幫你轉成一個 agent。
  • 02:09 定位比較：workspace agents 給團隊用，適合共享工作，任務在雲端執行，電腦關機也能跑
    ↳ 雲端執行是指工作在 OpenAI 的伺服器上跑，不在你的電腦上。所以你闔上筆電下班，它照樣按時做事。它的設計本來就是給團隊共用。
  • 02:09 Codex 適合個人搭配個人 agent 完成工作；Agents SDK 則給想把自訂 agent 直接做進自家產品與客戶體驗的團隊
    ↳ 三者分工不同。Codex 偏向個人自己用的助手。Agents SDK 是給工程師的開發工具包，讓公司把 agent 做進自家 App 或服務，提供給客戶使用。
  • 02:39 OpenAI 內部案例：行銷團隊的 agent 能把產品簡介直接變成網站，需求來源是 Google Docs 與程式碼
    ↳ OpenAI 自己的行銷團隊，把寫在 Google Docs 的產品介紹和相關程式碼交給 agent，agent 就能直接做出網站。
  • 02:39 會計團隊建了 agent，協助更快、更一致地準備月底結帳（month-end close）
    ↳ month-end close 是會計每月月底對帳、關帳的例行工作，步驟多又容易出錯。agent 幫忙準備，讓這件事做得更快，每個月的做法也更一致。
  • 02:39 財務團隊的供應商風險審查 agent：研究供應商，評估制裁風險、財務健康、聲譽風險等訊號，並產出結構化報告
    ↳ 財務要跟新廠商合作前，agent 先查這家公司有沒有被制裁、財務穩不穩、名聲好不好，再整理成格式固定的報告，方便比較和存檔。
  • 03:09 會議準備 agent 是為了減輕客戶會議準備中，需要橫跨多個系統的手動工作
    ↳ 準備客戶會議時，常要在行事曆、雲端硬碟、網路之間來回翻資料。這種重複又零碎的手工活，就是這個 agent 要接手的部分。
  • 03:39 Hojun 每天早上會收到名為 Auto 的 agent 寄來的 email：它查行事曆，在網路或 Google Drive 研究客戶，並為每場會議建立簡報附上連結
    ↳ 講者 Hojun 的實際用法：每天早上會收到名叫 Auto 的 agent 寄來的信。它已經看過當天行程、查好客戶資料，每場會議都附上一份簡報連結。
  • 03:39 過去每晚花數小時做會議準備文件（用來和團隊對齊議程），現在都由 agent 在背景完成
    ↳ 以前他每晚要花好幾小時寫會前文件，讓團隊對齊要談什麼。現在這段工作改由 agent 在背景自動完成，他直接看成果就好。
  • 04:10 這個 agent 可以分享，讓其他人依自己的工作流程客製化，得到類似的價值
    ↳ 做好的 agent 可以分享給同事。對方能依自己的工作習慣調整，不用從零開始做，也能得到差不多的幫助。
  • 04:10 示範依照一份 cookbook 進行，觀眾可以跟著操作，也可以會後再回頭參考
    ↳ cookbook 是官方的逐步操作說明文件。示範照著它走，你可以邊看邊做，也可以之後再拿出來一步步照做。
  • 04:41 示範素材都是假資料：模擬的行事曆事件與虛構客戶，另有帳戶筆記、公司資訊與一份 sales meeting prep 範本
    ↳ 示範用的全是假資料，包括假的行程、虛構的客戶、客戶筆記、公司資料，還有一份業務會前準備範本。畫面上的公司和人名都不是真的。
  • 05:11 workspace agents 只要用自然語言就能建立 agent；可以從空白開始，也可以使用下方的範本
    ↳ 建立 agent 只要用文字描述你要什麼。可以從空白開始寫，也可以挑現成範本修改。不知道怎麼開頭時，範本是很好的起點。
  • 05:41 示範的 prompt 內容：協助 sales meeting prep、列出需要的工具與 apps、說明有範本可用，最後要求寄出 email，附上即將到來的會議摘要與完整簡報連結
    ↳ prompt 就是你下給 AI 的指令。示範的指令講清楚四件事：要幫什麼忙、會用到哪些工具、有範本可以參考、成果怎麼交（寄信附摘要和簡報連結）。
  • 05:41 送出 prompt 後，ChatGPT 會引導整個建置流程，先產出 agent plan 大綱讓你審閱，再開始建置
    ↳ agent plan 是建置前的計畫大綱。ChatGPT 先列出它打算怎麼做，讓你確認方向沒錯再動工，免得做完才發現它誤會你的意思。
  • 06:11 建置過程可以一直用自然語言跟 ChatGPT 互動，給回饋、一起迭代，打造強大而複雜的 agent
    ↳ 過程中隨時可以直接用說的給回饋，例如「簡報再精簡一點」，它就會改。來回幾輪，就能做出步驟複雜、又符合需求的 agent。
  • 06:41 建置時 ChatGPT 留在左側窗格，右側負責設定排程、apps、工具，並產生精調過的指令集（instruction set）
    ↳ 畫面分成兩半：左邊跟 ChatGPT 對話，右邊顯示設定，包括什麼時候自動執行、能用哪些 App，還有 instruction set，也就是 agent 的工作說明書。
  • 06:41 這是 no-code 的建立方式，但 agent 的運作仍像 Codex agent：可在背景跑長時間任務、存取資料、跨系統採取行動
    ↳ no-code 是不用寫程式的意思。你雖然只是用講的，做出來的 agent 能力跟 Codex 一樣，可以在背景長時間工作、讀取資料、在不同系統之間動手做事。
  • 07:44 指令完成後，可以直接手動修改設定，也可以在左側給 ChatGPT 回饋，由它處理所有設定
    ↳ 設定完成後有兩種改法：直接在右側手動修改，或在左側告訴 ChatGPT 要改什麼，讓它幫你調整。看你習慣哪一種。
  • 07:44 對使用到的每個 app，都可以限制 agent 能存取的權限
    ↳ 每個接上的 App，都能分別設定 agent 可以做什麼、不能做什麼。只給它完成工作需要的權限，就能降低出錯的風險。
  • 08:16 Google Calendar 範例：agent 只需讀取行事曆，因此停用寫入類動作，確保它不會調整或更改任何事件
    ↳ write actions 是會改動資料的動作，例如修改會議。這個 agent 只需要看行程，所以把寫入關掉，確保它不會動到你的行事曆。
  • 08:47 再加入 Google Drive 與 Gmail；Gmail 需要寄信給自己，但可以停用這個流程不需要的其他動作
    ↳ 接著接上 Google Drive 查資料、Gmail 寄信。Gmail 只需要寄信給自己，其他這個流程用不到的動作都可以關掉。
  • 08:47 workspace agents 的重點：掌控 agent 能做什麼、提供 playbook，讓它依排程執行任務，或透過團隊現有工具與它互動
    ↳ 核心概念有三件事：你決定它能做什麼；給它一套 playbook（做事守則）；讓它照排程自動跑，或在團隊原本用的工具裡直接找它。
  • 09:18 加入 skill：apps 與工具之外，再給 agent 額外指引，讓它更好地協助建立會議準備文件
    ↳ skill 是額外的做事指引，例如一份好的會前簡報該有哪些內容。App 和工具給它能力，skill 教它怎麼把事情做好。
  • 09:18 skills 可以從你現在使用的其他工具和平台匯入，把已經整理成文的最佳實務與流程帶進來，讓專業與一致性擴展到整個組織
    ↳ 如果你們已經有整理成文的 SOP 或做事規範，可以直接匯入成 skill。這樣資深同事的做法就能變成全公司共用的標準。
  • 09:48 也可以選用組織內已有的熱門 skills，或讓 ChatGPT 幫你撰寫全新的 skill
    ↳ skill 不一定要自己寫。可以選組織裡大家常用的 skill，也可以請 ChatGPT 幫你寫一份新的。
  • 10:55 agent 從 Google Docs 找到範本，加入格式指示，會議簡報會用表格、標題、條列呈現，方便一眼掌握重點，例如通勤時在手機上看
    ↳ agent 從 Google Docs 找到範本，並照指示用表格、標題、條列來整理簡報。這樣在手機上掃一眼就能抓到重點，例如通勤路上看。
  • 11:26 切換到經過多次回饋與 preview run 調整過的版本，已經到可以排程與分發的階段
    ↳ 示範直接切換到另一個已經調整多次、試跑過的版本。這代表實際使用時要來回修好幾輪，才會到可以設定排程、分享給團隊的程度。
  • 11:56 可以請 ChatGPT 執行 preview 測試，例如「用我明天的行事曆跑一次 preview」，跑完再給回饋、持續迭代
    ↳ preview run 是正式上線前的試跑。你可以說「用我明天的行事曆跑一次」，看實際產出哪裡不對，再告訴它怎麼改。
  • 11:56 建立這些工作流程不需要 IT 或工程支援，目標是讓領域專家（subject matter experts）自己建立流程，再分發給團隊共享
    ↳ 重點是不用等 IT 或工程師排時間。subject matter experts（最懂這份工作的人）自己就能做出流程，再分享給團隊使用。
📘 術語
workspace agents（工作區代理）：ChatGPT 中由 Codex 驅動的 agents，處理跨系統的長時間工作，可分享給團隊
research preview（研究預覽版）：workspace agents 目前的釋出形式，開放給特定 ChatGPT 方案
Codex（Codex）：workspace agents 的驅動核心；也指給個人使用的 agent 產品
Agents SDK（Agents SDK）：給想把自訂 agent 直接做進自家產品與客戶體驗的團隊
memory（記憶）：讓 agent 能在對話中被引導，並隨時間改善
meeting brief（會議簡報）：agent 為每場會議產出的準備文件，會附上連結寄給使用者
cookbook（操作指南）：逐步說明如何建立示範 agent 的文件，可跟著做或會後參考
agent plan（agent 計畫）：ChatGPT 建置前產出的大綱，讓使用者先審閱
instruction set（指令集）：ChatGPT 建置時為 agent 產生的精調指令
no-code（無程式碼）：用自然語言與 ChatGPT 互動就能建立 agent，不必寫程式
write actions（寫入動作）：例如修改行事曆事件；示範中把它停用，讓 agent 只能讀取
skill（技能）：給 agent 的額外指引，可從其他工具匯入、選用組織現有的，或請 ChatGPT 撰寫
playbook（作業手冊）：提供給 agent 的執行指引，skill 會加入其中
preview run（預覽測試）：請 ChatGPT 實際試跑 agent，跑完可以給回饋再調整
month-end close（月底結帳）：會計團隊 agent 協助更快、更一致準備的工作
subject matter experts（領域專家）：不需 IT 或工程支援，就能自己建立並分享工作流程的人
✏️ 小考一題

在示範中，Hojun 為什麼停用 Google Calendar 的寫入類動作？

A. agent 只需要讀取行事曆，停用後可確保它不會調整或更改任何事件B. research preview 階段禁止所有寫入動作C. Google Calendar 不支援 workspace agents 寫入D. 企業管理員強制所有 app 只能唯讀
看答案
答案：A。[08:16] 他說只需要 agent 參考行事曆、不需要寫入動作，停用後就能確信它不會調整或更改任何事件
