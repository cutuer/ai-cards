🧑‍🏫 這是 OpenAI 訪談節目的後半段。來賓 Pietro Schirano 示範用 Codex 把抽屜裡的舊裝置改成遊戲機和通知器，也分享他的公司 MagicPath 怎麼靠 AI 用 6 個人跑出很大的產出。值得看的地方是，他把 AI 當成全能助理，也拿它換回自己的時間，而不只是拿來寫程式。

  • 14:16 Pietro 會找以前試過卻做不出來的點子重新嘗試，並用 5.5 處理抽屜裡放了多年的舊裝置
    ↳ 他專挑以前做不出來的點子重新試，也把抽屜裡放了很多年、沒在用的舊裝置拿出來，交給 5.5（影片裡講的新版模型）處理。
  • 14:16 他不懂這些裝置用什麼語言寫，可能是 C，也可能是專有語言
    ↳ 他根本不知道這些裝置是用什麼程式語言寫的。C 是很常拿來寫硬體的語言；專有語言則是廠商自己定的，外人通常不熟。
  • 14:47 他想看看 Codex 搭配 5.5 能不能理解這些裝置的本質，再替它們開發東西
    ↳ 他想讓 Codex（OpenAI 能寫程式、操作電腦的 AI 工具）自己搞懂裝置底層的 firmware，也就是裝在硬體裡控制它運作的內建程式，懂了再替它開發新東西。
  • 14:47 這種做法等於讓過時的科技重新復活，把壞掉、閒置的東西拿來做別的用途，帶有一點環保意味
    ↳ 很多裝置其實沒壞，只是被淘汰。人不懂它，就只能丟掉；AI 讀得懂，它就能換個用途繼續用，不用變成垃圾。
  • 15:17 示範裝置是一台用來做安全控管的工作用裝置，他想替它做一款遊戲
    ↳ 這台原本是公司拿來做安全控管的裝置，跟娛樂完全無關。他故意在上面做遊戲，測試 AI 能不能理解一台陌生硬體。
  • 15:49 他把裝置直接接上 Codex，下指令「read the USB」，Codex 辨識出裝置與序號，並判斷可以在上面做東西
    ↳ 他只把裝置插上電腦，叫 Codex 讀 USB。Codex 就自己認出這是什麼裝置、序號多少，也判斷可以在上面開發。事前沒有人告訴它規格。
  • 16:21 Codex 在這台裝置上做出類似 Doodle Jump 的無盡跳躍遊戲
    ↳ Doodle Jump 是一款手機遊戲，角色一路往上跳、踩平台，沒有終點。Codex 在這台小裝置上做出了類似的遊戲。
  • 16:21 該裝置的 API 文件沒有提到可以垂直捲動螢幕，但 Codex 自己想出了做法
    ↳ API 是廠商給開發者的操作介面和說明，寫著能叫裝置做哪些事。文件沒提到畫面可以上下捲動，Codex 還是自己找出了做法。
  • 16:51 裝置上的小類比按鍵長按與短按的靈敏度不同，Codex 也自己摸清楚，讓操作更流暢；遊戲還能二段跳
    ↳ 按鍵長按、短按的反應不一樣，這種手感細節通常要人慢慢試。Codex 自己摸清楚、調順了操作，還加上二段跳。
  • 16:51 Pietro 表示整個遊戲真的只用了一個 prompt 就完成
    ↳ prompt 就是你打給 AI 的指令。他強調整個遊戲只下了一次指令就完成，中間沒有來回修改好幾輪。
  • 17:23 接著他思考如何把這台裝置用在工作上，Codex 做了一個 app，讓裝置能跟 Codex 自己連線
    ↳ 玩完遊戲，他轉向實用。Codex 寫了一個 app，讓這台裝置跟 Codex 本身連起來，兩邊可以互相傳東西。
  • 17:55 Codex 做出的控制功能：傳訊息到裝置時，裝置會震動並顯示訊息內容
    ↳ 連線之後，只要傳訊息過去，裝置就會震動並顯示內容，等於變成一個小型通知器。
  • 18:25 他仍會擔心 Codex 卡住，所以讓裝置在 Codex 完成時震動，他可以離開座位去拿咖啡
    ↳ 他還是怕 Codex 中途卡住沒人發現，所以設定成完成時裝置會震動。這樣他可以放心離開座位去拿咖啡，震了再回來看。
  • 18:55 他把這個用法形容為近似一個遙控器
    ↳ 他說像遙控器，意思是人不必守在電腦前，也能掌握 AI 的工作進度。
  • 18:55 MagicPath 是讓 agent 與人類一起設計與開發的無限畫布，也是可從任何地方存取的共同工作區
    ↳ MagicPath 是他公司的產品，形式是 infinite canvas（可以一直往外延伸的無限白板）。agent（能自己接任務、做完工作的 AI）和人在上面一起設計開發，在哪裡都能打開。
  • 19:26 他認為未來每個人都會有自己的 agent，裡面有自己喜歡的資訊與脈絡；MagicPath 想成為產品團隊的參考工具
    ↳ 他預期每個人都會有一個懂自己偏好和背景的 AI 助手。MagicPath 想成為產品團隊共同參考的地方。
  • 19:26 PM、設計師、工程師的角色正被 AI 打破，因為 AI 成了一種翻譯層，也被形容為平衡器
    ↳ PM 管產品方向、設計師管外觀、工程師寫程式，原本分得很清楚。AI 當 translation layer（翻譯層），把一方的想法轉成另一方做得出來的東西，界線因此變模糊，大家的能力也被拉近。
  • 19:58 大家使用 5.5 的地方不同（Codex、ChatGPT 或其他地方），MagicPath 想成為共同的地方；Codex 可以在 MagicPath 裡探索與設計
    ↳ 有人在 Codex 用 AI，有人在 ChatGPT 用，大家各在各的地方。MagicPath 想當大家匯合的地方，Codex 也能直接進去探索、做設計。
  • 19:58 MagicPath 約一年前上線，已經有非常多客戶
    ↳ MagicPath 大約一年前上線，他說現在已經有非常多客戶在用。
  • 20:32 MagicPath 即將推出 2.0 版，他說若沒有 5.5 就走不到現在的進度
    ↳ 2.0 版快推出了。他直接說，沒有 5.5 的話，進度根本走不到今天這一步。
  • 20:32 他們的產品團隊約 6 人；讓所有員工都能用 Codex，就像多了一百或兩百位開發者，或五位很強的新開發者
    ↳ 產品團隊只有 6 人左右。讓每個員工都能用 Codex，產出就像多了一兩百個開發者，或多了五個很強的新工程師。
  • 21:03 身為創辦人，他還得募資、和客戶談、照顧員工；因為 5.5，他的 PR 數量大約增加十倍
    ↳ PR（pull request）是工程師提交一份程式修改、請人審核合併的單位，可以看成寫了多少改動。他身兼募資、見客戶，PR 卻多了約十倍。
  • 21:33 他提醒自己，雖然現在什麼都能自己做，也要信任自己聘來的優秀人才；他內心一直在「想動手做」和「創辦人的其他職責」之間拉扯
    ↳ AI 讓他什麼都能自己做，但創辦人的工作不只寫程式。他提醒自己要放手，信任請來的人，雖然心裡一直很想親自動手。
  • 22:04 他跟 Codex 對話的時間多到女友會問他在跟誰講話
    ↳ 一個小趣事：他跟 Codex 講話講到女友以為他在跟真人聊天，可見他整天都在用對話的方式工作。
  • 22:04 他不只用 Codex 寫程式，也用它整理電腦檔案，並修正多年前音樂庫的封面與 metadata
    ↳ 他也用 Codex 整理電腦檔案，還修好多年前音樂庫的封面和 metadata，也就是附在檔案上的資訊，像歌名、歌手、專輯。
  • 22:34 這次訪談要講的內容，他也請 Codex 寫進 Apple Notes，因為 Codex 能存取他的本機系統與檔案
    ↳ Codex 能直接讀寫他電腦裡的檔案和程式，所以他連這次訪談要講的重點，都請它寫進 Apple 的備忘錄。
  • 22:34 他建議朋友把 Codex 當成日常的萬用助理，而不只是寫程式的助理
    ↳ 他勸朋友別只把 Codex 當寫程式工具。整理資料、寫文件、處理電腦上的雜事，都可以交給它。
  • 23:04 他把 mix panel、Stripe 等 MCP 接到 Codex，拉出公司數據後，替投資人做出漂亮的 dashboard 設計
    ↳ MCP 是讓 AI 連上外部服務、拿到資料的接法。他接上 Mixpanel（產品數據分析工具）和 Stripe（金流服務），讓 Codex 抓公司數據，做成給投資人看的漂亮儀表板。
  • 23:34 主持人說 OpenAI 內部從法務、財務到 HR，幾乎所有人都在用 Codex，不只工程師
    ↳ 主持人說，OpenAI 內部連法務、財務、HR 都在用 Codex，它不是工程師專屬的工具。
  • 23:34 主持人表示，因為看到 OpenAI 以外的人也拿 Codex 做各種事，所以讓 onboarding 變得更簡單
    ↳ onboarding 是新使用者第一次上手時的引導流程。他們看到很多非工程師的外部用戶，就把入門做得更簡單。
  • 23:34 主持人提到 Codex 現在有 plugins，也能操控瀏覽器和電腦來完成任務
    ↳ plugins（外掛）是替 Codex 加上額外能力的模組。現在它還能自己操作瀏覽器和電腦，例如點網頁、開程式，把任務做完。
  • 24:05 主持人認為大家常談 vibe coding，但現在似乎已經遠遠超過那個階段
    ↳ vibe coding 指不太懂程式的人，靠跟 AI 描述想要的感覺讓它寫程式。主持人覺得 AI 現在能做的早就不只這樣。
  • 24:05 開發速度變快，讓產品能更早交到客戶手上，並立即得到回饋
    ↳ 做得快，就能早點把東西交給客戶用，也馬上知道他們喜不喜歡。
  • 24:35 他過去在大型科技公司時，蒐集回饋再開發要花好幾個月，而且做完仍不確定方向對不對
    ↳ 他以前在大公司，收集意見再開發要好幾個月，做完了還是不確定方向對不對，時間卻已經花掉了。
  • 24:35 現在一天就能做出一個功能，再交給 MagicPath 的 beta 測試群組，很快就知道好不好
    ↳ beta tester group 是一群先試用新功能的使用者。現在一天就能做完一個功能，丟給他們試，很快就知道好不好。
  • 25:05 主持人總結：模型不只能扮演潛在客戶，也讓團隊能更快接觸到真正的客戶，回饋循環快得多
    ↳ feedback loop（回饋循環）是「做出來→給人用→收意見→再改」這一整圈。模型能先模擬客戶的反應，也讓團隊更快碰到真客戶，這一圈轉得快很多。
  • 25:05 Pietro 非常相信「工作走向監督」這個觀點，甚至把公司建立在上面
    ↳ supervision（監督）指人不再親手做每件事，而是負責下指令、檢查成果。他非常相信這個方向，公司就是照這個想法建起來的。
  • 25:35 他認為未來的工作重點會從「親手做事」轉為「指揮做事」，並看好可從任何地方存取的去中心化 agent
    ↳ 他認為以後的重點是指揮 AI 做事。decentralized agents（去中心化 agent）指不綁在某台電腦上的 AI，拿手機就能隨時叫它工作。
  • 25:35 例子：凌晨 2 點用手機透過 OpenClaw 丟出想法，agent 完成後傳連結給他，他看完再給回饋，不必坐在桌前
    ↳ 舉例來說，半夜兩點想到點子，用手機透過 OpenClaw 丟給 agent，它做完會傳連結回來，他看完再給意見，全程不用坐在電腦前。
  • 26:05 他說人類共同擁有的只有時間，把 AI 形容為「人類對時間的復仇」
    ↳ 不管是誰，一天都只有 24 小時。他說 AI 是人類對時間的復仇，意思是把被工作吃掉的時間搶回來。
  • 26:05 原本要 6 個月才能做完的產品，現在只要 2 週，省下的時間可以陪家人和朋友
    ↳ 原本要六個月的產品，現在兩週就能做完。他想把省下的時間拿去陪家人朋友，而不是塞進更多工作。
  • 26:39 他對這個工具抱持強烈的樂觀：有 agent 在跑工作時，他也能出門找朋友
    ↳ 工作交給 agent 在背景跑，他自己就能出門見朋友。他對這件事非常樂觀。
  • 27:09 他想留給觀眾的感受是一種狂喜：知道自己現在想做什麼、想打造什麼都可以
    ↳ 他想傳達的是一種興奮感：現在只要有想法，幾乎都做得出來，技術不再是擋住你的門檻。
  • 27:09 主持人呼應 OpenAI 的使命是為所有 builder 打造工具，現在人人都是 builder
    ↳ 主持人說 OpenAI 的使命是替所有動手打造東西的人做工具，而現在每個人都可以是這樣的人。
  • 27:09 Pietro 認為這個新模型讓原本對很多人陌生的東西普及化，變成人人都能用
    ↳ 過去做軟體、做產品要專業訓練，很多人碰不到。他認為新模型把這些能力變成一般人也用得上。
  • 27:39 他在義大利長大，覺得當時的機會不如美國；現在人人都能取得這種智慧，某種程度上拉平了差距
    ↳ 他在義大利長大，覺得當時的機會比不上美國。現在不管住在哪裡，都能用到一樣聰明的 AI，起跑點的差距因此縮小。
  • 27:39 主持人提到 Pietro 會在模型發布前提供他的眼光、品味與創意
    ↳ 主持人提到，OpenAI 在模型發布前，Pietro 會提供他的眼光、品味和創意。
📘 術語
Codex（Codex）：影片中的 AI 工具，能讀 USB 裝置、寫程式、整理檔案，也能操控瀏覽器和電腦
firmware（韌體）：Pietro 讓 AI 去理解舊裝置的 firmware，再替它開發遊戲
prompt（提示詞）：給 AI 的指令；Doodle Jump 般的遊戲真的只用了一個 prompt
API（應用程式介面）：裝置的 API 文件沒提到垂直捲動，Codex 仍自己找到做法
MagicPath（MagicPath）：讓 agent 與人類一起設計與開發的無限畫布
infinite canvas（無限畫布）：MagicPath 的形式，是可從任何地方存取的共同工作區
agent（代理人）：會接收想法、完成工作、回傳連結的 AI；每個人未來都會有自己的 agent
translation layer（翻譯層）：AI 在 PM、設計師、工程師之間扮演翻譯層，打破角色界線
PR (pull request)（PR）：Pietro 說因為 5.5，他的 PR 數量增加約十倍
metadata（中繼資料）：他用 Codex 修正多年前音樂庫的封面與 metadata
MCP（MCP）：他把 mix panel、Stripe 等 MCP 接到 Codex，用來拉取公司數據
plugins（外掛）：主持人提到 Codex 現在有各種 plugins
onboarding（新手上手流程）：因為 OpenAI 外部也有很多人在用 Codex，所以讓 onboarding 更簡單
vibe coding（vibe coding）：主持人說大家常談 vibe coding，但現在似乎已遠超過那個階段
beta tester group（beta 測試群組）：MagicPath 的測試群組，新功能做好就交給他們快速回饋
feedback loop（回饋循環）：做出功能到取得客戶回饋的循環，現在快得多
supervision（監督）：工作會從親手做事轉為指揮做事
decentralized agents（去中心化 agent）：可從任何地方存取的 agent，例如用手機就能下指令
