🧑‍🏫 這支是 Anthropic 團隊介紹 Claude Code 新功能 routines 的前半段。Claude Code 是 Anthropic 出的 AI 助手，能幫人讀程式、寫程式。routines 讓 AI 不必等你開口：時間到了，或發生某件事，它就自己開工。講者用公司內部「自動補文件」的真實例子示範怎麼設定。想把固定、重複的工作交給 AI 的人很值得看。

  • 00:22 講者 Maya 是 Anthropic applied AI 團隊成員，一半時間開發自家產品功能，一半時間協助客戶在模型上打造產品與 agent
    ↳ 講者 Maya 在 Anthropic 的 applied AI 團隊。她一半時間開發自家產品，一半時間幫客戶用 Claude 做產品和 agent（能自己分步驟完成任務的 AI 助手），所以做的人和用的人的角度她都懂。
  • 00:54 本場主題是 Claude Code 裡的 routines 功能
    ↳ 這場只講一件事：routines。它是讓 Claude Code 照排程或在某件事發生時自動開工的功能，後面的內容都圍繞它。
  • 00:54 很多人試過把 Claude Code 放在 cron 上跑，但自己建置和維護這些基礎設施很辛苦；Anthropic 內部開發主動式 agent 時也遇到同樣的痛點
    ↳ cron 是電腦內建的定時器，可以設定「每天幾點執行某個指令」。很多人用它定時叫 Claude Code 做事，但機器和設定都得自己顧。Anthropic 自己開發會主動做事的 agent 時，也被這件事困擾。
  • 01:24 理念：coding agent 不該等你按下 Enter 才開始；目標是把 Claude Code 從強大的 coding 工具變成 coding 隊友
    ↳ 以前的 AI 都要你下指令、按 Enter 才會動。他們的目標是讓 Claude Code 從「好用的工具」升級成「隊友」，會自己看情況出手，不用等人叫。
  • 01:54 隊友會發現東西壞了並主動處理；工具則要等你輸入 prompt、按下 Enter
    ↳ 差別在誰先動。工具像計算機，你不按它就不算；隊友像同事，看到系統出錯會自己去修再告訴你。prompt 就是你打給 AI 的那段指令文字。
  • 02:27 本場四個主題：打造主動式 agent 的挑戰、routines 功能、Anthropic 內部用 routines 自動產生文件的實例、把 routines 應用到自己的工作流程
    ↳ 這場分四段：先講自己做主動式 agent 會卡在哪，再介紹 routines，接著看 Anthropic 內部怎麼用它自動寫文件，最後談怎麼套進你自己的工作。
  • 02:57 挑戰一：agent 要在哪裡跑。放在本機的話，筆電闔上或沒電，session 就結束了
    ↳ 第一個難題：AI 要放在哪台電腦上跑。放在自己的筆電上，一闔上或沒電，session（AI 從開工到收工的一整段工作）就會中斷。
  • 03:27 因此得自己處理 hosting、資料保存（data persistence）、authentication，等於要在 prompt 之外建一整套基礎設施，還有大量樣板程式碼
    ↳ 想讓它不停地跑，就得自己租主機（hosting）、確保資料不會掉（data persistence）、處理登入權限（authentication），還要寫一大堆重複的樣板程式碼。光這些就比寫指令本身麻煩得多。
  • 03:27 挑戰二：什麼時候觸發 agent。可以用 cron，或自己架 endpoint 來接收 post，但這些基礎設施都得自己建
    ↳ 第二個難題：什麼時候叫醒它。可以用 cron 定時，或自己架一個 endpoint（一個專用網址，別的系統把訊息送過來就能觸發），但這些都要自己建。
  • 03:57 挑戰三：有時需要 human in the loop，有時不需要；headless 的 Claude Code session 很難即時看到 agent 在做什麼，也沒辦法觀看、引導、設限或恢復 session
    ↳ 第三個難題：你要參與多少。有時你想盯著、隨時插手（human in the loop），有時想完全放手。但 headless（沒有畫面、在背景跑）的方式很難看到它在做什麼，也沒辦法中途指揮、設限或接著做。
  • 04:27 Routines 是 Claude Code 的新功能：只要定義 prompt、要連的 repo、可用的 connector 和 trigger，就能啟動遠端 Claude Code session，其餘由 Claude Code 處理
    ↳ routines 把上面這些麻煩都包好了。你只要給指令，指定 repo（放程式碼的專案庫）、connector（讓它連外部工具的接口）和觸發條件，它就會在雲端開一個 Claude Code 工作階段。
  • 04:58 設計重點一：隨時可用。routines 跑在 Claude Code 的託管基礎設施上，hosting、session 狀態和 connector 都由官方處理，不需要開著筆電
    ↳ 第一個好處：隨時都在。它跑在 Anthropic 代管的雲端機器上，主機、進度保存和工具連線都有人處理，你的筆電關機它也照跑。
  • 05:29 設計重點二：可自訂 trigger 主動運作，可以依時間排程，也可以由事件觸發
    ↳ 第二個好處：會主動開工。你可以設定 trigger（觸發條件），可以按時間排，例如「每週一早上九點」，也可以設成「某件事發生時」。
  • 05:29 事件觸發原生支援 GitHub events，也可以把自訂事件 post 到 webhook／endpoint，event payload 會作為 context
    ↳ 事件觸發直接支援 GitHub（常見的程式碼存放平台）上的動作。你也可以把自訂事件送到 webhook（接收通知的網址），跟著送來的資料（event payload）會交給 Claude 當背景資訊。
  • 06:00 設計重點三：可互動、可引導。每個 routine 本質上就是一個 Claude Code session，可以從 web、CLI、desktop 開啟、觀看、追問、引導和恢復
    ↳ 第三個好處：可以互動。每個 routine 其實就是一次普通的 Claude Code 工作。你可以從網頁、CLI（在終端機打文字指令的介面）或桌面版打開，看它做到哪、追問、改方向，或接著做下去。
  • 06:31 實例背景：Claude Code 的每週 PR 數從今年初到現在增加了 200%
    ↳ 案例背景：今年以來，Claude Code 每週的 PR（修改程式的申請，審核後才會併入正式版本）數量成長了 200%，程式改得很快。
  • 07:01 負責維護 Claude Code 和 agent SDK 文件的那位工程師壓力變大，她很早就開始用 routines，設了幾個 routine 來自動產生文件
    ↳ 負責維護 Claude Code 和 agent SDK（給開發者打造 agent 的工具包）文件的工程師因此壓力大增。她很早就開始用 routines，設了幾個自動產生文件的排程。
  • 07:33 做法：在終端機啟動 Claude Code，輸入 /schedule，再描述要排程的任務
    ↳ 設定方法：在終端機（輸入文字指令的視窗）打開 Claude Code，輸入 /schedule 這個指令，再用平常說話的方式描述你想排定的工作。
  • 07:33 Sarah 的 prompt：每週一次，檢查所有 merge 到 main 的新變更，跟文件 repo 比對，有需要就開 PR 更新文件
    ↳ 這位工程師 Sarah 的指令是：每週檢查一次有哪些改動已經 merge（合併）進 main（正式主線程式碼），拿去對照文件庫，缺了就開 PR 補上。等於請 AI 每週幫她對一次帳。
  • 08:05 講者建議大家想想：每天做的哪些任務，如果能排程執行或由 Claude Code 主動啟動會有幫助
    ↳ 講者請大家想想：每天有哪些事是固定時間要做，或某件事發生後就得跟著做的？這類工作最適合交給 Claude Code 定時或自動開工。
  • 08:05 送出後 Claude 會反問細節，例如每週幾點執行、建立 PR 後要不要通知你（例如在 Slack 上 ping），回答完就會建立 routine，可以在 Claude Code on the web 查看
    ↳ 送出後 Claude 會反問細節，像每週幾點跑、開好 PR 要不要在 Slack（常用的團隊聊天工具）通知你。回答完 routine 就建好了，可以在 Claude Code 網頁版查看。
  • 08:35 建立任何 routine 都有三個主要決定：一、什麼時候觸發（事件或固定週期）
    ↳ 不管設什麼 routine，都要先想好三件事。第一件：什麼時候啟動？是某件事發生時，還是每隔一段固定時間？
  • 08:35 二、Claude 需要哪些 context 才能成功，例如某些文件，或用來通知你的工具
    ↳ 第二件：Claude 需要拿到哪些資料才做得好？例如某些文件，或能用來通知你的工具。就像交代新同事工作，要把資料和聯絡方式一起給對方。
  • 09:07 三、怎麼在 session 中引導 Claude、讓它不偏離，得到你要的產出
    ↳ 第三件：過程中怎麼帶著 Claude 走，讓它別跑偏，最後交出你真正要的東西。
  • 09:38 Trigger 有兩種：依時間排程，例如每週比對 Claude Code 原始碼和文件 repo 的差異；或事件觸發
    ↳ 觸發方式有兩種。一是按時間，例如每週比對 Claude Code 程式碼和文件庫差在哪；二是按事件，某件事一發生就啟動。
  • 09:38 事件觸發例子一：每次切出 release 時，把 release branch 跟文件做 diff，看有沒有新功能需要開文件 PR
    ↳ 事件例子一：每次切出 release branch（準備對外發佈的版本分支），就拿它跟文件做 diff（逐項比對差異），看有沒有新功能還沒寫文件，有的話就開 PR 補上。
  • 10:08 事件觸發例子二：工程師在 PR 上加「need docs」之類的 label，每當這種 PR 被 merge，就啟動 Claude Code session
    ↳ 事件例子二：工程師在 PR 上貼「need docs」之類的 label（標籤）。貼了這個標籤的 PR 一被合併，就自動啟動 Claude Code。貼標籤等於點名要 AI 處理。
  • 10:38 Context：通常要讓 agent 存取一個或多個 repo；在文件案例中，Claude 需要 Claude Code 原始碼（找新變更）和文件 repo（開 PR）
    ↳ 資料方面，通常要讓 agent 能進入一個或多個 repo。以文件案例來說，Claude 要讀 Claude Code 的程式碼才找得到新改動，也要能進文件庫才能開 PR 補文件。
📘 術語
routines（例行任務（routines））：Claude Code 的自動化功能：定義 prompt、repo、connector、trigger，就能啟動遠端 Claude Code session
proactive agent（主動式 agent）：不用等人按 Enter，會自己發現問題並處理，像隊友而不是工具
cron（cron 排程）：有人拿來定時跑 Claude Code，但要自己建置和維護基礎設施
trigger（觸發條件）：決定 routine 什麼時候執行，分成時間排程和事件觸發兩種
connector（連接器）：routine 可以用的工具／服務，由 Claude Code 託管基礎設施代為處理
webhook / endpoint（webhook／端點）：可以把自訂事件 post 過去觸發 routine，event payload 會作為 context
event payload（事件資料內容）：自訂事件觸發時一起送進來的資料，會作為 Claude 的 context
headless session（無介面 session）：字幕說這種 session 很難即時看到 agent 在做什麼，也無法引導或恢復
human in the loop（人在迴圈中）：有時你想參與 agent 的過程，有時想完全不介入
/schedule（/schedule 指令）：在終端機的 Claude Code 裡輸入，描述任務後建立 routine
data persistence（資料保存）：自己架主動式 agent 時需要處理的基礎設施項目之一
boilerplate code（樣板程式碼）：自建基礎設施時要寫的大量重複程式碼
release branch（發布分支）：事件觸發例子：切出 release 時跟文件做 diff，看有沒有新功能要寫文件
label（標籤）：例如在 PR 上標「need docs」，這類 PR 被 merge 時就觸發 Claude Code session
