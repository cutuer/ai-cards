🧑‍🏫 這段影片講 Grok bot 的「主動出擊」功能改版：改了什麼、團隊為什麼有信心推出。後半段由 PM 現場示範怎麼做一個全隊共用的 team bot。如果你想讓 AI 不只幫自己，也能幫整個團隊查資料、做事，這段的步驟可以直接照著用。

  • 11:17 團隊做完調整後先在內部重新上線，大家覺得新版好很多，某種程度上達到了他們自己的 PMF 門檻，之後才正式重新推出
    ↳ PMF（product-market fit）是指產品真的符合使用者需求。團隊沒有直接對外推，而是先在內部天天用，等大家都覺得「這版真的好用」，才正式重新推出。
  • 11:17 核心功能改動之一是 background job
    ↳ background job 一般是指讓 bot 在背景持續做事，你不用一直盯著聊天視窗。影片只說這是核心改動之一，沒有細講怎麼運作。
  • 11:17 另一項改動是開放更多存取權限：原本限制了 bot 能存取的東西，現在讓它可以存取所有東西
    ↳ 以前 bot 能碰的資料和工具都被限制，能幫的忙有限。現在放開讓它存取所有東西，它才有足夠的資訊主動替你做事。
  • 11:17 primary bot 收到的第一名回饋是使用者想要能自訂它
    ↳ primary bot 是你的主力 bot，也就是平常最常找的那一個。大家用過之後最常提的要求是：想照自己的習慣改它，不想只能用預設版本。
  • 11:49 現在已開放自訂：可以把現有的 chief of staff、新的 chief of staff 或任何 bot 設為 primary bot，再從那裡繼續調整
    ↳ chief of staff 是一種現成的 bot，原意是「幕僚長」。現在你可以挑舊版、新版或任何一個 bot 當主力，再慢慢調成你要的樣子。
  • 11:49 上線前先蒐集大量內部回饋，是團隊對這次上線有信心的關鍵
    ↳ 團隊敢正式上線，靠的不是感覺。內部先大量試用、回報問題，確認大家真的覺得變好了，才有把握推出。
  • 11:49 proactivity 訊息不會計入你的用量
    ↳ proactivity 是讓 bot 主動傳訊息給你的功能。這類主動訊息不算進你的用量，所以 bot 常常找你，也不用擔心額度被吃光。
  • 12:20 proactivity 是 grok bot 內建的功能，主持人鼓勵大家放心讓 bot 主動出擊
    ↳ 這個功能不用另外開，grok bot 本來就有。主持人的意思是：別怕被打擾，放手讓它主動提醒你、主動做事看看。
  • 12:20 聊天室的使用範例：用 bot 協助開會、準備生活大小事，以及訓練 primary bot、調整它，讓它成為對你最有效的同事
    ↳ 觀眾分享的用法很生活化：幫忙準備會議、處理生活瑣事。還有一種是持續調教主力 bot，讓它越來越像一個懂你的同事。
  • 12:58 重點是訓練 bot 照你想要的方式回應、使用你想要且每天依賴的工具，並確保這些工具都有串接好
    ↳ bot 好不好用，要看你有沒有教它：回覆要用什麼風格、該用哪些你每天在用的工具。而且這些工具要真的接上，不然它也用不了。
  • 13:29 Ari 是 PM，原本在 cursor，現在在 SpaceX AI，負責 grok bot 和 cloud agents
    ↳ Ari 是 PM（產品經理，負責決定產品要做什麼）。他原本在 AI 寫程式工具 cursor，現在在 SpaceX AI 負責 grok bot 和 cloud agents。
  • 13:29 用 grok bot 處理 coding 任務時，背後實際啟動的是一個 cloud agent 在做事
    ↳ cloud agent 是在雲端替你執行任務的 AI。你在 grok bot 叫它寫程式時，真正動手的是背後另外啟動的 cloud agent。
  • 13:29 團隊把 grok bot 定位成可以交付真正工作的自主隊友；只有你一個人能對話的隊友稱不上隊友，所以做了 team bots
    ↳ 他們希望 grok bot 能把工作真的做完，不只是陪你聊天。但隊友應該是全隊都能找的，只有你能用的不算，所以才做了 team bot。
  • 14:02 team bot 的概念：由一個人建立 bot，幫它裝好 skills、secrets、plugins 和各種資訊
    ↳ team bot 是一人設定、全隊共用的 bot。設定的人先幫它裝好 skills（做事方法）、secrets（連線用的金鑰）、plugins（接外部資料的管道）和背景資料。
  • 14:02 建好後全隊都能 DM 它、在 Slack 跟它對話，也能把它拉進群組聊天，像真正的隊友一樣合作
    ↳ 設定好之後，大家都能私訊它，也能在 Slack（團隊聊天軟體）找它或把它拉進群組，就像多了一個隨時在線、誰都能問的同事。
  • 14:32 示範步驟一：點「+」選單，裡面有 team bots 區塊，可看到 SpaceX AI 實際在用的 team bots，這次選擇建立新的
    ↳ 建立入口在「+」選單裡的 team bots 區塊，可以看到 SpaceX AI 自己在用的例子。這次示範是從零建立一個新的。
  • 15:02 建立時 bot 會先告知自己是 team bot，並詢問要用來幫團隊做什麼
    ↳ 建立時，bot 會先說明自己是給團隊用的，再問你要它幫團隊做什麼。等於用對話的方式完成設定，不用自己填表單。
  • 15:02 這次要做的是給整個 GTM 團隊用的 source of truth 和資料查詢工具
    ↳ GTM（go-to-market）團隊負責把產品賣出去，例如業務。source of truth 是大家公認最準的資料來源。這個 bot 要當他們查資料的統一窗口。
  • 15:02 GTM 團隊常問的問題包括：各客戶狀況、各種用量來源，以及某個帳戶上最大的 power users 是誰
    ↳ 這些都是業務天天要查的事：某個客戶現在狀況如何、用量從哪裡來，還有某個帳戶裡的 power users（重度使用者）是誰。
  • 15:32 GTM 團隊也有內建的 skills，例如用來做 prospect：找出某個帳戶最適合聯絡的人
    ↳ prospect 在這裡是指找出某間客戶公司裡最該聯絡的人。這類固定流程也做成了 skill，bot 照著步驟做就好。
  • 16:02 這是 SpaceX AI 內部的真實案例：史上第一個 team bot 就是這個 bot 的某個版本
    ↳ 這不是為了示範臨時做的。SpaceX AI 內部第一個 team bot，就是這種 GTM 查資料 bot 的某個版本，代表他們真的在用。
  • 16:34 輸入基本描述後，bot 會依用途自己改名（這次的用途是回答 GTM 問題）
    ↳ 你只要大概講一下用途，bot 就會自己取一個貼切的名字（這次叫 GTM helper），不用你另外想。
  • 16:34 步驟二是加入 plugins。plugins 是 GROK bot 連接外部資料來源的方式；team bot 的 plugins 分成兩種
    ↳ plugin 是讓 bot 連到外部服務、讀取那邊資料的管道。team bot 的 plugin 分成兩種，差別在於用誰的帳號連線。
  • 16:34 第一種是個人 plugin，例如 Salesforce：team bot 會使用當下跟它對話的那位使用者自己的帳號
    ↳ personal plugin 用的是當下跟 bot 對話那個人自己的帳號，例如客戶管理系統 Salesforce。也就是說，查資料時是照你本來的權限在查。
  • 17:04 第二種是 team shared plugin，例如 Databricks：所有人共用一把唯讀的 shared key，全隊都能查詢資料但不能寫入
    ↳ team shared plugin 是全隊共用一把唯讀的 shared key（共用金鑰），例如資料平台 Databricks。大家都能查資料，但沒有人能改動資料。
  • 17:04 另外加入 granola（業務很常用）和 Gong（銷售團隊用來追蹤通話紀錄），之後需要還能再加
    ↳ 業務很常用 granola，Gong 則是銷售團隊用來追蹤通話紀錄的工具。接上之後，bot 能參考這些內容回答問題，以後要再加也可以。
  • 17:34 因為之後要放進 Slack，所以也加入 Slack plugin
    ↳ 這個 bot 之後要放進 Slack 跟大家對話，所以要先接上 Slack plugin，它才能在 Slack 裡收發訊息。
  • 17:34 步驟三是 secrets（這次跳過）：設定 secret 後 bot 可以呼叫 API，或執行要讓全隊共用的工作
    ↳ secret 是讓 bot 能呼叫 API（程式之間互相溝通的介面）的金鑰，也能用來跑全隊共用的工作。這次用不到，所以跳過。
  • 17:34 步驟四是 skills：系統會讀取你個人 bots 已有的 skills，依任務挑出相關的推薦給你
    ↳ skill 是教 bot「這件事該怎麼做」的說明。系統會看你個人 bot 已經有哪些 skill，挑出跟這次任務相關的推薦給你，不用重寫。
  • 18:04 推薦的 skills 例如「如何從 Databricks 撈資料」，以及和 GTM 同事溝通用的 style guide
    ↳ 推薦的例子很實際：一個教 bot 怎麼從 Databricks 撈資料，另一個是 style guide（說話風格規範），讓它跟 GTM 同事溝通時口吻一致。
  • 18:04 你可以加入自己任何 bot 用過的 skill；這次另外加了 account research
    ↳ 不只推薦清單裡的，你任何 bot 用過的 skill 都能搬過來用。這次另外加了 account research，也就是研究客戶帳戶的方法。
  • 18:39 步驟五可以加入 files，例如 PDF、文件、文字檔形式的 PRD，或公司各系統的 source of truth；Ari 已用 skills 涵蓋，所以沒加
    ↳ files 是給 bot 參考的檔案，例如 PDF、PRD（產品需求文件）或公司系統的資料說明。Ari 需要的資訊 skill 已經涵蓋了，所以沒另外放。
  • 18:39 最後 bot 會問是否要發布給團隊；發布後 GTM helper 會出現在所有隊友的帳號中
    ↳ 最後 bot 會問要不要發布給團隊。發布之後，所有隊友的帳號都會出現 GTM helper，大家直接就能用。
  • 19:10 隊友在 team bots 搜尋就能找到 GTM helper
    ↳ 隊友想用的時候，在 team bots 裡搜尋名字就找得到，不需要自己重新設定一次。
  • 19:10 示範提問：從手上有資料的範例產業中，哪個最熱門？
    ↳ 示範問了一個典型的業務問題：在手上有資料的產業裡，哪一個最熱門？用這題來看 bot 能不能從真實資料找出答案。
  • 19:48 回答時 bot 會用設定好的 connectors 和 skills：靠 skill 知道怎麼查詢資料，再到 Databricks 查出答案
    ↳ bot 不是憑印象回答。它先靠 skill 知道該怎麼查，再透過設定好的 connectors（plugins 這類連線）到 Databricks 實際撈出答案。
  • 19:48 Ari 分享最酷的案例：team bots 這個功能大部分是由一個 team bot 打造出來的
    ↳ Ari 說最酷的是：team bots 這個功能本身，大部分是一個 team bot 做出來的。等於用自己的產品打造產品。
  • 20:20 工程、產品、設計都在那個 team bot 裡協作，它累積了大量知識庫，涵蓋做過的工作、產品決策和設計決策
    ↳ 工程、產品、設計三方都在同一個 team bot 裡協作。它因此累積了大量背景知識，包括做過哪些工作，以及產品和設計為什麼這樣決定。
  • 20:20 它還透過一個 cursor 專案啟動 cloud agents，實作了大部分功能
    ↳ 真正寫程式的部分，是這個 bot 透過一個 cursor 專案啟動 cloud agents 去實作。功能大多是這樣做出來的。
  • 20:54 它每晚用 GROK bots 上的測試帳號 dogfood 產品，在 UI 上四處操作、嘗試各種功能
    ↳ dogfood 是指自己人先用自家產品、找出問題。這個 bot 每晚用測試帳號在介面上到處點、試各種功能，替團隊先試用一輪。
  • 20:54 每天早上它會開出 15 到 20 個 PR，修正小瑕疵、令人困惑的文案和不好的 loading states
    ↳ PR（pull request）是提交程式修改、等人審核的請求。它每天早上開 15 到 20 個 PR，修正小瑕疵、讓人看不懂的文字和不好的讀取畫面。
  • 20:54 原本出去蒐集客戶或內部使用者回饋要花好幾天，改由 GROK bot 每晚自己做，團隊只要核准 PR，出貨速度快很多
    ↳ 以前要花好幾天去問客戶或同事哪裡不好用。現在 bot 每晚自己試、自己修，團隊只要審核通過就好，產品更新快了很多。
  • 21:33 這個 bot 被暱稱為 team bots bot
    ↳ 團隊幫它取了暱稱 team bots bot，意思就是「做出 team bots 功能的那個 bot」。
  • 21:33 接著把 bot 加進 Slack 讓多人對話；其實可以直接用 prompt 叫 bot 自己加，這次改用 UI 示範
    ↳ 接著把 bot 加進 Slack，讓多人一起用。其實直接打字叫 bot 自己加入就可以，這次是為了示範，才用介面一步步點。
  • 21:33 bot 建好後隨時可以回頭修改 plugins，或新增 secrets、files、skills
    ↳ 設定不是一次就定案。bot 建好後，隨時能回頭增減 plugins、secrets、files、skills，用了覺得缺什麼再補就好。
  • 22:05 示範加入的是名為 fly low airlines 的測試 Slack workspace；當場因為 bot 加太多，需要先移除一個
    ↳ fly low airlines 是示範用的測試 Slack 空間。現場因為裡面的 bot 太多，得先移除一個才加得進去。
  • 22:35 如果你的 Slack workspace 沒有 admin approval 步驟（多數人通常沒有），就可以直接把 bot 加進 Slack
    ↳ admin approval 是加入前要等管理員核准的步驟。如果你的 Slack 沒有這一關（多數人沒有），就能直接把 bot 加進去。
📘 術語
PMF（PMF）：字幕沒有解釋縮寫；只說團隊內部重新上線後，覺得新版某種程度上達到了他們的 PMF 門檻
background job（背景工作）：字幕列為這次改版的核心功能改動之一，沒有進一步說明
primary bot（主要 bot）：使用者最想自訂的 bot；可以把現有或新的 chief of staff 等 bot 設為 primary bot
chief of staff（幕僚長（bot））：字幕中可以被設為 primary bot 的一種 bot
proactivity（主動性）：bot 主動發訊息的功能；這類訊息不計入用量，是 grok bot 內建的
team bot（團隊 bot）：由一人建立並設定，全隊都能 DM、在 Slack 對話、拉進群組的 bot
cloud agent（雲端 agent）：用 grok bot 做 coding 任務時，背後實際執行工作的 agent
plugin（外掛）：GROK bot 連接外部資料來源的方式
personal plugin（個人 plugin）：會使用當下對話者自己的帳號，例如 Salesforce
team shared plugin（團隊共用 plugin）：全員共用一把唯讀的 shared key，能查詢但不能寫入，例如 Databricks
secret（機密設定）：設定後 bot 可以呼叫 API，或執行要讓全隊共用的工作
skill（技能）：告訴 bot 怎麼做事的設定，例如怎麼從 Databricks 撈資料、溝通用的 style guide
GTM (go-to-market) team（GTM 團隊）：字幕稱為 go-to-market team，會問客戶、用量相關問題，也會做 prospect
prospect（開發潛在客戶）：字幕中指找出某個帳戶最適合聯絡的人
power user（重度使用者）：GTM 會問的問題之一：某個帳戶上最大的 power users 是誰
source of truth（權威資料來源）：這次 team bot 要扮演的角色；files 也可以放公司各系統的 source of truth
PRD（產品需求文件）：字幕只把它列為可加入 files 的文件類型，沒有展開解釋
dogfood（內部自用測試）：bot 每晚用測試帳號實際操作產品 UI、嘗試各種功能
PR（PR）：team bot 每天早上開出 15 到 20 個，修正問題後交給團隊核准
admin approval（管理員核准）：如果 Slack workspace 沒有這個步驟，就可以直接把 bot 加進 Slack
✏️ 小考一題

在 team bot 的示範中，Databricks 屬於哪一種 plugin、權限如何？

A. 它不是 plugin，而是要另外設定的 secretB. 個人 plugin，使用每位對話者自己的帳號C. team shared plugin，全員共用一把唯讀的 shared key，可查詢但不能寫入D. team shared plugin，全員都能讀取和寫入資料
看答案
答案：C。[17:04] Databricks 是 team shared plugin 的例子，所有人共用一把只有唯讀權限的 shared key，全隊都能查詢資料，但不是每個人都能寫入；使用者自己帳號的是 Salesforce 這類個人 plugin（[16:34]）
