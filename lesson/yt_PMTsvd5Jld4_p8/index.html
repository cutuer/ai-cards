🧑‍🏫 這段是 Grockbot 直播第一天的中段。前半回答新手最常問的問題：帳密放哪裡、bot 怎麼記事情、複製 bot 會怎樣，再用三點總結 bot 的特色。後半介紹當天的議程和來賓，開始示範「僱用」第一批 bot。想知道怎麼放心把工作交給 AI 助理的人很值得看。

  • 83:33 如果想在 Marketplace 上架 bot，可以說明 bot 的功能並附上連結；參加的人有機會去 Starbase，也可能看到 Starship 發射
    ↳ Marketplace 是上架、分享 bot 的地方。想放自己的 bot，就寫清楚它能做什麼並附上連結。參加的人有機會去 SpaceX 的基地 Starbase，說不定還能看到 Starship 火箭發射。
  • 83:33 講者展示了一個報名用的 QR code，並說最後會再放一次
    ↳ 講者秀了報名用的 QR code（手機一掃就會打開網址的方塊圖），並說直播最後會再放一次，現在沒掃到也不用急。
  • 84:03 Q&A：需要在 bot 的虛擬電腦上登入 1Password 嗎？答案是要，系統會跳出 modal 請你登入 1Password
    ↳ bot 有自己的虛擬電腦。要讓它用你的帳號，得登入 1Password（密碼管理工具）。系統會跳出 modal（畫面上彈出的小視窗），讓你在裡面登入。
  • 84:33 在 modal 裡輸入的 API secrets、環境變數等機密，會安全地存在 Grockbot 內，不會外露給講者團隊或 SpaceX 的任何人
    ↳ API secrets 是讓程式連上某個服務的密鑰，環境變數是程式執行時會讀的設定值。這些機密在彈出視窗輸入後存在 Grockbot 裡，講者團隊和 SpaceX 的人都看不到。
  • 84:33 登入資訊是在這個 modal 裡輸入，不是在 bot 的 VM 上輸入；bot 之後會用這些憑證登入你需要的服務
    ↳ 重點在輸入的位置：帳密填在那個彈出視窗，不是打進 bot 的 VM（虛擬電腦）。存好之後，bot 需要時會自己拿去登入服務。
  • 85:04 Q&A：記憶怎麼運作？記憶存在 Grockbot 內的 S3 buckets，會長期保存（persistent），也可以修改
    ↳ bot 的記憶存在 S3 buckets（亞馬遜雲端的儲存空間）裡。persistent 的意思是長期保存，關掉不會忘，而且你可以修改它記住的內容。
  • 85:04 例子：講者為了 demo 刪掉幾個 bot 後，主動告訴 chief of staff bot 不要再把工作分派給那兩個 bot
    ↳ 講者有個 chief of staff bot（幕僚長 bot，負責把工作派給其他 bot）。他為了 demo 刪掉兩個 bot 之後，特地告訴它別再派工作給那兩個。
  • 85:36 要注意的地方：bot 記得你跟它說過的所有事，但它不會知道自己分派過工作的 bot 已經被刪除，所以這類資訊要你自己更新它的記憶
    ↳ bot 會記得你講過的每件事，但它不會自己發現被派工作的 bot 已經刪掉，可能照樣派過去。這種變動要你主動告訴它，更新它的記憶。
  • 85:36 複製（duplicate）bot 時，新 bot 的 context 和記憶都是全新的，但保留同樣的 persona（例如 email Ethan）
    ↳ duplicate 就是複製 bot。新 bot 的 context（手上的對話內容）和記憶都是全新的，只有 persona（角色設定）一樣，例如同樣是 email Ethan 這個角色。
  • 86:06 複製出來的 bot 就像零記憶的新人或新機器人，但仍然懂得怎麼做事
    ↳ 所以複製出來的 bot 就像剛報到的新人：過去發生什麼都不知道，但會做的事都還會做，交代下去一樣能上手。
  • 86:38 講者最大的建議是：直接試用 Grockbot，要建立任意數量的 bot 都很簡單
    ↳ 講者最大的建議是：別只看，直接去試。要建幾個 bot 都很容易，多開幾個試不同用途也不費事。
  • 86:38 找應用情境的方法：想想一天中最煩、最希望不必自己做的事
    ↳ 找用途的方法很簡單：想想一天裡最煩、最希望不用自己動手的事，那就是最適合交給 bot 的工作。
  • 86:38 舉例：建立 Google 表單、寄出後分析資料；寄開發信（outbound emails），可參考 Grockbot for sales 與 Grockbot for SDRs 場次
    ↳ 例子：做 Google 表單、回收後分析資料；或寄開發信給潛在客戶。SDR 是業務開發代表，專門開發新客戶，寄信的做法另外有專門場次講。
  • 86:38 工程團隊的例子：清理過時的 feature flags
    ↳ 工程團隊可以讓 bot 清掉過時的 feature flags。feature flags 是程式裡控制某個功能開或關的設定，這種雜事沒人想做，卻總得有人做。
  • 87:09 field engineers 的例子：回覆被遺忘的客服工單
    ↳ field engineers 是在客戶現場處理技術問題的工程師。他們可以讓 bot 去回那些被遺忘的客服工單，客戶就不會一直等不到回覆。
  • 87:09 做法：設計幾個 agent，給它們個性和做事所需的能力，把那部分工作交出去，把省下的時間投入其他地方
    ↳ 做法是設計幾個 agent（能自己動手完成工作的 AI 助理），給它們個性和做事需要的工具，把那塊工作整個交出去，省下的時間拿去做別的事。
  • 87:39 講者省下的時間可以拿來準備更多 demo，或多喝點咖啡
    ↳ 講者說他省下的時間可以拿去準備更多 demo，或多喝杯咖啡。意思是時間還給你了，怎麼用你自己決定。
  • 87:39 鼓勵大家和現場其他人交流，聽聽不同規模的公司怎麼用 Grockbot 處理各種情境

    ↳ 總結一：MCP 是讓 AI 連接外部工具的標準接口。bot 不只能用 MCP 的工具，還能做表單、在 Qualtrics（問卷平台）建資料、用客戶 VPN 裡的內部系統。
  • 88:10 好處是不必再去連 MCP，只要把電腦交給 bot，告訴它要存取什麼、要做什麼
    ↳ 好處是不用再一個個服務去接 MCP。bot 有自己的電腦，你只要告訴它可以進哪些地方、要完成什麼，它會自己去操作。
  • 88:40 從結果（outcome）開始交代，bot 會反推出達成結果需要做哪些事
    ↳ 交代工作時先講你要的結果（outcome），例如「週五前把回饋整理成一張表」。要做哪些步驟，讓 bot 自己往回推，不用一步步教。
  • 88:40 總結二：bot 有記憶，也能從影片教學中學習；例如講者先教 bot 做動畫，再把它變成 skill 之後持續使用
    ↳ 總結二：bot 有記憶，也能看影片教學學新本事。講者先教 bot 做動畫，再把它存成 skill（可以重複叫用的技能），之後就一直用下去。
  • 89:10 bot 是某個領域的專家，是一個 persona 而不是單一任務，所以可以跨多個專案、長期運作，這是它強大的原因
    ↳ bot 被設定成某個領域的專家角色，不是只做一次的單一任務，所以能同時顧好幾個專案、長期做下去，這就是它強的地方。
  • 89:10 總結三：bot 執行任務前會請人類核准，確保適合企業環境、在對的事情上請求許可，不會做危險的事
    ↳ 總結三：bot 動手前會先請人核准（human approval）。它會在該問的地方先問過，不會自作主張做危險的事，所以公司裡也能放心用。

📘 術語
Marketplace（市集）：可以上架 bot、附上 bot 連結的地方，也能在這裡連接 X MCP
modal（彈出視窗）：要求登入 1Password 或輸入 API secrets 時跳出的視窗，資料會安全存在 Grockbot 內
API secrets / environment secrets（API 金鑰／環境機密）：在 modal 輸入，安全存在 Grockbot 內，不會外露
VM（虛擬機）：bot 的虛擬電腦；憑證是在 modal 輸入，不是在 VM 上輸入
S3 buckets（S3 儲存桶）：Grockbot 儲存記憶的地方，記憶會長期保存，也可以修改
persistent（持久保存）：指記憶會長期存在，不會自動消失
duplicate（複製 bot）：新 bot 的 context 和記憶全新，但 persona 相同
persona（角色設定）：bot 是某個領域的專家角色，不是單一任務，所以能跨多個專案運作
delegate（分派工作）：bot 把工作交給其他 bot；被分派的 bot 刪掉後，主 bot 不會自己知道
chief of staff bot（幕僚長 bot）：講者用來分派工作給其他 bot 的 bot
feature flags（功能旗標）：字幕沒有解釋，只說清理過時的 feature flags 是工程團隊的例子
SDR（業務開發代表）：字幕沒有解釋，只提到 Grockbot for SDRs 場次會講寄開發信
MCP（MCP）：字幕說 bot 可以使用 MCP 以外的工具，不必再去連 MCP
skill（技能）：講者教 bot 做動畫後，把它變成 skill 之後繼續使用
human approval（人類核准）：bot 執行任務前會請人核准，確保適合企業環境、不做危險的事
voice of the customer（顧客之聲）：字幕沒有解釋，只說可以從使用者研究開始了解顧客的聲音
