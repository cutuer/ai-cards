🧑‍🏫 這支影片是 Slack 團隊分享他們怎麼用 Claude 處理「訊息多到看不完」這個老問題：做 AI 搜尋和自動摘要，工程師內部也用 Claude 寫程式。如果你每天都被群組和通知淹沒，這支片能讓你看懂 AI 在工作工具裡到底解決了什麼，也能看到一家大公司的工作方式正在怎麼變。

  • 00:01 Slack 一直以來面臨的挑戰之一是「資訊過載」（information overload）
    ↳ information overload（資訊過載）指的是訊息多到看不完，重要的事反而被淹沒。Slack 上頻道多、@ 也多，一打開就是上百則，這是他們長期要面對的痛點。
  • 00:01 Slack 的產品原則之一是「be a great host」，一開始就想幫使用者從雜訊中篩出真正重要的資訊
    ↳ be a great host（當個好主人）是 Slack 的產品原則之一：像主人會招呼客人一樣，主動幫使用者擋掉雜訊，把真正要緊的東西送到眼前。這個想法在有 AI 之前就有了。
  • 00:01 AI 出現後，Slack 想解決的問題很明確：一是搜尋，二是摘要大量資訊
    ↳ 有了 AI 之後，他們把目標收斂成兩件事：一是讓你更快找到要的資料（搜尋），二是把一長串討論濃縮成幾句重點（摘要）。
  • 00:32 他們開始用 AI 做實驗，特別是 Claude；拿到第一批搜尋答案時，覺得跟 Claude 幾乎「心意相通」，是第一個「holy cow moment」
    ↳ 他們拿 Claude 試做搜尋，第一批答案準到好像 Claude 懂他們想問什麼。holy cow moment 就是「哇，這真的行」的驚嘆時刻，這是他們的第一次。
  • 00:32 系統會自動幫忙回答問題、摘要資訊，每天都能幫使用者省下好幾分鐘
    ↳ 做出來的功能會自動回答同事的問題、整理長串對話的重點，不用自己一則一則往上翻。每個人每天可以省下好幾分鐘。
  • 00:32 Slack 追蹤的指標包括：query success rate（查詢成功率），以及自己回報覺得 Slack「很吵」的使用者人數
    ↳ 他們看兩個數字：query success rate（查詢成功率，也就是搜尋後有沒有真的找到要的東西），還有多少人自己說 Slack「很吵」。前者看好不好用，後者看負擔有沒有變輕。
  • 00:32 這兩項指標都出現了 Slack 最大幅度的改善之一
    ↳ 導入 Claude 之後，這兩個數字的進步幅度是 Slack 歷來最大的幾次之一。意思是搜尋變準了，覺得被訊息轟炸的人也變少了。
  • 01:03 Slack 不只在面向客戶的功能用 Claude，內部也用 Claude Code 修 bug，讓團隊動得更快
    ↳ Claude Code 是 Anthropic 給工程師用的工具，可以直接讀程式碼、幫忙修改。Slack 內部用它修 bug，工程師不必每個問題都從頭慢慢查，團隊的進度就推得更快。
  • 01:03 現在的限制在於創意和想像力：問題不再是「怎麼做」，而是「你想做什麼」
    ↳ 以前卡關的常常是「技術上做不做得到、要花多久」。現在 AI 能幫忙把東西做出來，真正的瓶頸變成你有沒有想清楚要做什麼，點子夠不夠好。
  • 01:03 工作方式改變：花更多時間在規劃和架構，實際寫程式的時間變少，深度思考變多
    ↳ 工程師的時間分配變了：動手寫程式的部分由 AI 分擔，人把力氣放在事前規劃和架構，也就是決定系統要怎麼拆、各部分怎麼接，花更多時間在想清楚。
  • 01:34 主要好處是省時間；希望和 Claude 一起讓人們每天完成更多事
    ↳ 講到底，最大的好處就是省時間。Slack 希望和 Claude 一起，讓每個人每天能多完成一些事。
  • 01:34 受訪者表示，這是他整個職涯中對科技業最興奮的時候
    ↳ 受訪者說，這是自己整個職涯中對科技業最興奮的時候。也就是說，在受訪者眼中這不是小小的改良，而是做事方式真的在改變。
📘 術語
information overload（資訊過載）：Slack 一直面臨的挑戰；需要幫人從雜訊中篩出重要資訊
be a great host（當個好主人）：Slack 的產品原則之一，要幫使用者從雜訊中篩出重點
query success rate（查詢成功率）：Slack 追蹤的指標之一，導入 Claude 後有大幅改善
Claude Code（Claude Code）：Slack 內部用來修 bug、讓團隊動得更快的工具
✏️ 小考一題

影片中，Slack 提到導入 Claude 後有明顯改善的兩項指標是什麼？

A. 付費轉換率，以及使用者留存率B. 每日活躍使用者數，以及訊息傳送量C. query success rate，以及自己回報覺得 Slack 很吵的使用者人數D. 客服工單數量，以及 bug 修復時間
看答案
答案：C。[00:32] 字幕說追蹤的指標有 query success rate，以及自己回報覺得 Slack noisy 的使用者人數，這兩項都有最大幅度的改善之一。
