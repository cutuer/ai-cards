🧑‍🏫 這支影片教你在 Claude Code 裡怎麼挑模型：Sonnet、Opus、Fable 各自適合做什麼，還有一個叫 effort level 的設定可以調。如果你習慣什麼事都用同一個模型，看完就會知道什麼時候該換模型，什麼時候只要把這個設定調高或調低。

  • 00:01 影片主題：如何在 Claude Code 中選擇合適的模型
    ↳ Claude Code 是 Anthropic 出的寫程式助理，能直接幫你讀、改、跑程式。它背後可以換不同的「模型」，也就是實際負責思考的 AI，影片就是在教怎麼挑。
  • 00:01 Sonnet 是日常使用的標準選擇，速度快，是優秀的通才型模型
    ↳ Sonnet 是 Claude 的其中一款模型，定位是日常主力：回得快，什麼事都做得不錯。一般任務先用它就夠了，不用一開始就搬出最重的。
  • 00:01 Sonnet 適用例子：在發布前審查程式碼片段（reviewing code snippets）
    ↳ 例如程式寫好、正式上線前，請它看看一小段程式有沒有問題。範圍小、又希望很快有結果，正好是 Sonnet 擅長的。
  • 00:01 工作變得比較複雜時，講者會改用 Opus
    ↳ 當問題牽扯的東西變多、需要想得比較深，講者就會換成 Opus。Opus 是另一款模型，強項是慢下來把事情想清楚。
  • 00:01 Opus 適用例子：排查棘手的錯誤，或在開始寫程式前找出系統設計的缺陷
    ↳ 例如一個錯誤怎麼查都找不到原因，或想在動手寫之前，先檢查整個系統的架構有沒有漏洞，這類事就交給 Opus。
  • 00:01 原因是 Opus 很擅長深度推理（deep reasoning），所以講者大部分的規劃都從 Opus 開始
    ↳ deep reasoning（深度推理）是指一層一層推敲、把前因後果想透的能力。做規劃本來就很需要這種能力，所以講者習慣先用 Opus 排計畫。
  • 00:01 Fable 是設計來處理你最困難的工作
    ↳ Fable 是這三款裡定位最高的模型，專門用來處理你手上最難、最複雜的工作。
  • 00:01 Fable 和 Opus 的差別：Fable 需要的逐步指引（step-by-step guidance）少很多
    ↳ step-by-step guidance（逐步指引）就是你一步步交代它先做什麼、再做什麼。用 Fable 時這類交代可以少很多，它比較能自己把事情拆開來做。
  • 00:01 Fable 例子：交給它「幫我的 app 加上使用者設定頁面」這種重要任務，看似簡單
    ↳ 例如跟它說「幫我的 app 加一個使用者設定頁面」。這句話聽起來很單純，但對 app 來說是一個實實在在的重要功能。
  • 00:31 但每個選項都必須連接到資料庫欄位和使用者權限，實際上有其複雜度
    ↳ 因為頁面上每個選項，背後都要接到資料庫裡對應的欄位才能存起來，還要判斷誰有權限改哪些設定，改一個地方就會牽動很多地方。
  • 00:31 Fable 能理解這種複雜度，會擬定計畫、執行，並交付完成的功能
    ↳ Fable 看得出這些藏在底下的關聯，會自己先排好計畫、動手做完，最後交出一個能直接用的完整功能，不是做到一半的東西。
  • 00:31 選模型只是流程的一半；若 Claude Code 的回答不如預期，可以試著調整 effort level
    ↳ 挑對模型只解決了一半。如果 Claude Code 交出來的結果不理想，不一定要換模型，也可以先試著調整 effort level。
  • 00:31 effort level 控制 Claude Code 要做得多徹底，以及要花多少時間處理你的應用程式
    ↳ effort level（投入程度）是一個設定，決定 Claude Code 做事要多仔細、願意花多少時間處理你的程式。
  • 00:31 需要快速回應時把 effort 調低；想讓 Claude Code 想久一點、跑測試、檢查自己的成果時就調高
    ↳ 只想快點拿到答案就調低；希望它多想一下、自己跑測試、回頭檢查有沒有做錯，就調高，只是要等比較久。
📘 術語
Sonnet（Sonnet 模型）：日常使用的標準模型，速度快、優秀的通才
Opus（Opus 模型）：擅長深度推理，適合排查困難錯誤、找系統設計缺陷與規劃
Fable（Fable 模型）：設計來處理最困難的工作，比 Opus 需要更少的逐步指引
deep reasoning（深度推理）：Opus 很擅長的能力，因此講者多數規劃從 Opus 開始
step-by-step guidance（逐步指引）：Fable 比 Opus 需要的這類指引少很多
effort level（努力程度設定）：控制 Claude Code 要多徹底、花多少時間；調低求快，調高會想更久、跑測試、檢查成果
