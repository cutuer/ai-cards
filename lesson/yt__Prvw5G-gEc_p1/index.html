🧑‍🏫 這是 xAI 團隊直播「72 小時打造一間公司」第三天的開場。前段是 Grokbot 新用戶限時免費一個月的優惠；後段示範他們怎麼讓一群 AI bot 分工寫程式、互相檢查，一個晚上合併上百個修改。值得看的是「人決定方向、AI 大量執行」實際跑起來是什麼樣子。

  • 06:14 今天是第三天，要把公司正式推出（shipping our company）；團隊在舊金山的 Grokbot Galaxy 活動中，要用 72 小時打造一間公司
    ↳ 今天是活動第三天，目標是把公司正式推出。shipping 就是產品正式上線。團隊在舊金山辦 Grokbot Galaxy 活動，挑戰用 72 小時從零做出一間公司。
  • 06:14 主持人：Matt 在 xAI 負責 developer experience；potato（本名 Lauren）在 xAI 做 Grokbot；Roshan 在 xAI 做 Grokbot 等產品
    ↳ 三人都在 xAI（馬斯克創辦的 AI 公司）工作。Matt 負責 developer experience，也就是讓開發者用工具時更順手。potato（本名 Lauren）和 Roshan 負責 Grokbot 這個 AI 助理。
  • 06:14 昨晚團隊進展很多，因為 Lauren 架了一座「software factory」（軟體工廠）
    ↳ 昨晚進度特別快，是因為 Lauren 架了一座 software factory。它不是真的工廠，而是讓一隊 bot（會自動做事的 AI 程式）分工合作寫程式的系統。
  • 06:50 優惠公告：沒用過 Grokbot、還沒有帳號的新用戶，在接下來 10 分鐘內註冊，就能免費使用 Grokbot 一個月，畫面下方有倒數計時
    ↳ 限時優惠：從沒用過 Grokbot、也還沒有帳號的人，只要在直播接下來 10 分鐘內註冊，就能免費用一個月。畫面下方有倒數，時間一過就結束了。
  • 06:50 領取條件：下載 Grokbot、建立帳號，並設定一個 recurring task（定期任務）；potato 會在推特上分享設定範例
    ↳ 領取要做三件事：下載 Grokbot、註冊帳號，再設一個 recurring task。recurring task 就是請 Grokbot 定期自動做的事，時間到它就自己執行。potato 會在推特分享設定範例。
  • 07:24 適合自動化的例子：搜尋 email、追蹤 GitHub issues、看 Slack 等耗時的例行工作；只要跟 Grokbot 說「每天幫我檢查 email」，它就會自己設定好
    ↳ 最適合交出去的是每天都要做、又很花時間的雜事，例如翻 email、追 GitHub issues（程式專案的問題回報清單）、看 Slack（公司常用的聊天工具）。直接跟它說一句話，它就會自己設好。
  • 07:24 畫面上有 QR code；這個免費一個月的方案只限新帳號使用
    ↳ 掃畫面上的 QR code 就能去註冊。要注意這個優惠只給新帳號，已經有帳號的人不能領。
  • 08:02 這個免費月價值 200 美元，而且是最高方案（highest tier），可用量很大
    ↳ 這個免費月價值 200 美元，而且給的是最高方案（highest tier），能用的額度最大，不是功能縮水的試用版。
  • 08:40 他們在打造一間遊戲工作室，今天會推出第一款遊戲，預計幾小時內上線，上線前還要再做一些打磨（polish）
    ↳ 他們這 72 小時做的公司是一間遊戲工作室，今天會推出第一款遊戲，預計幾小時內上線。上線前還要 polish，也就是修細節、讓玩起來更順。
  • 08:40 這款遊戲是由「一整支軍隊」的 Grokbot 一起打造；昨天傍晚組了一隊 bot 來當 software factory
    ↳ 這款遊戲不是人一行一行寫出來的，而是一大群 Grokbot 分工做出來的。昨天傍晚他們把這群 bot 組成那座 software factory。
  • 08:40 Roshan 畫面上的是他自己那一份工廠，參考了 Lauren 分享給他的 bot templates
    ↳ Roshan 畫面上展示的是他自己的那座工廠。他照著 Lauren 分享的 bot templates 搭起來。bot templates 就是事先設定好的 bot 範本，所以他不用從頭設計。
  • 09:15 Lauren 和 Roshan 昨晚花很多時間 brainstorm 遊戲機制和打磨方向，重點是讓遊戲真的好玩
    ↳ 程式交給 bot 寫，人負責想方向。Lauren 和 Roshan 昨晚主要在 brainstorm（大家一起丟點子），討論遊戲規則和要修的地方，目標是讓遊戲真的好玩。
  • 09:45 遊戲一開始是 1v1 剪刀石頭布，有 Elo、計分系統和排行榜，但實際玩了之後覺得不好玩，於是參考其他喜歡的遊戲機制來改
    ↳ 初版是一對一剪刀石頭布，有 Elo（西洋棋常用的實力評分制度）、計分系統和排行榜。但他們自己玩過覺得不好玩，就參考其他喜歡的遊戲機制重新改。
  • 09:45 他們跟 Grokbot 和 cloud agents 一起擬好計畫，接著使用 p-stack：Lauren 自己整理的一套 skills，同時是 Cursor plugin 也是 Grokbot plugin
    ↳ 他們先和 Grokbot、cloud agents（在雲端執行任務的 AI）一起擬好計畫，再用 p-stack 來做。p-stack 是 Lauren 整理的一套 skills（AI 技能包），可以當外掛裝進 Cursor（AI 寫程式軟體）和 Grokbot。
  • 09:45 p-stack 裡有一個 skill 叫 potato mode
    ↳ p-stack 裡有很多 skill，其中一個叫 potato mode。後面整晚的自動開發，就是靠這個 skill 開始的。
  • 10:21 potato mode 會教 bot 做事更嚴謹，也更擅長 orchestrate（協調指揮）其他 bot 和 agent
    ↳ potato mode 主要做兩件事：讓 bot 做事更仔細、不馬虎；也讓 bot 更會 orchestrate，也就是像工頭一樣分派工作，調度其他 bot 和 agent 一起完成。
  • 10:21 輸入 /potato mode 並說「full autopilot this plan」，它會把計畫拆成很多小階段，再架起一座 mini factory
    ↳ 用法是輸入 /potato mode，再說「full autopilot this plan」，意思是全自動執行這份計畫。它會把大計畫拆成很多小階段，再自己架一座小工廠去做。
  • 10:56 mini factory 分工：有 agent 負責實作一個個小 PR，也有 agent 負責驗證，會實際跑應用程式並做 fuzz（到處點擊測試）來找 bug
    ↳ 小工廠分工很清楚：有的 agent 負責寫程式，每次只交一個小 PR（提交給專案的一小包修改）；有的專門驗收，會實際打開程式到處亂點（fuzz），藉此找出 bug。
  • 10:56 因為驗證和檢查做得很嚴謹，讓人可以放心；在 full autopilot 模式下 PR 會自動合併（auto-merge）
    ↳ 因為驗收很嚴格，人才敢放手讓它做。在全自動模式下，PR 通過檢查就會 auto-merge，也就是自動併進正式程式碼。
  • 11:26 這批 PR 的內容包括：改版 UI（字幕寫作 re-damping the UI）、升級後端、確認安全性，以及確保能承受流量；能不能扛住，他們說上線後就知道
    ↳ 這些修改包括：改版 UI（使用者看到的畫面）、升級後端（在背後處理資料的伺服器）、確認安全性，還有確保遊戲撐得住大量玩家。到底撐不撐得住，他們說上線後就知道。
📘 術語
software factory（軟體工廠）：由一隊 bot 組成、協助打造遊戲的系統，由 Lauren 架設
recurring task（定期任務）：讓 Grokbot 定期自動執行的工作，例如每天檢查 email；也是領取免費月的條件之一
bot templates（bot 範本）：Lauren 分享的範本，Roshan 參考它們建了自己的工廠
Elo（Elo 積分）：字幕只提到它是初版 1v1 剪刀石頭布遊戲的機制之一，沒有進一步解釋
leaderboard（排行榜）：初版遊戲設計中的排行榜
cloud agents（雲端 agents）：字幕只說團隊和 Grokbot、cloud agents 一起擬計畫，沒有進一步解釋
p-stack（p-stack）：Lauren 個人的一套 skills，同時是 Cursor plugin 和 Grokbot plugin
skill（技能）：p-stack 裡的功能單位，例如 potato mode
plugin（外掛）：p-stack 以 Cursor plugin 和 Grokbot plugin 的形式提供
potato mode（potato 模式）：讓 bot 更嚴謹、更會協調其他 bot 和 agent 的 skill
orchestrate（協調指揮）：指揮、調度其他 bot 和 agent 一起工作
full autopilot（全自動駕駛模式）：把計畫拆成小階段、架起 mini factory，PR 驗證後自動合併
PR（Pull Request）：agent 實作的一個個小改動；一夜合併超過 100 個
fuzz（模糊測試）：agent 實際在應用程式裡到處點擊、測試，藉此找出 bug
auto-merge（自動合併）：在 full autopilot 模式下，PR 通過嚴謹驗證後會自己合併
✏️ 小考一題

根據影片，在 p-stack 裡輸入 /potato mode 並說「full autopilot this plan」後，會發生什麼事？

A. 自動幫新用戶註冊帳號並領取一個月免費方案B. 把計畫拆成很多小階段，架起 mini factory，由 agent 實作小 PR、驗證後自動合併C. 把整份計畫合成一個大 PR，等人工審查後才合併D. 只產生遊戲的美術素材和 UI 設計稿
看答案
答案：B。[10:21] 說明它會把計畫拆成許多小階段、架起 mini factory；[10:56] 提到 agent 實作小 PR、跑程式並做 fuzz 驗證，在 full autopilot 模式下 PR 會自動合併
