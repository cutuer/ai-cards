🧑‍🏫 這是 OpenAI 在 DevDay 2026 介紹 Codex 的後半段。Codex 是 OpenAI 用來寫程式、改程式的 AI 助手。這段的主軸是「Codex 離開筆電」：它可以在雲端執行，也能走進 Slack、網頁和終端機，還能主動幫你盯工作。就算你不寫程式，也能從這段看到「把整件工作交給 AI，人只負責審核和決定」大概是什麼樣子。

  • 11:04 在雲端跑任務的另一個好處：可以把任務帶進團隊已經在用的環境，示範案例是 Slack
    ↳ 「在雲端跑」是指任務在遠端伺服器上執行，不佔用你的電腦。另一個好處是能在團隊平常用的工具裡直接叫它做事。這次示範的是 Slack，一種很多公司在用的團隊聊天軟體。
  • 11:04 示範情境：講者和同事在 Slack 討論一個 bug，web app 的視覺沒有正確實作，講者請 ChatGPT 去查原因
    ↳ 情境是講者和同事在 Slack 聊到一個 bug（程式錯誤）：網頁應用程式（web app）的畫面跟設計稿不一樣。講者沒有自己去翻程式，而是在對話裡直接請 ChatGPT 查原因。
  • 11:34 ChatGPT 調出 pull request，也存取 Figma 檔案來找出問題
    ↳ ChatGPT 調出了 PR（pull request，工程師送出、等人審核合併的一包程式修改），也打開 Figma（設計師畫介面的工具）的設計檔，把兩邊對照，找出畫面哪裡沒照設計做。
  • 11:34 發現已有 PR 在解這個問題，講者請它深入研究並測試這些變更
    ↳ 它發現已經有人送出 PR 在修這個問題。所以講者沒有重做一次，而是請它把這份修改研究清楚，再實際測試，確認真的修好了。
  • 11:34 測試用的是講者先前建立、並分享給組織的同一個雲端環境
    ↳ 測試用的是講者之前建好、分享給整個組織的雲端環境（cloud environment），也就是事先設定好、可以直接跑程式的地方。準備一次，全團隊都能重複使用。
  • 11:34 兩人在 Slack 上一起協作，最後讓這個 PR 進入可以 review 的狀態
    ↳ 整個過程中，講者和同事都待在同一個 Slack 對話裡，一起看結果、一起下指令，最後把 PR 推到「可以請人審核」的狀態，沒有人需要離開聊天軟體。
  • 12:05 講者觀察：agent 寫的程式越多，自己花在 review 程式碼的時間也越多，因此大幅改造了 desktop app 的 code review 分頁
    ↳ 講者發現，agent（能自己接下任務、一步步做完的 AI 助手）寫的程式越多，人花在 review（審核檢查）的時間也越多。所以他們大改了桌面版 app 的 code review 分頁。
  • 12:05 新版 code review 分頁可直接在 app 裡看到指派給你、或由你建立的所有 PR
    ↳ 新版分頁會把「指派給你審的」和「你自己送出的」PR 全部列在 app 裡，不用再到別的網站一個一個找。
  • 12:05 可做一般 code review 的事：看程式碼、留言
    ↳ 審核的基本功能都有：逐行看程式改了什麼，在有意見的地方留言，就像在文件上加註解。
  • 12:35 也能看別人的留言、送出 review 回饋，甚至用 Codex 跑一次 review
    ↳ 你也能看別人留了什麼意見、正式送出自己的審核結果，還能先叫 Codex 幫你審一輪，當作第一道把關。
  • 12:35 講者覺得最有用的是能直接在 app 裡發問，了解這個 PR 在做什麼、可能有哪些副作用
    ↳ 講者最常用的是直接在 app 裡發問，例如「這個 PR 到底在改什麼」「會不會影響到其他功能」，也就是副作用。看不懂的地方當場問，不用自己硬啃。
  • 13:07 確認沒問題後，就能直接送出回饋
    ↳ 問清楚、確認沒問題之後，就在同一個地方直接送出審核意見。從看、問到回覆，一路在同一處做完。
  • 13:07 agent 接手的工作越大，規劃和團隊協作就越重要
    ↳ 交給 agent 的工作從小修改變成大專案時，事前怎麼規劃、團隊怎麼對齊分工，就比以前更重要。
  • 13:07 space 讓你同時和 agent 及團隊協作，不必來回複製貼上資訊
    ↳ space 是一個共用的工作空間，你、同事和 agent 在同一處一起編計畫。重點是不用再把 AI 的回答貼進文件，又把同事的意見貼回去給 AI。
  • 13:07 示範情境：講者在做 API reference 的改版，並規劃要怎麼部署
    ↳ 示範情境是講者在改版 API reference，也就是給開發者查「這套程式介面怎麼用」的說明文件，同時規劃改好之後要怎麼上線。
  • 13:38 Codex 先寫出計畫，講者把計畫放進 space，分享給團隊並取得回饋，同時也能繼續和 Codex 迭代計畫
    ↳ 流程是：Codex 先擬計畫，講者把計畫放進 space 分享給團隊收意見，同時繼續跟 Codex 修改。團隊討論和 AI 修改，在同一份文件裡同步進行。
  • 13:38 講者請 Codex 在計畫裡加上系統圖，說明各部分如何組合，也加上任務追蹤表
    ↳ 講者請 Codex 在計畫裡加一張系統圖（system diagram），畫出各部分怎麼串在一起，再加一張任務追蹤表（task tracker），列出每件事做到哪裡。
  • 13:38 Codex 執行任務時可同步更新追蹤表；整個團隊一起做時，大家的 dot 和 Codex 都能貢獻同一份文件
    ↳ Codex 一邊做任務，一邊自己更新追蹤表。整個團隊一起做時，每個人的 dot（個人專屬的 AI 分身，後面會細講）和 Codex 都能寫進同一份文件。
  • 14:12 這樣所有人都能同步掌握目前的進度
    ↳ 結果就是大家看同一份文件，就知道現在做到哪裡，不用另外開會，也不用一個個去問。
  • 14:12 對計畫滿意後，可以請 Codex 實作，它會接手執行，也能視需要持續回報資訊
    ↳ 計畫定案後，直接叫 Codex 動手做。它會接手執行，過程中有需要也會回報狀況，你不用一直盯著。
  • 14:12 最後一部分是主動性（proactivity）：講者問現場有多少人用 loops 或 threads of threads 管理工作，回答「不少」
    ↳ 最後一個主題是主動性（proactivity），意思是 AI 不等你吩咐，自己留意狀況。講者問現場多少人用 loops 或 threads of threads 管理工作，答案是不少。這兩種做法影片沒有細講。
  • 14:45 dot 可管理既有的 Codex 任務，也能把更多任務交給 Codex，同時持續主動留意各種動態
    ↳ dot 能幫你管已經在跑的 Codex 任務，也能把新任務再交給 Codex，同時一直留意周遭有什麼新動靜。
  • 14:45 dot 能追蹤產品與工程討論、幫你注意程式碼變更，必要時主動建立任務
    ↳ 它會追蹤產品和工程團隊在討論什麼、注意有人改了哪些程式。覺得有需要時，它會自己開任務，不用你開口。
  • 14:45 示範：同事 Carolis 在一個 PR 標記了講者，講者沒注意到，dot 在 Slack 發通知提醒他去看
    ↳ 示範中，同事 Carolis 在一個 PR 裡標記了講者，講者沒注意到。dot 發現後在 Slack 提醒他去看，像一個幫你盯信箱的助理。
  • 15:15 當時是星期天晚上十點多，講者沒空細看，就先問 dot 這個 PR 在講什麼，dot 開始 review
    ↳ 當時是星期天晚上十點多，講者沒力氣細讀，就先問 dot「這個 PR 在講什麼」，dot 開始幫他審。
  • 15:15 講者再請它做更完整的 review，dot 直接從 Slack 建立一個完整的雲端任務
    ↳ 講者想看更完整的審核，就再請它做一次。dot 直接從 Slack 開出一個完整的雲端任務（cloud task），不用切到別的 app。
  • 15:45 雲端任務會深入研究 PR、找出問題並回報；因為是真正的任務，之後可以接著追問，甚至用它把 PR 完成
    ↳ 這個雲端任務會深入研究 PR、找出問題再回報。因為它是正式任務，不是隨口回一句，之後還能接著追問，甚至直接讓它把 PR 做完。
  • 15:45 講者預期觀眾會問：Slack 裡有 @ChatGPT 也有自己的 dot，差別在哪、何時用哪個
    ↳ 講者先替觀眾問了一個問題：Slack 裡既有 @ChatGPT，又有自己的 dot，兩個差在哪？什麼時候該叫哪一個？
  • 16:16 dot 是你自己的延伸，刻意用「你的名字＋dot 名稱」命名，讓 Slack 裡的人知道它和你本人綁在一起
    ↳ dot 是你自己的延伸。它刻意命名成「你的名字＋dot 名稱」，讓 Slack 裡的同事一看就知道，這是代表你、跟你綁在一起的那一個。
  • 16:16 dot 知道你在做什麼、有你的記憶，適合處理和你工作相關的持續性任務
    ↳ dot 知道你手上在做什麼，也有你的記憶，所以適合處理跟你工作有關、需要長期持續盯著的事。
  • 16:46 dot 會定期關注你在意的頻道；你給權限時它會發表意見；你也能隨時在 Slack 或其他頻道把任務轉給它
    ↳ 它會定期看你在意的頻道。你允許的話，它會在頻道裡發言。你也能隨時在 Slack 或其他地方，把事情轉交給它。
  • 16:46 @ChatGPT 則是為協作設計，適合你和同事在同一個 thread 裡同時互動，例如一起處理 PR
    ↳ @ChatGPT 是為多人合作設計的。你和同事可以在同一串對話（thread）裡一起叫它、一起處理同一件事，例如前面修 PR 的例子。
  • 17:16 字幕說：因為這樣，你的 dot 能存取你所有的雲端資訊，讓協作容易很多
    ↳ 字幕的原話是：因為這樣，你的 dot 能存取你所有雲端上的資料，協作會容易很多。這句的前後因果，影片沒有講得很清楚。
  • 17:16 目標是讓你在任何地方、用任何方式使用 Codex；目前展示了 desktop、也談了 mobile，另外很多人喜歡用 CLI
    ↳ 目標是讓你在任何地方、用任何方式都能用 Codex。前面示範了桌面版，也提到手機版。另外很多人愛用 CLI，也就是在終端機的文字視窗裡打指令操作的方式。
  • 17:47 因此 CLI 也大幅改造，新增 agent view，可看到 Codex 裡所有正在跑的任務
    ↳ 所以 CLI 也大改版，新增了 agent view：一個總覽畫面，列出你在 Codex 裡所有正在跑的任務。
  • 17:47 agent view 能留意哪些任務需要你處理、開新任務，也能輕鬆平行跑多個任務
    ↳ 在 agent view 裡，你能看出哪些任務在等你決定，可以開新任務，也能很輕鬆地讓好幾個任務同時跑。
  • 17:47 CLI 現在可以用 @ mention 叫出你在用的所有 plug-ins
    ↳ 在 CLI 裡打 @，就能叫出你正在用的各種 plug-ins。plug-in 一般指可以額外裝上的擴充功能，影片沒有細講有哪些。
  • 18:18 CLI 選取文字等操作變得快很多，也能直接在終端機裡渲染圖表
    ↳ CLI 裡選取文字之類的基本操作變得順很多，也能直接在終端機裡畫出圖表，不必另外開視窗看。
  • 18:18 CLI 新增 voice mode，可在終端機裡直接和 agent 對話，用的是 desktop app 上同一個 GPT live model（現場麥克風沒開，未實際示範）
    ↳ CLI 新增語音模式（voice mode），可以在終端機直接用說的跟 agent 溝通，背後用的是桌面版同一個 GPT live model。現場麥克風沒開，所以沒有實際示範。
  • 18:52 更多功能可直接在網頁使用：示範用的是 Chrome 而不是 desktop app，但介面很熟悉
    ↳ 更多功能現在用瀏覽器就能用。講者這段是開 Chrome 示範，不是開桌面 app，但介面跟桌面版很像，不用重新學。
  • 18:52 在瀏覽器裡就能存取所有在 Codex Cloud 跑過的雲端任務，也能看到先前傳過的截圖和影片
    ↳ 在瀏覽器裡，能看到所有在 Codex Cloud（Codex 的雲端執行服務）跑過的任務，連之前傳給它的截圖和影片都還在。
  • 19:22 在網頁介面裡可直接操作已部署的網站
    ↳ 網站部署（也就是正式放上網路）之後，可以直接在這個網頁介面裡實際點選、操作，不用另外開分頁測試。
  • 19:22 網頁版也能使用 dot；code review 分頁預計在未來幾天內上線網頁版，不必安裝 desktop app
    ↳ 網頁版也能用 dot。code review 分頁預計幾天內會推出網頁版，到時候不裝桌面 app 也能審 PR。
  • 19:56 開發方式已大幅改變：從交辦單一任務，變成把越來越大的問題交給 agent
    ↳ 講者總結：寫程式的方式已經變了。從「一次交代 AI 一件小事」，變成把越來越大、越複雜的問題整個交給 agent。
  • 19:56 這讓你能真正做出高品質的解決方案，而不只是原型
    ↳ 這樣做出來的東西品質夠好、真的能拿來用，而不只是原型（prototype，先求能動、用來展示想法的初版）。
  • 19:56 不需要一次採用今天展示的全部功能，可依自己的工作方式在任何地方使用 Codex
    ↳ 今天展示的功能不必一次全用。挑適合自己工作習慣的就好，在哪裡用 Codex 都可以。
  • 20:28 建議一：如果你還開著筆電不關，或在管理一堆 def boxes，就試試 CodexCloud，可離開筆電、重用已準備好的環境，少花時間維護基礎設施
    ↳ 如果你為了讓任務跑完不敢闔上筆電，或要管一堆 def boxes（聽起來應是指開發用的機器），可以試 Codex Cloud：離開筆電任務照跑，能重用設定好的環境，少花時間顧機器。
  • 21:00 建議二：如果你厭倦在團隊文件之間跳來跳去、再把計畫複製回文件，就試試 space，讓功能和計畫集中在同一處，Codex 也會在文件裡持續更新進度
    ↳ 如果你常在團隊各份文件之間跳來跳去，再把計畫貼回文件，可以試試 space：功能和計畫集中在同一處，Codex 也會在文件裡自動更新進度。
  • 21:00 建議三：如果你厭倦每次都手動轉交工作、重新下 prompt 給 Codex，就把一項持續性的職責交給 dot，讓它追蹤並推進工作
    ↳ 如果你常要手動交接工作，每次都得重新對 Codex 下指令（prompt），可以把一件長期要做的事交給 dot，讓它自己追蹤、推進。
📘 術語
cloud environment（雲端環境）：講者預先建立、可分享給組織的環境，Codex 用它來測試變更
PR (pull request)（合併請求）：字幕中被調出、測試和 review 的程式碼變更
Figma（Figma 設計檔）：ChatGPT 存取的設計檔案，用來找出視覺沒做對的地方
code review tab（程式碼審查分頁）：desktop app 裡的分頁，可看 PR、留言、送出回饋、用 Codex 跑 review、直接發問
space（space（協作空間））：同時和 agent 及團隊協作計畫的地方，不必來回複製貼上，Codex 可持續更新進度
task tracker（任務追蹤表）：放在 space 計畫裡，Codex 執行任務時可以更新它
system diagram（系統圖）：講者請 Codex 加進計畫，說明各部分如何組合在一起
proactivity（主動性）：dot 持續留意動態，追蹤討論、注意程式碼變更，必要時主動建立任務
loops / threads of threads（loops／多層 threads）：講者提到有些人用來管理工作的方式，字幕沒有進一步說明
dot（dot（個人代理））：你自己的延伸，以你的名字命名，有你的工作脈絡與記憶，適合處理持續性工作
@ChatGPT（在 Slack 標記 ChatGPT）：為協作設計，讓你和同事在同一個 thread 裡一起工作
cloud task（雲端任務）：dot 從 Slack 建立的完整任務，之後可以追問，或用它完成 PR
CLI（命令列介面）：在終端機使用 Codex 的方式，這次大幅改造
agent view（agent 檢視）：CLI 中看到所有執行中任務的畫面，可開新任務、平行執行多個任務
at mention（@ 提及）：在 CLI 中用 @ 叫出你在使用的 plug-ins
plug-ins（外掛）：字幕只說可在 CLI 用 @ mention 叫出，沒有進一步解釋
voice mode（語音模式）：在終端機裡直接用說話和 agent 互動
GPT live model（GPT live 模型）：desktop app 使用的模型，CLI 的 voice mode 也用同一個
Codex Cloud（Codex 雲端）：在雲端跑任務，可離開筆電、重用準備好的環境，在瀏覽器也能存取
