🧑‍🏫 這段是 Grok 官方直播，示範同時開好幾個 Grok Bot（xAI 推出、有自己的電腦、能替你動手做事的 AI 助手）。講者讓它們分工做簡報、做問卷、寫信，還讓它們互相傳訊息合作。片中也叫這些 bot 為 agent，意思是能自己把任務做完的 AI 助手。如果你想把 AI 從「問答工具」變成「可以交辦工作的同事」，這段很值得看。

  • 47:45 Grok Bot 跑長時間任務時，使用者可以看到它正在做什麼，掌握它的進度
    ↳ 交代它一件要跑很久的事，你不用乾等，隨時看得到它做到哪一步。方向不對的話，你也能早點發現、早點喊停。
  • 47:45 每個 Grok Bot 用的電腦彼此隔離，一個 Grok Bot 不能存取另一個 Grok Bot 的電腦
    ↳ 每個 bot 都有一台自己的虛擬電腦，彼此看不到、也碰不到對方的東西。這樣資料不會混在一起，一個 bot 出問題也不會牽連到別的 bot。
  • 48:15 因為電腦彼此隔離，Data Dan 做 Google Form 不會影響 Slide Sonia 做簡報，多個 bot 可以同時做不同的事
    ↳ Data Dan、Slide Sonia 是講者幫 bot 取的名字。Google Form 是 Google 的線上問卷工具。它們各用各的電腦，一個做問卷、一個做簡報，可以同時進行。
  • 48:15 講者常和 Slide Sonia 同時編輯同一份簡報：Sonia 改第 1、2 張，講者改第 10、11 張，兩邊不會衝突
    ↳ 就像兩個同事在同一份線上簡報各改各的頁面。bot 改前面幾張，你改後面幾張，兩邊不會打架，它也不會把整份檔案鎖住不讓你動。
  • 48:46 講者認為 Grok Bot 說到底就是一位可以一起合作的同事
    ↳ 講者的態度是：不要把它當成只會照指令做的機器，要當成同事，可以分工、交辦，邊做邊溝通。
  • 48:46 在 Slide Sonia 的 description 裡寫了很明確的指示：怎麼編輯現有簡報、要用哪種字型和顏色
    ↳ description 就是你寫給 bot 的工作說明書，每次做事都會照著走。講者在裡面寫清楚要怎麼改現有簡報、用什麼字型和顏色，等於先講好規範。
  • 48:46 講者要求 Sonia 做完投影片後截圖傳回來，這樣來回溝通比較方便
    ↳ 做完就截圖傳回來，你不用自己打開檔案，看圖就知道對不對。要修改也能直接指著圖說，來回溝通快很多。
  • 49:17 給 bot 很明確的指示，它的表現會比較一致
    ↳ 跟帶新人一樣，交代得越具體，產出越穩定。講得模糊的話，它每次都可能照自己的理解做，結果就會不一樣。
  • 49:17 可以替 bot 加上 skills 或 routines
    ↳ skills 是加給 bot 的專門能力或做事方法，routines 是讓它定時自動做的例行工作。前者教它怎麼做，後者讓它按時去做。
  • 49:17 routine 範例：請 Sonia 每天早上 9:00 整理這份簡報有哪些修改、是誰改的
    ↳ 像設鬧鐘一樣：每天早上 9 點，Sonia 自動整理這份簡報被改了哪裡、是誰改的，你不用每天自己去問。
  • 49:47 這份簡報和很多同事共用，所以講者想知道有沒有人刪掉投影片或新增內容，由 Sonia 保留這些脈絡，每天 9:00 回報
    ↳ 多人共用的簡報，最怕有人刪了頁面或亂加內容。讓 Sonia 記住每次變動、每天固定回報，你就不用自己翻版本紀錄一頁頁對照。
  • 49:47 routine 可以跨多個 bot 設定，例如讓 Slide Sonia 和 Email Ethan 合作，每週寄一次簡報修改摘要給老闆
    ↳ 例行工作可以讓好幾個 bot 接力：Sonia 整理修改內容，專門寄信的 Email Ethan 每週把摘要寄給老闆，一條流程串起兩個 bot。
  • 50:19 Data Dan 做表單時一直要求使用者核准，講者開玩笑說可能是因為它知道自己在鏡頭前
    ↳ Data Dan 做表單時一直停下來問可不可以，講者開玩笑說它大概知道自己在鏡頭前。這也看得出 bot 在關鍵步驟會先請你同意。
  • 50:49 表單完成後，Data Dan 會把它轉成 QR code 讓觀眾掃描，不用再傳連結
    ↳ QR code 是手機一掃就能打開網址的方形條碼。表單做好後，Dan 直接把它轉成 QR code，觀眾用手機一掃就能填，不用另外傳連結。
  • 50:49 講者對外需要展示的連結或 URL，一律用 Grok Bot 產生的 QR code
    ↳ 講者只要有連結要給別人看，都交給 Grok Bot 做成 QR code。這種小事也可以交出去，幫自己省時間。
  • 50:49 表單收集到的資料會存進 Google Sheet，Grok Bot 可以在它自己的電腦上存取
    ↳ Google Sheet 是 Google 的線上試算表，用起來類似 Excel。問卷回覆會自動存進去，bot 在自己的電腦上就能打開來讀、來整理。
  • 51:20 使用者可以直接進 Grok Bot 的電腦，查看它做過的表單、試算表和回覆
    ↳ bot 的電腦不是黑盒子。你可以直接進去看它做好的表單、試算表和收到的回覆，確認成果或抓錯都很方便。
  • 51:20 如果 bot 某件事做太久或不清楚該怎麼做，使用者可以自己接手做完，再教它怎麼做
    ↳ 它卡住或做太慢時，你可以自己進去接手做完，再告訴它正確做法，下次它就會了。跟教新人一樣，先做一次給它看，之後再交給它。
  • 51:50 Email Ethan 的工作：彙整 Slide Sonia 和 Data Dan 的資料，寄給外部利害關係人（external stakeholders）
    ↳ Email Ethan 專門負責對外寄信：把 Sonia 和 Dan 的成果彙整起來，寄給 external stakeholders，也就是公司外部的相關人士，例如客戶或合作夥伴。
  • 51:50 講者提到會搭配 Grok Bot 與 Google Drive、Google Docs 的整合來處理 email
    ↳ Google Drive 是雲端硬碟，Google Docs 是線上文件。講者會搭配 Grok Bot 跟這些服務的串接來處理 email，寫信時需要的資料就不用自己複製貼上。
  • 51:50 講者讓 Email Ethan 讀自己以前寫過的真實 email，整理成一個 skill 或語氣，之後寫信都用這個風格
    ↳ 講者讓 Ethan 讀自己以前寄過的真實信件，整理成一個寫信風格的 skill。之後它擬的信，讀起來就像講者本人寫的。
  • 52:22 示範：請 Ethan 寫信給聯絡人 Jason Deore，內容是收集到的咖啡習慣資料；因為資料還在做，暫時還拿不到
    ↳ 講者請 Ethan 寫信給聯絡人 Jason Deore，內容是收集到的咖啡習慣資料。可是問卷資料還在做，Ethan 暫時拿不到。

    ↳ modal 是畫面上跳出來、要你按同意或拒絕的小視窗。bot 要讀你的資料或寄信之前，會先跳這個視窗問你，不會自己動手。
  • 52:52 講者新增一條 rule：Grok Bot 要替我回 email 前，一定要先問我
    ↳ rule 是你替 bot 定的硬性規矩。講者加了一條：要替我回 email 前，一定先問我。寄出去就收不回來的事，最適合用規則把關。
  • 53:23 加了這條 rule 後，每封信寄出前都會先詢問，使用者就不用一直盯著它會寄什麼給外部客戶
    ↳ 有了這條規則，每封信寄出前都會先經過你。你不用整天盯著它會寄什麼給客戶，它來問的時候看一下再按同意就好。
  • 53:23 接下來示範 agent 之間互相對話，這也是 bot steering 的例子：讓 Ethan 向 Slide Sonia 取得資訊和脈絡
    ↳ 接下來示範 bot 之間直接對話。bot steering 是引導 bot 去跟其他 agent 要資訊，例如讓 Ethan 去問 Sonia 簡報的內容，你不用當傳話的人。

    ↳ 其中一種做法，是在 description 裡寫明：這類工作要交給其他 agent 做。這樣它就會去找對的 bot，不會全部自己攬下來。
  • 53:54 例子：有人設了 chief of staff agent，description 寫「一律委派給團隊」，它自己不動手，交給有相關脈絡的下屬 agent
    ↳ chief of staff 原意是幕僚長。有人設了這樣一個 agent，說明裡寫「一律交給團隊」，它只負責分派工作，交給最了解狀況的下屬 agent 去做。
  • 54:24 Email Ethan 自己主動傳訊息給 Data Dan，取得咖啡相關資料
    ↳ Ethan 發現需要咖啡資料，就自己傳訊息去問 Data Dan。講者沒有下指令，它知道資料在誰手上。

    ↳ 你也可以直接指定它去找誰：講者叫 Ethan 去問 Sonia「Grok Bot Galaxy 101」這份簡報的細節，好寫信給同事。讓它自己找或由你指定都可以。

    ↳ persona 是替 agent 設定的角色和身分。每個 bot 只專精一個領域，做簡報的就管簡報、寄信的就管寄信，這正是它們強的地方。
  • 54:54 Grok Bot 的 agent 是長期存在的 persona，有記憶，不只限於單一任務或專案
    ↳ 這些 agent 做完一件事不會消失，而是長期存在、有記憶的角色。下次交辦工作時，不用從頭再解釋一次背景。
  • 55:25 Email Ethan 可以做上一整年，累積所有寄過信件的脈絡並從中學習
    ↳ 例如 Ethan 可以做上一整年，累積所有寄過的信和往來脈絡，並從中學習，越做越懂你的聯絡對象和寫信方式。
  • 55:25 Slide Sonia 的工作是做各種投影片，可以教她不同的品牌風格或主題；agent 的範圍和 persona 隨時可以調整
    ↳ Sonia 負責做各種投影片，你可以教她不同的品牌風格或主題。這些角色不是定死的，負責的範圍和個性隨時都能調整。
  • 55:25 講者把使用 Grok Bot 比喻成在打造自己的公司、自己的 agent 團隊，由你決定怎麼編排
    ↳ 講者說，用 Grok Bot 就像在開自己的公司、組自己的 agent 團隊。要設幾個 bot、各自負責什麼、怎麼排，都由你決定。

    ↳ 可以依專案分，一個專案配一個 bot；也可以依專長分，例如做簡報的、寄信的。怎麼分組、怎麼合作，看你的需求決定。

    ↳ agent-to-agent protocol 就是 agent 之間互傳訊息的溝通方式。有了它，bot 可以直接跟彼此要資料、分工，不需要你在中間轉達。

    ↳ Linux VM 是跑 Linux 系統的虛擬電腦，不是一台實體機器，而是在雲端開出來的電腦。它很輕量、開起來很快，所以每個 bot 都能配一台。

    ↳ 講者在飛機上網路很差時，會把要上網操作的工作丟給 Grok Bot。它的虛擬電腦網路又好又快，不會被你這邊的網路拖累。

    ↳ 字幕寫 MTP，從上下文看，是指讓 bot 能直接串接某個服務的管道。Google Forms、Qualrixs（字幕原文）這類沒有這種管道的服務，講者就交給 bot 在自己的電腦上操作。
  • 59:01 適合交給它做很長的任務，不用自己手動操作，可以專心做別的事
    ↳ 很適合交代耗時又要一步步操作的任務，例如建一份問卷。丟給它去跑，你專心做別的事，之後再回來看成果。
  • 59:31 bot 連接外部服務時一定會請求許可；它想回 email 時被講者自己設的 autoreview rule 擋下，表示有遵守規則
    ↳ bot 連接外部服務時一定會先請你同意。它想回信時，被講者自己設的 autoreview rule（自動審核規則）擋了下來，證明它真的有遵守規則。
📘 術語
routine（例行任務）：讓 bot 定時自動執行的工作，例如每天早上 9:00 整理簡報的修改紀錄；可以跨多個 bot 設定
skills（技能）：可以加給 bot 的能力；例如把過去 email 整理成一個寫信語氣的 skill
description（描述／設定說明）：寫給 bot 的明確指示，例如字型、顏色、做完要截圖，或要求委派給其他 agent
persona（角色設定）：每個 agent 是某個領域的專家角色，長期存在、有記憶，範圍可以調整
rule（規則）：使用者設的限制，例如回 email 前一定要先問我
autoreview rule（自動審查規則）：講者自己設的規則，bot 想回 email 時會被它擋下
bot steering（引導 bot）：指示 bot 去和其他 agent 溝通、取得資訊和脈絡
chief of staff agent（幕僚長 agent）：自己不做事，把工作委派給有相關脈絡的下屬 agent
agent-to-agent protocol（agent 間溝通協定）：agent 彼此傳訊息溝通，讓它們很容易一起合作
orchestration（編排／統籌）：決定 agent 怎麼分工、怎麼合作；使用者只要確認它運作正常
computer use（電腦操作）：bot 在自己電腦上操作的能力；速度取決於模型，會持續改進
Linux VM（Linux 虛擬機）：Grok Bot 用的機器，很輕量、容易啟動，網路很快
modal（彈出視窗）：Grok Bot 用來詢問使用者能不能取用資料或寄信的小視窗
external stakeholders（外部利害關係人）：Email Ethan 寄送彙整資料的對象
QR code（QR code）：Grok Bot 把表單轉成 QR code，不用再傳連結
