🧑‍🏫 這段影片示範 Grok 的 Team bots 加進 Slack 之後怎麼用、適合哪些情境、有哪些特性，最後介紹 GrokBot 的語音模式。如果你的團隊常在 Slack 上問來問去，這段很實用：它說明了怎麼讓 AI 當團隊裡的共用隊友，不只是個人的助理。

  • 22:35 Slack workspace 若沒有 admin 審核步驟（字幕說多數人沒有），可直接把 bot 加進 Slack；有審核的話則會送出申請，由 admin 核准
    ↳ Slack 是很多公司用的工作聊天軟體，workspace 是一間公司在 Slack 裡的空間。admin approval 指要管理員核准：沒設這關就能直接加 bot，有設就會送申請，等管理員同意。
  • 22:35 字幕說明，把 Slack integration 或 connector 加到 GrokBot 之後，似乎就會自動建立與 Slack 的連線
    ↳ connector 或 integration 是把 Slack 這類外部服務接到 GrokBot 的設定。照字幕的說法，在 GrokBot 加好這個設定之後，連線似乎會自動建立，不用另外手動串接。
  • 23:08 功能在 SpaceX AI 內部上線後，bot 數量大增，例如 go to market bot、legal ops bot，也有用來協助規劃客服方式的 bot
    ↳ 這個功能在 SpaceX AI 內部開放後，各部門很快做出自己的 bot。例如 go to market（GTM，產品推向市場、業務銷售）的 bot、法務營運的 bot，還有幫忙規劃客服做法的 bot。
  • 23:44 適合使用 Team bots 的情境：多人協作進行同一件事，並希望為這些工作加入智慧與記憶
    ↳ Team bots 是整個團隊共用的 bot，大家看到同一份背景資訊、共用記憶。最適合好幾個人一起推同一件事，又希望有個幫手記得前因後果、幫忙出主意的情況。
  • 23:44 另一種用法是當第一線分流（triage）：讓 bot 待在公司內專門讓人提問的頻道，例如 legal、people ops、rev ops、finance
    ↳ triage 原本是醫院的檢傷分類，這裡指 bot 當第一線接問題。公司常有專門問法務、人資、營收營運、財務的頻道，就讓 bot 常駐在那裡，先接住大家的提問。
  • 24:15 讓 team bot 一直待在提問頻道，大約 70 到 80% 的問題可由 bot 直接回答，不需要真人介入，能省下時間
    ↳ 講者說大約七到八成的例行問題，bot 自己就能回答完，真人只要處理剩下比較難或特殊的。負責回答的同事就不用一直被同樣的問題打斷。
  • 24:47 bot 依據可被審核、監控、長期做 eval 的 sources of truth 直接作答，省去真人先問自己的 agent 再轉述的步驟
    ↳ sources of truth 指公認正確的依據資料，eval 是定期檢查答案品質。以前常是同事先問自己的 AI 再轉貼答案；現在 bot 直接根據這些可審核的資料回答，少了一手轉述。
  • 25:17 bot 加進 Slack 時會先發一則自我介紹訊息，例如「Hi, I'm GTM helper」，接著就能在 Slack 裡向它提問
    ↳ bot 被加進 Slack 時，會先發一則訊息介紹自己，例如「Hi, I&#x27;m GTM helper」，讓大家知道它是誰。之後就能像問同事一樣，在 Slack 裡直接問它。
  • 25:17 使用者要先在 Slack 連結自己的帳號（link account），才能和 bot 互動
    ↳ link account 是把你的 Slack 帳號和 GrokBot 帳號連在一起。一定要先做這一步，你才能和 bot 互動。
  • 25:47 bot 處理問題時會顯示 thinking 狀態，也會像真人一樣 tag 提問者，在 Slack 裡用起來很自然
    ↳ bot 處理問題時會顯示 thinking（思考中），讓你知道它正在做事。回覆時也會像同事一樣 tag（@）提問的人，所以混在 Slack 對話裡一點也不突兀。
  • 25:47 誰在 thread 裡跟 bot 說話，bot 就用那個人的 credentials 代表他做事
    ↳ credentials 是登入憑證，決定你能看什麼、能做什麼。thread 是 Slack 裡針對某則訊息的回覆串。誰在回覆串裡叫 bot 做事，bot 就用那個人的權限去做。
  • 26:17 bot 本身是有自己 credentials 的隊友，也能在你要求時代表你執行工作
    ↳ bot 本身是有自己權限的團隊成員，你開口時，它也能改用你的身分幫你辦事。簡單說，它既是隊友，也可以當你的代理人。
  • 26:17 bot 有共用的 team memory store，使用越多就學得越多
    ↳ team memory store 是全團隊共用的記憶庫。大家跟 bot 互動越多，它記住的團隊知識就越多，越用越懂這個團隊的狀況。
  • 26:47 例子：data bot 答錯時，資料分析師 Sally 糾正它（例如指出查錯了 table），bot 通常會存成記憶，下次就能拿到正確資訊
    ↳ 舉例來說，負責資料的 bot 答錯時，資料分析師 Sally 指出它查錯了資料表（table），bot 通常會把這次糾正記下來。下次有人問類似問題，就能拿到正確答案。
  • 27:18 目前需使用 cursor teams 或 enterprise linked account 的 GrokBot 才能用 Team bots
    ↳ 目前 Team bots 只開放給特定帳號：要用 cursor teams 或 enterprise（企業版）帳號連結的 GrokBot 才能使用。
  • 27:18 幾週後 SuperGrok teams 使用者也能使用；個人使用者版本也在開發中
    ↳ 影片說幾週後，SuperGrok teams（團隊方案）的用戶也能使用，個人用的版本也在開發中，但沒有說確切的上線時間。
  • 27:18 目前必須在同一個 team，因此權限較寬鬆；之後可能推出權限較受限、但不同 team 也能用的版本
    ↳ 現在大家必須在同一個 team 裡才能共用 bot，所以權限設得比較寬鬆。之後可能推出跨 team 也能用、但權限管得比較嚴的版本。
  • 27:56 DataBot 的用途包括回答 data science 問題、查看進度狀態、追蹤營收、追蹤產品使用量
    ↳ DataBot 是處理數據的 bot，可以回答 data science（資料科學、數據分析）的問題，也能查進度、追蹤營收，以及看產品被使用的情況。
  • 28:31 Team bots 之間可以互相溝通，在 Slack 上特別常見
    ↳ 不只人可以找 bot，bot 和 bot 之間也能互相溝通、互相轉問題。這種情況在 Slack 上特別常見。
  • 28:31 例子：deal desk bot 負責分流 GTM 的所有請求，遇到法律問題時會在 Slack tag legal bot，由 legal bot 回答
    ↳ deal desk bot 負責接所有業務銷售相關的請求，碰到法律問題就在 Slack 上 tag legal bot，由法務 bot 回答，就像同事把問題轉給負責的專人。
  • 29:01 某人讓 bot 跑很長的任務時，不會卡住其他人；bot 共用 context 與 memories，但每個人有各自的 session
    ↳ session 是你和 bot 之間一段獨立的對話。有人叫 bot 跑很久的任務，其他人不用排隊等；大家共用背景資訊和記憶，但各自的對話分開進行。
  • 29:01 bot 能同時在多個地方回應，這點比通常一次只能做一件事的真人隊友好一些
    ↳ 真人同事通常一次只能處理一件事，bot 卻可以同時在好幾個頻道、好幾段對話裡回應，這點比真人方便。
  • 29:33 加入後的 team bots 可以在 GrokBot 或 Slack 中對話；之後也會支援 Microsoft Teams
    ↳ 加進來的 team bots 可以在 GrokBot 裡對話，也可以在 Slack 裡對話。之後也會支援 Microsoft Teams，也就是微軟的工作通訊軟體。
  • 30:06 第三部分介紹 voice mode：GrokBot 介面上有一個語音圖示，點下去就能用說的跟 bot 對話
    ↳ 影片第三部分介紹 voice mode，也就是語音模式。GrokBot 介面上有個語音圖示，按下去就能直接用說的跟 bot 對話。
  • 30:37 講者喜歡每天早上開車上班時用 voice mode；設計靈感來自 Slack huddle，或打電話問同事一個簡短問題
    ↳ 講者自己喜歡在早上開車上班時用。設計概念來自 Slack huddle（Slack 內建的快速語音通話），就像臨時打電話給同事問個小問題。
  • 30:37 voice mode 是與 bot 的雙向（bidirectional）語音對話，可以很短，也可以很長
    ↳ bidirectional 是雙向的意思：你用說的，bot 也用聲音回你，像真的在講電話。對話可以問一句就結束，也可以聊很久。
  • 31:10 不想打字或不能打字時，可以透過語音和 bot 進行快速、高頻寬的對話
    ↳ 不想打字或沒辦法打字時，用說的就能和 bot 快速來回。「高頻寬」在這裡指短時間內能交換很多資訊，說話通常比打字快。
  • 31:40 示範用的是虛構航空公司 Flylo Airlines 的 team bots：PM Pete、chief of staff Cora、data scientist Ashley、designer Pixel、Emily，以及一個工程團隊
    ↳ 示範用的是虛構的 Flylo Airlines（航空公司），裡面有一組各有角色的 bot：產品經理 Pete、幕僚長 Cora、資料科學家 Ashley、設計師 Pixel、Emily，還有一個工程團隊。
  • 31:40 示範情境是這組 bots 正在一起分析行動版購票漏斗（mobile ticket funnel）
    ↳ funnel（漏斗）是顧客從進來到完成購買的流程，每一步都可能有人中途離開。示範情境是這組 bot 一起分析用手機買機票的流程。
  • 32:10 voice mode 支援所有已連接到 GrokBot 的 connectors，例如示範中 Cora 去檢查 Slack
    ↳ 用語音的時候，已經接到 GrokBot 的各種 connectors 都照樣能用。例如示範中請 Cora 去查 Slack，它就會去查。
  • 32:10 平常在 GrokBot 打字能做的事，都可以改用語音完成
    ↳ 語音不是陽春版。平常在 GrokBot 打字能叫它做的事，都可以改成用說的。
  • 32:46 講者認為 voice mode 回應很快：說話者一停下來，bot 幾乎立刻回應，甚至比跟真人開 huddle 還快
    ↳ 講者覺得語音模式反應很快：你一說完，bot 幾乎馬上接話，甚至比跟真人開 huddle 還快。
  • 32:46 示範中 Cora 主動詢問是否要把檢查範圍擴大到 email 和 calendar
    ↳ 示範中 Cora 不只是照指令做，還主動問要不要把查找範圍擴大到 email 和行事曆，像個會多想一步的助理。
  • 33:17 voice mode 設定可選多種聲音（由 Grok voice APIs 提供），也可調整說話速度
    ↳ 設定裡可以挑不同的聲音，這些聲音由 Grok voice APIs 提供（API 是讓程式互相呼叫功能的介面）。說話速度也可以調快或調慢。
  • 33:17 也可以更改語言，bot 會用你選的語言跟你說話
    ↳ 也可以更換語言，bot 就會用你選的語言跟你說話。設定時可以看看清單裡有沒有你想用的語言。
  • 33:48 現場示範時 Cora 卡在那次查詢，講者改請它做別的事
    ↳ 現場示範時，Cora 在那次查詢卡住了，講者就改請它做別的事。這說明功能還很新，現場也可能卡住。
📘 術語
Team bots（團隊 bot）：多人協作時使用的 bot，有共用的 context 與記憶，可加進 Slack，也能代表個人做事
admin approval（管理員審核）：部分 Slack workspace 要由 admin 核准，bot 才能加入
connector / integration（連接器／整合）：把 Slack 等服務連到 GrokBot 的設定，加入後會自動建立連線
triage（分流）：當第一線回答提問頻道的問題，必要時轉交給其他 bot
sources of truth（可信資料來源）：bot 作答的依據，可由人審核、監控並長期 eval
eval（評估）：字幕提到可以長期對 bot 的答案做 eval，沒有進一步解釋
credentials（憑證）：bot 會用跟它說話那個人的 credentials 代表他做事；bot 本身也有自己的 credentials
team memory store（團隊共用記憶庫）：讓 bot 隨使用學習，例如記住被糾正的內容
session（工作階段）：每個人與 bot 各有各的 session，所以長任務不會卡住其他人
GTM (go to market)（市場推廣）：字幕中的 GTM helper、go to market bot 屬於這類用途的 bot
deal desk bot（交易處理 bot）：負責分流 GTM 的所有請求，法律問題會轉給 legal bot
voice mode（語音模式）：在 GrokBot 中與 bot 進行雙向語音對話的功能
Slack huddle（Slack 語音通話）：voice mode 的設計靈感，像找同事快速通話問問題
bidirectional（雙向）：指 voice mode 是你和 bot 雙方都能說話的語音對話
funnel（漏斗）：讓想購買的顧客順利走完流程並完成購買，例子是 mobile ticket funnel
Grok voice APIs（Grok 語音 API）：voice mode 多種聲音背後使用的技術
✏️ 小考一題

根據影片，如果有一位使用者讓 team bot 執行一個很長的任務，其他人還能同時跟這個 bot 對話嗎？

A. 不行，其他人必須改用 voice mode 才能對話B. 可以，但必須先由 Slack admin 核准C. 可以，因為每個人有自己的 session，bot 能同時在多處回應D. 不行，bot 一次只能處理一個人的任務
看答案
答案：C。[29:01] 字幕說長任務不會擋住其他人，bot 共用 context 與 memories，但各自有 session，能同時在兩個地方回應。
