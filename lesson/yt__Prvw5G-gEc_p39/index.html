🧑‍🏫 這是 Grok 團隊連續三天直播做產品的最後一段。他們用一群 bot 從零做出一款網頁對戰遊戲並正式上線，這段回顧上線成果、修了哪些 bug，也聊到創業的心得。想用 AI 自己做點東西的人，可以從這段看到「做得出來」和「有人要用」差在哪裡。

  • 451:00 主持人的「cheater bot」讓分數不升反降：從 986 掉到 956，排行榜上還輸給同事
    ↳ bot 是自動執行任務的程式。主持人做了一個想作弊的 cheater bot，結果分數從 986 掉到 956，在 leaderboard（排行榜）上還輸給同事。想走捷徑反而表現更差。
  • 451:33 新增了 rules endpoint，可以叫自己的 bot 去讀規則來學怎麼玩；到第三天下午 4 點才終於有遊戲教學
    ↳ rules endpoint 是專門放遊戲規則的網址，bot 可以自己去讀、學會怎麼玩。不過直到第三天下午 4 點才有教學，在那之前玩家都只能自己摸索。
  • 451:33 規則頁面現在對 agent 友善：rules.md 可以正常顯示，也有提供給 LLM 讀的文字（agent 需要先驗證身分）
    ↳ agent 是能自己讀資料、自己行動的 AI 助理；LLM 是 Grok、ChatGPT 這類大型語言模型。規則頁現在有 rules.md 純文字版給它們讀，不過 agent 要先驗證身分。
  • 452:03 在 Google 搜尋 ThursdayArena 或 Thursday space arena，他們的遊戲已經排在第一筆，沒有花錢；SEO 文案「free browser auto battler」是 Cursor 自動選的
    ↳ SEO 是讓網頁在搜尋結果排前面的技巧，AEO 則是讓 AI 回答問題時會提到你。他們沒花錢就排上 Google 第一，連文案都是 AI 寫程式工具 Cursor 自己挑的。
  • 452:34 主持人新建一個 bot，指令是「讀這份規則，學會怎麼贏」
    ↳ 指令只有一句「讀這份規則，學會怎麼贏」，沒有教任何細節。意思是現在可以直接把目標交給 bot，讓它自己研究要怎麼達成。
  • 453:10 有人把自動修 bug 的工具設成 YOLO 模式，要輸入 /potato mode 開啟全自動駕駛（autopilot）
    ↳ YOLO 模式是不先問人、直接動手改的設定。輸入 /potato mode 就會開啟 autopilot（全自動駕駛），修 bug 的工具會自己找問題、自己修好。
  • 453:47 bot 做的三天回顧吐槽他們「13 PRs, no ICP」（開了 13 個 PR，卻沒有目標客群）
    ↳ PR（pull request）是「我改好程式了，請合併進去」的申請；ICP 是理想客戶輪廓，也就是產品要賣給誰。bot 吐槽他們程式改得很勤，卻沒想清楚客人是誰。
  • 453:47 三天的經過：第 1 天想做真實世界的生意，訪談來賓後發現太難；第 2 天改做遊戲工作室；第 3 天正式上線
    ↳ 第 1 天想做真實世界的生意，訪談來賓後發現太難；第 2 天改做遊戲工作室；第 3 天上線。重點是發現卡住就換方向，而不是硬撐下去。
  • 454:17 遊戲已經有 4.5K 場對戰。這些數字是 bot 自己上 X 查到的，還在 TL draw 上畫圖整理
    ↳ 遊戲已經累積約 4,500 場對戰。這個數字是 bot 自己上 X（原本的 Twitter）查到的，還在 TL draw 這個線上白板上畫圖整理。
  • 454:17 變現方式：遊戲裡有 billboard 廣告位和 leaderboard 廣告位，品牌可以買來曝光
    ↳ monetization 就是讓產品賺錢。他們在遊戲畫面上放 billboard（看板）和排行榜廣告位賣給品牌，就像球場邊的看板廣告一樣。
  • 454:53 修好了勝敗比的 bug；另外建了一套收集 App 內回饋的系統，有電話回饋和文字回饋兩種
    ↳ 勝敗比算錯的 bug 已經修好。另外做了一套收集 App 內回饋的系統，玩家可以打電話講，也可以打字留言，問題就能直接回到團隊手上。
  • 455:26 主持人排第 82 名，自嘲他們得學會玩自己的遊戲
    ↳ 主持人在自己做的遊戲裡只排第 82 名，自嘲得先學會玩自家遊戲。做產品的人不一定最會用自己的產品，所以更需要聽玩家的回饋。
  • 455:26 目前有 3 位 diamond 玩家，「Ari, the monk」整天都排第一；有玩家反映 Elo 計算有問題，團隊會再檢查 Elo 邏輯
    ↳ Elo 是西洋棋常用的積分制，贏了強的對手加分比較多。目前有 3 位 diamond（高段位）玩家，Ari, the monk 整天都排第一；有人反映分數算得怪，團隊會再檢查。
  • 455:57 開 GitHub repo 的寫入權限給 Eric，因為只有 Eric 需要發 PR（其他人都不用手寫程式碼）
    ↳ GitHub repo 是放程式碼的線上倉庫，有寫入權限才能改裡面的東西。只開給 Eric，因為只有他需要發 PR，其他人都不用自己手寫程式。
  • 456:58 團隊開了幾個 Slack 頻道：marketing、socials、metrics、bug reports、ad bids；廣告競標功能還沒上線，所以 ad bids 頻道目前沒有訊息
    ↳ Slack 是團隊聊天工具，頻道就像分主題的群組。他們開了行銷、社群、數據、bug 回報、廣告競標等頻道；競標功能還沒上線，所以 ad bids 頻道還是空的。
  • 457:31 反思：創業要做的事很多，包括開發產品、驗證點子、GTM（go to market）、變現，還有上線後的維護與收集回饋
    ↳ GTM（go to market）是把產品推上市場、讓人知道並開始用的計畫。他們反思，創業不只是寫程式，還要驗證點子、推廣、賺錢，上線後也要持續維護。
  • 458:07 心得一：一旦大家都認同某個點子、開始做 MVP，進度就快很多，不再卡在反覆討論點子
    ↳ MVP 是最小可行產品，也就是先做出最陽春但能用的版本去試水溫。大家一旦對點子點頭、開始動手，進度就快很多，不會一直開會繞圈。
  • 458:43 心得二：他們靠直播觀眾就有流量，但最難的是讓人在乎你的產品；如果不是在直播，可能根本沒人會玩這個遊戲
    ↳ 他們有直播觀眾撐流量，但最難的是讓人真心在乎這個產品；如果不是在直播，可能根本沒人會來玩。東西做出來不難，難的是讓人想用。
  • 458:43 能讓人興奮的點子（像宣布這場直播時反應熱烈）就是一門生意的起點
    ↳ 宣布這場直播時大家反應很熱烈，這種讓人興奮的反應本身就是做生意的起點：先有人在乎，後面的事才做得起來。
  • 459:17 前幾天和大公司員工的對談，原本以為用不上，結果其實很相關，例如和營收營運團隊的 Matt 討論怎麼建立 growth playbook
    ↳ growth playbook 是一套讓用戶持續變多的固定做法。本來以為和大公司員工的對談用不上，結果很相關，例如和營收營運團隊的 Matt 聊怎麼建立這套做法。
  • 459:17 growth 點子：只要有人在 X 上追蹤他們，就傳 DM 邀請對方來玩這個遊戲
    ↳ DM 就是私訊。做法很直接：只要有人在 X 上追蹤他們，就私訊邀請對方來玩。會追蹤的人本來就有點興趣，是現成的潛在玩家。
  • 459:50 合作模式：去找代管遊戲或發行遊戲的公司，爭取被放進它們的推薦清單
    ↳ 去找代管或發行遊戲的公司談合作，爭取被放進它們的推薦清單。等於借別人的平台和玩家群曝光，不必自己從零開始找人。
  • 459:50 一般的商業 playbook 都適用：需要 sales、partnerships、revenue operations；小公司可能一個人就包辦三個角色
    ↳ sales 是業務銷售，partnerships 是找夥伴合作，revenue operations 是管營收流程和數據的後勤。一般公司那套做法都適用，只是小公司可能一個人全包。
  • 460:23 要先由人親自去發現問題、想出解法，再把解法變成 bot 永遠跑下去；這是用 Grokbots 經營公司的新模式
    ↳ 先由人親自發現問題、想出解法，確定有效之後，再交給 bot 一直自動跑下去。人負責想，bot 負責重複做，這就是他們說的用 Grokbots 經營公司的新模式。
  • 460:58 有 bot 幫忙自動化時，優化自己的工作流程（怎麼把事情做完）威力很大，能快速迭代、推出下一個遊戲或 App
    ↳ 有 bot 幫忙的時候，最值得花力氣的是整理自己「怎麼把事做完」的流程。流程順了，bot 就能照著快速重做，更快推出下一個遊戲或 App。
  • 461:29 做產品不只是一開始華麗的上線，更要靠 flywheel 持續改進
    ↳ flywheel（飛輪）是一種一開始難推、越轉越順的循環：收回饋、改進、吸引更多人、再收到更多回饋。產品要成功靠的是這個循環，不是上線那天的熱鬧。
  • 461:29 要懂得克制：有了 AI 什麼都做得出來，但功能多達上百萬個的產品不見得好
    ↳ 有了 AI，想加什麼功能幾乎都做得出來，所以更要克制。功能塞越多不代表越好，反而可能讓人不知道該怎麼用。
  • 462:02 內部常討論的心態：永遠想著可以從產品拿掉什麼，讓它更簡單、更好用
    ↳ 他們內部常問的是「還能拿掉什麼」，而不是「還能加什麼」。少一個按鈕、少一個步驟，產品通常就更簡單好用。
  • 462:02 原本白板上規劃了複雜的角色屬性表（stat blocks）和多種戰場，最後砍掉這些，只專注在核心循環（core loop），遊戲才能在今天上線
    ↳ stat blocks 是角色的屬性數值表；core loop 是玩家一再重複、覺得好玩的核心流程。他們砍掉屬性表和多種戰場，只顧核心玩法，遊戲才趕得上今天上線。
📘 術語
rules endpoint（規則端點）：新增的規則頁面，可以叫 bot 去讀規則、學習怎麼玩
AEO / SEO（答案引擎優化／搜尋引擎優化）：字幕只說他們「AEO SEO」做得好，在 Google 搜尋排第一，而且沒花錢
PR（Pull Request（合併請求））：字幕說 Eric 要發 PR，所以要開 repo 寫入權限給他
ICP（理想客群）：bot 吐槽他們「13 PRs, no ICP」，字幕沒有另外解釋
Elo（Elo 積分）：排名積分系統，玩家反映有問題，團隊要檢查它的邏輯
GTM (go to market)（市場進入策略）：字幕把它列為創業必須考慮的工作之一
MVP（最小可行產品）：認同點子後就開始做 MVP，進度會快很多
monetization（變現）：例如遊戲裡的 billboard 和 leaderboard 廣告位
revenue operations（營收營運）：Matt 所在的團隊；和 sales、partnerships 並列為商業 playbook 的一部分
flywheel（飛輪）：做產品要持續改進，讓飛輪轉起來，不只看一開始的上線
core loop（核心循環）：砍掉複雜功能後專注的重點，也是遊戲能上線的關鍵

團隊認為，是什麼讓這款遊戲能在第三天順利上線？

A. 新增更多戰場和角色屬性，讓遊戲更豐富B. 先花錢打 Google 廣告拉到第一批玩家C. 砍掉複雜的角色屬性表和多種戰場，專注在核心循環D. 等 Elo 系統完全修好之後再上線
