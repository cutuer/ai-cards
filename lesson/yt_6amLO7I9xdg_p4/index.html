🧑‍🏫 這是 Code with Claude London 2026 開場主題演講的最後一段。前半介紹 Claude Code 的新功能，以及 Shopify、Mercado Libre 等企業怎麼用它。後半由 Claude Code 的創造者現場示範：先讓 AI 寫完程式後自己檢查，再用 routines 讓 AI 自動接手工作。想知道「AI 寫程式」接下來會往哪走，看這段最清楚。

  • 34:50 許多企業已全面導入 Claude Code。Anthropic 內部的工程組織規模大幅擴張，每位工程師的 PR 數量仍增加了 200%
    ↳ 很多企業已經整間公司導入 Claude Code。Anthropic 工程團隊擴大很多，每人送出的 PR（把改好的程式送去審核、再併進正式版本的申請）還多了 200%。人變多了，效率反而更高。
  • 35:21 使用者希望少花時間在 code review，所以推出 code review 產品。它會派出一組 agents 檢查所有程式碼變更和相關檔案，抓出重大 bug
    ↳ 程式寫得快，審查就變成卡關的地方。code review（上線前檢查別人改的程式）產品會派出一組 agents（能自己分工做事的 AI 助手），看過所有改動和相關檔案，專門抓嚴重的 bug。
  • 35:21 每天有數千家公司使用這個 code review 產品，Anthropic 內部每個團隊都在用
    ↳ 這個產品已經在實際使用：每天有數千家公司在用，Anthropic 自己每個團隊也都在用。
  • 35:52 為了讓使用者隨時隨地寫程式，推出 remote control 和 iOS、Android 版 Claude Code，在哪裡都能派出任務，不必綁在筆電或辦公桌前
    ↳ remote control 讓你不在電腦前也能操作 Claude Code，再加上手機版 App，通勤或排隊時也能交代任務讓它去做，不用守在筆電或辦公桌前。
  • 36:22 推出 autofix：它會監聽 flaky CI 測試、code review 留言、merge conflict 等事件並主動修好，讓 PR 保持綠燈
    ↳ autofix 會盯著 PR：遇到 CI（每次改動自動跑的測試）時好時壞的失敗、審查留言、merge conflict（兩人改到同一處，無法自動合併），它會自己修好，讓 PR 維持綠燈。
  • 36:52 推出 routines：設定一次後，Claude Code 可以依排程執行，也可以由 webhook 或 API 請求觸發，適合處理新 ticket 和客戶回報的 bug
    ↳ routines 是設定一次就會自動跑的工作。可以定時跑，也可以在 webhook（事情發生時自動送出的通知）或 API（程式之間互相呼叫的接口）請求進來時啟動，適合接新工單和客戶回報的 bug。
  • 36:52 推出 Cloud Security（字幕寫法）：程式碼產出量太大，安全團隊跟不上，所以它會在夜間掃描 codebase，依嚴重程度標出漏洞
    ↳ AI 產出程式的量太大，資安人員看不完。Cloud Security 會在晚上掃過整個 codebase（專案的全部程式碼），把找到的漏洞依嚴重程度排好，讓人知道要先處理哪個。
  • 37:24 Cloud Security 標出的每個漏洞都可以直接啟動 Claude Code 去處理
    ↳ 它找到漏洞後不只列清單：每一個漏洞都能直接交給 Claude Code 去修，從發現到修補連成一條線。
  • 37:24 這些 primitives 可以互相組合，方便因應未來的工程工作方式。以上功能個人今天就能開始用
    ↳ primitives 指基本積木，這裡就是上面這些功能。它們可以自由組合，例如掃出漏洞後交給 Claude Code 修，再讓 autofix 顧好 PR。這些功能個人今天就能開始用。
  • 37:54 Shopify 案例：全公司都在用 Claude Code，包括工程師，以及產品經理、設計師、資料科學家等非工程人員
    ↳ Shopify（知名的電商開店平台）不只工程師在用，產品經理、設計師、資料科學家這些平常不寫程式的人也在用，表示非工程背景的人也用得上手。
  • 37:54 Shopify 也把 Claude Code 直接帶進自家平台，大規模建置工具
    ↳ Shopify 不只內部自己用，還把 Claude Code 整合進自家平台，拿它大量打造各種工具。
  • 38:26 Shopify 的 applied AI 總監 Andrew McNamera 說速度快得驚人，Claude Code 改變了他們打造內部工具的方式
    ↳ Andrew McNamera 負責 applied AI（把 AI 實際用在業務上）。他說速度快到驚人，他們打造內部工具的方式整個被改變了。
  • 38:26 Marcato Libre（字幕拼法）是拉丁美洲最受歡迎的電商網站，買家超過 1 億人，23,000 名工程師的組織都靠 Claude Code 運作
    ↳ Marcato Libre（一般寫作 Mercado Libre）是拉丁美洲最受歡迎的電商網站，買家超過 1 億人。23,000 名工程師的整個組織都靠 Claude Code 在運作。
  • 38:58 Marcato Libre 的工程師讓 agents 處理沒人有空修的技術債。在人類監督下已審查超過 50 萬個 PR，並現代化超過 9,000 個 app
    ↳ tech debt（技術債）是過去趕進度留下、一直沒空整理的舊程式。他們交給 agents 處理、由人監督，已經審查超過 50 萬個 PR，並把超過 9,000 個 app 改成現代的寫法。
  • 38:58 技術負責人 Oscar Mowen 的目標是在今年 Q3 以前，在完全由 agent 驅動的 PR 流程中達到 90% 自主寫程式
    ↳ 技術負責人 Oscar Mowen 的目標是在今年 Q3（第三季，7 到 9 月）以前，在完全由 agent 跑的 PR 流程裡，讓九成的程式碼由 AI 自主寫完。
  • 38:58 講者最喜歡的細節：多年沒 commit 程式碼的經理和 VP，現在又開始出貨了
    ↳ commit 是把程式修改正式存進專案紀錄。講者最喜歡的細節是：很多年沒 commit 過的經理和 VP（副總），現在又自己動手做東西並上線了。
  • 39:30 Claude Code 讓過去十年都在開審查會、排 roadmap 的人重新回來寫程式。整個產業有數百萬開發者出貨更多產品，品質更高、速度更快
    ↳ 過去十年都在開審查會、排 roadmap（產品開發時程表）的主管，現在又回來寫程式了。講者說整個產業有數百萬開發者出貨更多產品，品質更好、速度也更快。
  • 39:30 主持人請出 Claude Code 的創造者 Boris Churnney（字幕拼法）上台示範
    ↳ 主持人請出 Claude Code 的創造者 Boris Churnney（一般寫作 Boris Cherny）上台親自示範。
  • 40:14 Boris 說用 Claude Code 至今仍有第一次寫出計算機程式時的感覺。Anthropic 內部整天在 Slack 分享工程師用 Claude Code 做出的東西
    ↳ Boris 說，用 Claude Code 到現在還有第一次寫出計算機程式時的那種興奮感。Anthropic 內部的 Slack（公司聊天工具）上整天都有人在分享用它做出來的東西。
  • 40:45 Demo 情境：假設你是支付基礎設施公司 Acme Pay 的工程師，從 Claude Code desktop app 開始，先處理單一任務
    ↳ 示範情境：你是支付公司 Acme Pay（示範用的虛構公司）的工程師，打開 Claude Code 桌面版 App，先從交代一件事開始。
  • 40:45 任務是在 merchant dashboard 加入退款功能，內容包括 idempotency（避免重複的 webhook 造成重複退款）、多幣別處理、給合規團隊的 audit log
    ↳ 任務是在商家後台加上退款功能，要顧好三件事：idempotency（同一個通知重送好幾次也只算一次，不會重複退款）、多種貨幣，以及給合規團隊查核用的 audit log（操作紀錄）。
  • 41:17 Claude 寫完之後會自己驗證：在瀏覽器開啟 dashboard 觸發退款，發現 modal 在成功提示出現前就關掉了，這是真實的 edge case
    ↳ Claude 寫完後會自己開瀏覽器按退款測試，結果發現 modal（跳出來的小視窗）在「成功」提示出現前就關掉了。這是真的會碰到的 edge case（少見但會出錯的特殊狀況）。
  • 41:17 Claude 追查出原因是 optimistic update 裡的 race condition，修好後先在瀏覽器確認真的能用，才把任務標為完成
    ↳ 原因是 race condition（兩個動作搶先後順序而出錯），發生在 optimistic update（畫面先假設成功就更新）裡。修好之後它先在瀏覽器確認真的能用，才把任務標成完成。
  • 41:49 Desktop app 可以看到所有 Claude Code sessions：哪些在執行、哪些需要你輸入、哪些的 PR 已經 merge 並關閉。多個 sessions 平行執行和管理
    ↳ session 就是一個進行中的 Claude Code 工作。桌面版能一次看到全部：哪些在跑、哪些在等你回覆、哪些的 PR 已經合併結案，好幾個可以同時平行進行。
  • 42:20 同步寫程式現在只佔一小部分，未來會有更多程式碼以非同步方式寫成
    ↳ 「同步」是你在旁邊盯著 AI 一來一往地寫；「非同步」是交代完就去做別的，讓它自己做。講者認為前者現在只佔一小部分，未來會有更多程式用後者寫成。
  • 42:20 這就是為什麼一直強調驗證：Claude 能檢查自己的成果，你就可以讓它跑著、自己去做別的事，回來時拿到完整可用的結果
    ↳ 非同步要行得通，前提是驗證：Claude 能自己檢查成果，你才敢放著讓它跑、自己去做別的事，回來時拿到的是能用的成品，而不是半成品。
  • 42:53 Boris 現在很多程式碼是 routines 寫的：他不自己下 prompt，而是建立一個會下 prompt 的 routine
    ↳ Boris 現在很多程式不是他親自下 prompt（給 AI 的指令）寫出來的。他改成建立一個 routine，由 routine 去對 Claude Code 下 prompt。
  • 42:53 比喻：routine 就像 higher order function，是一種「higher order prompt」
    ↳ higher order function 是程式裡「能產生或操作其他函式的函式」。套到這裡，routine 就是「會產生 prompt 的 prompt」，你只要管好上面那一層。
  • 42:53 例子：隊友半夜發了一個 GitHub issue，監看 repo 的 routine 以非同步方式接手，並啟動處理工作
    ↳ 例如隊友半夜在 GitHub（放程式碼的協作平台）開了一個 issue（問題回報單），一直盯著專案的 routine 就會自動接手開始處理，不用等人上班。
  • 43:24 開發者可以用 routines 設定非同步自動化，一覺醒來就有可以 merge 的 PR
    ↳ 開發者可以用 routines 把這類自動化設好，早上醒來就有已經寫好、可以直接合併的 PR 在等著。
  • 43:24 Routines 可以依排程執行，也可以由 webhook 或任意 API 呼叫觸發；可以在本機跑，也可以在遠端雲端運算資源上跑
    ↳ routines 有三種啟動方式：固定排程、webhook、任何 API 呼叫。可以在自己的電腦上跑，也可以放到雲端的遠端機器上跑。
  • 43:59 CI autofix 會盯著前一個 session 開的 PR，一路顧到上 production：自動處理 code review 和安全審查的留言、修 CI、遇到 merge conflict 自動 rebase
    ↳ CI autofix 會接手前一個 session 開的 PR，顧到上 production（正式上線環境）為止：回應審查和資安留言、修好測試，遇到衝突就自動 rebase（把修改重新接到最新版本上）。
  • 43:59 Demo 中 CI 因網路逾時失敗，routine 醒來判斷是已知的基礎設施問題，重新執行 job
    ↳ 示範中 CI 因為網路逾時失敗了。routine 自己醒來，判斷這是已知的基礎設施問題、不是程式寫錯，就重新跑一次。
  • 43:59 不過在 Claude Code 自己的 codebase 裡，他們會要求它修根本原因，而不只是重試
    ↳ 不過在 Claude Code 自己的專案裡，他們要求更嚴：不能只按重試過關，要找出根本原因修掉。
  • 44:30 CI 變綠燈，負責這個 PR 的工程師完全不會看到紅色叉叉，這份工作也就不用他處理
    ↳ 最後 CI 變成綠燈，負責這個 PR 的工程師從頭到尾沒看到紅色叉叉（失敗標記），這件雜事完全不用自己處理。
  • 44:30 核心轉變：預設不再是「我去 prompt Claude Code」，而是「讓 Claude 去 prompt Claude Code」
    ↳ 核心的轉變是：以前預設是你去對 Claude Code 下指令，現在預設是讓 Claude 去對 Claude Code 下指令。
  • 45:01 Demo 裡所有功能今天都能用，包括 routines 和 Claude desktop app 的最新更新
    ↳ 示範裡的所有功能今天都能用，包括 routines 和 Claude 桌面版的最新更新，不只是未來的概念展示。
  • 45:01 總結：Lisa 講的能力曲線、Angela 和 Caitlyn 講的在自己掌控的基礎設施上跑的 agents、Cat 和 Boris 的展示，是同一個故事的三個層次
    ↳ 總結成三個層次：Lisa 講 AI 能力進步的曲線、Angela 和 Caitlyn 講在自己掌控的基礎設施（主機、網路等底層環境）上跑 agents、Cat 和 Boris 做實際示範，講的是同一個故事。
  • 45:31 能力已經到位，剩下的差距在於多快把它用起來
    ↳ 講者的看法是：AI 的能力已經夠了，現在的差距在於誰能更快把它用進實際工作。

📘 術語
PR (pull request)（合併請求）：字幕沒有定義。提到每位工程師的 PR 數增加 200%，以及 PR 要保持綠燈
code review（程式碼審查）：新產品會派一組 agents 檢查所有程式碼變更與相關檔案，抓重大 bug
remote control（遠端控制）：跟 iOS、Android 版 Claude Code 一起推出，讓你在任何地方都能派出任務
autofix / CI autofix（自動修復）：監聽 flaky CI、review 留言、merge conflict 等事件並主動修好，讓 PR 保持綠燈
flaky CI tests（不穩定的 CI 測試）：字幕沒有定義，列為開發者得一直顧著 PR 的原因之一
merge conflict（合併衝突）：字幕沒有定義。CI autofix 遇到它會自動 rebase
rebase（重新定基）：字幕沒有定義，只說有 merge conflict 時 CI autofix 會自動 rebase
routines（例行自動化）：設定一次後，可依排程、webhook 或 API 請求觸發 Claude Code，就像「higher order prompt」
webhook（網路鉤子）：字幕沒有定義，是觸發 routines 的方式之一
higher order function（高階函式）：Boris 用來比喻 routines：routine 是會幫你下 prompt 的 prompt
Cloud Security（字幕寫法）（安全掃描產品）：在夜間掃描 codebase，依嚴重程度標出漏洞，可直接啟動 Claude Code 處理
primitives（基本元件）：指上面這些功能，它們可以互相組合，方便因應未來的工程工作方式
tech debt（技術債）：大家一直沒空修的東西，Marcato Libre 讓 agents 去處理
idempotency（冪等性）：讓重複送來的 webhook 不會重複退款給商家
audit logging（稽核日誌）：為合規團隊記錄的日誌
race condition（競態條件）：Demo 中 modal 提早關閉的 bug 根源，出在 optimistic update 裡
optimistic update（樂觀更新）：字幕沒有定義，只說 race condition 出在這裡
async / synchronous coding（非同步／同步寫程式）：同步寫程式只佔一小部分，未來會有更多程式碼以非同步方式寫成
verification（驗證）：Claude 能檢查自己的成果，你就能讓它跑著、回來拿到完整可用的結果
✏️ 小考一題

根據演講，routines 可以用哪些方式觸發？

A. 只能在每天夜間的安全掃描後觸發B. 只能由 GitHub issue 觸發C. 只能在本機手動按按鈕啟動D. 依排程、webhook 或任意 API 呼叫
看答案
答案：D。[43:24] 說 routines 可以依排程執行，也可以由 webhook 或任意 API 呼叫觸發，而且可在本機或遠端雲端運算資源上跑（[36:52] 也有相同說法）
