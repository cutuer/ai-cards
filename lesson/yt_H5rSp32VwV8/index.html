🧑‍🏫 這支 OpenAI 官方示範影片教你在 ChatGPT 裡做一個「每週自動寫報告」的 agent：它會連到 Google Drive 讀資料、算指標、畫圖，每週五自己交出報告。如果你每週都要手動整理同一份數字報表，這支影片示範的就是怎麼把這件事交給 AI 固定去做。

  • 00:05 講者 Harsha 示範建立一個簡單的報告 agent，協助為團隊產出定期的每週報告（weekly readout）
    ↳ 講者 Harsha 要做一個報告 agent。agent 是能自己分步驟完成任務的 AI 助手。weekly readout 是給團隊看的每週成果報告，這個 agent 的工作就是固定產出這份報告。
  • 00:05 第一步：新增資料來源的 connection，本例的資料來源是 Google Drive
    ↳ 第一步是新增一個 connection，也就是讓 agent 能連到你資料存放位置的設定。這個例子連的是 Google Drive，也就是 Google 的雲端硬碟，很多團隊的試算表都放在那裡。
  • 00:05 連接資料來源的好處：agent 可以直接處理資料所在的檔案與試算表，不必每週有人手動搬移資訊
    ↳ 連上以後，agent 可以直接打開原本的檔案和試算表來讀，不用每週有人把數字複製貼上給它。最麻煩、也最容易漏掉的搬資料步驟就省掉了。
  • 00:05 將這個 connection 設為 agent owned，可以把它想成是整合用的 service account
    ↳ 這個連線要設成 agent owned，意思是連線屬於 agent 自己。講者把它比作 service account，也就是專門給系統串接用、不屬於任何一個真人的帳號。
  • 00:35 agent owned 讓 agent 能在排程或背景工作中使用 connection，不必依賴某一個人的設定
    ↳ 這樣設的好處是：排程或在背景自動執行時，agent 用的是自己的連線，不會因為某位同事沒登入、改了設定或離職而斷掉。
  • 00:35 接著可以請 ChatGPT 改善 agent：不必從頭寫每條指令，只要描述想完成的工作，請 agent 讓工作流程更可靠
    ↳ 改進 agent 不用自己一條一條寫規則。直接跟 ChatGPT 說你想完成什麼工作，請它讓 workflow（agent 每次跑的整套流程）更穩定，它會提出建議。
  • 00:35 本例中 ChatGPT 建議建立一個「指標計算」skill（metrics calculation skill）
    ↳ 在這個例子裡，ChatGPT 看完需求後，主動建議加一個「指標計算」skill，專門負責數字要怎麼算。
  • 00:35 Skills 的用處：幫助 agent 遵循團隊的流程、定義與最佳實務
    ↳ skill 是一份可以重複使用的指引，把團隊的做事方法、名詞定義和慣用做法寫下來，讓 agent 照團隊的規矩做事，而不是照它自己的理解。
  • 01:06 本例的 skill 幫 agent 理解哪些指標重要、該如何解讀，以及每週報告該怎麼編排結構
    ↳ 這個 skill 會告訴 agent 哪些指標才是重點、數字變化代表什麼意思，以及報告要分哪幾段、怎麼排。等於把熟手腦中的報告寫法交給它。
  • 01:06 有了 skill，agent 不是每次都臨場發揮，而是有可重複使用的指引來處理每個新任務，讓流程更可靠
    ↳ 沒有 skill 的話，agent 每次可能用不同的算法或格式。有了 skill，每週都照同一套指引處理，結果前後一致，各週之間才能互相比較。
  • 01:06 設定每週執行：排程在每週五執行，並給一則簡單的起始訊息，例如「run analysis」
    ↳ 接著設定排程：每週五自動執行，再給一句簡單的起始訊息，例如「run analysis」（執行分析），當作每次開工的指令。
  • 01:37 排程後 agent 會定期跑同一套報告流程，團隊不用每週記得手動啟動
    ↳ 排好以後，agent 每週會自己跑同一套流程。團隊不需要有人記得週五去啟動它，也不會因為有人忘記而少了一週的報告。
  • 01:37 設定好後可到 activity history 查看 agent 做過的事，讓團隊能掌握 agent 的工作情況
    ↳ activity history 是 agent 的工作紀錄，可以看到它每次做了什麼。自動化不代表放著不管，團隊隨時都能查它有沒有正常運作。
  • 01:37 在 activity history 可以打開某次執行，檢視 agent 的步驟、用了哪些工具，並審閱它產出的結果
    ↳ 點開其中一次執行，可以看到它一步步怎麼做、用了哪些工具，以及最後產出的內容。先確認結果對不對，再拿去用。
  • 01:37 示範的這次執行中，agent 先查看試算表裡的資料
    ↳ 以示範的那次執行為例，agent 的第一步是先讀試算表，搞清楚裡面有哪些資料。
  • 02:08 接著 agent 執行程式碼來計算指標並製作圖表
    ↳ 接著它自己寫程式、跑程式來計算指標並畫出圖表。用程式計算數字，通常比讓 AI 直接估算更可靠。
  • 02:08 最後 agent 把分析彙整成一份報告，可以再分享給團隊
    ↳ 最後它把分析整理成一份報告，可以直接分享給團隊，也就是影片一開始說的每週報告。
📘 術語
connection（連線／連接）：agent 連到資料來源（本例為 Google Drive）的設定，讓它能處理資料所在的檔案與試算表
agent owned（由 agent 擁有）：connection 的一種設定，讓 agent 在排程或背景工作中使用連線，不依賴單一個人的設定
service account（服務帳號）：講者用來比喻 agent owned：可想成整合用的 service account
skill（技能）：幫 agent 遵循團隊流程、定義與最佳實務的可重複使用指引，讓流程更可靠
weekly readout（每週報告）：agent 要為團隊定期產出的每週成果報告
activity history（活動紀錄）：可查看 agent 做過的事，打開某次執行檢視步驟、用到的工具與產出
workflow（工作流程）：agent 每次執行的報告流程，可透過 skill 變得更可靠、可排程重複執行
