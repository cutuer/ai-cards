🧑‍🏫 這支影片在講怎麼挑 Claude 模型才真的省錢。很多人以為「挑最便宜的模型、叫它少想一點」就最省。影片用模型、effort、快取三個因素算給你看：比較聰明的模型有時候反而更便宜。如果你常覺得方案額度不夠用，或者不知道該選哪個模型，這支很值得看。

  • 00:00 選最便宜的模型、用最低 effort，看似最省錢或最省方案用量，但 Claude Fable 5.1 推出後，更聰明的模型完成任務反而可能更便宜
    ↳ 直覺上，挑最便宜的模型、把 effort（模型回答前想多深）調到最低最省。但 Fable 5.1 出來後，聰明的模型一次就做對，總花費反而可能更低。
  • 00:00 影響任務成本的三個因素：模型（model）、effort、快取（cache）
    ↳ 一件工作最後花多少錢，看三件事：用哪個模型、讓它想多深（effort），還有能不能重複利用已經處理過的內容（快取，英文叫 cache）。
  • 00:00 一般來說，模型能力越強，每個 token 的價格越高
    ↳ token 是模型計算文字量的單位，大約是一個字或字的片段，費用就按它算。一般來說，越強的模型，每個 token 越貴。
  • 00:00 比喻：大學生解數學題的步驟比五年級生少；同樣地，更聰明的模型常常用更少的工作量完成任務
    ↳ 同一題數學，大學生幾步就解完，五年級生要繞好幾圈。聰明的模型也一樣，常常用比較少的步驟、比較少的 token 就把事情做完。
  • 00:34 Effort 是模型回答前做多少推理；effort 越高成本越高，但通常結果更好
    ↳ effort 就是模型回答前花多少力氣推理。想得越多，用掉的 token 越多、越貴，但答案通常也越好。這是品質和成本之間的取捨。
  • 00:34 模型在不同請求之間不會記得任何東西，每次送出訊息都要重新處理整段對話
    ↳ 模型沒有記憶。你每傳一則新訊息，它都要把前面整段對話從頭再讀一次，所以對話越長，每次要處理的量就越大。
  • 00:34 Caching 讓模型重複使用已處理過的內容，成本約為原本的十分之一
    ↳ 快取就是把已經讀過的內容先存起來，下次直接拿來用、不必重算。這部分的成本大約只剩原本的十分之一。
  • 00:34 每個 token 的價格只是任務成本的一部分：模型和 effort 決定任務要用多少 token，caching 則幫忙降低成本
    ↳ 只看單價會看走眼。真正的帳單是單價乘上用量：模型和 effort 決定要用掉多少 token，快取則讓重複的部分變便宜。
  • 01:06 以 Claude Fable 5.1 和 5 為例：5.1 每個 token 的價格和 5 相同
    ↳ 拿 Fable 5.1 和上一版 Fable 5 比：兩者每個 token 的標價一樣。所以 5.1 省下的錢不是來自降價。
  • 01:06 在按 token 計費的情況下，5.1 的 cache read 便宜 75%
    ↳ 按 token 計費時，5.1 讀取快取內容（cache read）的價格比 5 便宜 75%。對話越長、重複讀的內容越多，這點就越有感。
  • 01:06 整體而言，一般工作成本約降低 25%，長時間的 agentic 任務最多可降約 45%
    ↳ 加總起來，一般工作大約省 25%。agentic 任務（AI 自己規劃、連續執行很多步驟的工作）如果跑得久，最多可以省約 45%。
  • 01:06 在第三方程式碼 benchmark CursorBench 上，5.1 用 medium effort 的結果與 5 用 max effort 相近，成本約只有五分之一
    ↳ benchmark 是比較模型表現用的標準測驗。在第三方的程式碼測驗 CursorBench 上，5.1 開 medium effort，成績就接近 5 開到最高，花費只有約五分之一。
  • 01:36 該選哪個模型和 effort，取決於你做的工作類型
    ↳ 沒有一個「永遠最划算」的組合。要先看你手上的工作是哪一種，再決定用哪個模型、effort 開多少。
  • 01:36 任務大致分兩類：不受限、開放式的工作，例如深度研究、複雜分析、長時間執行的 agent 工作
    ↳ 第一類是開放式工作：沒有標準答案、範圍會一路延伸，例如深度研究、複雜分析，或讓 AI 自己長時間跑的任務。
  • 01:36 另一類是受限的例行工作，例如摘要文件、草擬 email、從報告中擷取資料
    ↳ 第二類是範圍明確的例行工作，例如摘要一份文件、草擬 email、從報告裡抓出特定數據。做法和結果大致都能預期。
  • 02:07 如果工作多為開放式任務：使用 Fable 5.1 並調整 effort，從 medium 開始，需要時再調高
    ↳ 如果你多半做開放式工作，就用 Fable 5.1。effort 先開 medium（中等），不夠好再往上調，不用一開始就開最高。
  • 02:07 如果工作多為例行任務：繼續用 Opus 或 Sonnet，需要時再改用 Fable
    ↳ 如果多半是例行工作，繼續用 Opus 或 Sonnet（Claude 的另外兩個模型系列）就好，遇到特別難的再換 Fable。
  • 02:07 例行任務用較便宜的模型也能得到相近結果，就不用為任務根本用不到的能力付費
    ↳ 例行工作用便宜的模型，成果也差不多。這時候選貴的模型，等於在為任務根本用不到的能力付錢。
  • 02:07 Subagent 被限定在特定任務上，因此較便宜的模型通常就夠用
    ↳ subagent 是主要的 AI 分派出去、只負責某一小段工作的幫手。因為它的任務範圍很窄，通常用便宜的模型就夠了。
  • 02:37 管理組織 Claude 的 admin 可以為所有人或依角色設定可用的模型和 effort 等級
    ↳ admin 是組織裡管理 Claude 帳號的管理員。他們可以替全公司或特定職務，設定能用哪些模型、effort 最高能開到哪裡。
  • 02:37 三種控制項之一：Model entitlements 決定使用者可以選哪些模型
    ↳ Model entitlements（模型使用權）：決定使用者的選單裡有哪些模型可以選。
  • 02:37 三種控制項之二：Effort caps 設定使用者在某個模型上可選的最高 effort
    ↳ Effort caps（effort 上限）：限制使用者在某個模型上，effort 最多只能開到哪一級，避免成本失控。
  • 02:37 三種控制項之三：Defaults 設定新對話一開始使用的模型和 effort
    ↳ Defaults（預設值）：每次開新對話時自動套用的模型和 effort，使用者不用每次自己調。
  • 02:37 工作以長時間開放式任務為主的角色：可把 Fable 5.1 設為預設，並考慮設定 effort cap
    ↳ 主要做長時間開放式工作的職務，可以把 Fable 5.1 設成預設模型，並考慮加上 effort 上限，控制花費。
  • 03:08 工作多為例行任務的角色：保留 Opus 或 Sonnet 為預設模型，並開放 Fable 的使用權，讓使用者在任務需要時切換
    ↳ 主要做例行工作的職務，預設模型維持 Opus 或 Sonnet，同時開放 Fable 的使用權，讓大家遇到難題時可以自己切換。
  • 03:08 總結一：決定模型和 effort 時，要考慮每個任務的成本，而不是每個 token 的價格
    ↳ 算帳要看「做完一件事總共花多少」，不是看「每個 token 多少錢」。單價高的模型，可能因為做得又快又準，總花費反而更少。
  • 03:08 總結二：依任務類型（長時間開放式或例行）選擇模型
    ↳ 先判斷工作是長時間的開放式工作還是例行工作，再挑模型：前者用 Fable 5.1，後者用 Opus 或 Sonnet。
  • 03:08 總結三：能力較強的模型，先從較低的 effort 開始，需要時再調高
    ↳ 用比較強的模型時，effort 先從低一點開始，結果不夠好再往上加，不要一開始就開到最高。
📘 術語
effort（推理投入程度）：模型回答前做多少推理；越高成本越高，但通常結果更好
cache / caching（快取）：讓模型重複使用已處理過的內容，成本約為十分之一
token（token（計費單位））：字幕以「每 token 價格」計費；模型和 effort 決定任務用多少 token
cache reads（快取讀取）：讀取已快取的內容；Fable 5.1 在按 token 計費時這部分便宜 75%
agentic tasks（agent 型任務）：字幕提到長時間的 agentic 任務，用 5.1 成本最多可降約 45%
CursorBench（CursorBench）：字幕稱其為第三方的程式碼 benchmark
subagent（子代理）：被限定在特定任務上，所以較便宜的模型通常就夠用
Model entitlements（模型使用權）：admin 控制項，決定使用者可以選哪些模型
Effort caps（effort 上限）：admin 控制項，設定使用者在某模型上可選的最高 effort
Defaults（預設值）：admin 控制項，設定新對話一開始使用的模型和 effort
