🧑‍🏫 這支影片的後半段在介紹 Claude Code 最近的新功能。Claude Code 是 Anthropic 推出、讓 Claude 直接在你電腦上寫程式和執行指令的工具。這些新功能有共同的方向：讓 Claude 能同時做好幾件事、記得住之前學到的東西、自己先審一遍程式碼，還能按時間表或在某件事發生時自動開工。就算你不寫程式，看完也能知道現在的 AI 助手能自己做到什麼程度。

  • 12:30 work tree 原本會複製整個 repo 的所有檔案、使用上有很多眉角；團隊把這些眉角整理成對人和 Claude 都更友善的介面
    ↳ work tree 是替同一個專案另開一個獨立的工作資料夾，在裡面改東西不會影響原本那份。以前要把整個 repo（放程式碼的專案庫）整份複製一遍，細節很多，現在團隊把這些麻煩包起來了。
  • 12:30 Claude Code settings 新增一個欄位，可以宣告哪些檔案要在各個 work tree 之間共用，例如 node modules
    ↳ 像 node modules（專案下載來的一大包外部套件）這種檔案很大，放在哪個工作資料夾內容都一樣。現在可以在設定裡指定這類檔案讓大家共用，不用每個資料夾各放一份。
  • 12:30 開新 session 時加上 --worktree，這個 session 就會配一個新的 work tree；也可以直接請 Claude 幫你建 work tree
    ↳ session 是你和 Claude Code 的一次工作對話。啟動時加上 --worktree，它就會在一個新的獨立資料夾裡工作。不想記指令也行，直接跟 Claude 說「幫我開一個」就好。
  • 13:01 Demo 用 Excalidraw，要加兩個功能：新增一種顏色，以及加一個滑桿讓圖形邊角更圓
    ↳ Excalidraw 是一個手繪風格的線上白板工具。示範拿它來同時做兩個互不相干的小改動，剛好可以看出 work tree 好用在哪裡。
  • 13:32 claude -W 是 --worktree 的縮寫；Demo 開了 colors 和 border radius 兩個 work tree，分別下指令「stroke/background 加第六種顏色」和「加滑桿調整 border radius」
    ↳ 打 -W 和打 --worktree 效果一樣。示範開了兩個獨立空間，一個加第六種顏色，一個加調整 border radius（邊角圓的程度）的滑桿，兩邊同時進行。
  • 14:04 Claude 現在有 enter work tree 和 exit work tree 工具，可以自己判斷要不要在隔離環境裡實作新功能（例：「建一個 work tree 來加星形」）
    ↳ tool（工具）是 Claude 可以自己決定要不要使用的功能。有了進出 work tree 的工具，你只要說「開一個 work tree 來加星形」，Claude 就會自己開一個隔離空間去做。
  • 14:36 Demo 裡講得很明確是為了示範；你可以把這個指示寫進 ClaudeMD，不用講這麼明確，Claude 也會知道你的意圖
    ↳ CLAUDE.md 是放在專案裡的說明檔，Claude 每次對話都會先讀。把「做新功能請開 work tree」寫進去，之後就不用每次交代，Claude 會照這個原則做。
  • 14:36 Claude 會先問你什麼時候開始實作；如果選擇離開 work tree，harness 會幫你把 work tree 清掉
    ↳ harness 是包在 AI 模型外面、負責執行工具和管理環境的那套程式。Claude 動手前會先問你什麼時候開始；做完選擇離開，系統會自動把那個臨時資料夾清掉。
  • 15:06 這樣一個長時間執行的 session 就能同時處理很多個 PR
    ↳ PR（pull request）是把改好的程式碼送給別人審核、再合併進專案的申請。因為每個功能都有自己的隔離空間，同一個一直開著的對話就能同時推進好幾個 PR。
  • 15:06 Demo：請 Claude 在背景跑 yarn start 並回報 port；顏色功能跑在 localhost 3003，多了第六種顏色，主 checkout 上原本的版本也還在跑
    ↳ port 可以想成電腦上服務的門牌號碼，localhost 就是你自己這台電腦。新版跑在 3003 號，看得到第六種顏色；原本的版本也同時開著，可以直接並排比較。
  • 16:07 work tree 很適合同時開多個 agent、各自做不同功能
    ↳ agent 是能自己一步一步把事情做完的 AI 助手。同時開好幾個 agent，每個待在自己的 work tree 裡做一個功能，就不會互相改到對方的檔案。
  • 16:07 Auto memory：以前 Claude Code 每次都像從零開始，同樣的事情一直重複花 token；現在 Claude 會跨 session 累積知識，你不用自己設定
    ↳ token 是 AI 計算讀寫份量的單位，用越多越慢也越貴。以前每開一個新對話，Claude 都要重新摸索一次專案；現在它會自動記下學到的東西，你什麼都不用設定。
  • 16:38 可以請它記住重要的 build 指令、除錯心得和其他專案偏好；Claude 會看資訊對之後的對話有沒有用，自己決定要記什麼
    ↳ build 指令是把程式組裝成可以執行的版本時要下的指令。你可以主動叫它記住某件事，它也會自己判斷這件事以後用不用得到，用得到才記，不是什麼都存。
  • 16:38 Claude 會為每個專案管理一個目錄，裡面有 memory.md 當索引檔，跟 Claude.md 一樣會被載入對話，但只由 Claude 管理
    ↳ 每個專案都有一個記憶資料夾，memory.md 是裡面的目錄頁，每次對話都會讀進來。和 CLAUDE.md 不同的是，CLAUDE.md 由你寫，memory.md 只由 Claude 自己維護。
  • 17:10 索引檔可以連到同一個目錄裡寫得更詳細的其他檔案，用的是跟 skills 類似的 progressive disclosure
    ↳ progressive disclosure 的意思是先看摘要，需要時再翻細節。skills 是 Claude 需要時才載入的技能包。memory.md 目錄頁只放重點和連結，細節另外存成檔案，用到才打開。
  • 17:10 subagent 也能用 auto memory：自訂 subagent 可以設 memory user 或 memory project 來建立記憶目錄
    ↳ subagent 是主要的 Claude 派出去處理特定任務的小幫手。自訂 subagent 時設定 memory user 或 memory project，系統就會替它建一個記憶資料夾，讓它也能累積經驗。
  • 17:40 這個功能靠的是模型的新進展：跟 Opus 4 比，Opus 4.7 等較新的模型更會把記憶當成目錄裡的一組檔案來管理；Claude 玩 Pokemon 進步很多也是因為這個能力
    ↳ 這個功能靠的是模型本身變強了。Opus 4.7 這類新模型比 Opus 4 更懂得把記憶整理成一組檔案來管理；Claude 玩 Pokemon 進步很多，也是因為這個能力。
  • 17:40 Code review：Anthropic 內部發現一種更有效的 code review 做法，是多階段、多 agent 的
    ↳ code review 是程式寫完後請別人檢查有沒有問題。Anthropic 內部發現，分成好幾個階段、派好幾個 AI 分工檢查，會比只看一遍更有效。
  • 18:14 做法是開一組 reviewer 各看程式碼的不同面向，再驗證這些發現是否真的值得回報；原本要花好幾小時或根本會漏掉的問題也抓得到
    ↳ 做法是找一組審查者，每個負責檢查一個面向，最後再核對找到的問題是不是真的值得回報，避免誤報。人要花好幾小時才找得到、甚至會漏掉的問題，這樣也抓得到。
  • 18:14 可以透過 GitHub app 對所有 PR 設定這個 code review，也可以在 Claude Code 用 /ultra review 手動試用
    ↳ GitHub app 是裝在 GitHub（存放程式碼的平台）上的整合程式。裝好之後每個 PR 都會自動審；想先試試看，可以在 Claude Code 裡打 /ultra review 手動跑一次。
  • 18:48 整體效果：要批准的動作更少、更多 agent 安全地平行工作、session 會隨時間累積知識、你看 PR 之前已經有一組 Claude 審過了
    ↳ 前面這些功能加起來的效果：Claude 比較少停下來等你按同意，多個 agent 可以安全地同時工作，越用越懂你的專案，而且 PR 到你手上之前，已經有一群 Claude 先審過。
  • 19:19 Routines：前面的功能讓 agent 從想法到 PR 更自主地完成，現在連產生想法這件事也自動化
    ↳ 前面的功能讓 Claude 能從「有一個點子」一路做到「交出 PR」。Routines 再往前一步，連「接下來該做什麼」都交給它自己去找。
  • 19:19 routine 設定一次就好：填入 prompt、repo 和相關 connectors，再選觸發方式
    ↳ routine 只要設定一次：寫好 prompt（給 Claude 的指示），指定 repo，接上需要的 connectors（連接 Slack 等外部服務的接口），再選什麼情況下啟動。
  • 19:19 觸發方式有三種：cron 排程（例如每小時、每天）、GitHub webhook 事件，或者設一個 API endpoint，打它就會執行
    ↳ 啟動方式有三種。cron 是照時間表定時執行；webhook 是 GitHub 上發生某件事時通知它開始；API endpoint 是一個專屬網址，別的程式一連過來它就開始跑。
  • 19:57 之後 Claude 會自己跑，例如每天整理 GitHub issues，啟用 Slack connector 就能把熱門 issue 摘要傳到 Slack；也能設成電商網站每成交一筆就執行
    ↳ 例如每天自動整理 GitHub issues（使用者回報的問題清單），把最熱門的幾則做成摘要傳到 Slack（團隊聊天軟體）；也可以設成網站每成交一筆訂單就執行一次。
  • 20:32 Routines 現在在側邊欄很顯眼；另外也推出 /loop，可以在單一 Claude Code session 裡設定自動化，例：/loop 一分鐘 講個笑話
    ↳ Routines 現在放在側邊欄，很好找。/loop 是比較輕量的版本，只在目前這個對話裡重複做同一件事。例如輸入「/loop 一分鐘 講個笑話」，它就每分鐘講一個。
  • 21:05 Claude 有一個 cron create 工具（類似 enter work tree 工具），可以自己判斷要不要幫你開排程工作；不想要的話可以在 settings 關掉
    ↳ 和 work tree 工具一樣，Claude 有一個「建立排程」的工具，會自己判斷你是不是需要一個定時任務，需要就幫你開。不希望它自作主張的話，可以在設定裡關掉。
  • 21:05 Demo 結果：每分鐘講一個笑話，例如程式設計師偏好 dark mode，因為光會吸引 bugs
    ↳ 示範的結果真的每分鐘冒出一個笑話，例如「程式設計師愛用深色模式，因為光會吸引 bugs」。bug 在英文裡是蟲，也是程式錯誤的意思。
  • 21:35 routine 可以在桌機上本地啟動，也可以遠端啟動；講者偏好遠端，因為本地的話筆電要一直開著，遠端則由官方伺服器排程和執行
    ↳ 本地啟動是在你自己的電腦上跑，電腦一關就停了。遠端啟動則是交給官方的伺服器排程、執行。講者偏好遠端，因為這樣筆電不必一直開著。
  • 21:35 講者自己的 routine：掃描前一天以來反應數最多的公開 GitHub issues，只看 area plug-ins 和 area hooks 標籤，按反應數列出前十名
    ↳ 講者自己的 routine 會找出前一天以來反應數最多的公開 issue，只看 plug-ins（外掛）和 hooks（在特定時機自動觸發的動作）這兩類標籤，列出前十名。
  • 22:09 這個 routine 跑了一週，每天都會產出報告，不用自己再 prompt Claude；還可以再設其他自動化來讀這些報告、開 subagent 去修
    ↳ 這個 routine 跑了一週，每天都自動產出一份報告，講者完全不用再下指令。還可以再加一層：設另一個自動化來讀這些報告，派 subagent 去修上面列的問題。
  • 22:42 要停止時說「stop the loop」，Claude 會理解你的 prompt，對應到正確的工具呼叫，把排程刪掉
    ↳ 要停掉定時任務，直接說「stop the loop」就好。Claude 聽得懂你的意思，會自己找到對應的工具把排程刪掉，你不用記任何指令。
  • 22:42 新增 tool search 工具：在你和實際的工具定義之間多一層間接，所以能同時提供更多工具，又不直接佔用 context
    ↳ context 是 Claude 一次能「放在腦中」的內容量。以前所有工具的說明都要先塞進去；tool search 讓它需要時才去查，所以能提供更多工具，又不會擠掉空間。
  • 23:46 給團隊或企業管理者的功能：Windows 支援比幾個月前好很多、cloud provider 設定、原生安裝、管理員設定管理、公司層級改善 harness 的 plug-in 功能
    ↳ 給公司管理者的改進包括：Windows 支援比幾個月前好很多、可以設定雲端服務供應商、原生安裝、管理員統一管理設定，還能用外掛在公司層級調整 Claude Code 的運作方式。
  • 23:46 可以看公開的 changelog 追蹤更新
    ↳ changelog 是每次更新改了什麼的公開紀錄。想知道有什麼新功能，最直接的方法就是去看它。
  • 24:17 其他追蹤新功能的管道：在 X 上追蹤 ClaudeDevs、看文件裡每週的 What's New Digests，或訂閱開發者電子報
    ↳ 其他追新功能的管道：在 X（以前的 Twitter）上追蹤 ClaudeDevs、看官方文件每週的 What&#x27;s New Digests，或是訂閱開發者電子報。
📘 術語
work tree（工作樹）：原本會複製 repo 的所有檔案；讓新 session 在隔離環境裡開發功能，可同時開多個 agent 各做一個功能
--worktree / -W（work tree 參數）：開新 session 時加上它，就會配一個新的 work tree；-W 是 --worktree 的縮寫
enter work tree / exit work tree tool（進入／離開 work tree 工具）：讓 Claude 自己判斷是否要在隔離環境實作新功能的工具
harness（執行框架）：字幕沒有定義；提到離開時 harness 會幫你清掉 work tree
auto memory（自動記憶）：讓 Claude 跨 session 累積知識，例如 build 指令、除錯心得、專案偏好
memory.md（記憶索引檔）：每個專案記憶目錄裡的索引檔，像 Claude.md 一樣載入對話，但只由 Claude 管理
progressive disclosure（漸進式揭露）：索引檔再連到有更多細節的其他檔案，做法跟 skills 類似
subagent（子代理）：自訂 subagent 可設 memory user 或 memory project 來建立記憶目錄
code review（multi-phase, multi-agent）（多階段、多 agent 程式碼審查）：開一組 reviewer 各看不同面向，再驗證發現是否值得回報
Routines（例行任務）：設定一次 prompt、repo、connectors 和觸發方式後，Claude 會自己執行
cron schedule（cron 排程）：routine 的觸發方式之一，例如每小時或每天執行
GitHub webhook（GitHub webhook）：routine 的觸發方式之一：GitHub 事件發生時觸發
connector（連接器）：routine 可以設定相關 connectors，例如啟用 Slack connector 把摘要傳到 Slack
/loop（/loop 指令）：在單一 Claude Code session 裡設定自動化，例如每分鐘講個笑話
cron create tool（建立排程工具）：讓 Claude 自己判斷是否幫你開排程工作，可在 settings 關掉
tool search（工具搜尋）：在你和工具定義之間多一層間接，能提供更多工具又不直接佔用 context
changelog（更新日誌）：公開的更新紀錄，可以用來追蹤新功能
✏️ 小考一題

根據影片，設定 Routine 時可以選哪些觸發方式？

A. 只能用 cron 排程B. 只能在本地筆電開著時手動觸發C. cron 排程、GitHub webhook 事件、API endpointD. Slack 訊息、Email、cron 排程
看答案
答案：C。[19:19] 講者說觸發方式可以選 cron schedule（每小時或每天）、GitHub webhook event，或設一個 API endpoint 讓 routine 執行。
