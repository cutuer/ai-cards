🧑‍🏫 這段是 Grok 團隊的直播實況：他們一邊叫 AI 幫忙寫程式，一邊籌備一場舊金山的快閃餐廳。內容從選哪種程式語言、傳單怎麼寫，一路講到場地、預算和許可。值得看的地方，是能看到一個真實團隊怎麼把 AI 放進日常工作，也能看到他們怎麼從「讓人在乎」的角度去做行銷。

  • 322:18 討論要不要全部用 Rust 寫：restaurant finder 和 landing page 大概不用；UI 雖然也能用 Rust 做，但怕太痛苦；部分 backend 或許可以用 Rust 或 Go
    ↳ 要不要全用 Rust（執行快、規則嚴格的程式語言）寫？找餐廳工具和 landing page（活動宣傳網頁）不用；畫面硬用 Rust 會太折磨；只有部分 backend（幕後處理資料的程式）考慮 Rust 或 Go。
  • 322:18 專案已經有一些 TypeScript，講者認為 agents 很愛 TypeScript
    ↳ 專案裡已經有 TypeScript（網頁開發很常見的語言）寫的程式。講者覺得 agent（會自己寫程式、做事的 AI 助手）特別會寫它，順著用最省事。
  • 322:49 講者自己不喜歡寫 Go，但認為 Go 很適合 agents；Rust 也不錯，只是編譯時間很慢，不想拖慢進度
    ↳ Go 是 Google 推出、寫法簡單的語言。講者自己寫得不開心，但覺得交給 agent 寫很合適。Rust 也不錯，只是每次改完都要等很久編譯（轉成電腦能跑的檔案），會拖慢進度。
  • 323:19 bot 詢問傳單標題，列出的選項有：one night October 15th、SF pop-up October 15th、dinner finds you，或自己寫
    ↳ bot 在問傳單大標要用哪個。選項有強調日期的「10/15 一晚限定」、「舊金山快閃 10/15」，比較有畫面感的「晚餐來找你」，也可以自己寫。
  • 323:19 寫文案要從「大家想要什麼」出發，不要只顧著講功能；沒人在乎這個 popup，要讓他們在乎
    ↳ 寫文案要從讀者想要什麼出發，不是列出你做了什麼。路人本來就不在乎一場快閃，文案的任務是給他一個在乎的理由。
  • 323:19 這個 popup 的獨特之處是即時、現場一起創造的新體驗
    ↳ 這場 popup（快閃活動，只短暫出現）最特別的地方在於體驗是在現場即時、大家一起創造出來的，之前從沒有過。
  • 323:49 講者認為沒人想聽「這是用 AI 做的」，重點應該是讓人覺得自己在嘗試新東西
    ↳ 就算整個活動是用 AI 做的，也別拿這點當賣點。一般人不在意用了什麼技術，在意的是「我可以試到新鮮事」的感覺。
  • 324:19 標題提案：「你上次嘗試新事物是什麼時候？」，後面接「Now is your opportunity. 舊金山獨特餐廳 popup 即將登場」，目的是喚起情緒
    ↳ 開頭先用問句戳人：「你上次嘗試新事物是什麼時候？」讓人意識到自己很久沒冒險，接著說「機會來了」，最後才講活動資訊。靠的是情緒，不是規格。
  • 324:19 有成員已在 Slack 分享街角地圖的初版
    ↳ 有成員已經把活動街角地圖的初版丟到 Slack（公司常用的團隊聊天工具）。大家是分頭同時在推進的。
  • 324:51 提議把 popup 做成 Grokbot 主題，並在現場推出限量的秘密 Grokbot merch，也可以把這種出席誘因做進平台
    ↳ 提議整場用 Grokbot 當主題，現場偷偷推出限量 merch（印有品牌的周邊商品）。這種「到場才拿得到」的誘因，也能做成平台的功能。
  • 324:51 popup 的吸引力在於時間感和稀缺性：一次性、只辦一天，東西數量有限
    ↳ 快閃吸引人的地方在於「錯過就沒了」：只辦一次、只有一天、東西數量有限，人會因為怕錯過而想來。
  • 325:22 限量商品可以結合其他限定活動，帶動流量與關注；也提到社交遊戲等現場互動
    ↳ 限量商品可以和其他限定活動綁在一起，互相拉人潮、增加話題。現場也可以安排社交遊戲，讓來賓互動。
  • 325:53 構想事先預告現場會有體驗或遊戲，提前炒熱氣氛
    ↳ 活動前先預告「現場會有體驗和遊戲」，讓大家還沒到場就開始期待。
  • 326:24 傳單行銷活動已有初版，並在 Slack 開了 marketing 頻道
    ↳ 傳單的第一版已經做好了，也在 Slack 開了專門的 marketing（行銷）頻道，行銷相關的討論都集中在那裡。
  • 326:24 最後決定繼續用 TypeScript，不想浪費時間
    ↳ 最後拍板繼續用 TypeScript。改用別的語言要多花時間，他們不想浪費在這上面。
  • 327:30 講者很喜歡 Cloud Agents 能直接產出影片；不會自動貼出來，但可以叫它貼；如果有做影片，會放進 PR 描述，方便 review
    ↳ Cloud Agents（在雲端自己跑任務的 AI）能錄下操作過程的影片。它不會自動貼出來，但叫它貼就會。影片放進 PR 描述，審查的人一看就知道改了什麼。
  • 328:00 這次 PR 沒附影片，因為 verification skill 沒要求；於是更新 skill：有視覺影響的改動一律附影片，backend 改動也仍要驗證
    ↳ skill 是寫給 agent 的工作守則。這次沒附影片，是因為負責驗證的守則沒要求，所以直接改規則：畫面有變就一律附影片，後台改動也照樣要驗證。
  • 328:32 有成員已在 Resend 設定好網域驗證，正在檢查 DNS，準備寄送 email
    ↳ Resend 是幫網站寄 email 的服務。寄信前要先證明網域（網址）是你的，做法是在 DNS（管網址的設定）加上指定設定，確認生效後才能開始寄。
  • 329:02 講者偏好極簡設計；先把傳單做完，之後直接從 repo 拉設計，repo 是程式碼的 source of truth
    ↳ 講者偏好簡潔的設計。先把傳單做完，之後需要設計就直接從 repo（放程式碼的專案倉庫）拿。source of truth 的意思是「一切以它為準的正本」。
  • 329:32 講者的 GitHub CLI 還有奇怪的問題，正在處理登入（輸入 device code）
    ↳ GitHub CLI 是用打指令操作 GitHub（存放程式碼的平台）的工具。講者登入時遇到怪問題，正照流程輸入 device code（登入用的一次性驗證碼）。
  • 330:03 prototype 只用純 HTML 和 JavaScript 寫成；之後可以再重構，重要的是持續前進、反覆迭代，先讓它跑起來
    ↳ prototype（試作版）只用最基本的 HTML 和 JavaScript（網頁的骨架和互動）寫成。先求能動，之後再重構（整理改寫），重點是一直往前推、邊做邊改。
  • 330:03 下一場 talk 在 2:30，大家確認到時候要完成到哪裡
    ↳ 下一場分享在 2:30，大家先約好到時候要做到哪一步，給自己一個短期的截止點。
  • 330:34 規劃在鏡頭外手動打電話，看看預訂有多難，藉此判斷哪些部分需要自動化；另一位成員的 prototype 已在開發中，之後可以拿來試用、迭代
    ↳ 他們打算先在鏡頭外真的打電話預訂，親身感受哪一步麻煩，再決定哪些值得自動化。另一位成員的 prototype 已經在做，之後可以拿來實際試、再修改。
  • 331:04 要做出 guerrilla marketing 計畫的雛形、傳單和設計；可能要雇人去貼傳單（還開玩笑問 TaskRabbit 有沒有 MCP）
    ↳ guerrilla marketing（游擊行銷：低成本、在街頭出奇招吸睛）要先做出計畫雛形、傳單和設計。可能得雇人貼傳單，還開玩笑問 TaskRabbit（找人跑腿的平台）有沒有 MCP（讓 AI 能直接操作外部服務的接口）。
  • 331:04 Notion 已建立 marketing 區塊，收集所有可考慮的點子，merch 是其中之一；同一位成員也會負責體驗型活動的設計
    ↳ Notion（筆記兼專案管理工具）裡開了行銷區，所有點子先收進去再挑，周邊商品是其中之一。同一位成員也負責設計現場的體驗活動。
  • 332:16 辦活動的本質是讓人產生某種感受，所以要考慮所有能掌控的環節；先決定賓客人數，暫定 100 人
    ↳ 辦活動其實是在設計來賓的感受，所以能掌控的細節都要顧到。第一步先定規模，暫定 100 人，其他事情才好往下排。
  • 332:48 場地要容納得下賓客，也要能讓團隊掌控環境和體驗
    ↳ 場地要坐得下這些人，也要讓團隊能自己掌控環境，這樣才做得出他們想要的體驗。
  • 332:48 先從人的在地知識出發：講者提到自家附近的 The Pearl 和 Dog Patch Studios，再找類似的場地（pattern match）
    ↳ 找場地先靠在地人的經驗：講者從自家附近的 The Pearl 和 Dog Patch Studios 想起，再去找條件相似的地方，這就是 pattern match（照熟悉的例子找相似的）。
  • 332:48 講者的 bots 也推薦過一些場地，可以據此建立一個 skill 或 context 給 bots 使用
    ↳ 講者的 bot 也推薦過一些場地。可以把這些整理成 skill 或 context（給 AI 的背景資料），之後 bot 找場地就有依據。
  • 333:18 預算也很重要但還沒討論，要打電話問了才知道；有成員會做市場調查了解費用
    ↳ 預算很重要但還沒討論，場地費要打電話問了才知道。有成員會做市場調查，先弄清楚大概的價格。
  • 333:18 研究資料都整理在 Notion（有 host finder），同時也在查許可
    ↳ 研究資料都整理在 Notion，裡面有一個 host finder（用來找場地）。同時他們也在查辦活動需要哪些許可。
  • 333:49 許可最難的是封街，還有要不要賣酒；可能需要提前幾週到一個月申請，一個月後舉辦有點趕但可行
    ↳ 許可裡最難的是封街，還有要不要賣酒。這類申請可能要提前幾週到一個月，所以一個月後就辦有點趕，但做得到。
