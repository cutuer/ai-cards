🧑‍🏫 這段是 Grok Bot 發表直播第一天的中段。講者先示範怎麼安排一個「管理者」AI 去盯其他 AI 的進度，再回答觀眾最在意的幾件事：它會不會自己亂寄信、亂付款？能不能連公司內部系統？怎麼教它新技能？如果你想把好幾個 AI 當成一個小團隊來用，這段很實用。

  • 71:37 agent 在自己的機器上卡住時（例如東西都準備好了卻分享不出去），可以推它一把，把它引導到你要的方向
    ↳ agent（能自己動手完成任務的 AI 助手）在自己的電腦上做事時可能卡住，例如表單做好了卻分享不出去。這時你可以插話提示它，把它拉回你要的方向，不用整件重來。
  • 72:07 如果不想自己盯著所有 agent，可以加一個 orchestrator agent，像「幕僚長」一樣即時收集各 agent 的工作進度
    ↳ 不想一個一個盯？可以多放一個 orchestrator agent（協調者 agent）。它不做實際工作，專門去問其他 agent 做到哪、有沒有卡住，再彙整給你，就像幕僚長。
  • 72:07 示範建立一個叫 manager 的 agent，並在設定裡寫明它管哪些人：「你的工作是向 email Ethan、slide Sonia、data Dan 收集他們正在做的事」
    ↳ 講者建了一個叫 manager 的 agent，在它的設定裡直接寫明它管誰：負責寄信的 Ethan、做投影片的 Sonia、處理資料的 Dan。範圍寫清楚，它才知道要找誰要進度。
  • 72:37 manager agent 也可以設定 routine，例如每兩小時向團隊收集進度，並確認有沒有 blocker
    ↳ 還能幫 manager 設 routine（固定排程的例行任務），例如每兩小時自動問一輪進度，並檢查有沒有 blocker（卡住、讓工作沒辦法往下走的問題），你就不用自己記得去問。
  • 72:37 這跟人類團隊的一般流程一樣：遇到 blocker 就回報給主管，一起想辦法解除，agent 也能照這樣做
    ↳ 這套做法跟一般公司一樣：員工卡關就跟主管講，主管幫忙想辦法。agent 之間也能照這個流程回報，不會各自卡著卻沒人知道。
  • 73:07 舉例：data Dan 做不出可分享的表單時，manager agent 會馬上收到消息，提出解決方式，並通知 Amita 和 slide Sonia
    ↳ 例如 Dan 做不出能分享的表單，manager 立刻就會知道，接著提出解決方式，並通知 Amita 和做投影片的 Sonia。問題不會被悶著，相關的人也同步知道。
  • 73:38 orchestrator agent 就是 agent 上面的協調層，能及時掌握哪些任務卡住、哪些沒辦法準時解決
    ↳ 簡單說，orchestrator 是蓋在所有 agent 上面的一層。它的重點不是做事，而是即時看出哪件事卡住、哪件事可能趕不上時間，讓你提早處理。
  • 73:38 群組聊天裡，email agent 在等 slide Sonia 用咖啡杯資料做出的截圖，接著會產出 email 草稿和投影片
    ↳ 在共用的群組聊天裡，負責寄信的 agent 正在等 Sonia 用咖啡杯資料做的截圖，拿到後才會產出 email 草稿和投影片。可以看到 agent 之間也有先後順序。
  • 74:39 講者讓所有 Grok Bot 保持運作，最後 15 分鐘開放現場觀眾提問
    ↳ 講者讓這些 Grok Bot（Grok 推出、會自己操作電腦做事的 agent 產品）繼續在背景運作，最後 15 分鐘改成回答現場觀眾的提問。
  • 75:39 遇到需要核准的動作（寄 email、付款等）時，由 autoreview tool 決定要不要問使用者，它底層有 classifier 判斷動作的風險
    ↳ 寄信、付款這類做了很難收回的動作，會先經過 autoreview tool（自動審查工具）。它底層用 classifier（分類模型）判斷這個動作風險多高，再決定要不要先問你。
  • 76:09 除了內建的 autoreview tool，還可以自己寫規則，例如就算只是在桌面建新資料夾這種安全的動作，也規定它要先問過你
    ↳ 如果覺得內建的判斷不夠，你可以自己加規則。就算是在桌面開一個新資料夾這種無害的小事，也能規定它一定要先問過你才能動手。
  • 76:39 規則要訂多細都可以，也可以全交給 autoreview tool 判斷，要多保守由你決定
    ↳ 規則要訂多細由你決定：可以一條一條自己訂，也可以全交給 autoreview 判斷。重點是它要多保守，你可以自己調。
  • 76:39 講者提到這次示範中 Grok Bot 甚至太謹慎：建立表單時一直確認表單沒有收集 PHI 或 PII，每一步都讓講者參與
    ↳ 講者說這次 bot 反而太小心：做表單時一直確認沒有收集 PHI（健康醫療相關的個資）或 PII（能認出是誰的資料，例如姓名、電話），每一步都拉講者進來確認。
  • 77:40 建立信任靠 memory：bot 問「這段文案可以寄嗎」，你回「很好，以後文案不用問我，直接寄」，它就會記住
    ↳ 信任是靠 memory（bot 記住你偏好的能力）累積的。它問「這段文案能寄嗎」，你回「很好，以後這類直接寄」，下次它就不會再問。
  • 77:10 講者表示，平常使用時 bot 並不會每建一個表單都來問權限，這次的情況並不常見
    ↳ 講者也說明，平常使用時 bot 不會每做一個表單就來要權限，這次問這麼多算是特例。
  • 78:11 人類和 bot 目前可以在 Slack 討論串裡協作：用 @bot 請它加新功能，同事也能在同一串補充需求，例如 API endpoint 的效能
    ↳ 人和 bot 現在可以在 Slack（公司常用的聊天軟體）的討論串裡合作：@bot 請它加功能，同事也能在同一串補充需求，例如某個 API endpoint（程式提供資料的接口）要跑更快。
  • 78:42 Grok Bot 內部「人類與 bot 一起的多人群組模式」還在開發中，講者說應該很快會推出
    ↳ 至於 Grok Bot 自己的產品裡，讓人和 bot 待在同一個群組一起討論的功能還在開發中，講者說應該很快就會推出。
  • 79:16 Grok Bot 的電腦要多封閉或多開放都可以；例如要存取 MongoDB，就把 credentials 給它的電腦
    ↳ bot 用的電腦要多封閉或多開放，由你決定。例如要讓它讀 MongoDB（一種常見的資料庫），就把 credentials（帳號密碼、金鑰這類登入憑證）交給它那台電腦。

    ↳ 它的電腦也能連上公司的 VPN（連進公司內部網路的加密通道）。只要給對憑證，它就能用公司內部系統。能碰到哪些資源，看你給了什麼。

    ↳ Grok Bot 剛跟 1Password（一款密碼管理軟體）完成整合，可以直接使用存在裡面、受保護的登入憑證。

    ↳ marketplace（bot 市集）裡有別人公開發布的 bot，用手機或筆電打開 Grok Bot 就能看到，例如 Claire、Lauren、Eric、Lenny 做的 bot。

📘 術語
orchestrator agent（協調者 agent）：像幕僚長，在其他 agent 上面當協調層，即時收集進度、發現卡住的地方
blocker（阻礙／卡點）：讓工作沒辦法繼續的問題，要回報給主管來解除
routine（例行排程）：讓 agent 定期做事，例如每兩小時收集團隊進度
autoreview tool（自動審查工具）：底層有 classifier，判斷動作的風險，決定要不要請使用者核准
classifier（分類器）：autoreview tool 用它來判斷一個動作有多危險或多安全
PHI / PII（受保護的健康資訊／個人識別資訊）：字幕只提到 bot 會確認表單沒有收集這類資料，沒有另外解釋
memory（記憶）：bot 會從你的回覆學習，例如以後某類文案不用再問就直接寄
credentials（憑證）：給 Grok Bot 的電腦，讓它能存取 MongoDB、內部系統等
VPN（虛擬私人網路）：Grok Bot 的電腦可以加入公司 VPN，藉此控管它能存取的內部資源
artifact（產出物）：例如 bot 產出的 PDF 或 PowerPoint 投影片，可以存到本機
skill（技能）：teach a task 學會後存下來的能力，之後可以重複叫用
marketplace（市集）：可以瀏覽別人公開發布的 bot
