🧑‍🏫 這段是 Grok 直播第一天的一小段。前半是一位創作者來賓在收尾，分享她怎麼用 Grockbot（影片介紹的 AI 助手，可以長期留著替你做事）處理和品牌的合作。後半由 Shub 開始給 founders 的工作坊，講一隊 bot 能怎麼分擔工作。值得看的原因是，它把 AI 從「問答工具」變成「長期幫手」這件事講得很具體。

  • 441:38 以前在好萊塢要靠經紀人和守門人；現在任何人都能在網路上經營品牌，再找合適的品牌合作夥伴來變現
    ↳ 以前要進演藝圈，得先過經紀人這一關。現在自己在網路上經營出名氣，就能直接找品牌合作賺錢，門檻低很多，但接洽、談判這些事就得自己來。
  • 441:38 創作者範例：用四個 Grockbot 分工，分別負責找出該聯繫的品牌、實際去聯繫、談價碼、想內容點子
    ↳ 她把經紀人的工作拆成四份，交給四個 bot：一個列出該找哪些品牌，一個去聯繫，一個談價碼，一個想內容點子，像有個小團隊在幫她。
  • 441:38 每個企業主都能套用類似做法：檢視自己的工作流程，找出「可驗證」的 workflow 和 loop，也就是看得出來有沒有成功
    ↳ workflow 是一套固定的工作流程，loop 是反覆在跑的循環。先挑「可驗證」的，也就是做完能清楚判斷成不成功，這種最適合交給 bot。
  • 442:08 coding 是可驗證 loop 的例子，這類工作就適合交給 bot 盡情去做
    ↳ coding 就是寫程式，是最典型的例子：程式能不能跑，結果很清楚。bot 可以自己做、自己檢查，所以放手讓它一直做沒問題。
  • 442:08 來賓在 X 上只有公司帳號 Tri Carrot；想找她在其他平台的帳號可以 Google 她的名字
    ↳ 純資訊：來賓在 X（就是以前的 Twitter）上只有公司帳號 Tri Carrot。想找她本人在其他平台的帳號，直接 Google 她的名字。
  • 442:38 來賓希望觀眾帶走的重點：大家對 Grockbot 能做到的事都很興奮
    ↳ 來賓收尾很簡短：大家對 Grockbot 能做到的事都很興奮。這段沒有再補充具體內容。
  • 443:10 下一場是給 founders 的 Grockbot 工作坊（主持人介紹為 Howard from San Francisco），講者自我介紹叫 Shub，平常協助 founders 最佳化 Grockbot 設定、加快出貨速度
    ↳ founder 是創辦人、創業者。下一場由 Shub 主講，他平常幫創辦人把 Grockbot 設定調好，讓團隊更快把產品做出來、推出去（也就是出貨）。
  • 443:40 工作坊預計 60 到 90 分鐘：先講 Grockbot 背景和它為什麼對 founders 特別有用，接著 demo、power user 技巧，最後是現場 Q&A
    ↳ 約 60～90 分鐘：先講背景和為什麼適合創辦人，再 demo（現場示範），接著分享 power user（重度使用者）的技巧，最後 Q&A 開放提問。
  • 444:10 彩蛋：最後會分享其中一個 bot 讓觀眾直接拿去用；不是 founder 的人（例如公司某部門的負責人）也適用大部分內容
    ↳ 最後會送一個做好的 bot 讓大家直接拿去用。就算不是創業者，只要你負責一塊業務，例如部門主管，大部分內容也用得上。
  • 444:41 AI 成熟度曲線：從 chatbot，到做完任務就丟掉的 ephemeral agent，再到可以自動化工作、長期留著用的 bot
    ↳ chatbot 是一問一答的聊天機器人。ephemeral agent 是交代一件事、做完就丟的 AI 助手。再往上是 bot：長期留著，替你自動跑工作。
  • 445:11 關鍵是 bot 會 compound（累積成長）：不要用完就丟，持續投資在它身上，它會像員工一樣跟著你一起變強
    ↳ compound 原意是複利。bot 別用完就丟，持續餵它資料、調整它，它記得越多就越好用，就像新人待久了會越來越上手。
  • 445:41 目標是用一隊 bot 完整自動化某個職能（staff function）來放大自己；講者說內部已經很接近，外部也有例子
    ↳ staff function 是公司裡一整塊職能，例如業務或客服。目標是讓一隊 bot 撐起整塊工作，一個人就能做到一個部門的量。講者說他們內部已經快做到了。
  • 446:13 Grockbot 可以像同事一樣互動，用類似 iMessage 的方式傳訊息給它；它很主動、企圖心也強
    ↳ 用起來不像開軟體，比較像傳訊息給同事，類似 iMessage（蘋果的聊天 App）。而且它很主動、企圖心強，不會只等你下指令。
  • 446:13 Grockbot 有自己的電腦。傳統 agent 沒有 MCP、API 或直接連線就做不了事，Grockbot 在權限不完美時也能自己完成
    ↳ MCP 是讓 AI 連接外部工具的標準接口，API 是程式之間溝通的窗口。一般 agent 少了這些就卡住；Grockbot 有自己的電腦，權限不完整也能自己做完。
  • 446:43 Grockbot 會向你學習、很主動、有自己的裝置；除了直接串接其他產品，也能像你一樣操作你的工具
    ↳ 它做事有兩種方式：可以直接串接的產品就直接連，連不上的就像你本人一樣去操作你的工具。另外它會向你學習，也會主動做事。
  • 446:43 任務可以從頭到尾（end to end）完全交給 Grockbot，你只要委派，不用再花心力盯 agent 有沒有做完
    ↳ end to end 就是從頭到尾。任務交出去之後整個過程都由它負責，你不用一直回來看它卡在哪、做完了沒。
  • 447:14 founders 的三大執行責任：一是保持專注，二是維持團隊各項出貨的速度，三是持續做出高品質的洞察，也就是好決策和未來規劃
    ↳ 講者認為創辦人最重要的三件事是：不分心、讓團隊各項成果持續快速推出、做出好判斷和未來規劃。
  • 447:46 Grockbot 能處理日常中必要但不是最重要的瑣事；講者認為省下的心力可能是這場最重要的一點，值得花時間盤點自己有哪些
    ↳ 很多事一定要做但不是最重要，卻很耗腦力。講者認為把這些交給 bot、省下心力，可能是這整場最重要的一點，值得先列清單盤點。
  • 448:16 prompt bot 的時候要讓它做完全部的工作，不是只做一部分，執行和驗證都要包含在內
    ↳ prompt 就是你給 AI 的指令。交代時要完整：不只「幫我做」，還要「做完自己檢查對不對」，免得最後還要你去收尾。
  • 448:46 每天湧入的資訊量非常大，要維持洞察品質就得分流整理（triage）這些資訊，Grockbot 很適合做這件事
    ↳ triage 原本是急診的檢傷分類，這裡指把每天大量湧入的資訊分出輕重、過濾雜訊。bot 先幫你篩過一輪，你的判斷品質才守得住。
  • 448:46 講者認為現在是史上最適合打造產品的時機，尤其是軟體；工程師 Lingi 說用 Grockbot 出貨比以前快很多
    ↳ 講者認為現在是史上最適合做產品的時機，尤其是軟體。工程師 Lingi 也說，用 Grockbot 之後推出東西的速度比以前快很多。
  • 449:16 可以用 routine 把重複的事自動化，依排程、webhook 或訊號觸發，設定一次之後就會一直自動執行
    ↳ routine 是設定一次就會自動重複跑的例行任務。可以定時觸發，或用 webhook（別的系統有事發生時自動通知）或其他訊號觸發。
  • 449:46 「做不能規模化的事，但真的把它規模化」：新創常用很陽春的客製原型拿下第一個客戶，Grockbot 能讓你重複做一百次也不頭痛
    ↳ 新創常說「先做沒辦法規模化的事」：為第一個客戶手工做一個粗糙的原型（試作版）。以前很難一直這樣做，現在 bot 可以輕鬆幫你重複一百次。
  • 450:16 founders 通常是最有主動性（high agency）的一群人，能放大這種主動性的產品會帶來很酷的成果
    ↳ high agency 是指很主動、會自己想辦法把事做成的人。講者認為創辦人多半是這種人，能放大這種主動性的工具就會做出很驚人的成果。
  • 450:16 用例一「成交客戶」：讓 bot 處理大部分的客戶流程，只在絕對必要時才親自介入
    ↳ 用法一是談成客戶：大部分的客戶流程交給 bot 跑，你只在真的非本人不可的時候才出面。
  • 450:46 用例二「掌握產品變更」：講者曾在 demo 時指著側邊欄一個已經被移除的功能，因為他不知道已下架，很尷尬
    ↳ 用法二是掌握產品改了什麼。講者曾在 demo 時指著側邊欄一個早就移除的功能，因為他根本不知道已經下架，很尷尬。
  • 451:16 用例三「因應競爭對手」：bot 能以你的身分實際操作競品，得到比手動更多的洞察
    ↳ 用法三是研究對手：bot 能用你的身分實際去用競爭對手的產品，看到的會比你自己手動點一點還多。
  • 451:47 用例四「快速處理回饋並出貨」：每天會收到大量回饋，快速落實非常重要
    ↳ 用法四是處理使用者回饋：每天會湧進一大堆意見，能多快改好、推出新版本非常關鍵。
  • 452:19 四個 bot：closebot 負責客戶、prodbot 追蹤已出貨的東西、stockbot 盯競爭對手、protobot 做設計並把回饋轉成 PR，另外還有一位客串嘉賓
    ↳ closebot 顧客戶，prodbot 追蹤推出了什麼，stockbot 盯對手，protobot 做設計並把回饋變成 PR（提交給團隊審核的程式修改），另外還有一位客串嘉賓。
  • 452:50 demo closebot 時要記住兩點：一是 bot 會 compound，持續給它資訊，它會存起來、需要時引用、越來越好；二是它能用你的電腦和工具
    ↳ 看 closebot 示範前先記兩件事：它會越用越強，你給的資訊它都存著、需要時拿出來用；另外它能直接用你的電腦和工具做事。
  • 453:21 closebot 的功能之一是準備通話（prepping calls）；講者會在旁邊放一份 cheat sheet
    ↳ closebot 的功能之一是幫你準備通話，也就是在通話前把要談的東西先備好。講者旁邊會放一份 cheat sheet（重點小抄）對照著講。
📘 術語
verifiable loop（可驗證的循環）：你看得出來它有沒有成功的工作流程，例如 coding
AI maturity curve（AI 成熟度曲線）：從 chatbot、ephemeral agent 一路演進到 bot 的發展階段
ephemeral agent（一次性 agent）：做完一個任務就丟掉的 agent
compound（累積成長）：bot 不丟掉、持續投資，會像員工一樣越來越好
staff function（職能）：目標是用一隊 bot 完整自動化某個職能
MCP（MCP）：字幕提到傳統 agent 缺少 MCP、API 或直接連線就沒辦法做事
end to end（從頭到尾）：整個流程都交給 bot，包括執行和驗證
triage（分流整理）：把每天大量湧入的資訊整理過濾，才能維持洞察品質
routine（例行自動化）：依排程、webhook 或訊號觸發，設定一次就會一直自動執行
webhook（webhook）：routine 的觸發方式之一
high agency（高主動性）：講者形容 founders 通常是最有主動性的人
PR（PR）：protobot 會把回饋轉成 PR
