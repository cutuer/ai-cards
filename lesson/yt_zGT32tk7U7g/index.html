🧑‍🏫 這支影片是 Wasmer 創辦人 Siraj 分享他們怎麼用 Codex（OpenAI 會自己寫程式、改程式的 AI 工具），只花兩週半就做出一個原本估計要一年的產品。重點不只是快，還有用自己不熟的程式語言也做得出來，以及團隊的工作方式因此變了。

  • 00:02 Wasmer 用 Codex 在 2 週（約 2 週半）內做出一個 JavaScript runtime；沒有 Codex 的話，他們說輕易就要花 1 年
    ↳ JavaScript runtime 是讓 JavaScript 程式能實際跑起來的執行環境。Wasmer 靠 Codex 約兩週半就做出來，他們估計沒有 Codex 輕易就要一年，時間差了快二十倍。
  • 00:02 講者是 Siraj，Wasmer 的 founder 兼 CEO
    ↳ 講這些經驗的是 Wasmer 的創辦人兼執行長 Siraj，所以這是公司老闆自己的第一手說法，不是外人的評論。
  • 00:02 他們不只用 Codex 開發，也用 Codex 來抓 bug
    ↳ bug 就是程式裡的錯誤。他們除了叫 Codex 寫新程式，也讓它檢查哪裡寫錯，等於同時當寫手和校稿的人。
  • 00:02 原因：新平台是用 C++ 寫的，他們認為 C++ 最適合這個平台，但團隊的專長其實是 Rust，對 C++ 的一些細節不熟
    ↳ C++ 和 Rust 都是寫程式的語言。他們判斷新平台用 C++ 最合適，但團隊平常拿手的是 Rust，等於要用一個不熟的語言做重要產品。
  • 00:32 團隊不熟的那些 C++ 細節，Codex 很早就能抓出來
    ↳ 對 C++ 不熟，最怕的就是踩到自己不知道的細節。Codex 在早期就把這些問題抓出來，補上團隊經驗不足的地方，不用等出事才發現。
  • 00:32 他們要推出的是可以在 edge 執行的 JavaScript runtime，Siraj 說這在以前做不到
    ↳ edge 一般指放在離使用者比較近的伺服器上執行，回應通常比較快。Siraj 說能在 edge 跑的 JavaScript runtime 以前做不到，影片沒說原因。
  • 00:32 他們曾讓 Codex 連續工作好幾個小時，中間完全不給任何輸入，最後得到想要的結果
    ↳ 他們曾讓 Codex 連續做好幾個小時，中間沒人插手下指令，最後還是交出想要的成果。代表它能自己處理一長串工作，不用人一直盯。
  • 00:32 工作方式的改變：他們漸漸離開 IDE，比較少直接碰程式碼，主要是引導 Codex 往想要的方向走
    ↳ IDE 是工程師寫程式用的專門軟體。他們越來越少打開它親手改程式，角色從自己動手寫，變成告訴 Codex 方向、檢查結果是否對路。
📘 術語
JavaScript runtime（JavaScript 執行環境）：Wasmer 用 Codex 約 2 週半做出的產品，可以在 edge 執行；字幕沒有進一步定義
edge（邊緣（端））：字幕說他們的 JavaScript runtime 能在 edge 執行，而且以前做不到；字幕沒有進一步解釋
C++（C++ 程式語言）：Wasmer 新平台使用的語言，他們認為最適合這個平台，但團隊對它的細節不熟
Rust（Rust 程式語言）：Wasmer 團隊真正擅長的程式語言
IDE（整合開發環境）：字幕說他們漸漸不用 IDE、較少直接碰程式碼；字幕沒有定義這個詞
bug（程式錯誤）：他們除了開發，也用 Codex 來抓 bug
