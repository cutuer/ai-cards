🧑‍🏫 這是 xAI 團隊三天直播挑戰的最後一天。他們用 Grok 的 AI 機器人從零做出一家遊戲公司，這一段在報告卡牌遊戲上線前卡在哪裡、做到哪裡。值得看的是，他們讓 AI 機器人自己修 bug、自己測試、自己審程式碼，你可以看到 AI 實際接手了哪些工作。

  • 77:27 這是三天任務的第 3 天：一群 xAI 成員用 Grokbot 從零打造一個事業，發想幾天後決定做遊戲工作室和第一款遊戲
    ↳ 直播總共三天，這是最後一天。一群 xAI 員工用 Grok 的 AI 機器人從頭創業，前幾天先想點子，最後決定開一間遊戲工作室，先做出第一款遊戲。
  • 77:58 團隊正在處理 client secrets 和 web secrets，所以暫時不分享螢幕，不會在直播上部署正式環境的 secrets
    ↳ secrets 是程式連線要用的密碼和金鑰，外流了別人就能冒用。他們現在正在設定這些東西，所以先關掉螢幕分享，也不會在直播上處理正式版要用的密碼。
  • 77:58 他們做的是一款 card battler（卡牌對戰）類型的遊戲，稍早已經預覽過
    ↳ card battler 是卡牌對戰遊戲：玩家用手上的卡牌互相出招比輸贏，像寶可夢卡或爐石戰記那樣。這款遊戲稍早已經給觀眾看過一次。
  • 78:34 正在做 UI polish pass，想幫整個遊戲重新上漆、讓卡牌更精緻；團隊自嘲請大家降低期待，有好一點，但還有很多地方要改進
    ↳ UI 是玩家看到、會去點的畫面。polish pass 就是整體再修一輪：不加新功能，專心把畫面和卡牌做漂亮。團隊自己也說有進步，但還差得遠。
  • 78:34 直播現場在舊金山的 Grokbot Galaxy：樓下有演講，樓上是小型攝影棚，當天會在不同內容之間切換，可能也會有來賓
    ↳ 直播地點在舊金山一個叫 Grokbot Galaxy 的場地：樓下有人在演講，樓上是小攝影棚。所以今天節目會在不同內容之間切換，也可能有來賓加入。
  • 79:07 前幾天陸續請來業界專家講怎麼經營事業，也請熟悉 Grokbot 的 xAI 成員分享簡報
    ↳ 前兩天除了寫程式，也請了業界的人來講怎麼經營一家公司，另外請很會用 Grokbot 的 xAI 同事上台分享，所以不只是寫程式，也有在學做生意。
  • 79:07 Matt 今天早上在做回饋管道，讓玩家把遊玩時遇到的問題直接回報到 app 裡
    ↳ 團隊成員 Matt 今天早上在做一個回報功能。玩家在遊戲裡碰到問題，可以直接在 app 裡回報，不用另外寄信或跑去社群貼文。
  • 79:41 下午預計談營利模式，並請 xAI 成員協助規劃行銷計畫和營收計畫
    ↳ 下午要談怎麼靠這款遊戲賺錢，也會請 xAI 同事幫忙擬行銷計畫（怎麼讓人知道這款遊戲）和營收計畫（錢從哪裡來）。
  • 79:41 目標是先推出 play test，上線之後再根據回饋持續 ship and iterate
    ↳ play test 是試玩版：先給真人玩家玩，看哪裡有問題。他們打算先推出試玩版，之後一邊收回饋一邊改，一有改好的就上線，一直循環下去。
  • 80:13 引用新創圈的老話：如果你不覺得產品有點丟臉，就代表還沒準備好上線。團隊承認有些地方確實丟臉，但認為這是好事
    ↳ 新創圈有句老話：產品第一次上線時，如果你不覺得有點丟臉，代表你拖太久才上線。意思是別等完美，先上線才拿得到真實回饋，團隊也坦承確實有點丟臉。
  • 80:13 Grok bots 是這個事業的核心動力
    ↳ 這整個事業主要靠 Grok 機器人在撐。很多原本要人一件一件做的事，交給機器人自動處理，這家公司才有辦法在幾天內做出東西。
  • 80:45 一組 Grok bots 負責 software factory：自動修 bug、自動 play test、自動做 PR review
    ↳ software factory 是一條自動生產線：一組機器人分工，有的修 bug，有的試玩，有的做 PR review。PR 是「我改了這段程式，請合併進去」的申請；review 就是審核這份申請。
  • 80:45 正式環境一抓到 bug，bot 就會發現，接著叫 cloud agent 去修並開 PR
    ↳ 正式上線的遊戲一出錯，機器人會自己發現，然後派 cloud agent（在雲端跑、能自己寫程式的 AI 助手）去修，修好後開一份 PR 等審核。
  • 81:22 play tester bot 會拿到修改、放進遊戲引擎跑一遍確認正常，然後核准 PR；這是額外的一關，其他核准步驟和 CI 測試照跑
    ↳ 負責試玩的機器人會把改好的版本丟進遊戲實際跑一次，確認沒壞才核准。這是多加的一道關卡，原本的人工核准和 CI（每次改動都會自動跑的一整套測試）照樣要過。
  • 81:22 上述流程由 Grok bots 和 GitHub 搭配完成，另外也串接了其他工具
    ↳ 上面這條流程靠 Grok 機器人加上 GitHub 完成。GitHub 是工程師存放程式碼、提交和審核 PR 的平台。另外他們也串接了其他工具。
  • 81:22 Matt 正在用 Clerk 做身分驗證，團隊申請了 Clerk 開發者帳號來支援 login with X
    ↳ Clerk 是一個現成的登入服務，網站不用自己寫帳號密碼系統。Matt 用它做「用 X 帳號登入」，就像很多網站可以用 Google 帳號登入那樣。
  • 81:22 玩家用 X 登入後可以參加 leaderboard（排行榜）
    ↳ leaderboard 就是排行榜。玩家用 X 帳號登入才能上排行榜，因為有綁帳號，系統才知道每筆成績是誰打的。
  • 81:58 每位玩家都有一個 Elo score，打得好就能慢慢往上爬；排行榜只開放給用 Twitter 登入的玩家
    ↳ Elo score 是西洋棋用的積分制度：贏了加分、輸了扣分，打贏比自己強的人加更多分，所以打得好分數就會慢慢往上爬。排行榜只開放給用 X（Twitter）登入的玩家。
  • 81:58 app 裡也有 practice mode（練習模式）
    ↳ practice mode 是練習模式。不想登入、不想上排行榜，或只是想先熟悉規則，就可以在這裡玩，輸贏不影響積分。
  • 81:58 Matt 在整理 Clerk 設定，確認各個網域和 DNS 紀錄都指對地方
    ↳ DNS 就像網路的電話簿，把網址對到真正放網站的那台主機。Matt 在檢查每個網址都有對到正確的地方，不然登入或網站本身都會連不上。
  • 81:58 團隊開玩笑說「問題永遠出在 DNS」，剛剛才在除錯 DNS；也在處理 CORS（cross origin）問題
    ↳ 工程師圈常開玩笑「出事一定是 DNS 的錯」，因為這類問題常常很難查。CORS 是瀏覽器的安全規則，管一個網站能不能跟另一個網域拿資料，沒設好功能就會失靈。
  • 82:38 hosting 用的是 Vercel；從開發模式切到正式模式時，有很多 Vercel 設定要調
    ↳ hosting 就是找地方把網站放上網、讓大家連得到，他們用的是 Vercel 這家服務。從開發中的版本切換成正式對外的版本時，有很多設定要一個一個調。
  • 82:38 每個 PR 都會先測過；play tester bot 是透過 Vercel preview 來測（字幕在這裡中斷）
    ↳ 每個 PR 合併前都要先測過。Vercel preview 會替每次改動自動生一個臨時的試用網站，試玩機器人就在那個網站上測，不會動到正式版。字幕在這裡斷掉。
📘 術語
client secrets / web secrets（用戶端／網站機密金鑰）：部署時要管理的機密資料，團隊說不會在直播上部署正式環境的 secrets
card battler（卡牌對戰遊戲）：團隊做的遊戲類型，UI 改版的重點之一是讓卡牌看起來更精緻
UI polish pass（介面打磨）：幫整個遊戲「重新上漆」，讓卡牌更精緻
play test（試玩測試）：先推出試玩版，上線後再依回饋迭代；也有 bot 自動做試玩測試
software factory（軟體工廠）：由一組 Grok bots 管理，負責自動修 bug、自動試玩、自動審查
PR review（PR 審查）：bots 會自動做 PR review；play tester bot 確認沒問題後會核准 PR
cloud agent（雲端 agent）：bot 在正式環境抓到 bug 後，會叫它去修並開 PR
continuous integration suite（持續整合（CI）測試）：除了 play tester bot 核准之外，PR 還要通過的其他檢查
Clerk（Clerk（身分驗證服務））：負責處理身分驗證，用來做 login with X
login with X（用 X 帳號登入）：玩家登入後可以參加排行榜
leaderboard（排行榜）：開放給用 X（Twitter）登入的玩家
Elo score（Elo 分數）：每位玩家都有一個，打得好就能提升排名
practice mode（練習模式）：app 裡除了排行榜之外的另一種模式
DNS records（DNS 紀錄）：要確認網域都指對地方；團隊開玩笑說問題永遠出在 DNS
CORS (cross origin)（跨來源資源共用）：團隊正在除錯的 cross origin 問題
Vercel（Vercel（hosting 服務））：團隊用的 hosting provider，從開發切到正式模式時有很多設定要調
Vercel preview（Vercel 預覽環境）：play tester bot 透過它來測試每個 PR
