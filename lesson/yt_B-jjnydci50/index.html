🧑‍🏫 這支影片裡，測試者 Ben Davis 拿 DEF CON 解謎挑戰裡最難的題目考 GPT-6 Astra。結果它不只解出他們自己沒解出的題目，還搶先解出一題全世界都沒人解開的謎題。影片也說明它怎麼同時派出多個分身分頭試線索，想了解 AI 怎麼處理複雜任務的人可以看看。

  • 00:00 Astra 解出了他們自己沒解出的三題，還解出一題全世界沒人解出的謎題，是第一個解出的
    ↳ 講者和朋友當年卡住的三題，Astra 都解出來了。還有一題全世界沒人解開過，它是第一個解出的。也就是說，它不只追上人類，還跑到前面。
  • 00:00 測試方式：從 DEF CON 大會的解謎挑戰中挑出最難的題目丟給 Astra，他和朋友當時花了好幾天解這些題
    ↳ DEF CON 是一個大型會議，裡面有大型解謎挑戰。他們挑最難的題目給 Astra 做，這些題講者和朋友當年花了好幾天才解，是很硬的考卷。
  • 00:31 Rubik's cube 謎題：多個方塊排成 3×4 圖案，需從中推出訊息；Astra 三次都解出
    ↳ 這題把好幾顆魔術方塊（Rubik&#x27;s cube）排成 3×4，要從方塊的圖案推出藏在裡面的訊息。Astra 試了三次，三次都解出來，不是靠運氣。
  • 00:31 Astra 需要出題者的官方提示才能解出，但這和人類參賽者拿到的提示相同
    ↳ Astra 要有出題者的官方提示才解得出來。不過人類參賽者拿到的是同一份提示，所以這樣比較是公平的，不算偷吃步。
  • 00:31 串珠洋裝謎題：一件佈滿多色珠子的大洋裝，也要從中找出訊息；拿到主要提示後同樣解出
    ↳ 另一題是一件縫滿各色珠子的大洋裝，一樣要從珠子裡找出訊息。拿到主要提示之後，Astra 也把這題解出來了。
  • 01:01 這題需要看懂大量零散的圖片，而且照片拍得不好，Astra 仍然解出來了
    ↳ 這題要看懂一大堆零散的照片，而且照片拍得不好、看不太清楚。在資訊這麼不完整的情況下，Astra 還是拼出了答案。
  • 01:01 解題流程：模型先提出理論，再派另一個 agent 去測試，看結果後研究方向再分支
    ↳ 它解題像一個小組：先猜一個理論，再派另一個 agent（模型派出去執行任務的分身）實際去試，看完結果再分成幾條方向繼續往下挖。
  • 01:01 模型大約有 10 個欄位可以放其他 agent 去執行任務，這些 agent 平行運作
    ↳ 模型大約有 10 個位子可以派 agent 出去做事，它們同時進行。就像十個人分頭查不同線索，比一個人一條一條慢慢試快很多。
  • 01:32 主 agent 負責協調（orchestrating）這些平行的 agent
    ↳ 主 agent 負責 orchestrating（統籌調度）：決定派誰去試什麼、收回結果，再安排下一步，角色就像專案裡的組長。
  • 01:32 從起點到得出答案之間沒有中間驗證，模型很容易因錯誤假設走錯路、陷進行不通的方向
    ↳ 解謎從開始到答案之間沒有 verification（中間檢查），走到一半也不知道對不對。只要前面的假設錯了，後面就會一路錯下去，很容易鑽進死胡同。
  • 01:32 他發現這個模型比較能讓自己保持在正軌上，這是它能持續專注並解出題目的主要原因
    ↳ 講者發現，Astra 比較能讓自己不偏離正軌，不容易被錯的假設帶著跑太遠。他認為這是它能一直專注、最後解出題目的主要原因。
  • 01:32 他認為 sub-agent、swarm workflow 等讓多個 agent 實例合作的做法，現在已可處理更大更複雜的問題，值得嘗試
    ↳ sub-agent 是主 agent 派出去幫忙的其他 agent，swarm workflow 是讓多個 agent 一起合作。講者認為這類做法現在已經能處理更大更複雜的問題，值得試試。
📘 術語
DEF CON（DEF CON 大會）：一個大型會議，有大型解謎挑戰，講者和朋友花好幾天解題
agent（代理）：模型派出去測試理論、執行任務的單位，可以同時開多個
sub-agent（子代理）：由主 agent 派出、協助處理任務的其他 agent
swarm workflow（群集工作流程）：把多個 agent 實例放在一起，處理更大、更複雜的問題
orchestrating（協調編排）：主 agent 統籌多個平行運作的 agent
verification（驗證）：解題過程中間的檢查；缺少驗證時，模型容易因錯誤假設走偏
