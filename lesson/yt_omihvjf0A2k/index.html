🧑‍🏫 這支影片介紹 Claude Code 的新功能 Projects。你只要說出一個大目標，Claude 就會自己拆成小任務，分給好幾條工作線同時做，還會送出改動申請、修正錯誤，並每天幫你做檢查。如果你手上有大工程、又不想一條一條自己盯，這支很值得看；最後的三個秘訣能幫你省下方案額度。

  • 00:00 示範把一個大目標整個丟給 Claude。使用者不必自己規劃 sub-agents、管理多個 session 或 work trees，直接提出要求就好。
    ↳ 以前做大工程，得自己安排好幾個 session（一段跟 Claude 的工作對話）、sub-agents（分出去做子任務的小幫手）和 work trees（同一份程式碼的多個工作副本）。現在只要說出目標就好。
  • 00:00 Claude 會把目標拆成較小的任務，再分派給一個團隊平行處理。這個功能就是 Claude Code Projects。
    ↳ 重點在「同時做」。Claude 不是一件做完才做下一件，而是自己當工頭，把大目標切成幾塊，同時派給好幾個分身。這整套做法就叫 Claude Code Projects。
  • 00:00 project 是一個持續進行的對話，由 Claude 替你協調工作。你給它任務清單，它會為每個任務開一個 thread。
    ↳ project 不是問完就結束的問答，而是一條一直延續下去的主對話。你交一張待辦清單，Claude 就替每一項開一個 thread，也就是專門處理那件事的獨立工作線。
  • 00:00 每個 thread 都是獨立的 session，在雲端各自的 branch 上執行。
    ↳ 每個 thread 各做各的，互不干擾。它們都在雲端跑，各自有一個 branch（程式碼的分支）。可以想成在副本上修改，不會直接動到正式版本。
  • 00:33 因為在雲端執行，闔上筆電後工作仍會繼續，也可以用手機查看進度。
    ↳ 在雲端跑，代表運算不靠你的電腦。所以筆電闔上、人出門了，工作照樣進行。想看進度，拿手機打開就行。
  • 00:33 任務需要用到本機檔案或工具時，可以請 Claude 改在你的電腦上執行該 thread。
    ↳ 雲端碰不到你電腦裡的東西。如果某個任務需要用到你本機的檔案或工具，可以請 Claude 把那條 thread 改到你自己的電腦上跑。
  • 00:33 適用情境：橫跨多個 session 甚至多個 repo 的大目標。例如把 app 從已棄用的 package 遷移出來，或在 API、web、mobile 各 repo 更新同一個 endpoint。
    ↳ 適合一次對話做不完的事。例如換掉已停止維護的 package（別人寫好的程式套件），或在後端、網頁、手機各個 repo（專案程式碼庫）同步修改同一個 endpoint（對外的資料接口）。
  • 00:33 本片範例：建立一個 project，調查並修正網站一連串的效能問題，再設定每日檢查，及早抓到日後的 regression。
    ↳ 影片的實例是這樣：網站變慢有好幾個原因，讓 Claude 查清楚並修好。接著排每天自動檢查，提早抓到 regression，也就是原本正常的東西在改版後又退步了。
  • 01:05 開始方式：在桌面版或網頁版 app 開啟 Code 分頁，新增 project，填入名稱、Claude 要達成的目標，以及相關的 repo 或資料夾。
    ↳ 開始的方法：在桌面版或網頁版 app 點 Code 分頁，新增一個 project，然後填三樣東西：名字、你要 Claude 達成什麼，以及它要處理的 repo 或資料夾。
  • 01:05 建立後會進入 main conversation，你在這裡跟 Claude 對話，它也在這裡協調工作。你可以選它提供的建議、問個簡短問題，或給它任務清單。
    ↳ 建好後會進到 main conversation（主對話），這裡就是你和 Claude 的指揮台。你可以點它給的建議、隨口問個問題，或直接丟一張任務清單給它。
  • 01:35 示範中提供了指標與使用者回饋，請 Claude 探索 codebase 並建議如何改善效能。Claude 探索 repo 後回報它的發現。
    ↳ 示範的人先給了速度數據和使用者回饋，請 Claude 去翻 codebase（整個專案的程式碼），找可以改善的地方。Claude 看完後先回報它發現了什麼，沒有直接動手改。
  • 01:35 雙方決定好要做哪些工作後，Claude 會為每個任務各開一個 thread。
    ↳ 流程是先討論、後分工。你和 Claude 談定要做哪幾件事之後，它才替每件事各開一個 thread，開始同時動工。
  • 01:35 多數時候可以讓 thread 自己跑。你也可以點選卡片追蹤 Claude 的進度、在 thread 裡對話來引導任務，或直接停止。
    ↳ 大多數時候放著讓它跑就好。想插手的話，點開那個任務的卡片，就能看進度、在裡面跟它對話調整方向，或直接叫停。
  • 01:35 在 Threads 分頁可以看到正在等你回應的 thread。
    ↳ 你不用一條一條去巡。Threads 分頁會列出哪些 thread 正在等你回覆，看那裡就知道哪邊需要你出手。
  • 01:35 thread 一有具體變更（例如 bug fix）就會自行開 pull request，你要求時也會開。
    ↳ thread 改好東西，例如修好一個 bug，就會主動開 pull request（PR），意思是「我改好了，請審核後併進正式版本」的申請。你要求的話，它也會開。
  • 02:07 開 PR 後，thread 會持續關注這個 PR：CI 失敗時推送修正，也會處理 review 意見。
    ↳ 開完 PR，它會繼續追蹤。如果 CI（每次改動後自動執行的檢查和測試）沒通過，它會修好再送；有人留下審查意見，它也會去處理。
  • 02:07 Claude 會在 main conversation 顯示 PR 的下一步。要查看所有 PR 及其狀態，請到 Overview 裡的 Pull Requests 分頁。
    ↳ 每個 PR 接下來該做什麼，Claude 會在主對話告訴你。想一次看所有 PR 和它們目前的狀態，就到 Overview 裡的 Pull Requests 分頁。
  • 02:07 準備好 merge 時，直接跟 Claude 說即可。
    ↳ 確認沒問題、要 merge 的時候，不用自己操作。merge 就是把改動正式併進主要版本。你直接跟 Claude 講一聲就行。
  • 02:07 Projects 也支援 artifacts。示範中請 Claude 做一份變更摘要，附上修正前後的效能指標，方便分享給團隊。
    ↳ artifacts 是 Claude 做出來的成品文件。示範中請它寫了一份變更摘要，附上修正前後的速度數據，可以直接轉給團隊看。
  • 02:37 artifacts 放在 library 分頁。library 可以想成 project 的共享資料夾，存放 Claude 建立的 artifacts，以及你自己加入的檔案（例如 mockups 或 design spec）。
    ↳ library 是這個 project 的共用資料夾。裡面放 Claude 做的成品，也能放你自己的檔案，例如 mockups（畫面設計示意圖）或 design spec（設計規格書）。
  • 02:37 每個 thread 都能存取 library，所以下次處理效能問題時，Claude 可以直接更新這份報告。
    ↳ 因為每條 thread 都讀得到 library，下次再處理效能問題時，Claude 不用從頭重做報告，直接更新原本那一份就好。
  • 02:37 為了預防日後的 regression，把 Claude 連上監控服務，讓它能自己查看真實使用者的指標。
    ↳ 為了防止網站日後又變慢，把 Claude 接上監控服務（持續記錄網站實際表現的工具）。這樣它就能自己看真實使用者的數據，不用等你提供。
  • 02:37 接著請 Claude 設定一個每天執行的 routine，檢查有沒有效能 regression。
    ↳ 接著請 Claude 設定一個 routine，也就是定時自動執行的例行工作。這裡設成每天跑一次，檢查效能有沒有退步。
  • 03:08 Claude 一旦發現 regression，就會開一個 thread 去調查。等你下次查看時，它已經在 project 裡執行。
    ↳ 一抓到退步，Claude 會自己開一個 thread 去查。等你下次打開 project，調查已經在進行中，不必等你發現問題才開始。
  • 03:08 秘訣一：每個 thread 都是完整的 Claude Code session，一個 project 可以同時跑好幾個，因此用掉方案額度的速度比單一 session 快。可在 project settings 調整 model 和 effort level 來控管用量。
    ↳ 秘訣一：每條 thread 都是完整的 Claude Code 工作，好幾條一起跑，額度自然用得比較快。可以在 project settings 調整 model（用哪個 AI 模型）和 effort level（思考投入程度）來控管用量。
  • 03:38 coordinator 維持 low effort 即可。它主要負責分派工作，調高等級也不會得到明顯更好的結果。
    ↳ coordinator 是負責分派工作的總協調者，設成 low effort 就夠了。它主要只是派工，等級調高也不會明顯變好。
  • 03:38 大部分工作由 thread 完成，但每個任務的範圍都很明確。可以考慮預設用較小的模型，遇到較大、較複雜的任務時再到該 thread 切換。
    ↳ 真正動手做事的是 thread，但每個任務的範圍都很明確。所以可以預設用小一點的模型，遇到大而複雜的任務，再到那條 thread 單獨換成大模型。
  • 03:38 秘訣二：可以告訴 Claude 你希望它怎麼工作，例如同時跑幾個 thread、多久向你更新一次，或開工前先讓你看計畫。
    ↳ 秘訣二：工作方式可以直接跟它講好。例如最多同時開幾個 thread、多久回報一次，或者先讓你看計畫，你點頭了才開工。
  • 03:38 秘訣三：threads 共享 memory。可以請 Claude 記住某個偏好並套用到之後所有 thread，也能在 project settings 編輯 memory。
    ↳ 秘訣三：memory（Claude 記住的偏好和規則）是所有 thread 共用的。你說一次「以後都這樣做」，之後每條 thread 都會照辦。你也能到 project settings 手動修改。
  • 04:08 總結：目標大到一個 session 處理不完時，可以試著開 project。把目標交給 Claude 拆成 threads，等它需要你時再查看。
    ↳ 判斷很簡單：一次對話做不完的大目標，就開一個 project。你負責交代目標，Claude 負責拆工和推進，它需要你的時候你再去看。
  • 04:08 Claude Code projects 目前為 beta，正逐步開放給 Pro 和 Max 方案。詳情請看影片下方連結的文件。
    ↳ 目前是 beta，也就是還在測試、功能可能會調整的版本。正在分批開放給 Pro 和 Max 方案，不一定已經輪到你。細節請看影片下方連結的文件。
📘 術語
Project（專案）：一個持續進行的對話，由 Claude 替你協調工作，並為每個任務開 thread。
Thread（執行緒（子任務對話））：獨立的 session，在雲端各自的 branch 上執行；每個都是完整的 Claude Code session。
Main conversation（主對話）：你跟 Claude 對話、它協調工作的地方，PR 的下一步也會顯示在這裡。
Library（資料庫／共享資料夾）：project 的共享資料夾，存放 artifacts 和你加入的檔案，每個 thread 都能存取。

Coordinator（協調者）：主要負責分派工作，建議維持 low effort。
