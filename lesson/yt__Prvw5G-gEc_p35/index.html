    ↳ 最常被點開的是登入頁、贊助頁（sponsor）和意見回饋頁（feedback）。大部分人是在 X（原本的 Twitter）上點連結進來，也有人直接打網址進來。

    ↳ 當天的重點新功能是 voice mode（語音模式）。Grokbot 現在能開口講話，也聽得懂你說的話，不用打字，直接用講的就能交代事情。
  • 404:43 現場示範：用語音和名為 bake 的 bot（founding engineer）對話，詢問自己有哪些 PR 還開著、是否被卡住

    ↳ bot 回報：PR 269 修的是重抽時卡死的問題，CI 綠燈，CI 是自動跑的檢查，綠燈代表全部通過。PR 220 還是 draft（草稿），而且有 merge conflicts，也就是跟別人改到同一段程式、互相打架。
  • 405:13 用語音指示 bot 合併 PR 269，並派一個 agent 去解決 PR 220 的 merge conflicts，bot 答應稍後回報進度
    ↳ 講者用說的叫 bot 把 269 合併（merge），也就是把改動正式併進主程式。接著派一個 agent 去處理 220 的衝突，agent 是能自己接任務、動手做事的 AI。bot 答應晚點回報進度。
  • 405:47 講者形容這種用法就像和隊友開 huddle 一樣
    ↳ huddle 是團隊聊天軟體 Slack 裡隨手開的語音小會議。講者的意思是：跟 bot 講話就像跟同事開個快會，交代完大家各自去做。
  • 405:47 voice mode 當天才推出，接下來幾天會陸續開放到各帳號；講者感謝 xAI 團隊
    ↳ 語音功能當天才上線，接下來幾天會分批開放給各個帳號，所以你現在還看不到是正常的。講者也謝謝 xAI（開發 Grok 的公司）團隊。
  • 405:47 團隊成員近況：一位持續修 UI 細節和 bug；bug 回報會記錄在 Slack，由他的「bot factory」負責重現、修正、合併
    ↳ 一位成員在修 UI（畫面上看得到、按得到的部分）的小細節和 bug（程式錯誤）。使用者回報的 bug 記在 Slack，由他的一群 bot 自己重現、修好、合併，像工廠生產線。
  • 406:22 另一位在建置 ads marketplace，目前需要做 blob storage 的整合，正在處理 environment variable
    ↳ 另一位在做廣告交易平台（ads marketplace），要接上 blob storage，也就是存圖片、影片這類大檔案的雲端倉庫。他正在設定 environment variable，就是放金鑰、連線設定的參數。

📘 術語
voice mode（語音模式）：Grokbot 當天推出的新功能，Grokbot 有聲音、可以跟你對話
PR (pull request)（合併請求）：字幕中 bot 回報 PR 狀態，例如 CI 綠燈、draft、有 merge conflicts
CI green（CI 通過）：字幕說 PR 269 CI 綠燈，所以沒有阻礙、可以合併
merge conflicts（合併衝突）：PR 220 有 merge conflicts，所以派 agent 去修
draft（草稿）：PR 220 仍處於 draft 狀態
agent（代理程式）：可以被派去處理任務的 AI，例如修 merge conflicts、重現並修 bug
elo system（elo 評分系統）：排行榜依玩家表現給每個人一個評分
OJ image（連結預覽圖）：分享連結時產生的圖片；字幕提到用 Takumi 產生，且通常是動態的
Takumi（Takumi（開源函式庫））：和 Satori 類似但用 Rust 寫，能把 JSX 轉成圖片，用來產生 OJ image
Kanban board（看板）：管理待辦的看板，字幕提到大部分項目在 done 欄位
MCP（MCP）：有人提議用類似 MCP 的方式，讓 bot 之間可以互相對戰
anti-pattern（反模式）：agent 寫出的不良寫法，講者會找出來並加規則檢查
lit rules（檢查規則）：講者發現 anti-pattern 後加上規則來自動檢查（字幕原文為 lit rules）
skill（技能）：potato mode 內建的功能，例如 no comments skill 會啟動刪註解的 agent
blob storage（物件儲存）：建置 ads marketplace 時需要整合的儲存服務
✏️ 小考一題

講者為什麼在 Grokbot code base 中禁止 agent 留註解？

A. 因為註解會讓 CI 跑不過B. 因為 agent 常用註解替 workaround 或 hack 找理由，卻沒修好根本原因C. 因為 xAI 團隊規定不能寫註解D. 因為註解會拖慢 OJ image 的產生速度
看答案
答案：B。[413:54]–[414:24] 講者說 agent 用註解替 workaround 或 hack 辯護，從沒修好根本原因，檔案會充滿 band-aid 而變得脆弱，所以在 Grokbot code base 中禁止註解
