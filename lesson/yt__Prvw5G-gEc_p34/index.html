🧑‍🏫 這段前半是 Josh Kim 分享怎麼用 Grokbot 做行銷：怎麼讓好幾個 bot 分工合作、怎麼替 bot 客製個性、怎麼把別人做好的 bot 學過來。後半回到攝影棚，xAI 的 Eric 公布他們 72 小時做出來的遊戲 ThursdayArena 上線後的真實數據。想知道 AI 助理實際上怎麼當成團隊來用，這段有很多可以直接照做的做法。

  • 391:44 講者認為 bot 跟 campaign 不同，會一直運作，應該把它當成會越來越進步的個人或隊友
    ↳ campaign（行銷活動）通常有開始和結束的日期，bot（自動幫你做事的 AI 程式）卻會一直運作。所以別把它當成用一次就丟的工具，要像帶新同事一樣持續調教，讓它越做越好。
  • 391:44 一個 initiative 由好幾個個體一起負責：先分清楚每個人的 swim lanes，再把他們放進同一個 chat 一起做專案
    ↳ initiative（要一起推動的目標）通常不是一個 bot 就能搞定。先劃清 swim lanes（每個人各自負責的範圍，像泳道一樣各游各的），免得搶工作或漏掉，再把大家拉進同一個群組 chat 一起做。
  • 392:20 例子：把幾個 bot 組成 Tiger team 負責改善網站定位，群組 chat 的 initiative 是「website conversion」
    ↳ Tiger team 指為了特定任務臨時組成的精銳小組。講者讓幾個 bot 組隊專攻網站定位，群組的目標設成 website conversion，也就是讓更多訪客真的註冊或購買。
  • 392:20 觀眾提問：他在 Open Claw 上的 agent 叫 Ariel，個性一致又會嗆人，Grokbot 能不能也有穩定的個性？
    ↳ 有位觀眾在 Open Claw（另一套 AI 助理工具）上養了一個叫 Ariel 的 agent（能自己執行任務的 AI 助理），個性固定、還會嗆人。他問 Grokbot 能不能也維持這麼穩定的個性。
  • 392:53 講者當場示範：只給一個字「AIREAL」，請 Grokbot 依照這個字更新 avatar 並加上動畫
    ↳ 講者沒多解釋，只丟「AIREAL」一個字，叫 Grokbot 自己照這個名字重新設計 avatar（bot 的頭像）並做成動畫，示範只給很少的指令它也能自己動手。
  • 393:28 更新 avatar 不算個性設定，但這是很簡單的客製化方式，能讓產品感覺是自己的
    ↳ 講者坦白說，換頭像不算設定個性。不過這是最省力的客製方式，換完之後 bot 看起來就是「你的」，用起來比較有歸屬感。
  • 393:28 每個 bot 都有自己的 context 和 memory，例如可以要求 project manager 用 Harry Potter 的口吻說話，每次都叫你 wizard
    ↳ context 是 bot 做事時參考的背景資料，memory 是它長期記住的東西。每個 bot 各有一份，所以可以各自設定，例如讓專案經理 bot 用哈利波特的口吻，每次都叫你 wizard（巫師）。
  • 394:04 可以讓 Grokbot 去讀你現有的 agent，請它照樣複製一份，搬到 Grokbot 這邊
    ↳ 如果你已經在別的平台養好一個 agent，不用從頭設定。可以叫 Grokbot 去讀那個 agent 的設定，照樣複製一份到 Grokbot 裡。
  • 394:04 Open Claw 跟 Grokbot 目前沒有原生的互通方式，但有 import templates
    ↳ 目前兩邊不能直接連通，但有 import templates（匯入用的現成範本），可以把設定套進來，算是搬過來的替代做法。
  • 394:34 有人問 Grokbot 會不會上 Tesla，講者只回「We'll see」
    ↳ 講者沒證實也沒否認，只說「We&#x27;ll see」（再看看），所以目前沒有任何明確消息。
  • 395:11 回答能否串接 Grok build CLI：示範的 landing page 後端接的是 cursor，用 cloud agents 啟動工作並推送 PR，其他 coding 工具也能這樣接
    ↳ CLI 是打字下指令操作的工具。示範用的 landing page（宣傳用單頁網站）後端接的是寫程式工具 Cursor，由 cloud agents（在雲端跑的 AI）開工並送出 PR（程式修改申請）。其他寫程式工具也能這樣接。
  • 395:11 不用重建 context：讓 Grokbot 直接讀你既有的工作，把它當成這些工作的 harness
    ↳ harness 在這裡指把各種工作串起來統一操作的外殼。意思是原本的文件和工作不用重新餵一遍，讓 Grokbot 直接讀，它就能當你的總控台。
  • 395:49 德國觀眾提問：歐洲 B2B 法規嚴格，要怎麼確保公司資料不外流、不被拿去訓練？
    ↳ B2B 是企業對企業的生意。德國觀眾擔心歐洲對公司資料管得很嚴，想知道資料交給 Grokbot 會不會外流，或被拿去訓練 AI 模型。
  • 396:21 有 data privacy modes 可以選擇開或關，自己決定資料要不要被拿去訓練；安全性問題則是逐案處理，現場有團隊可以諮詢
    ↳ data privacy modes 是隱私模式開關，資料能不能被拿去訓練由你自己決定。更細的安全疑慮沒有一體適用的答案，要逐案討論，現場有團隊可以問。
  • 396:53 講者展示改好的 avatar；他自己的 avatar 原本是 Machimaro 主題，大約一週前換掉；avatar 可以完全客製並加上動畫
    ↳ 講者秀出改好的頭像，也提到自己的頭像原本是 Machimaro 主題，大約一週前換掉。重點是頭像可以完全照你的意思設計，還能加動畫。
  • 397:27 觀眾問講者怎麼把好幾個 bot 組合成新 bot，因為一般人只會去 marketplace 挑最好的那一個
    ↳ 一般人的習慣是上 marketplace（大家上架 bot 的市集）挑評價最好的一個直接用。觀眾好奇講者怎麼把好幾個 bot 混成一個新的。
  • 397:57 以 product positioning bot 為例，第一步：先用口述給它幾分鐘的初始 prompt，說明自己怎麼思考這件事
    ↳ 以幫產品找定位的 bot 為例，第一步是用說的，花幾分鐘告訴它你怎麼想這件事，當作初始 prompt（給 AI 的起始指示），讓它先懂你的思路。
  • 397:57 第二步：從現有網站抓 tone and voice
    ↳ 第二步讓 bot 讀你現有的網站，抓出 tone and voice（說話的語氣和品牌風格），之後它寫的東西才會像你們家說的話。
  • 397:57 第三步：在 marketplace 挑兩三個喜歡的 bot，把網址丟給它，請它抓取那些 bot 的 context 和 memory，複製成自己的做法
    ↳ 第三步是去 marketplace 挑兩三個你喜歡的 bot，把網址丟給自己的 bot，叫它讀那些 bot 的 context 和 memory，學起來變成自己的做法。
  • 398:35 最後串接 Superme：這是產品定位、包裝等領域的專家 marketplace，有 plug-in 可用
    ↳ Superme 是找產品定位、包裝等領域專家的平台。它有 plug-in（讓兩套系統直接接起來的外掛），所以 bot 可以直接連過去用。
  • 398:35 講者請 bot 不做大規模質性研究，改成每項產出都找 Superme 上的專家把關；bot 會直接跟 Superme 溝通，講者不用自己上網站、註冊帳號
    ↳ 講者不叫 bot 做大規模的質性研究（例如訪談），改成每份產出都請 Superme 上的真人專家把關。bot 自己跟 Superme 溝通，講者不用上網站註冊帳號。
  • 399:07 這段是 Josh Kim 分享 Grokbot 用於行銷；接著回到攝影棚，xAI 團隊的 Eric 加入
    ↳ Josh Kim 分享 Grokbot 怎麼用在行銷，到這裡告一段落。接著畫面切回攝影棚，由 xAI（開發 Grok 的公司）團隊的 Eric 接手。
  • 399:43 這是三天直播，目標是 72 小時內打造一個新事業，現在進入最後幾個小時的收尾階段
    ↳ 整場是連續三天的直播，挑戰在 72 小時內從零做出一個新事業。現在只剩最後幾個小時，準備收尾。
  • 400:13 這個事業是遊戲工作室，今天早上推出第一款遊戲 ThursdayArena；官方管道只有 ThursdayArena.com 和 X 帳號 ThursdayArena，其他帳號都不是他們
    ↳ 他們做的是遊戲工作室，第一款遊戲 ThursdayArena 今天早上上線。官方管道只有 ThursdayArena.com 和 X 上的 ThursdayArena 帳號，其他自稱官方的都不是。
  • 400:44 接下來要加新功能，也會做廣告和營收；今天花了一些時間在成長上，正在落實一份 growth playbook
    ↳ 遊戲上線還不是終點，後面要加功能、放廣告、開始賺錢。今天也花時間在拉用戶上，正照著一份 growth playbook（衝成長的步驟手冊）執行。
  • 401:15 用一個 data bot（講者的 data scientist）盯產品上線狀況，大約每 15 分鐘回報一次，即時 dashboard 接的是 production data stores
    ↳ 他們讓一個 data bot 當資料分析師，大約每 15 分鐘回報一次上線狀況。dashboard（即時數據儀表板）直接接 production data stores，也就是正式營運的真實資料庫。
  • 401:47 資料有兩組。第一組是 Vercel analytics，提供 page views 和 referral links：從當天中段開啟 analytics 到現在約 17,000 次 page views
    ↳ Vercel analytics 是網站流量統計工具：page views 是網頁被看的次數，referral links 顯示訪客從哪個連結來。從當天中段開啟到現在，累積約 17,000 次瀏覽。
  • 401:47 第二組是使用數據：練習賽剛好 4,500 場，X 登入接近 2,000 次，講者希望接下來幾小時衝到 5,000
    ↳ 第二組是實際使用數據：練習賽剛好打了 4,500 場，用 X 帳號登入的接近 2,000 次，講者希望接下來幾小時衝到 5,000。
  • 402:21 打過練習賽的使用者約 8% 會用 X 登入以進入排行榜；對戰總數接近 5,000 場；早上剛上線時流量有明顯高峰
    ↳ customer funnel（轉換漏斗）是看用戶一步步往下走時還剩多少人。這裡約 8% 打過練習賽的人會再用 X 登入，才能上 leaderboard（排行榜）。對戰總數接近 5,000 場，早上剛上線時流量最高。
  • 402:53 App 內的回饋會送進 Slack channel，由 agents 和真人一起看，盡量把回饋放進產品
    ↳ 玩家在遊戲裡留的意見會自動送進 Slack（團隊聊天工具）的頻道，由 AI agents 和真人一起看，能改的就盡量放進產品裡。
  • 402:53 流量圖上的高峰大多出現在每次回到直播的時候
    ↳ 流量圖上的高峰大多出現在直播切回這個專案的時候，看得出直播曝光直接帶來人潮。
📘 術語
swim lanes（分工範圍）：每個個體在一個 initiative 裡各自負責的範圍，先分清楚再把大家組成 chat
Tiger team（專案小組）：講者舉例把幾個 bot 組成一組，專門改善網站定位
initiative（專案目標）：一群個體一起在群組 chat 裡推動的目標，例如 website conversion
context and memory（脈絡與記憶）：每個 bot 都有自己的一份，所以可以各自客製說話風格
import templates（匯入範本）：Open Claw 跟 Grokbot 目前不能原生互通，但有 import templates 可用
cloud agents（雲端 agent）：示範的 landing page 用它啟動工作並推送 PR
PR（Pull Request）：字幕說 cloud agents 會把 PR 推送出去
harness（框架／外殼）：讓 Grokbot 讀你既有的工作，把它當成這些工作的 harness，不用重建 context
data privacy modes（資料隱私模式）：可選擇開或關，決定資料要不要被拿去訓練
marketplace（市集）：可以找到別人做好的 bot，講者從上面挑兩三個來複製它們的 context
Superme（Superme）：產品定位、包裝等領域的專家 marketplace，有 plug-in 可以串接
plug-in（外掛）：讓 bot 直接跟 Superme 溝通，不用自己上網站、註冊帳號
Vercel analytics（Vercel 分析工具）：提供 page views 和 referral links 等統計
customer funnel（顧客漏斗）：從練習賽到用 X 登入進入排行榜的轉換過程
leaderboard（排行榜）：使用者用 X 登入後才能上榜
