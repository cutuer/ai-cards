🧑‍🏫 這段是 Opus 5.5 實測的最後一段。作者先交代「抓車」測試失敗的原因，再示範兩款遊戲：一款是很多人拿來考模型的地鐵射擊遊戲，另一款是他自己新想的吉他行遊戲。最後他說，這些測試其實只用掉很少的額度。想知道它做遊戲到底多強、在沒看過的題目上表現如何，這段最有參考價值。

  • 25:07 前一個抓車測試：約 10～15 分鐘時，把 effort 從 max（或 X high）降到 high；約 1 小時 10 分時停止，因為夾爪下降不夠，沒抓到車
    ↳ 抓車測試跑了約10～15分鐘，作者把 effort（模型要花多少力氣思考，分 max、X high、high 等級）從最高調到 high。跑到約1小時10分就停了，因為夾爪降不夠低，一直抓不到車。
  • 25:07 這個測試它一步步有條理地嘗試，後端實作令人印象深刻，但沒有完成任務
    ↳ 它沒有亂試，而是照順序一步步排查。背後的程式邏輯（後端）寫得很扎實，只是最後還是沒抓到車，任務沒有完成。
  • 25:07 作者推測如果時間和 token budget 無限，它一定做得到；他也懷疑改用較低的 reasoning effort 也許反而比較好
    ↳ 作者猜，只要不限時間和 token budget（能用多少 token，token 是模型算用量的單位），它遲早做得到。他也懷疑 reasoning effort 調低一點，結果說不定更好。
  • 25:38 Subway FPS 一開始不小心沒在 Claude Code 裡啟動，結果它試著在瀏覽器裡做，所以完全停掉重來，改用 max effort
    ↳ Subway FPS 是在地鐵站裡的第一人稱射擊遊戲。作者一開始忘了在 Claude Code（讓 Claude 直接在電腦上寫程式的工具）裡開，它就改在瀏覽器裡做。作者乾脆全部停掉，用 max 重來。
  • 25:38 用 max 跑了大約一小時後降回 X high，因為這個測試可能被 benchmark，他想拿額度去做一個確定不會被 benchmark 的測試
    ↳ 用 max 跑了約一小時，作者降回 X high。原因是這題可能是 benchmark（大家拿來比模型的常見考題），他想把額度留給一題確定沒人考過的題目。
  • 26:08 Subway FPS 成果：有滑鼠靈敏度、視野、音量、畫質設定（有 ultra）；場景有像工地燈的光源和「Day nine, don't let them in」字樣
    ↳ 做出來的遊戲有設定選單，可以調滑鼠靈敏度、field of view（畫面看出去有多寬）、音量和畫質，畫質最高到 ultra。場景有像工地燈的照明，牆上寫著「Day nine, don&#x27;t let them in」。
  • 26:38 遊戲裡有多種武器，連霰彈槍的木紋都有做出來
    ↳ 遊戲裡有好幾種武器，連霰彈槍槍托的木頭紋路都畫出來了，細節做得很足。
  • 27:22 作者覺得音效比這類遊戲平常聽到的好；牆上沒有彈孔，因為子彈會反彈
    ↳ 作者覺得音效比這類 AI 做的遊戲平常好。牆上看不到彈孔，是因為遊戲設定子彈打到牆會彈開，不算漏做。
  • 28:03 作者評價很棒，但提醒這已經是常見的 benchmark，有可能是被刻意設計成表現這麼好
    ↳ 作者覺得成果很棒，但也提醒：這題已經被很多人拿來考，模型可能事先被特別調教過，所以不能直接當成實力證明。
  • 28:42 有反射效果，列車加速的方式做得很好，玩家還可以走進隧道
    ↳ 地面有反光效果。列車進站、出站的加速做得很自然，玩家還可以走進隧道裡。
  • 29:44 總結 Subway FPS：音效設計大幅勝過他看過的其他結果；列車先慢後快的加速很接近現實；磁磚畫得很好
    ↳ 作者對 Subway FPS 的總評：音效比他看過的其他版本好很多，列車先慢後快的加速很像真的，牆上磁磚也畫得漂亮。
  • 30:16 最後一個測試是作者自創、從沒做過的題目，目的是確認模型在完全沒看過的東西上也一樣強
    ↳ 最後一題是作者自己想的、從來沒考過的題目。目的是確認模型碰到完全陌生的東西，也能做得一樣好，不是只會背答案。
  • 30:16 Prompt：用 3js 做瀏覽器遊戲 Guitar Store Shred，店面仿 Guitar Center，所有樂器都能互動；要有吉他、鍵盤、鼓組、貝斯，每種都有擬真的數量和款式
    ↳ 他給的 prompt（下給 AI 的指令）要求用 Three.js（在網頁上做 3D 畫面的程式工具）做一款吉他行遊戲，店面仿照美國樂器連鎖店 Guitar Center。店裡要有吉他、鍵盤、鼓、貝斯，數量和款式要像真的。
  • 30:46 Prompt 續：NPC 店員和顧客共用一種 anger bar，玩樂器越吵值越高，太高時他們會攻擊你，變成 beat 'em up；要求高畫質、好玩、有音效又擬真
    ↳ 店員和客人是 NPC（電腦控制的角色），共用一條 anger bar（怒氣條）。你玩樂器越吵，怒氣越高，爆表時他們會來打你，遊戲就變成 beat &#x27;em up（一路打架的遊戲）。
  • 30:46 這個任務在 Extra 上跑了超過 2 小時，全程沒降 effort；最後要它存到本機，方便實際測試
    ↳ 這題用 Extra 等級跑了兩個多小時，中間都沒降 effort。最後作者叫它把檔案存到自己電腦上，方便實際打開來玩。
  • 31:17 遊戲很卡，因為它做了 340 個獨立的吉他模型；有語音台詞和畫質選項，開場廣播「Welcome to Shred Center」
    ↳ 遊戲很卡，因為它做了 340 把各自獨立的吉他模型，電腦跑不動。遊戲有角色語音和畫質選項，一開場會廣播「Welcome to Shred Center」。
  • 31:49 吉他都有名字，也能拿起來，例如 Fender Custom Shop 63 Stratoblaster（作者說好笑，因為真品叫 Stratocaster）；另外有背景音樂、Flying V、音箱和木吉他專區
    ↳ 每把吉他都有名字，也拿得起來。有一把叫 Stratoblaster，作者覺得好笑，因為真品叫 Stratocaster。店裡還有背景音樂、Flying V 造型吉他、音箱區和木吉他區。
  • 32:20 有 J-45、Epiphone Hummingbird 等型號，但作者沒看到 resonator 吉他
    ↳ 還有 J-45、Epiphone Hummingbird 這些真實存在的型號，不過作者沒看到 resonator（琴身裝金屬共鳴盤的吉他），這個類別缺了。
  • 32:54 作者說畫面沒有應有的好，是因為延遲太嚴重，但它完成的工作量很驚人
    ↳ 作者說畫面沒有應有的好看，主要是太卡、延遲太重拖累了，但它一口氣做出的東西量多到很驚人。
  • 34:09 店內有鼓組；作者覺得幾乎不可能把怒氣值拉到那麼高
    ↳ 店裡有鼓組可以打。作者覺得怒氣條很難拉到會被攻擊的程度，可能要非常吵才會觸發。
  • 34:54 走到音箱前按 E 可以互動；吉他可以摔在地上（例如一把 $4,000 的吉他），NPC 會喊 Security
    ↳ 走到音箱前按 E 可以互動。吉他可以直接摔在地上，例如一把 4,000 美元的琴，旁邊的 NPC 就會喊「Security（保全）」。
  • 35:25 作者認為 Three.js 不是做這個遊戲的最佳選擇，打算讓它改用 Blender 和 Godot 重做
    ↳ 作者認為 Three.js 不是做這種遊戲的最好選擇。他打算請 Claude 改用 Blender（做 3D 模型的軟體）和 Godot（做遊戲的引擎）重做一次。
  • 35:25 遊戲裡可以抓住經理，吉他也能拿來當武器
    ↳ 玩家可以把經理抓起來，吉他也能拿來當武器打人，打鬥那一段確實有做出來。
  • 36:05 作者做這個測試，是為了找一個絕對不可能出現在 training data 裡的題目；吉他還能被砸碎，他會讓 Claude 繼續做這款遊戲
    ↳ 他出這題，是要找一個絕對不可能出現在 training data（模型學習時看過的資料）裡的題目。吉他還砸得碎，他打算讓 Claude 繼續把這款遊戲做下去。
  • 36:40 用量：整支影片的測試沒用掉多少用量。作者說官方表示 usage limits 已經提高，這些測試只讓用量增加微不足道的量
    ↳ 用量方面，整支影片的測試都沒吃掉多少額度。作者說官方表示 usage limits（每段時間能用多少的上限）已經調高，這些測試只多用了一點點。
  • 36:40 作者這次不做結果總覽，評語是「This model slaps」，建議想看總覽的人直接看影片
    ↳ 作者這次不做結果總整理，只丟下一句「This model slaps」（英文俚語，意思是這模型超讚），想看整理的人請直接看影片。
  • 37:13 作者認為這個模型是 game creation monster，其他方面可能也不錯，除了 frontier LLM development
    ↳ 作者認為它是做遊戲的怪物，其他用途應該也不錯。唯一的例外是開發最尖端的大型語言模型，他覺得這件事它還辦不到。
📘 術語
effort level / reasoning effort（推理投入程度）：字幕提到 max、X high（Extra）、high 幾個等級，作者在任務中途調降過
token budget（token 預算）：作者認為如果時間和 token budget 無限，模型應該能完成抓車任務
benchmark（基準測試）：常見的測試題目；作者擔心模型可能被刻意設計成在這類題目上表現好
training data（訓練資料）：作者刻意出一個不可能出現在訓練資料裡的題目來測模型
Three.js（3js）（Three.js（網頁 3D 函式庫））：prompt 指定用它做瀏覽器遊戲；作者事後認為它不是最佳選擇
Blender / Godot（Blender／Godot）：作者打算讓 Claude 改用這兩套工具重做吉他行遊戲
NPC（非玩家角色）：遊戲裡的店員和其他顧客
anger bar（怒氣條）：玩樂器越吵值越高，太高時 NPC 會攻擊玩家
beat 'em up（清版格鬥遊戲）：怒氣條爆表後，遊戲會變成這種打鬥玩法
field of view（視野）：Subway FPS 設定選單裡的一個選項
usage limits（用量上限）：作者說官方表示已經提高，本片的測試只用掉微不足道的量
