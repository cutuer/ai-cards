🧑‍🏫 這支影片是 Anthropic 發表 Claude Tag 的介紹：在團隊的聊天頻道裡點名 Claude，它就會加入討論並直接動手做事。值得看是因為它示範了 AI 怎麼從「一個人跟它聊天的工具」變成「團隊裡的一員」，也講清楚了它能碰什麼、會記得什麼的界線。

  • 00:12 講者 Lydia 在 Anthropic 負責 Claude Code，今天發表 Claude Tag，讓 Claude 能直接跟你的團隊一起協作
    ↳ Claude Code 是 Anthropic 給寫程式用的 Claude 工具，Lydia 負責這一塊。這次推出的 Claude Tag，就是在團隊頻道裡 tag（點名）Claude，讓它加入一起做事。
  • 00:12 Anthropic 今年大部分時間都在 tag Claude 進來幫忙，這已經是他們現在的工作方式
    ↳ 這不是剛做出來的實驗品。Anthropic 自己今年大部分時間都這樣工作，有事就在頻道裡叫 Claude 進來。他們是自己先用了很久，才拿出來推。
  • 00:12 在 Anthropic 內部，65% 的產品 pull request 是由 Claude Tag 開的
    ↳ pull request（PR）是工程師提出的申請：「我改了這些程式碼，請審過後併進正式版本」。Anthropic 內部產品的這種申請，有 65% 是 Claude Tag 開的。
  • 00:12 範例情境：某團隊距離產品上線約一週；Drew 從業務那邊聽說 Scheduled Exports 這個功能是他們最大幾筆交易在等的東西
    ↳ 情境是這樣：產品再一週左右就要上線，Drew 從業務那邊聽說，最大的幾筆生意都在等 Scheduled Exports（排程匯出）這個功能，事情一下子變急了。
  • 00:43 Drew 不是這個功能的負責人，所以去問負責的人；整個過程是多人（multi-player）一起進行的
    ↳ Drew 不是這個功能的負責人，只好去找負責的人問。影片用 multi-player（多人一起玩）強調：這件事是好幾個人在同一個地方一起推，不是一個人私下跟 AI 聊。
  • 00:43 Nadia tag 了 Claude，Claude 會跟上群組討論串，即時回應大家做出的產品決策
    ↳ thread（討論串）是頻道裡接在某則訊息下面的一串回覆。Nadia tag 了 Claude 之後，它會把前面的討論讀完，大家當下決定了什麼，它就跟著調整。
  • 00:43 Claude 開了 PR，並把變更 land（合併）進去
    ↳ Claude 不只給建議，而是真的動手：它開了 PR，還把改動 land 進去。land 就是正式合併進產品程式碼的意思，這樣改動才算真的上去了。
  • 00:43 Claude 知道這個功能是什麼、該去 codebase 的哪裡改；它會依每個頻道劃定範圍，也掌握每個團隊各自的脈絡
    ↳ codebase 是一個產品全部的程式碼。Claude 知道這個功能要改哪裡。channel（頻道）就是它的工作範圍，每個頻道背後是哪個團隊、有什麼背景，它都清楚。
  • 01:13 隨著工作進行，Claude 會慢慢累積 memory
    ↳ memory（記憶）是 Claude 做事時一路記下來的東西。一起工作得越久，它就越了解這個團隊，大家不用每次都從頭跟它交代背景。
  • 01:13 Claude 知道自己剛 push 的東西會影響上線行銷，讓團隊持續推進，省掉一般跨團隊溝通的延遲
    ↳ Claude 知道自己剛推上去的改動會影響行銷那邊的上線宣傳，所以會一併顧到。平常這種事得工程去找行銷、來回確認，這裡就省下了那段等來等去的時間。
  • 01:13 Priya 不用自己打開 drive，Claude 直接改好了，因為它有自己的帳號和權限
    ↳ drive 指的是團隊放文件的雲端硬碟。Priya 本來得自己打開去改，現在 Claude 直接改好了。它做得到，是因為它有自己的帳號和 permissions（權限，決定能進哪些系統）。
  • 01:13 Claude 能存取哪些系統是按團隊、按頻道設定：在 legal 頻道看得到合約資訊，在 engineering 頻道則能修改 codebase
    ↳ Claude 能碰哪些系統，是按團隊、按頻道分開設定的。同一個 Claude，在 legal（法務）頻道看得到合約，到了 engineering（工程）頻道則能改程式碼。
  • 01:45 如果在 legal 頻道 tag Claude 叫它改 codebase，它不會改；不是因為客氣，而是在那裡它真的看不到 codebase
    ↳ 所以在法務頻道叫它改程式碼，它不會改。原因不是它懂分寸，而是在那個頻道它根本看不到程式碼。這條界線是系統設定好的，不是靠 AI 自己克制。
  • 01:45 Memory 也遵守同樣的界線：在私人頻道或 DM 學到的東西只會留在那裡
    ↳ 記憶也照同一套界線走。DM 是一對一的私訊。Claude 在私人頻道或私訊裡學到的事，只會留在那裡，不會帶到別的頻道去。
  • 01:45 Claude 有自己的帳號，所以每一次使用憑證（credential）都會被記錄下來
    ↳ credential（憑證）是存取系統時用來證明身分的東西，像帳號密碼或金鑰。Claude 用的是自己的帳號，所以它每次用憑證都會留下紀錄，事後查得到是它做的。
  • 01:45 講者建議：先把 Claude 加進一個頻道，tag 它，看看會發生什麼事
    ↳ 講者的建議很簡單：別一開始就大規模導入，先把 Claude 拉進一個頻道，tag 它一次，看看實際會發生什麼事。
📘 術語
Claude Tag（Claude Tag（標記 Claude 功能））：讓 Claude 直接跟你的團隊一起協作；在頻道裡 tag 它就能請它幫忙
tag（標記／點名）：在頻道或討論串中點名 Claude，請它加入工作
pull request (PR)（合併請求）：字幕沒有解釋；只提到 Claude 會開 PR 並把變更 land 進去
land (the change)（把變更合併進去）：字幕沒有解釋；用在「開 PR 並 land 變更」的語境
multi-player（多人協作）：字幕用來強調整個流程是多人一起參與的
thread（討論串）：Claude 會跟上群組討論串，即時回應產品決策
codebase（程式碼庫）：Claude 知道要改 codebase 的哪裡；只有在 engineering 頻道能修改它
channel（頻道）：Claude 的存取權限和 memory 都是依頻道劃分的
memory（記憶）：Claude 在工作過程中累積的記憶；在私人頻道或 DM 學到的只留在那裡
DM（私訊）：字幕沒有解釋；只提到在 DM 裡學到的東西會留在 DM 裡
permissions（權限）：Claude 有自己的帳號和權限，依團隊、依頻道決定能存取哪些系統
credential（憑證）：因為 Claude 有自己的帳號，每一次使用憑證都會被記錄
