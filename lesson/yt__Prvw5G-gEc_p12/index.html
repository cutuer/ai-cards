🧑‍🏫 這段是 Grok 團隊第三天直播做遊戲的過程。遊戲剛上線，他們讓 AI 把一大堆玩家意見分好類，決定先修哪些問題，也順便講了網站貼到社群時的預覽怎麼設定。想知道小團隊怎麼用 AI 處理用戶意見、怎麼讓產品被看見的人，這段很實用。

  • 130:40 玩家透過遊戲內的 feedback 回報問題，團隊會開始檢視並修正；他們知道目前有很多 bug 和需要打磨的地方
    ↳ 玩家在遊戲裡按 feedback（回饋）按鈕回報問題，團隊會一條一條看、再修。他們也承認現在 bug（程式錯誤）很多，很多地方還很粗糙。
  • 130:40 商店機制的問題：第一回合後每回合都重設成同樣的 Gold，玩家每次都在賣一隻 bot、買一隻新 bot、套用一個升級
    ↳ Gold 是遊戲裡的金幣，bot 是玩家操控的機器人角色。第一回合之後，每回合都重新給一樣多的金幣，結果玩家每次都只夠賣一隻、買一隻、加一個升級。
  • 131:15 這樣每回合都在做一樣的動作，商店機制顯得重複，團隊考慮怎麼改善
    ↳ 每回合能做的事都一樣，玩起來沒有變化，很快就會膩。團隊知道這是問題，還在想怎麼改商店的設計。
  • 131:15 Laura 叫自己剛做的 bot 去看 Slack 上的回饋，把它們分類並畫圖表，看問題大多是遊戲玩法還是真正的 bug
    ↳ Slack 是團隊常用的聊天工作軟體，回饋都送到那裡。Laura 叫她剛做好的 AI bot 去讀這些回饋，分類後畫成圖，看問題多半是「玩法不好」還是「程式壞了」。
  • 131:48 試玩發現 bug：把 Gold 全部花光之後會卡住，什麼都買不了，要回報成 issue
    ↳ 他們自己試玩時發現，金幣花光後遊戲會卡住，什麼都買不了。這要記成 issue，也就是在專案的問題清單上登記一筆，之後追蹤修掉。
  • 132:27 有人發現沒有 log out，sign out 按鈕也沒作用；回饋都送到 Slack，而且經過嚴格審核
    ↳ 有人發現網站沒有登出功能，sign out（登出）按鈕按了也沒反應。這些回饋都送進 Slack，而且會先經過嚴格審核。
  • 132:58 透過網路收自由輸入的文字一定要很小心；用戶端會先過濾長度等條件
    ↳ 讓陌生人在網路上隨便打字送進系統，風險很高。所以玩家自己的瀏覽器（用戶端）會先擋一輪，例如字數太長就不收。
  • 132:58 伺服器端會過濾髒話、sanitize 所有使用者輸入來防範 injection attack，再交給 xAI 模型做最後一道 catch-all 防護
    ↳ 他們的主機（伺服器端）會再濾掉髒話，並 sanitize（清洗）所有輸入，防止 injection attack，也就是有人偷塞指令讓系統誤執行。最後再交給 xAI 的模型做最後一道把關。
  • 133:35 另外也做了 rate limiting；有些人收到 429 too many requests，代表伺服器可能開始超載
    ↳ rate limiting 是限制一個人短時間內能送幾次，避免被洗版。有人看到「429 too many requests」，意思是請求太多被擋下，代表伺服器可能快撐不住了。
  • 134:13 使用 AI 時，context 或資料可以是任何形式；玩家回饋就是關於遊戲「哪裡壞了、大家想要什麼」的資料
    ↳ 給 AI 的 context（背景資料）不一定要是文件或程式碼，什麼形式都行。玩家回饋本身就是資料，告訴你遊戲哪裡壞了、大家想要什麼。
  • 134:13 回饋舉例：希望能買額外 Gold（被指出可能變成 pay to win，屬於產品方向要再想）、需要主題、Elo
    ↳ 有人想花錢多買金幣，但這可能變成 pay to win（花錢就能贏），屬於產品方向，要再想清楚。也有人想要主題、Elo（依輸贏算出的實力分數，西洋棋常用）。
  • 134:13 回饋混合了 bug 回報、功能需求和一般意見，所以要先分類
    ↳ 回饋裡混著三種東西：程式壞了、想要新功能、單純的感想。不先分開，很難判斷哪個該先做。
  • 134:43 Laura 讓 Grokbot 把圖表貼到頻道；她喜歡先讓 bot 掃過一輪回饋並分類，這樣能一眼看出主要該修的東西
    ↳ Laura 讓 Grokbot（他們這次用的 AI bot）把圖表貼到頻道。她習慣先讓 bot 把回饋全部掃過一輪、分好類，一眼就看得出最該修什麼，不用自己一條條讀。
  • 135:17 很多人回報 mobile layout 有問題，要最優先修；另外還有只能打 AI、沒有排名配對，以及 Elo 的問題
    ↳ mobile layout 是手機上的版面，很多人說跑版，所以排第一優先。也有人抱怨只能跟電腦打，沒有 matchmaking（依實力幫玩家配對），Elo 分數也有問題。
  • 135:17 這次是很倉促做出來的第一次上線，分類結果有 71 是 bug
    ↳ 這版是趕出來的第一次上線，分類後有 71 則回饋被歸為 bug。
  • 135:48 Laura 認為遊戲工作室剛上線時，最重要的是先處理 bug、穩定性、可靠度和效能問題，不要急著加一堆新功能
    ↳ Laura 的看法是，遊戲剛上線時，先顧好 bug、穩定性（不當機）、可靠度（每次都正常）和效能（跑得順），比急著加新功能重要。
  • 136:27 她覺得最好玩的遊戲都是對打磨體驗毫不放鬆的；回饋中 bug 佔 71，稱讚有 16
    ↳ 她認為最好玩的遊戲，都是把體驗打磨到毫不馬虎的。這次回饋裡 bug 有 71 則，稱讚有 16 則，可見現在該先把壞掉的地方修好。
  • 136:57 團隊正在做其他比較好玩的回饋提交方式，之後可能會 demo
    ↳ 除了現在打字的回饋框，團隊還在做更好玩的回饋方式，之後可能會 demo（現場示範）給大家看。
  • 137:29 Matt 合併了 favicon 的修改，網站現在有正式的 favicon
    ↳ favicon 是瀏覽器分頁上、網站名稱旁邊的小圖示。Matt 把這個修改合併進正式程式碼，所以網站現在有自己的圖示了。
  • 137:29 在瀏覽器開發者工具的 elements 搜尋 og／meta，就能看到 og 標籤；也可以裝 Chrome 擴充功能來看
    ↳ og 標籤是網頁特地寫給社群平台看的資料。在 Chrome 按 F12 打開開發者工具，到 elements 分頁搜「og」或「meta」就看得到，也可以裝 Chrome 擴充功能來看。
  • 137:59 要設好 og title、og description、site name 和圖片；他們做了 v1 版 og image，把連結貼到 Twitter 時就會顯示
    ↳ 要把標題、簡介、網站名稱和預覽圖都填好。他們做了第一版 og image（分享用的預覽圖），所以把網址貼到 Twitter，會自動變成有圖有字的卡片。
  • 138:31 可以用 SEO preview／Open Graph 檢查網站，貼上網址看分享預覽和 meta tags 對不對；他們目前還沒設好
    ↳ meta tags 是藏在網頁裡、說明這個網頁的標籤。用 SEO preview 或 Open Graph 檢查網站，貼上網址就能預覽分享出去的樣子、看標籤對不對。他們目前還沒設好。
  • 139:05 想讓人（之後還有 agent）看到你，就要把這些屬性填好並優化；讓別人知道你產品的第一步，是準確說清楚它是什麼
    ↳ 想被人看見，就要把這些資料填好。之後還有 agent（會自己上網做事的 AI）也會讀這些資料。讓別人認識產品的第一步，是把「它是什麼」講清楚、講準確。
  • 139:41 他們的 coding engine 流程：審核後的玩家回饋加上自己發現的問題→交給 bot 產生 PR→play test bot 試玩驗證
    ↳ coding engine 是他們自建的寫程式流程：審過的玩家回饋，加上自己找到的問題，交給 bot 產生 PR（一份等人審核的程式修改），再讓 play test bot 實際玩一次，確認有修好。
  • 140:11 UI 也在翻新；接下來幾分鐘的目標是盡量多修一些 bug；Twitter 有 476 位追蹤者，帳號還沒認證
    ↳ UI（使用者介面，就是畫面和按鈕）也在改版。接下來幾分鐘的目標是盡量多修幾個 bug。他們的 Twitter 帳號目前有 476 位追蹤者，還沒認證。
  • 140:45 UI redesign 還沒做完；剛開始的專案本來就不會完美，三個人加上不同 agent、不同 prompt 和美術方向，很容易做出低品質產品
    ↳ 介面改版還沒做完。新專案本來就不會完美；三個人各用不同的 agent、不同的 prompt（給 AI 的指令）和美術風格，成品很容易東拼西湊、品質不好。
  • 141:20 如果是更正式的事業會花更多時間打磨；他們刻意極早上線，好讓聊天室一起玩、給回饋，並展示用 Grokbot 三天能做到什麼
    ↳ 如果是正式的事業，會多花時間打磨。但他們故意很早就上線，讓聊天室觀眾一起玩、給回饋，也藉此展示用 Grokbot 三天能做出什麼。
  • 141:20 他們也想展示成立遊戲工作室或公司的幕後：除了產品開發，還要顧好其他支援環節
    ↳ 他們也想讓大家看到開遊戲工作室或公司的幕後：除了做產品本身，還有很多支援的事要顧好。
  • 141:57 Dr. Eggbot 是一個 bot 模板，負責幫 Laura 建立其他 bot；Matt 正在開一個 bot 來看 Lauren 的畫面
    ↳ Dr. Eggbot 是一個 bot 模板（可以重複套用的基本款），專門幫 Laura 做出其他 bot。Matt 則在做一個 bot，讓它能看 Lauren 的螢幕畫面。
📘 術語
play test（試玩測試）：讓使用者實際玩遊戲，再收集他們的回饋
sanitize（清理輸入）：處理所有使用者輸入，避免遭到 injection attack
injection attack（注入攻擊）：字幕只說 sanitize 使用者輸入就是為了防範它
rate limiting（流量限制）：用來確保收到的是好的使用者回饋的機制之一
429 too many requests（請求過多錯誤）：部分使用者收到這個錯誤，表示伺服器可能開始超載
Elo（Elo 積分）：字幕沒有解釋，只說是玩家回饋中很重要的問題
matchmaking（配對機制）：字幕沒有解釋；回饋指出目前只能打 AI、沒有排名配對
favicon（網站圖示）：網站上會顯示的小圖示，這次已經合併上線
og tags / Open Graph（Open Graph 標籤）：og title、description、site name、圖片等，貼連結到 Twitter 時會顯示成預覽
meta tags（meta 標籤）：可以用 SEO preview 網站檢查；要填好，告訴大家你的產品是什麼
PR（Pull Request）：他們的 bot 根據回饋產生 PR，再由 play test bot 試玩驗證
coding engine（程式碼引擎）：他們自建的系統：把回饋交給 bot 產生 PR，再讓 bot 試玩驗證
