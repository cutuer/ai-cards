🧑‍🏫 這段是 Grok 直播第一天的最後 12 分鐘。主持人和來賓 Jenny 一起規劃一場在舊金山辦的快閃活動，討論預算要怎麼拆，以及該讓哪些 bot 分工處理。值得看的地方在於 Jenny 分享了她實際用 AI agent 經營事業的做法，例如讓 agent 整晚起草 email、早上再由人檢查，還有 AI 看合約能做到哪裡。

  • 513:16 預設是一場 100 到 200 位賓客的 pop-up event，主持人說人數是先隨便定的，之後可以改
    ↳ 先假設要辦一場 100 到 200 人的 pop-up event（快閃活動，短期、臨時辦的活動）。人數只是先抓個數字，讓 bot 有東西可以算，之後隨時能改。
  • 513:16 請 bot 協助做預算，預算要包含場地費（venue）和餐飲（food and beverage）
    ↳ 請 bot 幫忙列預算，最基本的兩大塊是 venue（場地費）和 F&B（food and beverage，餐飲費）。就像辦婚宴，也是先想場地和吃的。
  • 513:46 預算也要算人事成本（staffing）：有些場地會附工作人員，有些不會，要看在哪裡辦
    ↳ 還要算 staffing costs（人事成本，也就是現場工作人員的費用）。有些場地的租金已經含人員，有些要自己找，所以這筆錢跟選哪個場地有關。
  • 514:16 行銷預算先列成獨立項目（separate line item），先專心處理辦活動本身的 logistics
    ↳ 行銷費先拆成獨立的 line item（預算表上單獨的一列），不混進活動預算。先專心處理 logistics（場地、餐飲、人力這些實際執行的細節）。
  • 514:16 Jenny：活動宣傳（例如邀請函設計、用 Meta ads 招募報名）放公司行銷預算或活動預算都可以，看公司怎麼規劃
    ↳ Jenny 說，邀請函設計、下 Meta ads（在 Facebook、Instagram 投的廣告）招人報名這類宣傳費，放公司行銷預算或活動預算都可以，看公司習慣。
  • 514:46 判斷方式：看這筆宣傳費只服務這場活動，還是服務整間新創公司
    ↳ 分法很簡單：這筆錢只為這場活動花，就算活動預算；如果同時也在幫整間新創公司打知名度，就歸公司行銷預算。
  • 514:46 決定先不算行銷預算，把問題簡化，先建立一個 baseline，之後再加回去
    ↳ 最後決定先不算行銷費，讓問題單純一點，先做出一個 baseline（基準版預算），之後再把行銷費加回去。
  • 514:46 其他基本成本：要不要音樂、DJ、AV；很多場地在這方面也有不同方案
    ↳ 其他基本開銷還有要不要音樂、DJ、AV（影音設備，像麥克風、喇叭）。很多場地在這方面也有不同的方案可以選。
  • 515:16 因為要向觀眾講解這次 launch，至少要有基本 AV（麥克風加喇叭）；不一定需要整個舞台
    ↳ 活動要向來賓介紹這次 launch（新產品發表），所以至少要有麥克風加喇叭，讓大家聽得到。但不一定要搭一整座舞台。
  • 515:46 bot 和場地協商 RFP 時會看哪些場地有 AV；目標是在同一個場地找齊最多廠商，不然還得另外做 bot 找廠商
    ↳ RFP 是 request for proposal，也就是把需求發給廠商、請對方報價。bot 詢價時會篩出有 AV 的場地，盡量讓一個場地包辦，免得還要另外做 bot 找廠商。
  • 516:16 主持人問：除了場地預算 bot，還應該做哪兩、三個 bot，才能確保活動不出錯
    ↳ 主持人問：除了場地預算 bot，還該做哪兩、三個 bot，才能確保活動不出包？意思是把容易出錯的環節，各交給一個 bot 負責盯。
  • 516:47 Jenny 建議做 permit Grok Bot（處理 red tape 的 bot）：研究執行這場活動在法律上需要什麼，因為 SF 管得很嚴
    ↳ Jenny 建議做 permit Grok Bot，專門處理 red tape（繁瑣的行政手續），去查辦這場活動在法律上要申請哪些許可，因為舊金山（SF）管得很嚴。
  • 517:17 每個城市的法規都不一樣，法規研究對辦活動的人來說很麻煩，用 bot 查各地政策是好主意
    ↳ 每個城市的規定都不一樣，查法規是辦活動的人最頭痛的事。交給 bot 去查各地政策，就像有個助理先幫你把各縣市的規定整理好。
  • 517:17 也可以做內部用的 bot，例如查員工政策等跟政策有關的工作，Jenny 認為 bot 很適合當 source of truth
    ↳ 同樣的概念也能用在公司內部，例如查員工規章。Jenny 覺得 bot 很適合當 source of truth（大家有疑問時統一參考的標準答案來源）。
  • 517:48 policy bot 或許也能幫忙初步看合約（first pass），但主持人說可能還是要找真正的專業意見
    ↳ 這種 policy bot（查政策用的 bot）也許能幫忙把合約做個 first pass（先粗看一遍、抓出問題），但主持人提醒，最後可能還是要找真正的專業人士。
  • 517:48 律師朋友建議把 AI 當成法學院二年級學生等級的審閱者：看得懂法條文字，但不懂實際運作的細節
    ↳ 律師朋友的建議是：把 AI 當成法學院二年級學生。它看得懂條文的字面意思，但沒有實務經驗，不知道現實中實際怎麼運作。
  • 518:18 例如 AI 不知道這個城市、這個產業的行情；適合做合約初審，之後仍要有經驗的人覆核
    ↳ 例如 AI 不清楚這個城市、這個產業的行情和慣例。所以適合讓它先初審合約，再交給有經驗的人把關。
  • 518:49 Jenny 能用很精簡的預算、靠 AI 經營代理商的方法：先由人自己做，照人會怎麼做建起來，再反推（reverse engineer）
    ↳ Jenny 能用很少的預算、靠 AI 經營代理商，方法是：先自己動手做一次，照人會怎麼做把流程建起來，再 reverse engineer（反推）成 AI 能照做的流程。
  • 519:20 收尾目標：找出今晚就能跑的 long-running agents；budget agent 可以先寄幾封 email 推進進度
    ↳ 收尾的目標是找出今晚就能跑的 long-running agents（能長時間自己持續工作的 AI 助手）。例如預算 agent 可以先寄幾封 email，把進度往前推。
  • 519:51 Jenny 建議跑 scout venue searching agent：搜尋、找出場地並起草 email，早上再審核它要寄給哪些人
    ↳ Jenny 建議跑一個找場地的 agent：讓它自己搜尋場地、起草詢問信，但先不要寄出。早上再由人檢查它要寄給哪些人。
  • 519:51 Jenny 最愛的用法：讓 agent 整晚起草 email，早上醒來只要按送出
    ↳ 這是 Jenny 最愛的用法：睡覺時讓 agent 整晚寫信，早上起來檢查一下，沒問題就按送出，省下大把時間。
  • 520:22 還要開始想怎麼讓人來參加：Jenny 讓 agent 存取 Meta，直接登入她的 Instagram
    ↳ 也要開始想怎麼找人來參加。Jenny 讓 agent 存取 Meta，直接登入她的 Instagram 帳號去操作。
  • 520:22 用 agent 建立邀請名單，例如找出在這個城市、追蹤她、且粉絲最多的 50 個帳號
    ↳ 讓 agent 整理邀請名單，例如找出住在這個城市、有追蹤她、而且粉絲數最多的前 50 個帳號。
  • 520:53 名單建好後先起草 outbound 訊息，讓最重要的人來參加，也幫忙宣傳活動
    ↳ 名單好了就起草 outbound 訊息（主動發出去的邀約），先邀最有影響力的人。他們來了，也會順便幫活動宣傳。
  • 520:53 主持人：他們在 X 上有很多觀眾，也可以當邀請來源

    ↳ 主持人稱讚 Jenny 的 sidebar（側邊欄）設定，上面有很多 agents 在幫她經營事業。可惜螢幕分享沒弄成功，之後會把截圖貼出來。

📘 術語
pop-up event（快閃活動）：本段規劃的活動，預計 100 到 200 位賓客
F&B (food and beverage)（餐飲）：活動預算中的餐飲項目
staffing costs（人事成本）：工作人員費用；有些場地會附人員，有些不會
line item（預算項目）：行銷預算先列成獨立項目，不併進活動預算
AV（影音設備）：字幕舉例：麥克風和喇叭是最基本的需求
RFP（需求建議書）：字幕沒有解釋，只說 bot 協商 RFP 時會看哪些場地有 AV
permit Grok Bot（許可證 bot）：研究活動在法律上需要哪些許可的 bot

first pass（初步審閱）：AI 適合先幫忙看一遍合約，之後再由有經驗的人覆核
reverse engineer（反推）：先照人的做法做出來，再反推成 AI 流程
long-running agents（長時間執行的 agent）：可以整晚持續工作的 agent
outbound（主動對外聯繫）：預先起草訊息，主動聯繫場地或邀請對象
