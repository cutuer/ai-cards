🧑‍🏫 這段是 Blender Studio 團隊在 BCON26 分享短片 Singularity 的幕後經驗，由三位講者輪流談：繪師談美術和技術怎麼互相影響，建模師談角色眼睛怎麼做、怎麼修，technical artist 談怎麼用「程序化」做材質和模型。重點不在按鈕怎麼按，而在真實製作中怎麼取捨、怎麼面對做錯重來，任何要和別人協作做東西的人都用得上。

  • 13:10 講者（繪師）表示能從技術成果中觀察到很多小細節，也很期待看這些東西會不會、會怎麼被實作進最終技術
    ↳ 繪師講者說，看技術同事做出來的成果，常能發現很多小細節。她也很好奇自己畫的東西，最後會不會、又會用什麼方式被做進成品。
  • 13:10 2018 年講者參加 Chris Oatley 的 mentorship 畫了一個角色，學會用非常受控的 quadruple-A 動畫工作室風格作畫
    ↳ 2018 年她參加 Chris Oatley 的 mentorship（業界前輩帶學生的指導計畫），學會「quadruple-A」（她用來形容最頂級規格）動畫工作室那種處處嚴格控制的畫法。
  • 13:43 那種作畫方式要求你為每一個 pixel 負責，講者形容這樣很酷，但也很可怕
    ↳ 意思是畫面上每個 pixel（畫面最小的點）都得是你刻意決定的，沒有交給運氣的地方。這很有成就感，但壓力也很大。
  • 13:43 2021 年做 Sprite Fright 時，Andy 要把 Vicky 的頭髮 sculpt 做成實際的 groom，講者主動提議全部用 pixel 畫出來給他參考，被 Andy 婉拒
    ↳ 2021 年做 Sprite Fright 時，Andy 要把頭髮的 sculpt（像捏黏土般雕出的造型）轉成 groom（實際一根根的 3D 頭髮）。她想把完整樣子畫好給他參考，被婉拒了。
  • 14:14 Andy 說最後本來就不會長那樣，讓講者困惑自己的工作到底是什麼
    ↳ Andy 的意思是，3D 頭髮做出來本來就不會和畫的一模一樣，畫到那麼細也用不上。這讓她一時搞不清楚自己該扮演什麼角色。
  • 14:14 講者後來發現是時機不對：美術當時已經給技術夠多啟發，該換技術來啟發 2D 美術，或直接用技術做出最終成品
    ↳ 她後來懂了：不是畫沒用，而是時機不對。前期由美術帶方向，到了那個階段，該換技術反過來給美術新靈感，或直接在 3D 裡把成品做出來。
  • 14:47 講者認為最大的樂趣是參與美術與技術之間的交流，也就是在 CG 這個實際媒材中用技術創作
    ↳ 她覺得最好玩的是美術和技術你來我往。CG（電腦繪圖）本身就是創作材料，不只是把畫稿照抄成 3D。
  • 14:47 團隊是在多個專案中學到這件事，Singularity 是技術上最瘋狂的一部；重點是投入探索過程、順其自然、享受過程
    ↳ 這個體會是累積好幾部片才懂的，而 Singularity 是技術上最大膽的一部。她的建議是別死抓著原稿，投入摸索，讓結果自然長出來，並享受過程。
  • 15:21 第二位講者負責角色製作，具體是 modeling 和 sculpting；很多內容 vlog 和 making-of 已經講過，這次專講眼睛
    ↳ 第二位講者負責角色的 modeling（用點線面搭出模型）和 sculpting（像雕塑般塑出細節）。製作花絮影片已經講過大部分，這次他只談眼睛。
  • 15:51 這段主題是做設計決策，以及講者自己常常重複學到的心得
    ↳ 他要談製作中怎麼做取捨，以及自己每部片都會再犯、再學一次的教訓。
  • 15:51 主角的設計目標之一是身體透明、完全看得穿，這樣眼睛等內部構造都看得到
    ↳ 主角設計成全身透明，觀眾能直接看見眼睛等體內構造，這是角色的一大特色。
  • 16:23 主角的另一個設計目標是卡通比例和表情；兩個想法都很酷，但同時達成有難度
    ↳ 主角同時又要有卡通式的誇張比例和表情。這兩個目標各自都好，放在一起就會互相打架。
  • 16:23 卡通角色常用的技巧是讓眼睛看起來又大又扁，例如 Disney 電影；做法是把眼球做得非常大
    ↳ 卡通角色常讓眼睛看起來又大又扁，Disney 電影很常見。實際做法是放一顆超大的眼球，只露出前面一小塊。
  • 16:55 眼球大到塞不進頭部，會從兩側穿出、插進口腔內部，所以要加 lattice 以非破壞方式把它壓回頭裡
    ↳ 大眼球會從頭的兩側穿出、插進嘴裡，所以用 lattice（包住物體的變形籠，拉籠子就能改形）把它壓回頭內。這是 non-destructively，也就是不動原始模型，隨時能撤回。
  • 16:55 這招通常很好用，但角色是透明的，最多只能把眼睛做成蛋形，無法完全壓扁
    ↳ 一般角色不透明，眼球怎麼被壓都看不到。但這個角色是透明的，壓太扁會被看穿，所以最多只能壓成蛋形。
  • 17:28 最後的解法是圍繞眼睛來設計頭部比例，讓它行得通
    ↳ 於是他反過來做：先確定眼睛的樣子，再依眼睛去調整頭部比例，讓兩者搭得起來。
  • 17:28 另一個技巧是把眼皮做成獨立幾何體，特別適合會交疊的卡通眼睛，做動畫時的形狀控制很大
    ↳ 另一招是把眼皮做成獨立的一塊模型。卡通眼的眼皮常會上下交疊，分開做能讓動畫師很細地控制眼皮形狀。
  • 17:28 團隊以為能用過去做過的 normal fading 和 blending，把眼皮融進臉部其他部分，結果行不通
    ↳ 團隊原本想沿用以前用過的 normal（決定表面受光方向的資訊）漸變與混合，讓獨立的眼皮看起來和臉連成一片，結果這次行不通。
  • 17:58 retopology 通過一個月後才發現：眼皮周圍有銳利的過渡，不會跟著臉部一起動，輪廓上也無法修平滑
    ↳ retopology（重新整理模型網格的佈線）通過一個月後才發現：眼皮邊緣有明顯折痕，不會跟著臉動，從 silhouette（外輪廓）看也修不平。
  • 17:58 另一個問題是眼球會透過臉被看到，看起來很怪
    ↳ 還有一個問題：臉是透明的，眼球會直接透過臉被看見，看起來很怪。
  • 18:30 講者重做了臉部拓樸，花掉排程外沒預期的時間，但最終結果好很多
    ↳ 他只好重做臉部的 topology（網格線怎麼排、怎麼連），多花了排程外沒預期的時間，但成果明顯好很多。
  • 18:30 新做法是一整片連續拓樸，可以直接開合眼睛；缺點是形狀控制較少、可能較難 rig
    ↳ 新做法讓眼皮和臉是同一片連續網格，直接就能開合眼睛。代價是形狀較難細調，也可能較難 rig（裝骨架和控制器讓角色能動）。
  • 18:30 另一個缺點是角色無法眨單眼，因為眼皮是連在一起的，講者稱為「uni-eyelids」
    ↳ 眼皮左右連成一體，所以角色沒辦法只眨一隻眼。他開玩笑叫這個「uni-eyelids」（連體眼皮）。
  • 19:00 新拓樸看起來平滑好看，講者認為最後是正確決定
    ↳ 雖然犧牲了一些功能，新網格平順又好看，他認為最後是對的決定。
  • 19:00 講者每個專案都在重學同一課：別人依賴你的成果和排程時，如何避免錯誤決定和突然的計畫外重做
    ↳ 他說每部片都在重學同一課：當別人要靠你的成果和進度往下做時，怎麼少做錯誤決定、少遇到突然得整個重來。
  • 19:31 解法一是早期測試：定案前多測試，沒確認可行前不要定案
    ↳ 第一招是早點測試。還沒驗證可行之前，不要把做法定下來。
  • 19:31 不要走做完一個任務才交下一棒的 waterfall 結構，要在團隊裡來回丟
    ↳ 別用 waterfall structure（瀑布式：前一人全做完才交給下一人）的流程，應該讓半成品早早在團隊間來回傳。
  • 19:31 可以測試 poses、shading、rigging、grooming，也請 concept artist 做 draw-over 和 paint-over
    ↳ 可以先擺 poses（角色姿勢），試 shading（表面材質和光影）、rigging、grooming，也請概念美術做 draw-over / paint-over（直接在截圖上畫修改建議）。
  • 20:04 多聽團隊各方意見：問「這可行嗎？」，如果不知道是否可行，就去測
    ↳ 多問各崗位的人「這樣做得到嗎？」。如果沒人確定答案，就實際做做看。
  • 20:04 但不可能什麼都測，測過頭會讓人猶豫不決，最終還是必須做決定
    ↳ 但資源有限，不可能什麼都測。測太多會一直猶豫不決，最後還是得拍板。
  • 20:04 解法二是預期會出錯：別人問要多久時，考慮把時間估計加倍甚至三倍
    ↳ 第二招是預設一定會出包。有人問你要多久時，考慮把估計時間放大到兩倍甚至三倍。
  • 20:39 多估的時間若用上了很好；沒用上就拿來做額外 polish 或處理途中冒出的小任務，這種環境更好工作、成果也更好
    ↳ 多估的時間真用上了最好。沒用上，就拿來 polish（修細節、打磨）或處理途中冒出的小事，大家做得輕鬆，成果也更好。
  • 20:39 現實通常是沒有解法：你一定會做錯判斷，但片還是得做完，只能撐過去
    ↳ 他坦白說，多半其實沒有萬全之策：誤判一定會發生，但片還是得做完，只能撐過去。
  • 21:11 每個決定都有利弊，沒有完美工具能讓一切一帆風順；創作工作要拿出毅力，投入時間做出美的東西
    ↳ 任何選擇都有好有壞，也沒有能讓一切順利的神奇工具。創作靠的是毅力，願意花時間，才做得出美的東西。
  • 21:45 Simon 是工作室的 technical artist，通常負責 shading 和特效，這段講程序化（procedural）的做法
    ↳ Simon 是工作室的 technical artist（介於美術和程式之間、替美術解決技術問題的人），平常負責 shading 和特效。這段談 procedural（訂好規則讓電腦自動生成）的做法。
  • 21:45 程序化的目的是用較少力氣增加複雜度、不必全部手工做；Simon 自嘲實際上常變成面對巨大 node graph 的恐懼
    ↳ 程序化的理想是少花力氣、多出細節，不必全部手工做。他自嘲現實常常是對著一大張 node graph（節點圖，把功能方塊連線組成效果）發愁。
  • 21:45 Shading 相對直接：沿用為 Gold 開發的技術，extension 照原樣使用，只在各處做些修正
    ↳ 這次的 shading 相對單純：沿用為先前專案 Gold 開發的技術，extension（擴充功能）原封不動拿來用，只在各處做些修正。
  • 22:17 大部分過程中 Andy、Vivien、Julian 照工具原設計使用，Simon 不太需要介入
    ↳ 大部分時候，Andy、Vivien、Julian 都照工具原本的設計在用，Simon 很少需要插手。
  • 22:17 這個工具也是程序化工作流程的例子：依你的手動輸入自動處理很多事，同時保有大量 artist control
    ↳ 這個工具本身也是程序化的例子：你手動給一點輸入，它自動處理大量工作，同時保留很多 artist control（藝術家可以自己調整的空間）。
  • 22:47 Simon 實驗了不同的 mapping 方法：用球體把貼圖（這裡是筆刷筆觸）貼上去，利用球體對稱性，讓效果不受視角影響
    ↳ 他試了不同的 mapping（決定貼圖怎麼貼到模型表面的方法），用球體把筆觸貼上去。球從哪個方向看都一樣，所以換視角效果也不會走樣。
  • 22:47 這招用在泡泡上，讓它看起來像畫出來的圓圈，不必另外做朝向攝影機的東西，開箱即用；也用在角色的眼睛
    ↳ 泡泡就用了這招，從任何角度看都像畫出來的圓圈，不用另外設定「永遠面向鏡頭」，直接就能用。角色的眼睛也用了這招。
  • 23:24 Simon 參考 Vivien 畫的參考圖來發展 shading，其中包括她提到的不同層次
    ↳ Simon 以美術 Vivien 畫的參考圖為目標來調 shading，包括她提到的顏色層次。
  • 23:55 層次效果在 shader 中取與 silhouette 的距離來做，因為要在任何視角都成立，無法直接畫上去
    ↳ 層次不能直接畫在模型上，因為鏡頭一轉就會錯位。所以 shader（決定表面怎麼上色的程式）依「離外輪廓多遠」即時算出層次。
  • 23:55 這套距離輪廓的設定沿用自 Wing It!
    ↳ 這套「算與外輪廓距離」的設定，是從工作室之前的短片 Wing It! 沿用過來的。
  • 23:55 做法是用程序化方式多次調整 mask 產生多個層次，再微調 shader 的 chroma 等參數，結果和水彩原稿相比相當有說服力
    ↳ 他把距離資料多次轉成不同的 mask（遮罩，決定效果作用在哪裡），疊出好幾層，再微調 chroma（色彩鮮豔程度）等參數，效果很接近水彩原稿。
  • 23:55 為了讓發光部分跳出來，並配合 HDR 和整體外觀，使用 additive glow
    ↳ 為了讓發光處跳出來，並配合 HDR（能表現超亮亮度的高動態範圍）和整體畫風，他用了 additive glow（加法發光，把亮度往上疊加）。
  • 24:27 additive glow 不只是在 shader 裡把透明度和 emission 混合，而是真正疊加，讓一層層筆觸都亮起來
    ↳ 一般做法是在 shader 裡混合透明度和 emission（讓表面自己發光的設定）。他們則是把亮度真正疊加上去，讓一層層筆觸都亮起來。
  • 24:27 建模也用 geometry nodes 加速工作流程、導入程序化方法
    ↳ 建模也用了 geometry nodes（Blender 用節點圖自動生成、修改模型的功能），加快工作速度，把程序化帶進建模。
  • 25:00 只要改基礎模型，上層的 FX 結果就會自動生成，能快速迭代和 retake，不必全部重做，省下很多時間
    ↳ 只要改底層的基礎模型，上面的 FX（特效）會自動重新產生，所以能快速修改和 retake（重做鏡頭），不必全部從頭來，省下很多時間。
  • 25:00 有個角色需要加大量細節，必須決定哪些部分手工建模、哪些程序化；判斷因素很多，一開始很難斷定
    ↳ 有個角色需要加大量細節，得決定哪些手做、哪些交給程序化。要考慮的因素很多，一開始很難判斷。
  • 25:31 判斷因素之一是整體工作量：這個角色大到基本上是一個場景的尺寸
    ↳ 其中一個因素是整體工作量：這個角色大到幾乎等於一整個場景。
  • 25:31 細節要夠獨特才能傳達尺度，又要相對高細節，用程序化做容易得多
    ↳ 細節要各不相同，才能讓人感受到它有多巨大，同時還要夠精細。這種需求用程序化做，比手工容易得多。
  • 25:31 另一個判斷因素是它需不需要動，這會造成很大差別
    ↳ 另一個因素是它需不需要動，會動和不會動，做法差很多。
  • 26:04 難處在於取得平衡：一邊是先把模型做完、程序化之後再說，另一邊是模型已烘入太多資訊，反而妨礙動畫等程序化流程
    ↳ 難處在拿捏平衡：一邊是先把模型做完、程序化以後再說；另一邊是模型裡寫死太多細節，反而卡住動畫等後續的程序化流程。
📘 術語
groom（毛髮整理／毛髮系統）：字幕提到把頭髮的 sculpt 轉成實際的 groom，也就是實際使用的頭髮
sculpting（雕刻）：講者負責的角色製作工作之一，與 modeling 並列
lattice（晶格變形器）：用來以非破壞方式把穿出頭部的大眼球壓回頭內
non-destructively（非破壞性地）：用 lattice 壓回眼球時的做法描述
retopology（重新拓樸）：通過一個月後發現眼皮問題，講者因此重做臉部拓樸
topology（拓樸）：最終改成可直接開合眼睛的一整片連續拓樸
silhouette（輪廓）：眼皮過渡在輪廓上無法修平滑；shader 也取與輪廓的距離來做層次
rig / rigging（骨架綁定）：連續拓樸的缺點之一是可能較難 rig；也是早期要測試的項目
waterfall structure（瀑布式結構）：做完一個任務才交給下一個的流程，講者建議避免
draw-over / paint-over（疊圖修改／疊繪）：請 concept artist 在成果上畫改圖，屬於早期測試的一環
procedural（程序化）：用較少力氣增加複雜度，不必全部手工做
node graph（節點圖）：Simon 自嘲程序化常變成面對巨大節點圖的恐懼
shading（著色）：Simon 負責的領域之一，本片沿用為 Gold 開發的技術
artist control（藝術家控制）：程序化工具自動處理之餘，仍保留給藝術家手動調整的空間
mapping（貼圖映射）：用球體映射筆觸貼圖，利用對稱性讓效果不受視角影響
mask（遮罩）：由距離輪廓的資料程序化調整多次，用來做出層次
chroma（彩度）：做出層次後微調 shader 的 chroma 等參數
additive glow（加成式發光）：不只混合透明度與 emission，而是真正疊加，讓多層筆觸亮起來
emission（自發光）：shader 中的發光成分，一般做法是與透明度混合
geometry nodes（幾何節點）：建模時用來加速工作流程、導入程序化方法
retake（重做）：用 geometry nodes 能快速重做而不必全部重來
