🧑‍🏫 這支影片用一個實際的範例 agent，示範 ChatGPT 裡的 Workspace agents 怎麼替團隊自動處理工作，也說明誰可以限制它能做什麼。如果你打算讓 AI 碰公司資料、幫你發信或開任務，這支影片講的正是怎麼讓它能做事，同時不會亂來。

  • 00:02 Workspace agents 可以全天候為團隊執行重要的工作流程
    ↳ Workspace agents 是放在團隊 ChatGPT 工作區裡的 AI 助手，能自己跑一整套固定流程。重點是不用有人坐在電腦前一句一句下指令，它可以一直替團隊處理例行工作。
  • 00:02 範例是 product feedback Intel agent：從 CRM 蒐集重要的客戶聯絡資訊與產品回饋
    ↳ 範例 agent 負責整理產品回饋。它去 CRM（客戶關係管理系統，公司記錄客戶資料與往來紀錄的地方）撈出重要客戶的聯絡資訊和意見，省下人工翻資料的時間。
  • 00:02 這個 agent 會產出 artifacts，例如 PRD briefs、投影片，並在 linear 等工具中建立可執行的 tickets
    ↳ 它會直接做出 artifacts（成品）：像 PRD brief（產品需求摘要，說明要做什麼、為什麼做）和投影片，還會在任務管理工具 Linear 開好 tickets（待辦任務單），讓大家接手就能動工。
  • 00:02 這個 agent 設定成依排程，每週在 Slack 提供更新
    ↳ 這個 agent 被設定成每週固定時間，自動在 Slack（團隊聊天工具）貼出更新。不用有人記得去問，時間到了它就回報。
  • 00:02 在 Slack 頻道中，agent 會整合團隊各工具裡的聯絡資訊，並主動在團隊共用頻道分享分析，藉此支援產品團隊
    ↳ 它會把散在各工具裡的資訊拼成完整的樣子，再主動貼到團隊共用頻道。它不只在被問的時候回答，也會主動把分析結果送到大家眼前。
  • 00:33 agent 可以回覆更多脈絡並吸收回饋；因為有 memory，下次執行時會套用這些回饋
    ↳ 團隊可以在頻道裡回它、補充背景或指出哪裡不對。memory（記憶功能）讓它記住這些意見，下次跑流程時會照著調整，不用每次重講。
  • 00:33 agent 能存取多個工具與 apps，因此影片接著介紹 agent builder 可用的控管設定
    ↳ agent 能連上的工具越多，能做的事越多，出錯或外洩的風險也越大。所以影片接著說明建立 agent 的人有哪些設定，可以管住它。
  • 00:33 Agent builder 負責決定 agent 能存取哪些資源，以及可以執行哪些動作
    ↳ Agent builder 就是建立和設定這個 agent 的人。他決定 agent 可以看哪些資料、連哪些工具，以及它被允許做哪些事。
  • 00:33 Builder 可以逐一開關特定的讀取（read）與寫入（write）動作
    ↳ 動作分成兩種：read（讀取，例如看信、查資料）和 write（寫入，例如寄信、改資料、開任務）。builder 可以一項一項決定要不要開放，例如只准看、不准改。
  • 00:33 Builder 也能用自然語言設定額外的 action constraints，方式和建立 agent 的流程類似
    ↳ 除了開關，builder 還能直接用一般的句子寫下 action constraints（額外的動作限制），寫法就跟當初用對話建立 agent 一樣，不需要會寫程式。
  • 01:03 範例限制：這個 agent 只能寄信給 openai.com 的收件者，因為它處理的是敏感的客戶與產品資訊
    ↳ 範例的限制是：這個 agent 只能寄信給 openai.com 的收件人。它經手的是敏感的客戶與產品資訊，這條規則可以避免資料被寄到公司外面。
  • 01:03 在 ChatGPT Enterprise 中，管理員可以透過以角色為基礎的存取控制（roles-based access controls），在整個 workspace 統一管理
    ↳ 在 ChatGPT Enterprise（企業版）裡，管理員可以用 roles-based access controls（依角色分配權限）一次管整個工作區，不用一個一個 agent 分別去設。
  • 01:03 管理員決定哪些人可以建立、發布 agent，以及 agent 能存取哪些 apps 和動作
    ↳ 管理員決定哪些人有資格建立 agent、哪些人可以把 agent 發布給大家用，也決定 agent 最多能碰哪些 app、做哪些動作。這是比 builder 更上一層的管控。
  • 01:33 以 Gmail 的 app 設定為例：管理員可以依使用者角色，限制對特定應用程式的存取
    ↳ 以 Gmail 為例，管理員可以依使用者的角色，決定誰的 agent 能連 Gmail、誰的不行。例如某個部門可以用，其他部門就不開放。
  • 01:33 管理員可以對特定 app 的參數與動作設定更進一步的限制
    ↳ 管理員還可以管得更細，針對某個 app 限制特定的參數或動作。也就是說，就算 app 本身開放了，裡面某些操作仍然可以另外鎖住。
  • 01:33 管理員可以設定 human in the loop 確認流程：遇到 ChatGPT 判定為重大的動作時，會先請使用者確認
    ↳ human in the loop 的意思是關鍵步驟要有人把關。遇到 ChatGPT 判定為重大的動作時，agent 會先停下來問使用者，確認後才執行，避免它自己做出難以收回的事。
  • 02:04 總結：有了 Workspace Agents，團隊能加快速度，IT 與管理員也能維持適當的控管
    ↳ 總結來說，Workspace agents 讓團隊把例行工作交給 AI、做事更快，同時 IT 和管理員仍然握有控制權，決定它能做到什麼程度。
📘 術語
Workspace agents（工作區 agent）：能全天候為團隊執行重要工作流程的 agent
CRM（客戶關係管理系統）：範例 agent 從這裡蒐集客戶聯絡資訊與產品回饋
PRD brief（產品需求文件摘要）：範例 agent 會產出的 artifacts 之一
artifacts（產出物）：agent 產出的成果，例如 PRD briefs、投影片
memory（記憶）：讓 agent 吸收回饋後，下次執行時能套用
Agent builder（agent 建置者）：決定 agent 能存取哪些資源、可以執行哪些動作的人
read / write actions（讀取／寫入動作）：builder 可以逐一開關的特定動作
action constraint（動作限制）：用自然語言設定的額外限制，例如只能寄信給 openai.com 收件者
roles-based access controls（以角色為基礎的存取控制）：ChatGPT Enterprise 管理員在整個 workspace 管控誰能建立、發布 agent，以及可用的 apps 與動作
human in the loop（人機協作確認）：ChatGPT 遇到判定為重大的動作時，會先請使用者確認
