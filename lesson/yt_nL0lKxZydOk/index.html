🧑‍🏫 這支影片是幾位使用者分享剛用 GPT-5.5 的第一印象。重點在工作方式的改變：指示不用寫得鉅細靡遺，它也能自己摸清方向、把事做完，所以人可以同時推進很多件事。

  • 00:02 第一印象：GPT 5.5「不一樣」。以前 prompt 得寫得很詳細、很像指令，例如告訴它「去看 code base 的這部分，做這件事」
    ↳ prompt 是你打給 AI 的指示文字；code base 是一個軟體專案的全部程式碼。以前得像帶新人一樣明講「去看哪一段、做哪件事」，它才做得對。
  • 00:02 用 GPT 5.5 時，有時偷懶只給很模糊的任務，它也能自己搞懂
    ↳ 現在就算偷懶，只丟一句模糊的需求，它也能自己推敲出你真正要什麼。你不必先把任務拆好、講清楚。
  • 00:02 它會把研究與探索導向 code base 中正確的區域，可能提出多種做法，再把事情完成
    ↳ 它會自己判斷該去專案的哪一塊找線索，先查清楚再動手，有時還會提出幾種做法。最後它會把事情做完，不是做到一半丟回來給你。
  • 00:33 另一位使用者一拿到 5.5，就為清單上所有事項、甚至還沒開始的點子開 work trees，讓它開始 build
    ↳ work trees 讓同一個專案能同時開好幾個互不干擾的工作區。有人一拿到 5.5，就為每件待辦、甚至還沒開始的點子都開一個，讓 AI 各自開工。
  • 00:33 感受：速度快、反應靈敏，而且真的把事情做完
    ↳ 實際用起來的感覺是回應快、反應靈敏，而且它不是只給建議，是真的把工作做到完成。
  • 00:33 模型智慧提升後，覺得自己跟著模型加快；模型決策更好、code 寫得更好、執行更自主，因此能同時開很多工作
    ↳ 模型判斷更準、程式寫得更好，也比較能自己往下做，人不用一直盯著。所以一次能開很多件工作並行，人的節奏也跟著變快。
  • 00:33 沒料到工程師手邊有這麼多智慧後，湧入如「浪潮」般大量的 pull requests 與變更
    ↳ pull request 是把改好的程式送出去、請團隊審核後再併進專案的申請。工程師手邊的 AI 變強後，送出的改動像浪潮一樣湧進來，多到超出預期。
📘 術語
prompt（提示詞）：字幕未定義；指下給模型的指示，以前需寫得很詳細、像指令
code base（程式碼庫）：字幕未定義；GPT 5.5 會自行把探索導向其中正確的區域
work trees（工作樹）：字幕未定義；講者為清單上每件事開 work trees，讓模型各自開始 build
pull requests（合併請求）：字幕未定義；工程師用 GPT 5.5 後大量湧入的程式變更
✏️ 小考一題

第一位講者說，用 GPT 5.5 時她有時會怎麼下任務？

A. 寫非常詳細、逐步的指令B. 要求它只提出一種做法C. 指定它只看 code base 的某一部分D. 給一個很模糊的任務，讓它自己搞懂
看答案
答案：D。[00:02] 講者說用 GPT 5.5 時有時會偷懶，只給很模糊的任務，它也能自己搞懂；詳細指令是她以前的做法。字幕還提到它可能提出多種做法，所以「只提出一種做法」不對。
