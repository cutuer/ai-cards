🧑‍🏫 這段是 Grok 官方直播的問答時間。講者一題一題回答 Grockbot（幫你實際動手做事的 AI 助手）要怎麼用比較順、比較省錢，最後介紹了來賓 Jenny。如果你已經在用或打算用 Grockbot，這段講的都是很實際的眉角：什麼功能先別碰、什麼時候該開什麼設定。

  • 489:24 提升 computer use 速度的做法之一：用指令直接點選 DOM 裡的元素，不必每次都截圖、判斷、再重來一輪
    ↳ computer use 是讓 AI 像人一樣看畫面、操作電腦。DOM 是網頁背後的元素清單，直接指定某個按鈕去點，就不用每一步都截圖、看圖、再決定。
  • 489:24 另一個做法是持續改進模型，讓它們在 computer use 上更快、更好
    ↳ 除了改操作方式，也從模型本身下手：把模型練得更會操作電腦，判斷更準、繞的路更少，速度自然就上來了。
  • 489:24 講者說要比 API 還快比較難，因為每多加一層，效能本來就會變差；目標是盡量接近 API
    ↳ API 是程式之間直接交換資料的管道，不用經過畫面。AI 去操作畫面等於多繞一層，本來就比較慢，所以目標是盡量接近 API，不是超過它。
  • 490:09 目前有一個功能可以把多個 bot 放進同一個群組聊天，有優點也有缺點
    ↳ group chat 就是把好幾個 bot 拉進同一個聊天室一起工作，有點像開小組會議，好用的地方和麻煩的地方都有。
  • 490:09 優點：bot 們很積極，會主動做很多事，也能互相合作，適合需要大家一起參與的複雜任務
    ↳ 好處是 bot 們很主動，會自己接手、互相分工。遇到需要多方一起想、一起做的複雜任務，這種模式很合適。
  • 490:40 缺點：bot 都很愛講話，放在同一個群組會互相搶話；做的事越多就越貴
    ↳ 麻煩的是每個 bot 都想回話，會互相搶著講。每次回話都在消耗 token（AI 計費用的文字單位），做的事越多就越貴。
  • 490:40 替代做法：讓一個 bot tag 另外兩個 bot 一次，再各自分開工作；講者建議目前先避免使用群組聊天
    ↳ 比較省的做法：讓一個 bot 一次 tag 另外兩個、把事情交代清楚，之後各做各的，不再來回聊。講者建議目前先別用群組聊天。
  • 491:10 官方持續調整，讓 bot 在 browser use、內部 bot 等各種情境下使用合適的模型
    ↳ 官方在調整讓 bot 依情境挑適合的模型，例如 browser use（bot 操作瀏覽器）或 bot 內部運作，各自用合適的模型。
  • 491:10 真正要出貨（shipping）時，目前的做法是透過 Cursor 或 Grock build 使用 cloud agents，可以自己指定要用哪個模型
    ↳ shipping 是把成品正式上線給人用。這時建議透過 Cursor（AI 寫程式工具）或 Grock build 開 cloud agent，也就是在雲端獨立做事的 AI 助手，模型可以自己選。
  • 491:40 也可以設定預設值：直接告訴模型「這類任務每次都用 XYZ 模型」
    ↳ 不想每次都重新挑的話，可以直接跟 bot 講好規則，例如「這類任務一律用某某模型」，之後它就照這個預設來做。
  • 491:40 很少人知道：可以直接傳訊息叫 bot 忘記某些事，例如「忘掉我們怎麼產生你的大頭貼」
    ↳ 很少人知道 bot 記住的東西可以叫它忘掉。直接傳一句像「忘掉我們怎麼做出你大頭貼的」就行了。
  • 491:40 如果 bot 太常引用某段 context，叫它忘記效果不錯，也能提升 token 使用效率
    ↳ context 是 bot 回答時會參考的前情資料。如果它一直重提某段舊內容，叫它忘掉效果不錯，也比較不浪費 token。
  • 492:42 官方內部的 marketplace 網址是 x.ai/botmarketplace（講者說「我想是這個」），目前全部經過官方人工審核
    ↳ marketplace 是 bot 的市集，別人做好的 bot 可以直接拿來用。講者印象中網址是 x.ai/botmarketplace，上面的 bot 目前全部經過官方人工審核。
  • 492:42 bot 範本非常多，官方會挑出最有價值的；取得作者同意後再幫忙最佳化，品質夠好才放上 marketplace
    ↳ 社群做的 bot 範本非常多，官方會挑出最有價值的，徵得作者同意後再幫忙調校，品質夠好才上架。所以上架的都是篩過一輪的。
  • 492:42 判斷一個 bot 好不好，最簡單的方法就是自己試用
    ↳ 介紹寫得再漂亮都不準，最簡單的判斷方法就是自己丟一個任務給它，看做出來的結果合不合用。
  • 493:14 大部分 bot 可以先問一個設定問題，例如「你做什麼、怎麼做」，不必跑完整個流程就能先篩選
    ↳ 不必把整套流程跑完才知道好不好。先問一句「你做什麼、怎麼做」，看它怎麼回答，就能先刷掉不合適的。
  • 493:14 官方 marketplace 上的 bot 大致可以信任：除了人工審核，還有專門審核 bot 的 bot
    ↳ 官方市集上的 bot 大致可以放心用：除了人工看過，還有專門檢查 bot 的 bot 再把關一次。
  • 493:45 不同使用者、不同帳號之間的 bot 互相溝通，目前還做不到，官方正在研究最適合的形式
    ↳ 你的 bot 目前沒辦法跟別人帳號裡的 bot 對話或合作。官方還在研究要用什麼形式開放比較好。
  • 494:36 想同時用本機和 bot 的電腦：到設定開啟 local execution，也可以設成預設允許
    ↳ local execution 是讓 bot 也能在你自己的電腦上做事。到設定裡打開就可以，也能設成預設允許，不用每次都按同意。
  • 494:36 開啟 local execution 後，可以直接從你的電腦傳訊息，也可以讓 bot 操作你的瀏覽器
    ↳ 打開之後，bot 可以從你的電腦傳訊息，也可以直接操作你電腦上的瀏覽器，替你點網頁、做事。
  • 495:07 官方偏向把工作移到 bot 的電腦上，因為他們認為隨著模型和電腦變強，工作交派到裝置外執行才是未來
    ↳ 不過官方比較希望工作放在 bot 自己的電腦上跑。他們認為模型和電腦會越來越強，把工作交到你的裝置以外去做才是未來方向。
  • 495:07 在本機執行的缺點一：某些 app 如果沒處理好，會在你工作時跳到畫面上，讓你沒辦法同時做別的事
    ↳ 缺點一：bot 在你電腦上操作時，有些 app 會突然跳到畫面最前面，把你正在用的視窗蓋掉，你就很難同時做自己的事。
  • 495:37 缺點二：會吃掉你電腦的資源，做高負載工作時特別困擾
    ↳ 缺點二：bot 跑任務會吃你電腦的資源。如果你剛好在做很吃效能的事，例如剪影片，電腦會明顯變卡。
  • 496:09 各個 bot 不共用記憶，但共用同一個檔案系統
    ↳ 每個 bot 各記各的，不知道彼此聊過什麼；但它們共用同一個 file system（檔案系統，就是存檔案的地方），檔案放在一起。
  • 496:09 bot 的電腦其實是一台 VM，每個 bot 各有一個 instance，就像電腦上的不同桌面；需要時 bot 會主動讀彼此的檔案
    ↳ VM（虛擬機）是用軟體模擬出來的一台電腦。每個 bot 各有一份（instance），就像同一台電腦上的不同桌面，需要時 bot 會主動去讀彼此的檔案。
  • 496:09 各個 bot 的 context window 並不相同
    ↳ context window 是 bot 一次能參考的內容範圍。每個 bot 各有一份、內容也不一樣，所以 A 知道的事，B 不一定知道。
  • 497:09 Grockbot 與 Cursor cloud agents 有一等整合：Grockbot 能啟動 cloud agent，並只傳相關的 context 過去
    ↳ Grockbot 跟 Cursor 的 cloud agent 有深度整合：Grockbot 可以自己開一個 cloud agent，而且只把跟任務有關的資料交過去。
  • 497:09 cloud agent 獨立工作後回報結果；只要 Grockbot 有環境的存取權，就能做 QA、測試，甚至直接看 PR 或已出貨的東西
    ↳ cloud agent 做完會回報。只要 Grockbot 有權限，還能做 QA（品質檢查）和測試，甚至直接看 PR（等人審核的程式修改）或已上線的成品。
  • 497:39 適合用 Cursor cloud agent 的情況：任務複雜、要出貨、想完全掌控用哪個模型、想進去大幅修改
    ↳ 適合用 Cursor cloud agent 的時機：任務很複雜、要正式上線、想自己決定用哪個模型，或是你想親自進去大改的時候。
  • 497:39 講者建議多開幾個試試看來培養判斷；把工作交給 cloud agent 的編排做得不錯，只要說一次就好
    ↳ 講者建議多開幾個試試，慢慢就知道哪些事該交出去。交辦的流程做得不錯，你只要講一次，Grockbot 就會自己安排。
  • 498:09 有一個挑戰活動可以贏得 Starbase 之旅，挑戰貼文已經發布
    ↳ 直播宣布了一個挑戰活動，贏的人可以去 Starbase（SpaceX 的火箭基地）參觀，挑戰貼文已經發出來了。
  • 498:51 得獎者還可以帶一位同行者（plus one）
    ↳ 得獎的人還可以多帶一個人一起去，也就是英文說的 plus one。
  • 500:08 來賓 Jenny：帶領一個女性用 AI 建造與探索的社群，背景包含創投、科技與社群經營，在多個平台、頻道和形式上經營媒體事業
    ↳ 來賓 Jenny 帶領一個女性一起用 AI 做東西、探索的社群。她待過創投、科技業，也做過社群經營，還在多個平台經營自己的媒體。
  • 500:38 直播主軸是打造一個由 Grockbot 驅動的事業；Jenny 是 Grockbot 的活躍使用者，受邀分享使用經驗
    ↳ 這場直播的主題是用 Grockbot 撐起一門生意。Jenny 本身常用 Grockbot，所以被找來分享實際的使用經驗。
  • 501:10 Jenny 除了是 VC，也是全職創作者
    ↳ Jenny 除了是 VC（創投，投資新創公司的人），同時也是全職創作者，兩種身分都有。
📘 術語
DOM（文件物件模型）：字幕只提到可以用指令點選 DOM 裡的元素，不必先截圖再判斷
computer use（電腦操作）：字幕提到官方正在讓模型在 computer use 上更快、更好
API（應用程式介面）：字幕說要比 API 更快比較難，因為多加一層效能就會變差
token optimization（token 最佳化）：控制 bot 的花費與效率；群組聊天可能會很貴，叫 bot 忘記事情則有助於 token 效率
group chat（群組聊天）：把多個 bot 放在一起合作，但它們會互相搶話、變得很貴
cloud agent（雲端代理）：透過 Cursor 或 Grock build 使用，可以自己指定模型，獨立工作後回報結果
marketplace（bot 市集）：官方內部市集，上面的 bot 都經過人工和 bot 審核
local execution（本機執行）：在設定中開啟，可以從你的電腦傳訊息、操作你的瀏覽器
VM（虛擬機）：bot 的電腦是一台 VM，每個 bot 各有一個 instance，就像不同的桌面
file system（檔案系統）：各個 bot 共用檔案系統，可以讀彼此的檔案
context window（上下文視窗）：各個 bot 的 context window 不同，也就是不共用記憶
QA（品質檢查）：Grockbot 可以對 cloud agent 做出來的成果做 QA、測試
PR（Pull Request）：字幕提到 Grockbot 可以去看 PR 或已出貨的東西，並直接處理
✏️ 小考一題

根據影片，多個 Grockbot 之間的記憶與檔案是怎麼運作的？

A. 記憶和檔案系統都完全獨立，無法讀取彼此的檔案B. 不共用記憶，但共用同一個檔案系統C. 共用記憶，但各自有獨立的檔案系統D. 記憶和檔案系統都共用
