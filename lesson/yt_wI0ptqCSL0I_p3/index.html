🧑‍🏫 這段是影片的最後一部分，講怎麼讓 Claude 做事時不用你一直在旁邊盯著。講者給了三個方法：讓 Claude 自己檢查結果、同時開好幾個 Claude 並管好它們、讓例行工作定時自動跑。如果你常覺得每一步都得回去看 AI 做得對不對，這段講的就是怎麼把自己從這個狀態裡解放出來。

  • 24:44 Demo：Claude 寫了程式、遇到問題，再寫更多程式修掉，這樣反覆循環，直到達成良好狀態
    ↳ verification loop（驗證迴圈）是 Claude 寫完程式後自己檢查，發現問題就改，改完再檢查，一直重複到結果沒問題為止。整個過程不需要你每一步去喊停。
  • 25:35 畫面出現彩帶效果，Claude 成功修好了自己的 lint errors；因為時間不夠，講者沒讓 demo 跑完
    ↳ lint errors 是檢查工具抓出來的程式寫法問題。畫面上灑彩帶，表示 Claude 自己把這些問題全部修好了。demo 沒跑完只是因為時間不夠，不是出了狀況。
  • 25:35 給 Claude 對的指示和工具，它就能靠 verification loop 在任務上持續 hill climb（一步步改進）
    ↳ hill climb 的意思是一步一步往更好的方向推進。關鍵不在 Claude 多聰明，而在你有沒有給它清楚的指示和能檢查結果的工具，它才知道該往哪個方向改。
  • 26:07 重點：先手把手教 Claude 怎麼做驗證；教會之後，它能把學到的東西整理成 skill file，讓你打包、分享出去
    ↳ 一開始你得親自教 Claude 怎樣檢查才算做對。教會之後，它能把這套做法整理成 skill file，也就是可以重複使用的說明檔，打包分享給別人，其他人就不用從頭教。
  • 26:42 掌握驗證之後，就能進一步 multi-Clauding（平行處理工作）；問題是每個 Claude instance 都在搶你的注意力，而注意力很有限
    ↳ multi-Clauding 是同時開好幾個 Claude，每一個叫一個 instance，各做各的事。Claude 能自己驗證，你才敢放手多開。但這時瓶頸就變成你，因為每個都可能停下來等你。
  • 26:42 講者自己的經驗：同時開超過 4～5 個 session，腦袋負擔就很重，很難再多開
    ↳ session 是開一次 Claude Code 的一段工作。講者同時開到四、五個就覺得很吃力。可見限制多開的不是電腦效能，而是一個人顧得過來的量。
  • 27:14 這次介紹四種多開策略：Claude Code 桌面 app、agent view（Claude Agents）、在雲端執行 Claude、remote control
    ↳ 講者介紹四種讓多開比較好管的方法：桌面 app、在 terminal（打文字指令的視窗）裡用的 agent view、放到雲端跑、用手機遙控。每一種解決的麻煩不一樣。
  • 27:14 桌面 app 提供 GUI，用起來比較簡單，很容易管理多個 session
    ↳ GUI 是有按鈕、清單可以點的圖形介面。不習慣打指令的人用桌面 app，就能清楚看到開了哪些 session，點一下就能切換。
  • 27:44 喜歡待在 terminal 的人可以用 Claude Agents，在 terminal 裡就能得到桌面 app 的部分好處
    ↳ 如果你習慣在 terminal 裡打指令、不想切到另一個 app，可以用 Claude Agents。它讓你不離開 terminal，也能得到類似桌面 app 的總覽清單。
  • 27:44 在官網上執行 Claude，它就會跑在 Anthropic 的雲端，而不是你的筆電
    ↳ 從官網開 Claude 的話，程式是在 Anthropic 的伺服器上跑，不會用到你筆電的電力和效能。
  • 27:44 remote control 是講者最喜歡的功能
    ↳ 講者最喜歡的是 remote control，因為它讓你離開電腦也能繼續接手工作。後面幾點會說明用法。
  • 28:14 桌面 app 左邊的 sidebar 會列出所有介面上的 session：本機 terminal、雲端、各個 Git repo 的都有，是管理 session 的中央控制台
    ↳ Git repo 是存放一個專案程式碼和修改紀錄的地方。桌面 app 左側的 sidebar 會把本機、雲端、各個專案的 session 全部列在一起，是總控台，不用到處找視窗。
  • 28:14 session 可以釘選、重新命名、設定顏色，這些功能都是為了幫你省注意力
    ↳ 釘選、改名、上色看起來都是小功能，但目的是讓你一眼看出哪個 session 重要、在做什麼，少花腦力去回想。
  • 28:45 把 session 改成你記得住的名字，之後回來看就知道它在做什麼
    ↳ 例如不要讓它叫「新對話 3」，改成「修登入頁錯誤」。隔一小時回來，看名字就知道它在做什麼，不用重讀整段內容。
  • 29:15 講者以前在 terminal 多開的做法：用 Tmux 開四個窗格，每個窗格跑一個不同的 worktree；行得通，但要管的東西很多
    ↳ Tmux 是把一個 terminal 切成好幾個窗格的工具。worktree 是替同一個專案另開一份獨立的工作資料夾，讓不同任務互不干擾。這樣做能多開，但全部要靠自己管。
  • 29:15 現場調查：很多人知道 Tmux，知道 worktree 的大約 50%
    ↳ 現場只有約一半的人知道 worktree。可見這種多開做法連對工程師來說都偏進階，所以才需要更簡單的管理工具。
  • 29:46 Claude Agents 大約一週多前才推出；原本輸入 claude，改成輸入 claude agents 就能打開，畫面跟桌面 app 的 sidebar 很像
    ↳ Claude Agents 是一週多前才推出的新功能。平常輸入 claude 會開一個 session，改成輸入 claude agents 就會打開總覽畫面，長得很像桌面 app 的左側清單。
  • 29:46 Claude Agents 的畫面會列出所有在你本機電腦上執行的 session
    ↳ Claude Agents 只管你這台電腦上正在跑的 session。它把這些 session 集中列出來，你就不用在一堆 terminal 視窗之間翻找。
  • 30:18 session 會依照需要你注意的程度排序：卡在 permission prompt、提問或等你輸入的排最上面，還在跑或已完成的排在下面
    ↳ permission prompt 是 Claude 要做某個動作前，先問你准不准。清單會把卡住等你的 session 排在最上面，你只要從上往下處理，就不會漏掉正在等你的那個。
  • 30:18 Claude Agents 一樣可以釘選、重新命名、調整 session 順序，幫你管理工作量和注意力
    ↳ Claude Agents 跟桌面 app 一樣可以釘選、改名、調整順序。這些功能都是在幫你決定先處理哪個，把有限的注意力花在對的地方。
  • 30:53 Claude Code on the Web 的主要目的，是讓 Claude Code session 不再綁在你的筆電上
    ↳ Claude Code on the Web 是網頁版的 Claude Code。session 跑在雲端，不需要你的筆電一直開著、一直連著網路。
  • 30:53 講者的痛點：在會議之間走動時得一直開著筆電；開車回家時車上沒網路，也不能讓筆電一直開著
    ↳ 講者實際遇過的麻煩：在會議之間走動時，得捧著開著的筆電；開車回家時車上沒網路，筆電也不能一直開著，工作就會中斷。
  • 31:24 session 跑在雲端，就不用煩惱實際用的是哪台機器的運算資源；到 claude.ai/code 就能輕鬆開始
    ↳ session 在雲端跑，運算由雲端負責，你不用在意實際用的是哪台機器。直接打開 claude.ai/code 就能開始用。
  • 31:24 remote control 讓你用手機控制任何介面上正在執行的任何 session
    ↳ remote control 讓你用手機操作正在執行的 session，不管這個 session 是在電腦上還是在雲端跑。
  • 31:57 使用方式：在執行 Claude Code session 的地方輸入 /remote-control，session 就會出現在手機 app 上
    ↳ 用法是在正在跑的 session 裡輸入 /remote-control，這個 session 就會出現在手機的 Claude app 上，接著就能用手機接手。
  • 31:57 Claude 需要你幫忙或輸入時，手機會收到通知；你人在車上或做別的事，也能直接回覆它需要的內容
    ↳ 最實用的是通知功能。Claude 卡住、需要你回答時，手機會跳通知。你在車上或忙別的事時回一句，它就能繼續做，不用回到電腦前。
  • 32:28 因為時間不夠，講者跳過了原本要展示 Claude Agents 的 demo，並建議大家試試看
    ↳ 講者因為時間不夠，沒有實際示範 Claude Agents，只建議大家自己試試看。
  • 32:59 就算會多開，還是得自己想好目標、手動開新 session；下一段要講的是怎麼讓自己更進一步退出迴圈
    ↳ 就算會多開，還是得你自己決定要做什麼，再一個一個手動開 session。下一段要再往前一步：讓某些工作連啟動都不用你動手。
  • 33:29 工程師的工作不全是寫新功能或修 bug，很多其實是雜務，例如一直盯著自己的 PR
    ↳ PR（pull request）是把改好的程式碼提出申請，合併進主要專案。工程師有很多時間不是在寫新功能，而是在追這些 PR 後續的瑣事。
  • 33:29 有了 Claude 和 AI，大家產出的 PR 變多了；每個 PR 合併前都要處理 review comments、merge conflicts 和 CI failures
    ↳ 用了 AI 之後 PR 變多了。每個 PR 合併前，都要回覆同事的 review comments，解決 merge conflicts（多人改到同一處），處理 CI failures（自動檢查沒通過）。
  • 33:59 如果一天要合併 20～30 個 PR，光是盯這些 PR 就可能花掉好幾個小時
    ↳ 如果一天要合併二、三十個 PR，每個都要點進去看、回覆、修正，光是追蹤就會花掉好幾個小時，真正想做的事就被擠掉了。
  • 33:59 其他類似的例子：更新文件（出功能速度變快，文件也得跟上）、triage、監看回饋、讓 CI 維持綠燈
    ↳ 類似的例行雜事還有：功能出得快，文件也得跟著更新；triage，也就是把新進來的問題分輕重、決定誰處理；看使用者回饋；讓 CI 的自動檢查保持通過。
  • 33:59 這些每天都要做的事不一定需要你本人參與，只需要有某種迴圈在持續執行
    ↳ 這些事的重點是要有人固定去做，但不一定要是你本人。只要有個機制定時去檢查、處理，就能從你手上拿掉。
  • 34:30 /loop 指令可以讓 Claude Code 每隔固定時間執行一次某個 prompt
    ↳ /loop 是 Claude Code 裡的指令，讓它每隔一段固定時間，自動執行一次同樣的指示（prompt）。
  • 34:30 例：/loop 10 minutes babysit my open PRs，執行這個指令的 session 會每 10 分鐘醒來跑一次這個 prompt
    ↳ 例如輸入 /loop 10 minutes babysit my open PRs，這個 session 就會每 10 分鐘自動醒來一次，去檢查你還沒合併的 PR。
  • 34:30 只要 CLAUDE.md 和工具都設定好，Claude 就能自己判斷該做什麼，你不用再手動盯 PR
    ↳ CLAUDE.md 是放在專案裡、寫給 Claude 看的說明檔，交代規則和做法。只要這個檔案和工具都設定好，Claude 醒來後就能自己判斷怎麼處理，不用你盯。
  • 35:02 Routines 基本上就是在遠端執行的 /loop，跟 Claude Code on the Web 跑在同一種遠端 container 裡
    ↳ Routines 就是在遠端跑的 /loop。它跑在 container 裡，也就是遠端一個隔離好、環境準備好的執行空間，跟網頁版用的是同一種，所以不靠你的電腦。
  • 35:02 設定方式：到 web app 或桌面 app 的 Routines 分頁，就能輕鬆建立新的 routine
    ↳ 到網頁版或桌面 app 的 Routines 分頁，就能直接新增一個 routine。
  • 35:34 routine 可以用時間觸發或事件觸發，兩種都會用指定的 prompt 開一個新的 Claude Code session
    ↳ routine 的觸發方式有兩種：時間到了就跑，或是某件事發生了就跑。每次觸發都會開一個新的 session，執行你事先寫好的指示。
  • 35:34 案例：Claude Code 團隊有一個 routine 每天更新文件，另一個每六小時整理進來的 issues 和回饋，發到 Slack 頻道
    ↳ Claude Code 團隊自己就在用 routine：一個每天自動更新文件，另一個每六小時整理新進來的問題和回饋，發到 Slack（團隊聊天工具）的頻道。
  • 36:07 把驗證、多開、loop／Routines 這三項技巧疊在一起，就能打造出不需要你坐在鍵盤前也能完成大量工作的系統
    ↳ 這三招各管一層：驗證讓結果可信，多開讓工作同時進行，loop 和 Routines 讓工作自己啟動。三招疊起來，你不在電腦前，事情也會繼續推進。
  • 36:40 最終目標：把注意力和時間留給你在乎的任務，其他事情都能高可靠、高信心地交給 Claude
    ↳ 最終目的不是讓你少做事，而是把時間和注意力留給你真正在乎、需要你判斷的工作，其他事情放心交給 Claude。
📘 術語
verification loop（驗證迴圈）：Claude 寫程式、遇到問題、再寫程式修正，一直循環到達成良好狀態
hill climb（爬坡式持續改進）：給 Claude 對的指示和工具，它就能在任務上持續往更好的方向推進
lint errors（程式碼檢查錯誤）：字幕只說 Claude 在 demo 中修好了自己的 lint errors，沒有進一步解釋
skill file（技能檔）：Claude 學會驗證後，可以把學到的東西整理成這個檔案，打包後分享出去
multi-Clauding（多開 Claude）：同時執行多個 Claude instance，讓工作平行進行
session（工作階段）：一次 Claude Code 的執行；可以在本機 terminal、雲端或 Git repo 裡跑
Tmux（終端機視窗管理工具）：講者以前用它開四個窗格，每個窗格跑一個不同的 worktree
worktree（工作樹）：講者以前每個 Tmux 窗格各跑一個 worktree，得自己手動管理
Claude Agents (agent view)（agent 檢視）：輸入 claude agents 打開，在 terminal 裡列出本機所有 session，並依需要注意的程度排序
permission prompt（權限確認提示）：session 卡在這種提示、等你回應時，會排到 Claude Agents 清單的最上面
control plane（中央控制台）：桌面 app 的 sidebar 集中所有 session，成為管理 Claude 的中心
Claude Code on the Web（網頁版 Claude Code）：session 跑在雲端，不綁筆電；到 claude.ai/code 就能開始用
remote control（遠端控制）：輸入 /remote-control 後，就能用手機控制 session，還會收到通知
PR (pull request)（合併請求）：合併前要處理 review comments、merge conflicts 和 CI failures
merge conflict（合併衝突）：字幕列為 PR 合併前必須處理的事項之一
CI（持續整合）：字幕提到要處理 CI failures，並讓 CI 保持綠燈
triage（分流、分類處理）：字幕列為每天都要做、但不一定需要本人參與的例行工作
/loop（定時迴圈指令）：在 Claude Code 裡每隔指定時間執行一次 prompt
CLAUDE.md（Claude 設定說明檔）：和工具都設定好的話，/loop 醒來後 Claude 就能自己判斷該做什麼
Routines（例行任務）：在遠端執行的 /loop，可以用時間或事件觸發，開新 session 並執行指定 prompt
container（容器）：Claude Code on the Web 和 Routines 在遠端執行時所用的環境
