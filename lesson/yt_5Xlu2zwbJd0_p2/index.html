🧑‍🏫 這段接續甜甜圈教學，先用 lattice 把甜甜圈調成真實油炸後中間內凹、不規則的樣子，再帶你第一次算圖，學會擺攝影機，並打開 Eevee 預設關著的 ray tracing。看完你會知道寫實感來自哪些小細節，也能避開新手算圖時畫面很假的常見原因。

  • 11:14 刪掉 lattice 後，模型會回到原本的樣子，所以這是 non-destructive workflow（非破壞性工作流程）
    ↳ lattice 是罩在模型外的一組控制點，拉動這些點，模型就會跟著變形。變形是外加上去的，刪掉 lattice 模型就復原。這種可以隨時反悔的做法叫 non-destructive workflow。
  • 11:14 lattice 的點讓你之後隨時能改變、變形 mesh。例如客戶後來說要改車子比例，你不必重做整個 mesh
    ↳ mesh 是由點、線、面組成的模型本體。有 lattice 在，比例要改時拉幾個控制點就好，不用回頭重建模型。客戶臨時改需求時特別省事。
  • 11:49 lattice 預設是低解析度的方塊。可在下方的 data property 調高 resolution，重點是在中間加一條
    ↳ lattice 預設很粗，只有角落幾個點。到下方 data property（物件資料設定）把 resolution（分段數）調高，重點是讓中間多一排點，才能單獨調整中間那圈。
  • 11:49 看甜甜圈參考圖會發現：除了形狀凹凸不平，中間那圈通常比較白，也比較不蓬
    ↳ 看真實甜甜圈的照片會發現，形狀本來就不平整。中間繞一圈的帶狀部分通常比較白，也比較扁，這就是做出寫實感的線索。
  • 12:19 原因在炸法：甜甜圈半泡在油裡，炸完一面再翻面。靠近油面的油溫度較低，所以中間那圈熟度較低
    ↳ 甜甜圈是半泡在油裡炸的，一面炸好再翻面。中間那圈剛好在油面附近，那裡油溫較低，所以炸得比較不熟。
  • 12:19 因此中間那圈顏色較淺、較不蓬。甜甜圈不會是完美的圓，中間通常幾乎是內凹的
    ↳ 結果就是中間那圈顏色淺、膨得少。所以真實的甜甜圈不是完美圓環，側面中間常常微微往內凹。
  • 12:52 選取中間的點要用 Shift 逐一選，不能 Alt-click 環選，因為 lattice 技術上不是 mesh
    ↳ 一般模型可以用 Alt-click 一次選整圈，但 lattice 技術上不算 mesh，這招不能用。只能按住 Shift，一個一個點選中間的點。
  • 12:52 先關掉 proportional editing，再把中間的點往內縮放
    ↳ proportional editing 是移動一個點時，周圍的點會依距離跟著一起動的功能。這裡要先關掉，只讓選到的中間點往內縮，上下才不會被牽動。
  • 12:52 這是眼睛不會特別注意到的細節，但能增加寫實感。大家以為甜甜圈是正圓，其實中間是內凹的
    ↳ 這種內凹觀眾不會刻意注意，但少了它就會覺得哪裡怪怪的。大家印象中甜甜圈是正圓，實際上中間是內凹的，照實做才像真的。
  • 13:22 還可以把某些區域拉高，做出一側比較蓬的效果
    ↳ 除了往內縮，也可以挑某些區域的點往上拉，讓甜甜圈一側比較膨，模擬真實油炸時膨脹不均勻的樣子。
  • 13:22 lattice 不如直接改底下的 torus 精細，做不了小細節或 sculpt，但應急夠用
    ↳ torus 是甜甜圈底下的環形模型，直接改它能做很細的細節。sculpt 是像捏黏土一樣雕刻模型。lattice 做不到這麼細，但調整大形狀夠用。
  • 13:22 隱藏盤子的方法之一：點 outliner 上的眼睛圖示（講者先口誤說成 eyedropper，隨即更正）
    ↳ outliner 是列出場景所有物件的清單面板。點盤子旁邊的眼睛圖示，就能把盤子藏起來，方便專心看甜甜圈的底部。
  • 13:57 也可以在 viewport 選物件後按 H 隱藏、按 Alt + H 顯示回來，這組快捷鍵值得記
    ↳ viewport 是中間操作 3D 場景的主畫面。在這裡選取物件後按 H 隱藏，按 Alt+H 全部顯示回來。比去清單點眼睛快，很常用，值得記住。
  • 13:57 底部也要處理：甜甜圈中間那圈有些地方看起來像微微離開盤面，要跟著調
    ↳ 藏起盤子看底部，會發現中間那圈有些地方像微微懸空、沒貼著盤子。要一起調到貼合，看起來才像真的放在盤上。
  • 14:30 雖然只是少量變形，看似多餘，但確實有幫助
    ↳ 底部只動一點點，看起來好像沒必要。但這種小修正累積起來，確實會讓畫面更可信。
  • 15:00 花功夫做這些細節，能讓成品感覺更寫實。講者說這「非常非常重要」
    ↳ 講者強調這「非常非常重要」：寫實感往往不是靠大動作，而是來自這些肯花時間處理的小細節。
  • 15:00 滿意後可以 Apply：選取甜甜圈、按 Apply，再刪除 lattice。形狀就像直接建模一樣固定在模型上
    ↳ Apply 是把 lattice 造成的變形正式寫進模型。選取甜甜圈按 Apply，再刪掉 lattice，形狀就固定下來，就像你親手建模做出來的一樣。
  • 15:00 若要更多細節，可 Shift 選多個物件、進 Edit Mode，用 proportional editing 做更精準的微調
    ↳ Edit Mode 是直接編輯模型點、線、面的模式。想調得更細，可以 Shift 選多個物件一起進入，開 proportional editing 微調，周圍會自然跟著動。
  • 15:35 這步驟會造成差異、很重要，但也是選擇性的，同時藉機介紹更多 Blender 工具
    ↳ 這段變形能讓成品差很多，但不做也能繼續後面的教學。講者同時藉這個步驟，帶你認識更多 Blender 工具。
  • 16:05 目前的灰色畫面叫 3D viewport view，只顯示灰色形狀，沒有陰影、燈光或表面互動，電腦處理起來較省
    ↳ 3D viewport view 就是平常工作時看到的灰色預覽畫面。它只顯示形狀、不計算光影，電腦負擔小，操作起來才順。
  • 16:36 有光線計算、看起來寫實的漂亮影像叫 render。按 F12，或選 Render > Render Image
    ↳ render（算圖）是讓電腦計算光線，產出接近照片的最終影像。按 F12，或從選單 Render > Render Image，就會開始算。
  • 16:36 算出來的畫面跟目前視角不同，因為 Blender 永遠從 camera 視角算圖
    ↳ 算出來的角度跟你眼前的畫面不一樣，因為 Blender 算圖一律使用場景裡攝影機（camera）的視角，而不是你目前看的角度。
  • 17:10 點畫面上的 camera view 圖示，可以透過攝影機看場景
    ↳ camera view 是透過攝影機看場景的視角。點畫面上的攝影機圖示切進去，就能先確認算圖會拍到什麼構圖。
  • 17:10 講者最早學的移動攝影機方法：選取 camera 後按 G 移動
    ↳ 講者最早學的方法很直接：選取攝影機後按 G（移動），把攝影機搬到想要的位置。
  • 17:42 按 G 再按滑鼠中鍵可 dolly，讓攝影機前後推進拉遠。也可以旋轉，或沿 z 軸旋轉來調角度
    ↳ dolly 是讓攝影機沿著鏡頭方向直直往前推或往後拉，按 G 後再按中鍵就能做。也可以旋轉攝影機，或只繞 z 軸（垂直軸）轉來調角度。
  • 17:42 很多新手偏好另一種方法：5.0 版在畫面上有一個按鈕，勾選後能用平常的視角操作來移動攝影機
    ↳ 另一種新手比較愛用的方法：5.0 版畫面上有一個可以勾選的按鈕，勾了之後，用平常轉視角的方式就能直接移動攝影機。
  • 18:16 沒勾選時，一按中鍵旋轉視角，攝影機就會被留在原地
    ↳ 沒勾那個按鈕時，用中鍵轉視角只會改變你自己的觀看角度，攝影機會停在原處，不會跟著走。
  • 18:16 勾選並透過攝影機看時，旋轉、縮放、Shift + 中鍵等操作都能直接擺放攝影機位置
    ↳ 勾選後在攝影機視角下，旋轉、縮放、Shift+中鍵平移都會帶著攝影機一起動，像拿著相機邊看邊取景。
  • 18:16 調好後要記得取消勾選，否則攝影機仍鎖在你的視角上，一旋轉就會跑掉
    ↳ 擺好後要記得取消勾選。否則攝影機會一直綁在你的視角上，之後一轉畫面，調好的構圖就跑掉了。
  • 18:47 Blender 是為環境等大型場景設計的，做小物件時攝影機顯示會太大
    ↳ Blender 的設計是以場景、環境這類大東西為主，所以做甜甜圈這種小物件時，攝影機圖示會顯得超大，擋住畫面。
  • 18:47 在 camera 設定的 Viewport Display 可縮小顯示尺寸。這不影響最終 render，只影響 viewport 顯示
    ↳ Viewport Display 是攝影機設定裡管理顯示方式的選項，把尺寸調小即可。它只影響操作時看到的大小，不會影響最後算出來的圖。
  • 19:18 按 Numpad 0 也能快速進出攝影機視角
    ↳ 按鍵盤右側數字區的 0（Numpad 0），可以一鍵切進或切出攝影機視角，比點圖示快。
  • 19:18 從攝影機按 F12 算圖，畫面仍是灰的，因為預設材質是灰色，但已經有陰影了
    ↳ 從攝影機視角按 F12，畫面還是灰的，因為還沒設定材質，預設就是灰色。但跟預覽畫面比，已經有陰影了。
  • 19:18 按 F11 可以把 render 視窗叫回來
    ↳ 算圖視窗關掉或被蓋住時，按 F11 就能把剛才的算圖結果叫回來。
  • 19:18 第一次開 Blender 就算圖，會先做 shader compilation，顯示類似「Updating shaders」的訊息
    ↳ shader 是決定物體表面怎麼受光、長什麼樣子的程式。第一次算圖時，電腦要先編譯它（shader compilation），畫面會顯示類似「Updating shaders」的訊息，要稍等一下。
  • 19:50 shader compilation 只需做一次，之後算圖會快很多；建立新的 shader 時也需要編譯
    ↳ shader 編譯一次就好，之後算圖會快很多。但每次新建 shader 時還要再編譯，那時候變慢是正常的。
  • 19:50 目前使用的算圖引擎是 Eevee，之後會再介紹
    ↳ Eevee 是 Blender 的算圖引擎之一，也就是負責把場景算成影像的核心程式。目前預設用它，細節講者之後會再介紹。
  • 20:20 現在的算圖沒有細節：現實中會看到盤子邊緣的反彈光，縫隙處也會比較暗
    ↳ 現在的算圖太乾淨了。真實世界裡，光會從盤子邊緣反彈上來，甜甜圈和盤子之間的縫隙也會比較暗，這些效果都還沒出現。
  • 20:20 原因是預設關閉了一個選項：在 render properties 裡，ray tracing 預設是關的
    ↳ 原因是 render properties（算圖設定面板）裡的 ray tracing 預設關閉。ray tracing 是模擬光線實際彈射路徑的計算方式。
  • 20:20 講者認為預設關閉是錯誤，應該改成預設開啟
    ↳ 講者直接表態：預設關閉是錯的，應該一開始就打開。所以你要記得自己手動開啟。
  • 20:50 很多人不喜歡 Eevee，覺得它算出來很假，但開啟 ray tracing 後效果好很多
    ↳ 不少人嫌 Eevee 算出來很假，但打開 ray tracing 之後，畫面質感會明顯提升。
  • 20:50 比較算圖：切換到新的 slot 再算一次，就能保留前一張，按 J 可來回切換，方便比較設定
    ↳ slot 是算圖視窗裡的存放格。切到新的 slot 再算一次，上一張會保留下來，按 J 來回切換，就能直接比較改設定前後的差別。
  • 21:21 開啟 ray tracing 後有 bounce lighting，光打到盤子會反彈上來，縫隙細節更多，整體更寫實
    ↳ bounce lighting 是光打到物體後再反彈，去照亮別的東西。開了 ray tracing 後，盤子反彈的光會照到甜甜圈，縫隙也更有層次，整體更寫實。
  • 21:21 ray tracing 還能帶來反射，之後介紹材質屬性時會示範
    ↳ ray tracing 還能讓物體表面產生反射，這部分講者之後介紹材質設定時才會示範。
  • 21:21 用 Eevee 時應該一直開著 ray tracing
    ↳ 結論很簡單：只要用 Eevee，就一直開著 ray tracing。
  • 21:21 另一個算圖引擎 Cycles 寫實得多，但慢很多。影片最後會比較兩者
    ↳ Cycles 是 Blender 的另一個算圖引擎，畫面寫實得多，但算一張圖慢很多。影片最後會把兩者拿來比較。
  • 21:52 講者說只要 Eevee 設定正確，兩者差距其實微乎其微
    ↳ 不過講者認為，只要 Eevee 設定正確，跟 Cycles 的差距其實很小，所以 Eevee 不該被小看。
  • 21:52 Eevee 是遊戲引擎風格的 rasterized 引擎，速度快；Cycles 是 path trace 引擎，運算量重很多
    ↳ rasterized（光柵化）是遊戲常用的快速畫法，速度快；path trace 會追蹤光線在場景中反覆彈射，運算量重很多。Eevee 屬於前者，Cycles 屬於後者。
  • 21:52 接下來都用 Eevee 示範如何做出好效果，最後再切到 Cycles 看最終結果
    ↳ 接下來講者都用速度快的 Eevee 示範怎麼調出好效果，到最後才切到 Cycles，看最終成品。
📘 術語
lattice（晶格變形器）：罩在物件外的點陣，移動這些點就能事後變形 mesh，刪掉後模型會回復原狀
non-destructive workflow（非破壞性工作流程）：變形可隨時更改或移除，不必重做 mesh
resolution（解析度）：在 lattice 的 data property 裡，用來增加 lattice 的分段
proportional editing（比例編輯）：縮放 lattice 點前要先關掉；在 Edit Mode 中可用來做更精準的微調
torus（圓環體）：甜甜圈底下的模型；直接改它能做到比 lattice 更精細的細節
sculpt（雕刻）：講者說用 lattice 做不到 sculpt 那種小細節
Apply（套用）：把 lattice 的變形固定到模型上，之後就能刪掉 lattice
Edit Mode（編輯模式）：Shift 選多個物件後進入，搭配 proportional editing 微調
3D viewport view（3D 視圖）：只顯示灰色形狀，沒有陰影與燈光，電腦處理較省、較快
render（算圖）：有光線計算、看起來寫實的影像，按 F12 產生
camera view（攝影機視角）：Blender 永遠從攝影機視角算圖，可點圖示或按 Numpad 0 進出
dolly（推軌）：按 G 再按中鍵，讓攝影機直直前後推進拉遠
Viewport Display（視圖顯示）：攝影機設定裡的選項，調整攝影機在 viewport 的顯示大小，不影響最終 render
shader compilation（著色器編譯）：第一次算圖時會出現，所以第一次較慢，之後就快
Eevee（Eevee 算圖引擎）：遊戲引擎風格的 rasterized 引擎，速度快
ray tracing（光線追蹤）：在 render properties 裡預設關閉；開啟後有反彈光、縫隙細節與反射
bounce lighting（反彈光）：光打到盤子後反彈上來照亮物體
slot（算圖欄位）：切換到新的 slot 算圖可保留前一張，按 J 切換比較
Cycles（Cycles 算圖引擎）：path trace 引擎，寫實得多但慢很多，運算量重
rasterized（光柵化）：講者形容 Eevee 是 rasterized 的遊戲引擎風格算圖引擎
path trace（路徑追蹤）：Cycles 的算圖方式，運算量比 Eevee 重很多
✏️ 小考一題

在不同的 render slot 各算一張圖後，要在前後兩張之間快速切換比較，該按哪個鍵？

A. JB. Alt + HC. Numpad 0D. F11
看答案
答案：A。[20:50] 講者說換到新的 slot 再算一次，就能按 J 切回前一張，快速比較設定。F11 是叫回 render 視窗，Numpad 0 是進出攝影機視角，Alt + H 是顯示被隱藏的物件
