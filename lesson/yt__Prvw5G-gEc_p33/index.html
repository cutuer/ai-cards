🧑‍🏫 這段是 Grok 官方 demo 的收尾。講者用一組分工明確的 Grokbot（Grok 的 AI 助理機器人）跑完整套行銷活動，最後再加一個「專案經理 bot」幫他統籌。後半段是使用心得和現場問答。如果你想把 AI 從「問答工具」升級成「幫你做事的隊友」，這段很值得看。

  • 379:51 分析 bot 依品牌、客戶承諾、時段等不同變體整理結果，列出 spend、CTR、CVR 等關鍵指標
    ↳ 分析 bot 把不同版本的廣告（換品牌說法、換對客戶的承諾、換時段）分開比較，看 spend（廣告花費）、CTR（點擊率：看到的人有多少點進來）、CVR（轉換率：點進來的人有多少真的下單）。
  • 379:51 bot 會提出建議；講者可以拿去跟團隊討論，也能引導 bot 代替自己做決定。給 agent 多少決策自由，目前還有討論空間
    ↳ bot 不只給數字，還會給建議。你可以拿去跟同事討論，也可以直接讓 bot 替你拍板。要放手讓 AI 決定到什麼程度，講者說目前還沒有標準答案。
  • 380:23 整個流程很順暢，沒有傳統組織裡常見的依賴關係卡關
    ↳ 一般公司常常是文案等設計、設計等工程，一個人卡住，大家都停擺。這次各 bot 一步接一步做完，沒有這種互相等待的情況。
  • 380:23 已走完的步驟：research、positioning、landing page、推上 prod、在 bot 內建立 campaign（bot 從 Grokbot instance 存取帳號）、跑分析
    ↳ 已完成：研究；positioning（定位：主打什麼、賣給誰）；landing page（廣告點進去的那頁）推上 prod（正式上線環境）；bot 用 Grokbot 裡的帳號開 campaign（廣告活動）；跑分析。
  • 380:53 整個 demo 都得由講者自己居中協調。真正的負擔（tax）在於 context switching、得知道每個 bot 擅長什麼，還要管理整條流程
    ↳ 問題是 bot 之間都靠講者傳話。最累的是 context switching：一直在不同 bot 之間切換，重講 context（背景資訊）。他還得記住誰擅長什麼，並盯著整條流程。
  • 380:53 協調這件事本身也能委派給 Grokbot，所以最後一個 bot 是 project manager
    ↳ 協調本身也是一份工作，可以交給 bot 做。這種統籌叫 orchestration，所以最後加入的是 project manager bot（專案經理 bot），專門管其他 bot。
  • 381:31 指示 project manager 研究整個協調流程並自動化，講者就不必一直在各 bot 之間傳遞 context、資訊和溝通
    ↳ 講者請專案經理 bot 先搞懂他平常怎麼協調，再把這件事自動化。這樣他就不用再當傳聲筒，把 A bot 的結果抄給 B bot。
  • 381:31 要它跟每個 bot 溝通、了解各自的角色，並從過去對話中找出講者插手、給指導或回饋的地方，融入自己的工作方式
    ↳ 它要逐一跟每個 bot 溝通，弄清楚各自負責什麼。還要翻過去的對話，找出講者插手糾正或給意見的地方，變成自己的做事習慣。
  • 381:31 要它全自動啟動三個新 campaign，並傳截圖和進度更新，讓講者隨時掌握狀況
    ↳ 接著請它全自動開跑三個新廣告活動，過程中傳截圖和進度給講者。講者不用追問，也知道現在做到哪。
  • 382:08 要它當唯一窗口：講者只跟 project manager 對話，不再跟其他 bot 直接溝通，省去 context switching
    ↳ 從此講者只跟專案經理 bot 講話，不再直接找其他 bot，就像裝潢只跟統包窗口聯絡，不用自己打給水電、木工。
  • 382:43 project manager 負責協調、交接、分享 context、推動團隊前進；最大價值是不用再同時被五個 bot 的訊息轟炸
    ↳ 專案經理 bot 負責派工、交接、同步資訊、推進度。講者覺得最大的好處，是不用再同時被五個 bot 的訊息淹沒。
  • 382:43 少了這些干擾，就能退一步看全局，把時間和精力放在槓桿最大的地方
    ↳ 不用再處理瑣碎的傳話，才有餘力退一步看整體方向，把時間花在最能拉開成果差距的決策上。
  • 383:14 bot 回報：它現在是唯一窗口，正在研究五個 specialist，並排好三個新 campaign 的 research、positioning、landing page 等流程
    ↳ 專案經理 bot 回報：它已經是唯一窗口，正在了解五個 specialist（專職 bot）各做什麼，也排好了三個新活動的研究、定位、活動頁等步驟。
  • 383:14 它會持續回報，講者可以監看進度，但不必親自參與每一步
    ↳ 之後它會主動回報進度。講者想看隨時能看，但不必每一步都親自參與。
  • 383:49 網站已上線並推到 prod；跟 bot 要 URL 它就會給。全部工作都在 Grokbot workspace 這一個地方完成
    ↳ 網站已正式上線，要網址直接問 bot 就有。從頭到尾都在 Grokbot workspace（Grokbot 的工作區）這一個地方完成，不用開一堆工具。
  • 384:24 心得一：做好 bot 的 scoping。定義一個 bot 就像寫職務說明（job description），等於找一位新隊友
    ↳ 心得一是 scoping（界定 bot 負責的範圍）。設定一個 bot 就像寫徵才的職務說明，先想清楚你要找什麼樣的新同事。
  • 384:54 要釐清 swim lanes 和職責，範圍盡量收窄讓 bot 專精，這樣整個 bot 團隊的效率才會最高
    ↳ 要分清楚 swim lanes（像游泳比賽的水道，各走各的、互不越界）和職責。每個 bot 範圍越窄就越專精，整隊的效率也越高。
  • 384:54 心得二：信任你的 bot。這些隊友積極主動、很想幫你做事
    ↳ 心得二：信任你的 bot。講者說它們很主動、很想幫你做事，別只丟小事給它。
  • 385:25 信任從給足權限開始，例如接上 Slack、email，請它讀完所有訊息和組織歷史，再告訴你它能幫忙接下哪些工作
    ↳ 信任從給權限開始，例如接上 Slack（公司常用的聊天工具）和 email，讓它讀完訊息和過往紀錄，再請它說說能幫你接哪些工作。
  • 385:25 給它權限、丟有挑戰性的任務給它，它的能力會讓你驚訝
    ↳ 權限給夠、任務給難一點，它的表現常會超出你的預期。
  • 385:25 心得三：投資你的 bot，它們會越用越好
    ↳ 心得三：在 bot 身上花心思，它會越用越好，不是設定完就定型了。
  • 385:58 bot 之間的協作會越來越自然（尤其有 prompt 時）；餵越多回饋、context、memory 進步越多，就像帶隊友一樣會累積成效
    ↳ bot 之間的配合會越來越順，有 prompt（你下的指令）引導時更明顯。回饋、context、memory（它記住的過往資訊）給得越多，它進步越多，跟帶新人一樣會累積。
  • 385:58 QR code 連到 bot marketplace，官方會把最好的 bot 模板（像講者展示的那些）放在上面
    ↳ 現場的 QR code 連到 bot marketplace（bot 市集），官方會把最好用的 bot 模板放上去，像講者示範的那些。
  • 386:33 可以自己建 bot、累積 context 和 memory，也可以直接複製別人的。講者做 demo 時就是向全隊徵集最好的 positioning bot、ads bot 等
    ↳ 你可以從零打造自己的 bot，慢慢讓它累積 context 和 memory，也可以直接複製別人做好的。講者這次就是跟全隊徵集最好用的定位 bot、廣告 bot。
  • 387:16 Q&A：demo 裡的行銷 bot 目前還在調整，還沒上 marketplace，之後會放上去；它們是整合 marketplace 上的 bot 和一些內部 bot 而成
    ↳ 有人問 demo 裡的行銷 bot 能不能直接拿來用。答案是還在調整，之後才會上架。它們是市集上的 bot 加一些內部 bot 組合起來的。
  • 387:47 Q&A：哪些事不該讓 bot 自主做？答：把 bot 當隊友，就像新人不會一開始就拿到所有權限，要先給 context、訓練、onboard
    ↳ 有人問哪些事不該讓 bot 自己做。講者說把它當新同事：新人第一天不會拿到所有權限，要先給背景、訓練和 onboard（到職引導）。
  • 388:19 建議循序漸進：先給簡單任務，接一兩個最快拿到 context 的工具，確認它真的有產出價值、而且持續進步
    ↳ 建議一步一步來：先給簡單任務，只接一兩個能讓它最快了解狀況的工具，確認它真的幫得上忙，而且越做越好。
  • 388:49 持續 prompt、給回饋、讓它熟悉你的工作方式和在乎的事，它就能接手更多工作、做到真正自動化
    ↳ 持續下指令、給回饋，讓它摸清你的習慣和在意的點，它就能接更多工作，最後做到不用你盯的真正自動化。
  • 388:49 也有功能和設定可以告訴它：原本要問你許可的事，一律允許（想放寬權限時使用）
    ↳ 想放手的話，也有設定能讓它把原本要問你「可以嗎？」的事一律直接做，等於減少 human in the loop（需要人批准才能往下做的環節）。
  • 388:49 理想狀態：xAI 有工程師手下有成群的 bot 在工作，而且真的把 code 推上 prod
    ↳ 講者描述的理想狀態：xAI 已經有工程師底下帶著一群 bot 工作，而且這些 bot 真的會把程式碼推上正式環境。
  • 389:28 要做到這樣得靠豐富的 prompting、memory 和 context，但一定要從簡單、低風險的事開始，再逐步擴大
    ↳ 要做到這樣，得先累積大量的指令、記憶和背景資訊。而且一定要從簡單、出錯也不嚴重的事開始，再慢慢放大。
  • 390:01 Q&A：行銷人員最大的障礙是不清楚產品能做到什麼。要轉換心態：它不是 Google 搜尋、AI 搜尋或一問一答的 LLM
    ↳ 有人問行銷人最大的障礙是什麼。講者說是不清楚它能做到什麼。它不是 Google 或 AI 搜尋，也不是問一句答一句的 LLM（大型語言模型聊天工具）。
  • 390:32 它的用法是信任它、讓它替你做事。例如團隊常把它接上 Slack，當成訊息的第一道防線
    ↳ 正確的用法是信任它、讓它替你做事。例如團隊常把它接上 Slack，當收訊息的第一道防線。
  • 390:32 它負責 triage Slack、DM、email：重要或緊急的事才通知 Josh，也會直接回覆傳訊息來的人
    ↳ 它會 triage（像急診分診，先分輕重緩急）Slack、私訊和 email：重要或緊急的才通知 Josh 本人，其他的直接回覆對方。

    ↳ 只把它當另一個聊天機器人問問題，價值不大。願意交任務、給背景、測試它能做到哪裡，它才會真的派上用場。

    ↳ 有人問 bot 一定要照公司職位分嗎？講者說也能按 initiative（某個專案或計畫）分，但專案一定有開始和結束。字幕在這裡斷了，後面沒講完。
📘 術語
CTR（點擊率）：字幕沒有解釋，只列為分析報告中的關鍵指標之一
CVR（轉換率）：字幕沒有解釋，只列為分析報告中的關鍵指標之一
spend（廣告花費）：字幕列為關鍵指標之一，沒有進一步解釋
prod（正式環境）：字幕沒有定義，只說 landing page 或網站「push to prod」後就上線了
context switching（情境切換）：講者說這是真正的負擔：得在各 bot 之間切換、傳遞資訊並管理流程
orchestration（協調／編排）：講者在各 bot 之間居中協調整條流程，這件事可以交給 project manager bot
project manager bot（專案經理 bot）：負責協調、交接、分享 context，並成為使用者唯一窗口的 bot
scoping（界定範圍）：像寫 job description 一樣，把 bot 的職責收窄，讓它專精
swim lanes（分工泳道）：字幕沒有單獨解釋，和角色、職責並列，是界定 bot 範圍時要釐清的項目
marketplace（bot 市集）：官方放最好的 bot 模板的地方，可以直接複製使用
human in the loop（人在迴圈中）：提問者提到的情況：仍有許多任務要人醒來後批准才能執行
triage（分流處理）：bot 當第一道防線過濾訊息，重要或緊急的才通知本人，也會回覆傳訊的人
initiative（專案計畫）：分配 bot 的另一種方式；講者說 initiative 一定有開始和結束
✏️ 小考一題

講者要 project manager bot 做的事中，哪一項是字幕明確提到的？

A. 刪除其他五個 specialist bot，由自己包辦所有工作B. 只負責產出 CTR 和 CVR 報表C. 成為講者唯一的聯絡窗口，講者不再直接跟其他 bot 對話D. 把所有 bot 上架到 marketplace
看答案
答案：C。[382:08] 講者說：I want you to now be my point of contact… I only want to talk to you to save myself the context switching.
