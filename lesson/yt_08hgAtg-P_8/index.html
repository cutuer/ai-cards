🧑‍🏫 這支是 OpenAI 自家員工的分享：一位 solutions engineer 示範她怎麼用 Codex，把「AI 能幫你什麼」從空泛的說法，變成客戶摸得到、看得到的實際成果。就算你不是工程師，也能學到一個重點：要說服別人，就拿對方自己的資料來示範。

  • 00:01 講者 Stephanie Annani 是 OpenAI 的 solutions engineer，這支影片屬於「OpenAI at OpenAI」系列
    ↳ 講者 Stephanie Annani 是 OpenAI 的 solutions engineer，就是懂技術、站在客戶那一端的人，負責幫客戶搞清楚產品能解決他們什麼問題。「OpenAI at OpenAI」系列從名稱來看，是 OpenAI 員工分享自己怎麼用自家工具。
  • 00:01 她認為 solutions engineer 的工作很大一部分不只是做東西，還要了解客戶
    ↳ 她的意思是，這份工作不是悶著頭寫程式、做 demo 就好。要先搞懂客戶的生意，還有他們卡在哪裡，做出來的東西才會真的打中對方。
  • 00:01 客戶想知道的一件事，是 OpenAI 的技術能怎麼改善他們自己的客戶體驗
    ↳ 客戶在乎的不是 AI 有多厲害，而是「用在我身上會有什麼不同」。說得更具體，就是能不能讓他們自己的顧客買得更順、覺得服務更好。
  • 00:01 她請 Codex 幫客戶分析 Trustpilot 上的評論，得到一整套分析，看出客戶的顧客怎麼評價他們
    ↳ Codex 是 OpenAI 的 AI 助手，可以照你的指示寫程式、跑分析。她請 Codex 整理客戶在 Trustpilot 的評論，Trustpilot 是公開的消費者評價網站。Codex 歸納出顧客誇什麼、抱怨什麼。
  • 00:31 接著用 Codex 做出客戶網站的 mockup，直接在他們的網站上示範：顧客要求的修改其實很容易做到
    ↳ mockup 是做來看樣子的示範版網站，不是正式上線的版本。她拿客戶自己的網站，改成顧客要求的樣子，讓客戶親眼看到：這些修改其實不難做。
  • 00:31 客戶很喜歡這種做法，因為它針對客戶自己的挑戰和問題，實際示範技術可以輕鬆處理
    ↳ 比起介紹一般功能，拿客戶自己的評論和網站來示範，對方馬上就懂 AI 能幫上什麼。這比簡報上的通用範例有說服力得多。
  • 00:31 跟 Codex 合作時，有時會出現 Codex 做得非常完美的「頓悟時刻」（epiphany moments）
    ↳ 用久了會碰到某一次，Codex 一下就做得剛剛好，完全是你要的結果。她把這叫「頓悟時刻」（epiphany moments），也就是心裡冒出「對，就是這樣」的那一刻。
  • 00:31 她用 Skills 把這些時刻記下來，變成日後固定工作流程的一部分
    ↳ Skills 是 Codex 用來存下一套做法的功能。她把做得好的做法存起來，變成 workflow（固定做事流程）的一部分，下次不用從頭摸索，直接照同一套做。
  • 01:01 結語：不論你是誰、做什麼、怎麼想，Codex 在任何情境下都能當你的夥伴
    ↳ 她最後想說的是，Codex 不只是給工程師用的。不管你是什麼職位、做什麼工作、習慣怎麼做事，都能找到讓它幫忙的地方。
📘 術語
Solutions Engineer（解決方案工程師）：講者的職稱；她說這份工作不只是做東西，更要了解客戶
Trustpilot（Trustpilot（評論平台））：字幕中 Codex 分析客戶評論時的資料來源
mockup（模型／示意稿）：用 Codex 做出的客戶網站版本，用來示範顧客要求的修改
Skills（Skills（技能））：用來保存 Codex 表現完美的時刻，讓它變成固定工作流程的一部分
workflow（工作流程）：講者日常持續使用的做事流程，Skills 可以把好的做法加進去
