🧑‍🏫 這支影片介紹新版 Codex Cloud：讓 Codex（OpenAI 幫忙寫程式的 AI）在雲端做事，你不用守在電腦前。影片也示範怎麼建立一個設定好、能重複使用、全團隊共用的雲端環境。想把 AI 當成背景幫手的人值得一看。

  • 00:03 任務是在雲端啟動的，所以不必一直開著本機視窗。
    ↳ 任務（task，就是你交給 Codex 的一件工作）在雲端的電腦上跑，不是在你自己的電腦上，所以不用一直開著視窗盯著。
  • 00:35 關掉視窗後任務仍會繼續執行。任務在雲端跑，可以隨時再接回來。
    ↳ 關掉視窗，任務也不會停。之後再打開，可以看到它做到哪裡，然後接著處理。
  • 00:35 可以用手機對執行中的任務追加指示，而且不會中斷任務。
    ↳ 在外面想到要補充什麼，可以直接用手機傳給正在跑的任務。它會照新指示調整，不必停下來重來。
  • 00:35 支援語音：戴上耳機出門散步時，也能開啟語音 session 操作任務。
    ↳ 不方便打字時可以用講的：開一段語音 session（一次語音對話），戴著耳機邊散步邊交代任務。
  • 01:06 任務會自己跑完，完成後通知使用者。
    ↳ 你不用一直守著。任務做完會通知你，到時再回來看結果就好。
  • 01:06 範例：講者找到一台能用真實雷射播放動畫的裝置，請 Astro 研究它的格式並產生 simulator。
    ↳ 講者拿到一台用真實雷射播放動畫的裝置，請 Astro 研究它的檔案格式，並做出 simulator（模擬器，在電腦上模擬裝置效果的程式）。
  • 01:06 講者說靈感隨時會出現，所以希望讓任務在背景建置，自己同時去做其他事。
    ↳ 想法常在不方便寫程式的時候冒出來。講者的做法是先把任務丟到背景去做，自己去忙別的事，兩邊同時進行。
  • 01:37 在 cloud environment 設定頁面可以建立新的環境。
    ↳ cloud environment 是任務在雲端執行時所用的那台電腦的設定。在專門的設定頁面就能新建一個。
  • 01:37 建立時有 chat-based onboarding flow：提供想用的 repo 後，流程會研究這個 repo 在設定上需要什麼。
    ↳ 建立環境時會用聊天方式引導你（chat-based onboarding flow）。你提供 repo（存放專案程式碼的地方），它會自己研究這個專案需要哪些設定。
  • 01:37 可處理進階設定，例如需要的 networking、environment variables 與 secrets。
    ↳ 比較深的設定也能處理，例如 networking（能不能連網、能連到哪裡）、environment variables（程式啟動時讀取的設定值）和 secrets（密碼、金鑰這類機密）。
  • 01:37 分享環境時，可以允許使用者用自己的 secrets 覆寫，方式有 inline 輸入或從個人 vault 帶入。
    ↳ 環境分享給別人時，可以讓對方改用自己的 secrets，不必共用你的。對方可以直接填入，或從個人 vault（存放機密的保管庫）帶入。
  • 02:13 環境發佈後會成為一個具名環境，之後可以在裡面啟動新任務。
    ↳ 設定好之後按發佈，它就會變成一個有名字的環境。之後開新任務，直接選它當起點就好。
  • 02:13 環境是一個 snapshot，所以不必一再重複做設定。
    ↳ snapshot 是把設定好的狀態整個存下來的快照。每個任務都從這份快照開始，不用每次重新安裝、重新設定。
  • 02:13 可以執行多個彼此獨立的任務，都以同一個環境為起點。
    ↳ 同一個環境可以同時開好幾個任務。它們各做各的、互不干擾，但起點都一樣。
  • 02:13 整個團隊都能使用這個環境。講者認為這比以前的做法進步很多。
    ↳ 環境是整個團隊共用的，一個人設好，大家都能用。講者認為這比以前各自設定進步很多。
  • 02:43 任務完成後，仍然可以在這台雲端電腦上繼續使用該任務。
    ↳ 任務做完後，那台雲端電腦不會馬上收掉。你還能在上面接著修改、接著問。
  • 02:43 完成後可以建立 PR 走一般流程，也可以改用全新的 code review flow。
    ↳ 做完後可以開 PR（pull request，把修改提交給團隊審查、通過後再併入的申請），照平常的流程走。也可以改用新的 code review（程式碼審查）流程。
  • 02:43 也可以交給 Dot 處理：建立 PR、確認內容沒問題、進行測試，並標出需要使用者核准的項目。
    ↳ 也可以交給 Dot 處理：它會開 PR、檢查內容、跑測試，並把需要你同意的地方標出來。你只要看那幾處就好。
📘 術語
cloud environment（雲端環境）：用來執行任務的雲端環境，可以設定、發佈成具名環境，並和團隊共用。
task（任務）：在雲端啟動後會持續執行，關掉視窗也不影響，可隨時接回或追加指示。
chat-based onboarding flow（對話式引導設定流程）：提供 repo 後，這個流程會研究該 repo 在設定上需要什麼。
repo（程式碼儲存庫）：字幕未解釋；建立環境時要提供給 onboarding flow 的對象。
networking（網路設定）：字幕列為進階設定之一，指 repo 需要的網路設定。
environment variables（環境變數）：字幕列為 onboarding flow 可以處理的設定之一。
secrets（機密資訊）：可在環境中設定；分享時可讓使用者用自己的 secrets 覆寫。
vault（保管庫）：使用者可以從個人 vault 帶入自己的 secrets。
snapshot（快照）：發佈後的環境是 snapshot，不必重複設定，可作為多個任務的起點。
simulator（模擬器）：範例中請 Astro 為雷射動畫裝置的格式產生的程式。
PR（合併請求（Pull Request））：任務完成後可以建立 PR，走一般流程。
code review flow（程式碼審查流程）：字幕說這是全新的流程，可以取代一般 PR 流程來使用。
✏️ 小考一題

根據影片，cloud environment 發佈後是一個 snapshot，這帶來什麼好處？

A. 不必一再重複做設定，還能當作多個獨立任務的起點B. 讓任務在沒有網路時也能離線執行C. 會自動刪除已完成的舊任務以節省空間D. 會自動把程式部署到正式上線環境
看答案
答案：A。[02:13] 字幕說環境是 snapshot，所以不需要一再重複設定，而且可以執行多個獨立任務，都以這個環境為起點。
