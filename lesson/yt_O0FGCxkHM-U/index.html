🧑‍🏫 這支影片介紹 CLAUDE.md。Claude Code 是 Anthropic 推出、能直接讀寫你電腦裡程式專案的 AI 助手，而 CLAUDE.md 是寫給它看的專案說明檔，讓它記得這個專案。影片說明為什麼有這份檔案，Claude 就能少走冤枉路，也教你怎麼建立和維護，才不會越寫越亂。

  • 00:03 CLAUDE.md 是 Claude Code 最有用的功能之一，它讓 Claude Code 對你的專案有 persistent memory（持久記憶）
    ↳ CLAUDE.md 是寫給 Claude 看的專案說明。persistent memory（持久記憶）的意思是關掉再打開，它還記得專案的基本狀況，不會每次都失憶。
  • 00:03 沒有 CLAUDE.md 時，每次開 Claude Code 都要從頭開始，得重新探索 codebase、搞懂需要哪些 dependencies、有哪些功能已經做好
    ↳ codebase 是整個專案的程式碼，dependencies 是專案要另外安裝的套件。沒有說明檔的話，Claude 每次都得重新翻一遍，才知道用了什麼、哪些已經做完。
  • 00:03 沒有 CLAUDE.md 時，Claude 有時必須自己做假設，比較難把 Claude 引導到正確方向
    ↳ 資訊不夠時，Claude 只能用猜的，例如猜你習慣哪種寫法。猜錯了你就得一直糾正，很難把它帶到你要的方向。
  • 00:35 CLAUDE.md 是放在專案根目錄的 markdown 檔，每次開始 session 時 Claude Code 都會自動讀取
    ↳ markdown 是用 #、- 這類簡單符號排版的純文字格式。session 是從打開 Claude Code 到結束的一段工作。每段開始時，它都會自動先讀這份檔。
  • 00:35 它就像是給你的 codebase 用的 onboarding script（新人導覽手冊）
    ↳ onboarding 指新人到職時的導覽。CLAUDE.md 就像交給 Claude 的新人手冊，寫清楚專案是什麼、東西放哪、規矩是什麼，讓它一上工就進入狀況。
  • 00:35 簡單說，CLAUDE.md 的內容會被附加到你自己的 prompt 後面
    ↳ prompt 是你打給 Claude 的指令。CLAUDE.md 的內容會自動附在你的指令後面一起送出，等於每次都幫你附上背景說明，不用自己重打。
  • 00:35 執行 /init 指令，Claude 會根據你的 codebase 自動產生一份 CLAUDE.md
    ↳ /init 是在 Claude Code 裡輸入的一個指令。執行後 Claude 會先看過你的專案，自動寫出第一版 CLAUDE.md，你再修改就好，不必從零開始寫。
  • 00:35 範例內容：說明這是用 app router、Tailwind、Drizzle ORM 的 Next.js 15 app，並列出啟動 dev server、跑測試、lint 的指令
    ↳ 範例先寫出專案用的技術，例如 Next.js（做網站的框架）和 Tailwind（處理畫面樣式的工具），再列出啟動網站、跑測試、做 lint（自動檢查程式寫法）的指令。
  • 01:06 範例中的 code style 規則：用兩個空格縮排、優先用 named exports、所有 API routes 放在 app/api、能用 server actions 就不用 API routes
    ↳ code style 是寫程式的格式規矩。範例寫明縮排兩格、API routes（網站處理資料請求的接口）集中放在一個資料夾，而且能用 server actions（Next.js 的另一種寫法）就優先用它。
  • 01:06 有了 CLAUDE.md 後，請 Claude Code 做 React component，它就知道要用 Tailwind 或你正在用的其他 CSS framework 來寫樣式
    ↳ React component 是網頁上可以重複使用的一塊畫面，CSS framework 是管理畫面樣式的工具組。有了說明檔，你叫它做元件時，它會沿用專案原本的樣式工具，不會自己換一套。
  • 01:06 Claude 一開始就能把事情做得比較好，不必先花時間搞清楚東西都放在哪
    ↳ 背景資訊已經事先給了，所以 Claude 第一次動手就比較接近你要的，不用先花一輪時間到處翻檔案、搞清楚東西放在哪。
  • 01:37 CLAUDE.md 可以放進 version control 跟團隊共用
    ↳ version control 是記錄檔案每一次修改的系統，常見的是 Git。把 CLAUDE.md 一起放進去，團隊每個人的 Claude 都讀同一份規則，做法就比較一致。
  • 01:37 記憶檔有階層之分，看是給誰用。project-level CLAUDE.md 放在專案根目錄
    ↳ 說明檔分成不同層級，看是給誰用。project-level（專案層級）那份放在專案最上層的資料夾，只對這個專案有效，適合寫專案本身的規矩。
  • 01:37 user-level CLAUDE.md 放在你的設定資料夾，只給你自己用，所有專案都適用；適合放個人偏好，例如你寫程式註解的方式
    ↳ user-level（使用者層級）那份放在你自己的設定資料夾，只有你會用到，但不管開哪個專案都會套用，適合寫個人習慣，例如你喜歡的註解寫法。
  • 01:37 技巧一：如果你得糾正 Claude（例如要它一律用 server actions 而不是 API routes），就明確叫 Claude 把這件事存進 memory，之後回到這個專案它每次都會記得
    ↳ 發現自己在糾正 Claude 時，例如「一律用 A 做法，不要用 B」，就直接叫它把這條存進 memory（記憶）。以後回到這個專案，你就不用再講一遍。
  • 02:07 技巧二：專案裡有想讓 Claude 參考的文件，用 @ 符號加上檔案路徑就可以
    ↳ 專案裡如果已經有規格書、設計說明之類的文件，用 @ 加上檔案路徑指給 Claude，它就會去參考，不用把整份內容複製貼上。
  • 02:07 技巧三：建議剛開始的專案先不要有 CLAUDE.md，觀察自己在哪些地方需要一直修正模型，這樣 CLAUDE.md 能保持精簡，只留下 Claude 用得到的必要資訊
    ↳ 新專案建議先別寫。用一陣子，記下自己一再 course correct（把它拉回正確方向）的地方，再寫進去。這樣檔案精簡，只留下 Claude 真正用得到的。
  • 02:40 Claude Code session 讓人挫折還是很有效率，差別在於 context，而 CLAUDE.md 就是提供 context 的方法
    ↳ context 是 Claude 做事時手上的背景資訊。同一個工具用起來卡卡還是順手，差別就在它知不知道狀況，而 CLAUDE.md 就是把狀況交給它的方法。
  • 02:40 建議先寫你的技術堆疊（stack）、偏好和指令，之後邊做邊補
    ↳ stack（技術堆疊）是專案用到的整組工具和技術。一開始先寫三樣：用了哪些技術、你的偏好、常用指令，其他的等實際用到再慢慢補。
📘 術語
CLAUDE.md（CLAUDE.md 檔案）：放在專案根目錄的 markdown 檔，Claude Code 每次開 session 都會自動讀取，內容會附加到你的 prompt
persistent memory（持久記憶）：CLAUDE.md 讓 Claude Code 記住專案，不用每次從頭開始
codebase（程式碼庫）：你的專案程式碼；沒有 CLAUDE.md 時 Claude 每次都得重新探索
dependencies（相依套件）：專案需要的套件；沒有 CLAUDE.md 時 Claude 得重新搞懂需要哪些
markdown（Markdown 格式）：CLAUDE.md 的檔案格式
session（工作階段）：每次啟動 Claude Code 的一段使用過程；每次開始時都會自動讀取 CLAUDE.md
onboarding script（新人導覽手冊）：用來比喻 CLAUDE.md：就像給 codebase 用的新人導覽
/init（/init 指令）：讓 Claude 根據你的 codebase 產生一份 CLAUDE.md
version control（版本控制）：可以把 CLAUDE.md 放進去跟團隊共用
project-level CLAUDE.md（專案層級 CLAUDE.md）：放在專案根目錄的那一份
user-level CLAUDE.md（使用者層級 CLAUDE.md）：放在設定資料夾，只給你自己用、所有專案都適用，適合放個人偏好
@ symbol（@ 符號）：加上檔案路徑，讓 Claude 參考專案裡的文件
course correct（修正方向）：一直要糾正模型的地方；建議先不寫 CLAUDE.md，觀察哪裡需要修正
context（脈絡）：決定 session 讓人挫折還是有效率的關鍵；CLAUDE.md 就是提供 context 的方法
server actions（server actions）：範例規則之一：能用 server actions 就不用 API routes
