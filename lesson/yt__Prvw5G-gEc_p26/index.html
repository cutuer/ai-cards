🧑‍🏫 這段是 Grok 團隊的直播：他們邊玩自己做的 bot 對戰遊戲，邊把發現的問題和新點子丟給一群 AI agent 處理。值得看的是他們怎麼「派工」給 AI，還建了一套流程，讓玩家回報的問題能自動被修掉。

  • 296:45 切到手機模式（mobile mode）看遊戲，比之前好很多，但 UI 還要調；底部的 ticker 很讚，不過按鈕位置可能要修
    ↳ 手機模式（mobile mode）就是用手機尺寸看網頁。畫面比之前進步，但介面還要調；底部的 ticker（一條會滾動顯示資訊的橫條）很受好評，只是可能擋到按鈕。
  • 297:15 遊戲有 leaderboard，從 X 報名的 1,000 多位玩家都在榜上；已經出現第一位 diamond 等級玩家
    ↳ leaderboard 是排行榜，依成績替玩家排名。從 X 報名的 1,000 多人都已經上榜，也已經有人爬到 diamond（鑽石）這個高階等級。
  • 297:15 主持人提到可以想想要發什麼獎品給排名最前面的玩家，細節之後再決定
    ↳ 團隊在考慮送獎品給排行榜前幾名，讓大家更有動力玩。要送什麼、怎麼送，現場還沒決定，之後再談。
  • 297:47 遊戲裡有意見回饋表單（feedback form），請觀眾繼續填寫
    ↳ 遊戲裡有意見回饋表單（feedback form），讓玩家填問題或建議。團隊靠這些回饋決定接下來修什麼，所以請大家繼續填。
  • 297:47 這款遊戲的類型是 auto-battler：玩家先挑選 bot，組成自己的隊伍
    ↳ auto-battler 是一種遊戲類型：你只在開打前挑角色、組隊，開打後系統自動對戰，不用即時操作。這款遊戲的角色就是各種 bot。
  • 298:18 每個 bot 都有名字、一個隨機分配的能力（ability），還有 attack 和 HP 兩個數值
    ↳ 每個 bot 都有名字，加上一個隨機分到的特殊能力（ability）。attack 是攻擊力，決定打對方多痛；HP 是血量，歸零就倒下。
  • 298:18 每回合要排好出場順序，三個 bot 排成一列，跟對手的 bot 陣容對打
    ↳ lineup 是有順序的陣容。每回合你要決定三個 bot 誰前誰後，排成一列對上對手的陣容，所以怎麼排本身就是策略。
  • 298:52 能力和效果會一個一個依序發動，最後場上剩下最多 bot 的隊伍贏這一輪；三輪贏兩輪就贏整場
    ↳ 開打後，能力和效果是照順序一個一個發動，不是同時亂打。打完場上剩最多 bot 的一方贏這輪，三輪先拿下兩輪就贏整場。
  • 298:52 排陣容要花 gold；有觀眾回饋 10 gold 可能太多或太少，打算請 game design bot 幫忙調整
    ↳ gold 是遊戲裡的錢，排陣容、買卡都要花。有玩家覺得每輪給 10 gold 不太對，團隊打算交給負責遊戲設計的 bot 重新調整數字。
  • 298:52 可以先看到接下來要對上的對手陣容（例如 3-5、3-3）
    ↳ 開打前就能先看到下一個對手的陣容，畫面上會標出像 3-5、3-3 這樣的數字，你可以照著對手的組合調整自己的排法。
  • 299:27 Freeze 按鈕可以先保留一張現在買不起的卡，等下一輪 gold 夠了再買
    ↳ Freeze 等於「先幫我留著」：看到想要但錢不夠的卡，可以先凍結保留，下一輪 gold 夠了再買。
  • 299:57 商店裡的卡都是 3 gold，玩家手上有 10 gold
    ↳ 商店每張卡都是 3 gold，手上有 10 gold，所以一輪最多買三張、還剩 1 gold。錢不夠全買，就得取捨。
  • 299:57 發現 bug：在商店介面看不到自己陣容裡 bot 的能力，而且不只手機版有這個問題
    ↳ 發現 bug（程式錯誤）：在商店畫面看不到自己陣容裡 bot 的能力，玩家就很難判斷該買什麼。而且不只手機版有這個問題。
  • 300:33 新的 voice mode 還沒開放，所以改用語音輸入（dictation）請工程師 bot 開一個 PR 修這個 bug
    ↳ dictation 是語音輸入，把講的話轉成文字。新的語音對話模式還沒開放，所以主持人用講的，請工程師 bot 開一個 PR（提交一份程式修改，審核後併進去）來修。
  • 301:04 主持人很喜歡新動畫，想把視覺效果做得更有野心，也想加音效
    ↳ 主持人很喜歡新加的動畫，希望視覺效果再大膽一點，也想幫遊戲加上音效，讓對戰更有感覺。
  • 301:35 前一晚已經做過音效原型；打算整體做一輪音訊處理並加入音樂，音樂素材放在 Notion team space 的文件裡
    ↳ 音效前一晚已經做了原型（先做出來試效果的版本）。接下來要把聲音整體處理一輪、加上音樂，素材放在團隊 Notion（線上文件工具）的共用空間。
  • 302:05 xAI 負責成長（growth）的 Vincent 建議讓玩家分享勝利，讓遊戲更容易擴散，所以要加分享按鈕
    ↳ growth 是指讓產品擴散、吸引新用戶。負責這塊的 Vincent 建議：玩家贏了會想炫耀，給一個分享按鈕，玩家自己就會幫遊戲宣傳。
  • 302:38 用 potato mode 開一個 cloud agent：在勝利畫面加分享按鈕，並附上 og image（顯示玩家的 bot 隊伍，或用通用的勝利卡），方便發到 X
    ↳ 用 potato mode（影片沒解釋）派一個 cloud agent（在雲端自己跑的 AI 工作者）加分享按鈕。og image 是貼連結到 X 時跳出的預覽圖，會秀出玩家隊伍或勝利卡。
  • 303:10 再開一個 cloud agent：首頁的「sponsor the lobby」表單改成跟 send feedback 一樣，要按按鈕才進入，並確認表單可以正常運作
    ↳ 再派一個 agent 處理首頁的「sponsor the lobby」（贊助大廳）表單：改成跟 send feedback 一樣，要先按按鈕才打開，也要確認表單真的送得出去。
  • 303:45 修「底部 ticker 蓋住按鈕」的 bug 時，可以附截圖讓 bot 更好理解；也可以請 Grokbot 用自己的瀏覽器開遊戲、打開 responsive mode 自己修
    ↳ 修 ticker 擋住按鈕這種版面問題時，附截圖讓 bot 直接看到哪裡不對。或讓 Grokbot 自己開瀏覽器、切到 responsive mode（模擬不同螢幕尺寸）自己看、自己修。
  • 303:45 心法：發現都是自己在做事、bot 沒在做時，就退一步想想怎麼把這件工作交給 bot 或 agent
    ↳ 心法：如果發現一直是你在動手、bot 反而閒著，就該停下來想：這件事怎麼交給 bot 或 agent 做？你的工作是分派，不是全部自己做。
  • 304:25 建議可以設一個 bot 每天提醒你：你是不是介入太多（too much in the loop）？怎麼讓工作流程更自動化？
    ↳ 可以設一個 bot 每天問你：我是不是介入太多（too much in the loop，意思是每一步都要自己經手）？哪些步驟可以改成自動跑？
  • 304:59 prompt 技巧：寫上「before writing any code」先做某件事，例如先跑 ThursdayArena.com 找出確切的 bug 和行為，再開始修
    ↳ prompt 是你給 AI 的指令。寫上「before writing any code」就是叫它先搞清楚問題、別急著改程式，例如先實際跑 ThursdayArena.com 找出確切的 bug 再動手。
  • 304:59 做法：讓一個工程師 bot 當帶頭的人（ringleader），由它派出一堆 cloud agent
    ↳ 不用你自己一個個派任務，而是讓一個工程師 bot 當帶頭的人（ringleader），由它派出一群 cloud agent 去做事。

    ↳ 這些是 Cursor（一款 AI 寫程式工具）的 cloud agent。每個都有自己的虛擬機（雲端上的一台虛擬電腦）和瀏覽器，能像人一樣點網頁、截圖、重現並找出 bug。
  • 305:33 最重要的是 cloud agent 能驗證自己的成果：不只是看程式碼 token，還會去看修正在 prod 上實際的樣子
    ↳ 最關鍵的是它會自己驗收：不只讀程式碼（token 是 AI 處理文字的單位），還會去看正式上線的版本（prod）實際長怎樣，確認真的修好了。

    ↳ 另一位主持人請 Grokbot 建一個 project agent，專門負責 UI（使用者介面，就是畫面和按鈕）的打磨和修 bug，等於指派一個固定負責這塊的人。
  • 306:10 Matt 做了使用者回饋功能：在 ThursdayArena 首頁有 send feedback 按鈕，可以回報 bug 或給意見
    ↳ Matt 做了使用者回饋功能：ThursdayArena 首頁有 send feedback 按鈕，玩家點下去就能回報 bug 或提意見。
  • 306:48 因為收到垃圾訊息，回饋內容規定最少要 20 個字元
    ↳ 因為有人灌垃圾訊息，所以規定回饋至少要寫 20 個字元。門檻很簡單，但能擋掉隨手亂打的內容。
  • 306:48 回饋會送進 Slack，bot 和 agent 會盯著那個頻道，自動重現問題；確認是 bug 就嘗試修正，並自動 merge
    ↳ 回饋會自動送進 Slack（團隊聊天工具）。bot 和 agent 盯著那個頻道，看到回報就自己重現；確認是 bug 就修，再自動 merge（把修改併進正式程式碼）。

    ↳ 現場示範 xAI 的語音 agent：很快就能做出一個會接電話的 AI，玩家打到指定號碼，用講的就能留下回饋。

    ↳ 電話裡講完，回饋幾乎馬上就出現在 Slack 頻道裡，跟打字送出的回饋進到同一個地方。

    ↳ 這個語音 agent 是用 xAI 的 voice workflow builder 做的，這是一個用來建立語音 agent 的工具，重點是做起來很容易。
📘 術語
auto-battler（自走棋類對戰遊戲）：先挑選 bot 組成隊伍，再跟對手的 bot 隊伍對打
leaderboard（排行榜）：報名的玩家都會以某種形式列在榜上，目前已經有 diamond 等級玩家
HP / attack（生命值／攻擊力）：每個 bot 除了名字和能力之外，都有的兩個數值
lineup（出場陣容）：有順序的陣容，三個 bot 排成一列，跟對手的陣容對打
gold（金幣）：排陣容、買卡時要花的資源，目前每輪有 10 gold
Freeze（凍結）：先保留現在買不起的卡，下一輪 gold 夠了再買
PR（合併請求（pull request））：用語音請工程師 bot 開一個 PR 修 bug
cloud agent（雲端 agent）：在雲端執行，有自己的虛擬機和瀏覽器，能重現問題並驗證自己的修正
potato mode（potato mode）：字幕只提到用這個模式開 cloud agent，沒有進一步解釋
og image（分享預覽圖）：分享勝利時附的圖，可以顯示玩家的 bot 隊伍，或用通用的勝利卡
responsive mode（響應式模式）：讓 bot 在瀏覽器裡用這個模式看手機版畫面、修版面問題
ticker（跑馬燈）：遊戲底部的滾動資訊列，目前會蓋住商店的按鈕
dictation（語音輸入）：voice mode 還沒開放，所以改用語音輸入對 bot 下指令
voice workflow builder（語音流程建構工具）：xAI 的工具，可以很容易建立語音 agent

A. 場上剩下的 bot 總 HP 比較高B. 先把對手的 10 gold 耗完C. 三輪中贏兩輪D. 連贏三輪
